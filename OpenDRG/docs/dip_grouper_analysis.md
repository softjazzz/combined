# OpenDIP 分组器逻辑分析

## 概述

OpenDIP 是基于 CHS-DIP（按病种分值付费）标准的分组器。与 DRG 不同，DIP 的分组逻辑**更简单直接** —— 核心是"主诊断 + 主要手术操作"的组合匹配，不涉及 MDC/ADRG 层级分组。

## 与 DRG 的核心区别

| 特性 | DRG 分组 | DIP 分组 |
|------|---------|---------|
| 分组依据 | 主诊断 → MDC → ADRG → DRG（层级） | 主诊断 + 主手术（直接匹配） |
| 分组编码 | 4位字母数字（如 BB11） | 主诊断编码 + 手术编码组合 |
| 组数 | 约 600-1000 组 | 数千个病种组合 |
| 付费方式 | DRG 权重 × 费率 | DIP 分值 × 系数 × 点值 |
| 并发症影响 | CC/MCC 升组 | 不区分 CC/MCC |

## DIP 分组核心流程

```
┌─────────────────────────────────────────────────────────────┐
│                    DIP 分组流程                              │
├─────────────────────────────────────────────────────────────┤
│                                                             │
│  1. 输入：主诊断列表 + 手术操作列表                           │
│     ↓                                                       │
│  2. 质控校验（index.js 中的 _0x4d5151 函数）                 │
│     • 检查主诊断是否有效（排除外因V/W/X/Y编码等）              │
│     • 检查性别一致性（男性/女性专属诊断）                      │
│     • 检查分娩编码规则（O80-O84 需配 Z37）                    │
│     • 检查手术编码有效性（排除附属操作等）                      │
│     • 过滤灰码/无效编码                                       │
│     ↓                                                       │
│  3. 编码版本转换（可选）                                       │
│     • 国临版 ICD → 医保版编码（通过 ZD_MAP/SS_MAP）            │
│     ↓                                                       │
│  4. DIP 分组匹配（CHS_10.js 中的 group_record 函数）          │
│     • 核心匹配：主诊断编码[前5位] + 主手术编码 → DIP 病种     │
│     • 精确匹配失败 → 模糊匹配（诊断3位/1位 + 手术）           │
│     • 输出：DIP编码 + DIP名称 + 基准分值                       │
│     ↓                                                       │
│  5. 费用计算（index.js 中的费用计算函数）                      │
│     • 倍率 = 实际费用 / 均费                                  │
│     • 类型判断：                                               │
│       - 倍率 > 2  → 高倍率病例                                │
│       - 倍率 < 0.5 → 低倍率病例                               │
│       - 其他 → 正常病例                                        │
│     • DIP点数 = 分值 × 系数（按医院等级/地区）                 │
│     • DIP费用 = DIP点数 × 点值                                │
│     • DIP差额 = DIP费用 - 实际总费用                           │
│                                                              │
└─────────────────────────────────────────────────────────────┘
```

## DIP 费用计算公式

从 `index.js` 中反编译的费用计算逻辑：

```python
# 通用公式（大多数地区）
均费 = 分值 × 系数 × 点值
倍率 = 实际费用 / 均费

if 倍率 > 2:    # 高倍率
    DIP点数 = (实际费用/均费 - 1) × 分值 × 系数
elif 倍率 < 0.5:  # 低倍率
    DIP点数 = 实际费用/均费 × 分值 × 系数
else:            # 正常
    DIP点数 = 分值 × 系数

DIP费用 = DIP点数 × 点值
DIP差额 = DIP费用 - 实际费用
```

## 可行性评估：构建新 DIP 分组器

### 已具备条件 ✅
1. **分组流程清晰**：DIP 分组是"主诊断+手术"直接查表，逻辑远比 DRG 简单
2. **质控规则已知**：所有质控校验规则已在 index.js 中完整暴露
3. **费用计算公式已知**：三种倍率类型的计算逻辑已反编译
4. **地区配置参数已知**：系数、点值等参数已提取

### 需要补充的数据 ⚠️
1. **DIP 病种目录（核心）**：主诊断+手术操作 → DIP编码+名称+分值 的映射表
   - 这部分数据在 `CHS_10.js`(409.js) 中，但被混淆，提取难度较 DRG 显著更大
2. **ICD 编码字典**：ZD_INFO / SS_INFO，同样被混淆
3. **国临版↔医保版映射**：ZD_MAP / SS_MAP
4. **灰码/无效编码列表**

### 建议方案
> 用户可以提供新的 DIP 病种目录数据（Excel/CSV 格式），
> 结合已知的分组流程和费用计算公式，即可快速构建 Python DIP 分组器。
> **不需要从混淆的 JS 中硬提取数据**，因为分组逻辑本身很简单——就是查表匹配。
