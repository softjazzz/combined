## 1. 产品概述

### 1.1 背景

随着国家医保局全面推进DRG/DIP支付方式改革，医疗机构面临巨大的运营和管理挑战：

- **支付方式改革压力**：从"按项目付费"转向"按病种/病组付费"，医院需要精细化管理成本
- **编码规范要求**：ICD-10/ICD-9-CM-3编码直接影响入组和支付金额，编码准确率要求极高
- **实时监控需求**：需要在治疗过程中实时掌握费用情况，避免亏损
- **绩效考核转型**：从单纯的业务量考核转向CMI、费用消耗指数等DRG指标

### 1.2 产品定位

本系统是一个基于AI技术的**DRG/DIP全流程决策辅助平台**，覆盖事前预测、事中监控、事后分析三大场景，为医院提供从编码辅助到支付分析的全链路决策支持。

**核心差异化**：
- ✅ **开源分组器**：基于OpenDRG实现，无第三方依赖，支持全国30+省市版本
- ✅ **AI编码辅助**：利用大语言模型辅助编码员工作，推荐ICD编码、校验编码合理性，提高编码效率
- ✅ **实时智能预警**：治疗过程中实时监控费用，提前预警亏损风险
- ✅ **多维度分析**：从科室、医师、病种等5个层级深度挖掘运营数据

### 1.3 目标用户

#### 主要用户角色

| 角色 | 核心诉求 | 使用场景 |
|------|---------|---------|
| **临床医生** | - 入院时快速了解患者预期入组和支付标准<br>- 治疗中实时掌握费用情况<br>- 获得编码优化建议（合规前提下） | 事前预测、事中监控 |
| **病案编码员** | - 自动提取病历信息辅助编码<br>- 编码智能推荐和校验<br>- 提高编码准确率和效率 | 事前预测、编码辅助 |
| **医务科/质控科** | - 监控全院入组情况和盈亏状态<br>- 识别高风险病例和异常费用<br>- 生成质控报告 | 事中监控、事后分析 |
| **科室主任** | - 了解科室DRG绩效指标（CMI、费用消耗指数等）<br>- 科室盈亏分析和成本控制<br>- 与其他科室对比分析 | 事后分析 |
| **医院管理层** | - 全院DRG运营态势监控<br>- 医保支付率分析<br>- 战略决策支持（学科发展、资源配置） | 事后分析、决策支持 |

### 3.2 事前分析模块

#### 3.2.1 编码智能辅助 ★

**功能描述**：利用大语言模型技术辅助编码员进行ICD编码工作，提高编码效率和准确性。

**重要说明**：
- ✅ **DRG分组的数据来源**：直接从**病案首页**读取已编码的诊断和ICD编码（由编码员完成）
- ✅ **LLM的作用**：辅助编码员工作，而非完全自动化编码
- ⚠️ **工作流程**：病历文本 → 编码员编码（LLM辅助）→ 病案首页 → DRG分组

**核心能力**：
- **编码推荐**：根据疾病/手术名称推荐候选ICD编码（Top-3）
- **智能检索**：支持疾病名称、拼音、编码多维度搜索ICD库
- **编码校验**：检查主次诊断逻辑关系、并发症标记合理性
- **遗漏提示**：基于病历内容提示可能遗漏的次诊断
- **知识辅助**：显示编码说明、包含/排除条目、编码示例

**使用场景**：

**场景1：编码员编码工作台**
```
编码员工作流：
1. 阅读病历，识别疾病名称（如"急性前壁心肌梗死"）
2. 在编码辅助界面输入疾病名称
3. LLM推荐候选ICD编码（置信度排序）
4. 编码员根据病历细节选择正确编码
5. 保存到病案首页
```

**场景2：编码合理性校验**
```
编码员完成编码后：
- LLM检查主次诊断逻辑关系
- 提示可能的并发症标记错误
- 提示编码与病历描述的不一致
- 编码员决定是否修正
```

#### 3.2.2 自动入组预测 ★

**功能描述**：在病案首页编码完成后，自动调用OpenDRG分组器进行DRG/DIP入组预测，生成入组结果推荐信息。

**重要说明**：
- ✅ **数据来源**：从**病案首页**读取已编码的诊断（ICD-10）、手术操作（ICD-9-CM-3）、患者基本信息
- ✅ **前置条件**：编码员已完成病案首页的编码工作（参见3.2.1节）
- ⚠️ **触发链路**：编码员完成编码 → 保存病案首页 → 自动触发DRG分组预测

**触发时机**：
- 病案首页编码完成/保存时自动触发
- 病案首页编码变更时实时更新（防抖1秒）
- 用户手动点击"预测入组"按钮

**核心能力**：
- 调用OpenDRG分组器计算ADRG和DRG
- 显示DRG组名称、权重、基准支付标准
- 预测入组置信度
- 支持全国30+地区版本切换

#### 3.2.3 支付预测

**功能描述**：根据入组结果和医院历史数据，预测本次住院的医保支付金额和可能的盈亏情况。

**计算逻辑**：
```javascript
// 支付金额计算
baseline_payment = drg_weight × region_rate × hospital_level_coefficient

// 盈亏预测（基于历史数据）
historical_avg_cost = getHistoricalAvgCost(drg_code, department)
predicted_profit = baseline_payment - historical_avg_cost
```

**展示内容**：
- 基准支付金额
- 历史平均费用
- 预期盈亏
- 风险等级（高/中/低）

### 3.3 事中分析模块

#### 3.3.1 实时费用监控 ★

**功能描述**：在患者住院治疗过程中，实时监控累计费用，并与DRG支付标准对比，提前预警超支风险。

**监控指标**：
- **累计费用**：当前已发生的总费用
- **预算剩余**：基准支付 - 累计费用
- **费用消耗率**：累计费用 / 基准支付
- **预计最终费用**：基于历史数据和当前趋势预测

**监控频率**：
- 每日自动更新（夜间批处理）
- 费用变化>1000元时触发实时更新
- 用户手动刷新

#### 3.3.2 分组动态更新

**功能描述**：当病案首页编码变更（如编码员修改诊断、新增手术操作）时，自动重新计算DRG入组结果。

**重要说明**：
- ✅ **监听对象**：
  - 编码端：病案首页的编码数据变更（主/次诊断、手术操作、并发症标记等）
  - 医生端：入院记录/病程记录等病历文本变更（用于“预入组推荐”，不替代最终编码）
- ✅ **触发机制**：
  - 编码端：编码员在病案首页修改保存后自动触发
  - 医生端：医生病历书写保存后触发（支持防抖与变更合并）

**触发条件**：
- 病案首页诊断编码变更（主诊断、次诊断）
- 病案首页手术操作编码变更
- 并发症标记变更
- 出院时间确定（影响住院天数）

**更新策略**：
- 变更后1分钟内触发重新分组
- 对比变更前后的入组结果
- 记录变更历史（审计追踪）

**医生端提示：预入组推荐（大模型驱动）★**

**功能描述**：医生完成入院记录（或关键病程记录）填写并保存后，系统调用大语言模型对病历文本进行信息抽取与结构化，生成“预入组推荐结果”。当病历书写发生变化时，系统自动更新预入组推荐并提示变化原因。

**定位与边界**：
- ✅ **定位**：用于医生端的事中提示与风险预警（控费、病种路径、床位/资源管理等），提供“预分组/预支付”参考
- ⚠️ **边界**：预入组推荐不等同于最终入组结果
  - 最终入组仍以编码员确认的病案首页 ICD 编码为准
  - 系统不得自动写入/修改病案首页编码
  - 严禁在无病历依据的情况下建议增加诊断以提高分组权重

**触发时机**：
- 入院记录保存/提交后自动触发

#### 3.3.4 编码优化建议

**功能描述**：在确保临床合理的前提下，基于病历文本和当前病案首页编码，提供编码优化建议，帮助医院获得更合理的支付。

**重要说明**：
- ✅ **建议依据**：病历文本中的明确记载 + 当前病案首页编码
- ✅ **建议对象**：编码员或临床医生
- ✅ **采纳方式**：人工确认后修改病案首页（非自动修改）
- ⚠️ **合规边界**：严禁在无病历依据的情况下建议增加诊断

**建议类型**：

1. **诊断完善建议**
   - 场景：病历中提到并发症，但未体现在诊断中
   - 建议：补充相应的次诊断编码
   - 示例："病程中记录'患者出现心力衰竭'，建议补充次诊断 I50.001"

2. **手术操作记录建议**
   - 场景：实施了某项操作，但未记录在手术操作中
   - 建议：补充手术操作编码
   - 示例："手术记录中提到'行IABP置入'，建议补充操作编码 37.6100"

3. **并发症识别建议**
   - 场景：符合并发症定义的情况未标记
   - 建议：标记为并发症，可能影响入组
   - 示例："术后出现切口感染，建议标记为手术并发症"

**合规性控制**：
- ✅ 只在病历有明确记载的前提下提供建议
- ✅ 不建议增加虚假诊断
- ✅ 记录所有建议和采纳情况，可审计
- ✅ 需要临床医生或编码员确认后才能修改

#### 3.4.1 DRG综合指标分析 ★

**功能描述**：提供院内DRG/DIP综合分析平台，从医疗服务能力、效率、安全等维度进行多层级绩效评价。

**分析层级**：
1. 医院整体
2. 科室级
3. 病区级
4. 主诊医师组
5. 个人医师

**核心指标**：

| 指标分类 | 指标名称 | 计算公式 | 意义 |
|---------|---------|---------|------|
| **服务能力** | DRG组数 | 去重DRG数量 | 反映诊疗范围广度 |
| | CMI (病例组合指数) | ΣDRGᵢ权重 / 病例数 | 反映病例复杂度 |
| | 四级手术占比 | 四级手术数 / 总手术数 | 反映技术难度 |
| **服务效率** | 费用消耗指数 | 实际费用 / (权重×费率) | <1盈利，>1亏损 |
| | 时间消耗指数 | 实际住院日 / 标准住院日 | <1效率高，>1效率低 |
| | 平均住院日 | 总住院日 / 病例数 | 反映诊疗效率 |
| **医疗安全** | 低风险组死亡率 | 低风险DRG死亡数 / 低风险病例数 | 反映医疗质量 |
| | 非计划再入院率 | 15日内再入院数 / 总出院数 | 反映诊疗质量 |
| **费用结构** | 药占比 | 药品费用 / 总费用 | 药品费用控制 |
| | 耗占比 | 耗材费用 / 总费用 | 耗材费用控制 |
| | 检查占比 | 检查费用 / 总费用 | 检查合理性 |
| **医保结算** | 医保支付率 | 医保支付 / 总费用 | 医保覆盖情况 |
| | 盈亏金额 | 医保支付 - 实际费用 | 直接经济效益 |

#### 3.5.4 数据对接

3. **文件导入**
   - Excel/CSV批量导入
   - 适合初期或HIS系统不支持接口对接的医院

4. **API对接**
   - RESTful API接口
   - 适合HIS厂商提供API的情况

**数据质量保障**：

    -- 审核追踪
    reviewer_id VARCHAR(50),  -- 审核员
    reviewed_at TIMESTAMP,

    -- 审计
    created_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP,
