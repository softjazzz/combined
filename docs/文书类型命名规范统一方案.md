# 文书类型命名规范统一方案

## 📋 问题分析

### 当前情况

数据库中的 `qc_rules.applicable_documents` 字段存在两种命名方式混用：

1. **英文代码格式**：`progress_note`, `admission_record`, `discharge_record`, `operation_record`, `examination_report`
2. **中文名称格式**：`病程记录`, `入院记录`, `出院记录`, `用药记录`, `医嘱记录`

### 存在的问题

- ❌ **命名不一致**：增加维护复杂度
- ❌ **前端需要维护映射表**：容易出错和遗漏
- ❌ **数据一致性差**：不符合数据库设计规范
- ❌ **查询效率低**：需要复杂的匹配逻辑

---

## 🎯 推荐方案：使用英文代码 + 映射表

### 方案概述

**核心原则**：数据库存储使用**英文代码**，前端显示使用**中文名称**，通过**映射表**进行转换。

### 为什么选择这个方案？

#### ✅ 优势

1. **符合数据库最佳实践**
   - 英文代码作为标识符，稳定不变
   - 避免中文编码问题
   - 便于国际化扩展

2. **提高查询性能**
   - 英文代码长度固定，索引效率高
   - 避免中文字符串比较的性能损耗

3. **易于维护和扩展**
   - 代码层面使用英文常量，IDE 支持更好
   - 新增文书类型只需添加映射关系
   - 支持多语言（中文、英文、繁体等）

4. **与现有系统兼容**
   - `medical_documents` 表已使用英文代码（`document_type` 字段）
   - 已有 `document_category_enum` 枚举类型定义
   - 已有 `document_category_config` 配置表

#### ❌ 其他方案的问题

**方案 A：统一使用中文名称**
- ❌ 不符合数据库设计规范
- ❌ 国际化困难
- ❌ 代码可读性差（中文字符串作为标识符）

**方案 B：保持双语混用**
- ❌ 维护复杂度高
- ❌ 容易出错
- ❌ 查询逻辑复杂

#### 1.1 创建文书类型映射表

```sql
-- 创建文书类型映射表
CREATE TABLE IF NOT EXISTS document_type_mappings (
    id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
    
    -- 标准代码（英文）
    type_code VARCHAR(50) UNIQUE NOT NULL,
    
    -- 多语言名称
    name_zh_cn VARCHAR(100) NOT NULL,  -- 简体中文
    name_zh_tw VARCHAR(100),           -- 繁体中文
    name_en VARCHAR(100),              -- 英文
    
    -- 别名（用于兼容旧数据）
    aliases TEXT[] DEFAULT '{}',
    
    -- 分类
    category VARCHAR(50),
    parent_type_code VARCHAR(50),
    
    -- 描述
    description TEXT,
    
    -- 排序和状态
    sort_order INTEGER DEFAULT 0,
    is_active BOOLEAN DEFAULT true,
    
    -- 元数据
    created_at TIMESTAMP WITH TIME ZONE DEFAULT NOW(),
    updated_at TIMESTAMP WITH TIME ZONE DEFAULT NOW()
);

-- 创建索引
CREATE INDEX idx_document_type_mappings_category ON document_type_mappings(category);
CREATE INDEX idx_document_type_mappings_aliases ON document_type_mappings USING GIN(aliases);
```

### 阶段 2：数据迁移

#### 2.1 创建迁移脚本

创建 `008_standardize_applicable_documents.sql`：

```sql
-- ============================================================================
-- Migration 008: 统一 applicable_documents 字段为英文代码
-- ============================================================================

BEGIN;

-- 步骤 1: 创建临时函数，将中文名称转换为英文代码
CREATE OR REPLACE FUNCTION convert_document_name_to_code(doc_name TEXT)
RETURNS TEXT AS $$
BEGIN
    RETURN CASE
        WHEN doc_name IN ('病程记录', '病程') THEN 'progress_note'
        WHEN doc_name IN ('首次病程记录', '首次病程') THEN 'first_progress_note'
        WHEN doc_name IN ('入院记录', '入院病历') THEN 'admission_record'
        WHEN doc_name IN ('24小时入院记录', '24h入院记录') THEN 'admission_record_24h_in'
        WHEN doc_name IN ('出院记录', '出院病历') THEN 'discharge_record'
        WHEN doc_name IN ('出院小结', '出院总结') THEN 'discharge_summary'
        WHEN doc_name IN ('手术记录', '手术') THEN 'operation_record'
        WHEN doc_name IN ('检查报告', '辅助检查') THEN 'examination_report'
        WHEN doc_name IN ('医嘱记录', '医嘱') THEN 'medical_order'
        WHEN doc_name IN ('用药记录', '用药') THEN 'medication_record'
        -- 如果已经是英文代码，直接返回
        ELSE doc_name
    END;
END;
$$ LANGUAGE plpgsql IMMUTABLE;

-- 步骤 2: 更新 qc_rules 表的 applicable_documents 字段
UPDATE qc_rules
SET applicable_documents = (
    SELECT ARRAY(
        SELECT DISTINCT convert_document_name_to_code(unnest(applicable_documents))
    )
)
WHERE applicable_documents IS NOT NULL
AND array_length(applicable_documents, 1) > 0;

-- 步骤 3: 清理临时函数
DROP FUNCTION convert_document_name_to_code(TEXT);

-- 步骤 4: 显示迁移结果
SELECT 
    unnest(applicable_documents) AS document_type_code,
    COUNT(*) AS rule_count
FROM qc_rules
WHERE is_active = true
AND applicable_documents IS NOT NULL
AND array_length(applicable_documents, 1) > 0
GROUP BY document_type_code
ORDER BY rule_count DESC;

COMMIT;
```

### 阶段 3：前端适配

#### 3.1 创建前端映射常量

创建 `src/constants/documentTypes.ts`：

```typescript
// 文书类型映射表
export const DOCUMENT_TYPE_MAPPINGS: Record<string, {
  code: string
  name: string
  category: string
  aliases: string[]
}> = {
  // 入院记录类
  admission_record: {
    code: 'admission_record',
    name: '入院记录',
    category: 'admission',
    aliases: ['入院记录', '入院病历']
  },
  // 病程记录类
  progress_note: {
    code: 'progress_note',
    name: '病程记录',
    category: 'progress',
    aliases: ['病程记录', '病程']
  },
  first_progress_note: {
    code: 'first_progress_note',
    name: '首次病程记录',
    category: 'progress',
    aliases: ['首次病程记录', '首次病程']
  },
  // ... 其他映射
}

// 根据中文名称获取英文代码
export function getDocumentTypeCode(name: string): string {
  for (const [code, mapping] of Object.entries(DOCUMENT_TYPE_MAPPINGS)) {
    if (mapping.name === name || mapping.aliases.includes(name)) {
      return code
    }
  }
  return name // 如果找不到，返回原值
}

// 根据英文代码获取中文名称
export function getDocumentTypeName(code: string): string {
  return DOCUMENT_TYPE_MAPPINGS[code]?.name || code
}
```

#### 3.2 更新前端过滤逻辑

简化 `qcDemo.ts` 中的过滤逻辑：

```typescript
import { getDocumentTypeCode } from '@/constants/documentTypes'

const applicableRules = computed<QualityControlRule[]>(() => {
  if (!selectedDocumentPrimary.value?.type) {
    return availableRules.value
  }

  // 将文书类型转换为标准代码
  const documentTypeCode = getDocumentTypeCode(selectedDocumentPrimary.value.type)

  const filtered = availableRules.value.filter((rule: any) => {
    const applicableDocs = rule.applicable_documents || []

    // 通用规则
    if (!applicableDocs || applicableDocs.length === 0) {
      return true
    }

    // 检查是否包含当前文书类型代码
    return applicableDocs.includes(documentTypeCode)
  })

  return filtered
})
```
