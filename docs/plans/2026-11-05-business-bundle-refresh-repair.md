# 业务刷新表与自建病例修复（复审候选）

基线 fa314c6c251fc5dd02eda96a7d30d70642cc1eb0；独立分支 codex/business-bundle-refresh-repair-20261105。本说明及候选仅供复审，不部署、不合并、不连接现场数据库或独立CDM、不调用模型。

## 根因与最小改动

原刷新gate限定public，但写入采用裸表名；062没有正式刷新表迁移。自建病例反射不指定schema，反射异常被转换为空表并跳过写入，样本登记仍可成功。材料提交后刷新失败是另一阶段，不能据此推断材料没有保存。medical_records不是本入口的写入目标。

新增正式063迁移，冻结v1 DDL和验证器，不导入未来可变的运行时建表函数。运行时只读验证并按每表真实owner限定SQL，删除全局已检查缓存。新增自建材料严格反射、同事务写入以及业务来源绑定；保留原有Bundle和医学判定机制。运行时不建临床/刷新表。

## 新合同与owner规则

这是一份新v1合同，不宣称已确认所有历史DDL。完整列、容量、可空、默认值、主键及索引见迁移063的JOBS/FAILURES/DDL常量；运行时对应refresh_storage.py。jobs包含应用生成64字符主键、请求元数据、计数默认0、error默认空、created_at默认当前时间；failures含生成整数主键、四坐标唯一键、非空attempt_count默认1、解决/重试可空时间及业务审计信息。JSON使用JSONB，业务时间继续timestamp无时区，不转换历史。

| 物理对象 | 处理 |
|---|---|
| 两表均无 | split建qc，single建public |
| 某表仅public或qc存在 | 验证兼容后保留原表、行、ID及序列 |
| 仅一张表存在 | 缺失表跟随其唯一owner |
| 两表各在不同schema | 分别显式绑定，不搬表 |
| 同一表在public/qc都出现 | 即使一边空也阻断，不猜行数、不合并 |
| 字段/默认/主键/唯一键/索引不兼容 | 明确对象及合同错误，事务回滚，不自动修存量 |

运行角色只需已确认schema的USAGE、每张刷新表SELECT/INSERT/UPDATE及实际生成ID序列USAGE。材料和样本表保持原有必要DML权限，不授所有表/序列、不授DDL、不加入属主角色。权限验证不自动授权。所有检查依据pg_catalog盘点物理对象，不能用不可见表列表证明权限齐全。

## 物理读写与事务

| 阶段 | 来源与存储 |
|---|---|
| 自建病例请求 | 强制legacy/business上下文；退出后恢复调用方来源 |
| 材料反射和DML | 同一Session，split业务cdm、single业务public；必需表失败整体rollback |
| pool/item/计数 | 同一初始事务，成功才commit，不因文书被跳过而虚报synced |
| visit_index | 本入口验证既有结构，不触发运行时DDL |
| Bundle取材 | 相同legacy上下文及显式本地schema；独立CDM不访问 |
| Bundle落库 | 既有业务public Bundle表，规则与证据合同不改 |
| 刷新状态 | 已校验真实owner的两表；失败不撤销已提交材料，返回pending与安全错误码 |

检查/检验报告显式保存report_time；其他文书保留记录时间，不能以缺少记录时间字段后只写提交时间来伪造成功。未知结构失败，普通业务DML错误被转换为无原文的503，字段/权限错误保留受控对象名。恢复应刷新已存在病例，不重新创建。

## 复审后才可执行的升级流程

1. 核实业务库及应用版本、运行任务，备份业务库和当前release；只读盘点两张刷新表public/qc owner及完整合同。
2. 歧义或存量不兼容立即停止并提交对象差异。不能drop/stamp/清表；本候选不会修改历史表结构来凑兼容。
3. 经批准由业务迁移角色执行alembic upgrade head（062→063），同步库保持不变。该迁移只新建缺失刷新表，不迁移临床材料。
4. 管理员依据实际owner逐表授运行角色USAGE/DML及对应ID序列USAGE；不执行全schema泛化授权。
5. 运行只读预检：bind_storage检查两表/权限；新建病例的材料表在请求写入前严格检查。normal服务器模式要求063；acceptance仍是可选规则验证环境，不用于绕过生产校验。
6. 使用虚构材料检查五份文书正文/时间、Bundle、刷新失败恢复。真实模型调用需另行授权和轮换后的Key。

## 回退

候选不含自动安装脚本。代码回退到旧release不代表可以安全继续旧版刷新操作；保留新增审计表及数据，暂停新建/刷新相关操作，待前向修复。063的downgrade明确拒绝删表；不得自动删除审计或恢复整库覆盖新结果。独立CDM、模型、自动任务开关不改，LLM_ADJUDICATOR_MODEL不改。

## 验证范围与未验收

本轮PG16使用新建owned集群、声明062合成夹具和真实063升级，不冒充完整000001→063历史空库迁移，也不证明全部历史schema兼容。外部网络、独立CDM及模型调用阻断；运行DML使用非超级用户、无DDL身份。源码自检和固定应答不证明医学质量。现场迁移/权限/现有虚构病例修复、代理真实调用均未执行。测试数字及CI证据见同目录test-report，包中PACKAGE注明真实提交与database_migrations_required=true。
