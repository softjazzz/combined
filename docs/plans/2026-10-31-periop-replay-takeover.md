# 第二批独立 replay 接管实施计划

**目标：** 把已验收的第二批快照交给正式抽取/发布引擎，在四个新库完成接管、幂等、回滚与恢复验收，不访问 Caché 或原13接口业务库。

**架构：** 保持全局13接口注册表与既有迁移原样。独立 profile 从已冻结的17接口合同选择13个有数据来源，四个受限接口禁用。源8表完整归档，再通过只读快照适配器执行显式日期 replay；查询日期语义未确认，因此禁止 incremental 与计划任务。

**技术：** Python 3.10、现有 ExtractService/PublishService、psycopg2、PG16客户环境；开发机独立合成PG18只验证兼容逻辑。

1. 新增 `periop_replay.py`：独立合同、数据库范围、严格数组/行哈希校验、只读快照适配器；测试全局注册表不变、禁用接口、模式和字段漂移。
2. 新增 `prepare_periop_takeover.py`：只读固定源、创建四新库、归档8表、重放74个活动来源历史批次（70成功/4预期源失败）、两轮发布、逐字段比对、故障回滚、备份恢复；不清理现场、不自动重试。
3. 新增 `run_periop_replay.py`：仅显式接口/日期，从接管归档读取并发布；不包含自动日期/增量/调度入口。
4. 在独立合成集群执行整包端到端验收；执行原服务测试和静态检查，记录PG18与客户PG16区别。
5. 归档非PHI客户结果摘要，提交代码，构建独立校验包及 `DSH_START.txt`。包不含凭据、原始键/正文、数据库备份和运行配置。

完成标准：9365条raw与历史；两轮CDM字段全等；历史4个失败窗口保留；故障注入回滚与恢复通过；源全表/序列不变；恢复库指纹相同；原13接口代码与注册不变；不连接Caché、不创建checkpoint或任务。
