# 第二批真实源显式日期验证实施计划

**目标：** 在四个全新独立库验证13个活动接口的真实ODBC dry、replay、发布与恢复，不改变原13接口和已验收第二批快照。

**架构：** 复用0.3.2 ODBC适配器及ExtractService/PublishService；新profile只包装严格源值类型和限定厂商失败分类。以已接受第二批ingest/CDM为只读基线复制四新库。只读原运行配置的Caché连接字段和已有口令文件，不执行旧服务或连接其数据库。默认无日期，调用必须显式传`--date`；本次DSH指定2026-10-28。

**技术：** Python3.10、pyodbc、psycopg2、客户PG16；开发机仅虚构ODBC+独立合成PG18，不访问客户网络。

1. 新增纯profile辅助和单测：启用13/禁用4不变、日期闸门、str/NULL值保持、有限历史失败判定、原配置只读字段筛选、无明文异常。
2. 新增直接Python验收工具：校验已接受结果和固定两源库→四新库克隆→dry前后全表序列指纹→成功来源replay/发布→两轮全量发布幂等/逐字段核验→两个新库备份恢复→基线库与归档/断点/配置保护复核。
3. 已知失败只接受合同指定接口/日期且实际HY000/native400的查询失败。dry失败不建批次、不执行该接口replay；新失败一律停止。源后续发生变更按实际insert/update报告，不要求dry与replay同数或第一次发布0变化。
4. 全新合成集群进行整包验证，跑聚焦/完整服务测试及静态检查。补齐错误、变化、失败保留和禁止越界测试。
5. 提交、构建校验ZIP与DSH_START：直接Python，不安装、不改策略、不清理既有库。只回传非PHI计数，所有凭据/配置/备份/私有日志留客户机。

不新增接口、不确认未知日期语义、不运行规则、不启用自动增量/checkpoint/任务。成功分为完整读取通过或带明确源限制通过，绝不把厂商失败当零行成功。
