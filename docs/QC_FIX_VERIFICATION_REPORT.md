## 🔍 问题根因分析

### LX-008 为什么仍然失败？

#### 可能原因 1：提示词不够强

当前提示词（`custom_rules_33.json` 第 112 行）：
```
【检查要点】
1. 在现病史、既往史或医师记录中列出所有提到的辅助检查项目...
2. 在"辅助检查"章节中逐项核对是否已经记录了对应检查的时间、单位或结果；
   若找到任意一处结果或描述，也视为合规。
3. 只有在完全找不到该检查的结果，或仅写"待结果/未回报"且后文也无补充时，
   才判定为不合规。
```

**问题**：
- LLM 可能没有严格遵循"若找到任意一处结果或描述，也视为合规"
- LLM 可能在第 1 步就产生了幻觉（认为现病史提到了"血常规"）

#### 可能原因 2：LLM 理解偏差

LLM 可能将"行胸部CT发现..."理解为"提到了检查但没有结果"，而忽略了辅助检查章节中的详细结果。

#### 可能原因 3：证据提取失败

LLM 在提取证据时，可能没有正确匹配"胸部CT"和"胸部CT平扫"，认为它们是不同的检查。

### 优先级 1：增强 LX-008 提示词

**建议修改**（`custom_rules_33.json`）：

```json
"custom_prompt": "你是一名经验丰富的病历质控专家，负责核对病历记录是否满足质控规则要求。

【重要提示】
在判定前，请先仔细阅读整个病历文本，特别是辅助检查章节。
只有在确认辅助检查章节中完全没有相关检查结果时，才能判定为不合规。

【规则信息】
- 规则ID: {rule_id}
- 规则名称: {name}
- 规则描述: {description}

【检查步骤】
第一步：提取现病史中提到的所有辅助检查项目
- 列出检查名称（如：胸部CT、血常规、肝功能等）
- 注意：不要将"行XX检查发现..."理解为"缺少结果"

第二步：在辅助检查章节中逐项查找对应结果
- 匹配规则：名称相似即可（如"胸部CT"和"胸部CT平扫"是同一项）
- 只要找到任何结果描述，就视为已记录

第三步：判定合规性
- 如果所有检查都在辅助检查中找到结果 → is_compliant: true
- 如果有检查完全找不到结果 → is_compliant: false
- 如果不确定是否为同一检查 → 倾向于 is_compliant: true

【输出要求】
输出一个 JSON 对象：
{
  \"is_compliant\": true/false,
  \"findings\": \"说明判定依据，必须引用具体的病历原文\",
  \"issues\": [...],
  \"evidence\": \"必须包含具体的病历原文片段（带引号）\",
  \"suggestion\": \"具体整改建议\",
  \"confidence\": 0.6-0.9
}

【病历文本】
{medical_text}

请严格按照上述步骤进行质控评估。"
```

### 优先级 2：增加证据验证机制

在 `unified_rule_engine.py` 中增加 LX-008 的证据验证：

```python
elif rule_id == "LX-008":
    # 验证 LLM 提取的证据是否真实存在于病历中
    if not result.get("is_compliant"):
        issues = result.get("issues", [])
        verified_issues = []
        for issue in issues:
            evidence = issue.get("evidence", "")
            # 检查证据是否真实存在于病历文本中
            if self._verify_evidence(evidence, medical_record["content"]):
                verified_issues.append(issue)
        
        # 如果所有 issues 都被过滤掉，改为合规
        if not verified_issues:
            result["is_compliant"] = True
            result["status"] = "compliant"
            result["issues"] = []
            result["findings"] = "经验证，现病史提到的检查在辅助检查中均有记录。"
```
