# A3/A4/A5 实现计划

**Goal:** 补齐独立重试身份、确认来源缺口的展示隔离与安全错误分类。

**Architecture:** 在现有任务、材料和结果合同上增加可追溯重试关系；旧任务、信封、快照保持不可覆盖。展示仅容忍捕获合同明确确认的缺口，其他错误继续拒绝。模型和执行错误使用统一安全分类，未知错误不自动重试。

**Tech Stack:** 现有 Python/SQLAlchemy/FastAPI、Vue/TypeScript。基线 `7833cd7115118ce53508806a41f78cadde8860d4`，独立分支 `codex/retry-display-errors-20261114`。

**Spec:** 用户本轮 A3/A4/A5 指令及 GPT PRO 固定3893审查。手术输血暂停、无首页取材、来源身份与完整性保护继续有效。禁止真实库、真实模型、质控执行及27份重跑，不合并不部署。

## 分工与顺序

- [x] A3：先用合成终态任务复现原地重试风险；在 workspace service 创建独立 job/attempt，可靠关联原任务、幂等及权限校验；原材料复用与新模型身份区分。父任务不得通过错误复用叶子身份伪装支持。
- [x] A4：定位已确认缺表/非身份缺列如何进入展示装配；最小范围承认捕获合同缺口，不把未捕获、连接、权限、身份及损坏降成空数据。
- [x] A5：统一受控 code/category/retryable，显式配置类错误不重试，暂态错误保持有界策略，未知 fail closed；不泄露内部异常、请求及患者材料。
- [x] 集成：前端重试跟随返回的新任务ID，显示追溯关系和安全原因；后端客户DTO只允许安全字段。自动补跑与新ID对齐。
- [x] 验证：仅对应合成单元/必要SQLite或隔离PG回归，验证历史完整行/结果/快照未改、当前暂停零执行、错误脱敏、权限及并发幂等。
- [x] 固定源码后独立复审，修复确认问题，再提交独立分支；不推送/合并/打包/部署。

## 重点负例

重复重试和并发请求；越机构请求；旧材料不存在/损坏/身份错配；已确认缺源与权限错误不可混淆；模型401/404与429/超时；原任务迟到写；旧暂停范围不能启用当前禁用规则；前端旧响应不能覆盖新任务。
