### **1. 背景与目标**

#### **1.1 项目背景**
随着国家DRG/DIP支付方式改革的深入，医保基金监管日益精细化。传统的事后人工审核模式已无法满足医院高质量发展的需求，存在审核周期长、干预滞后、医务人员负担重等问题。将医保质控规则前置到临床诊疗环节，在医生开具医嘱时进行实时提醒和干预，是提升医疗质量、保障基金安全、降低医疗成本的关键举措。本项目旨在开发一套嵌入医生工作站的智慧医保临床实时质控系统，变“事后惩罚”为“事中提醒”。

#### **1.2 产品目标**
*   **核心目标**：构建一个智能、高效的临床决策支持系统（CDSS），将医保及院内质控规则无缝融入临床工作流程，实现对不合规医嘱的实时识别、提醒与干预。
*   **近期目标 (1年内)**：
    *   将现有医保规则库（`医保规则_precise`目录内容）100%数字化、线上化。
    *   实现对80%以上确定性规则（如年龄、性别、就诊方式限制等）的实时自动审核。
    *   将目标科室因规则不明导致的医保违规申诉率降低50%。
*   **远期目标 (2-3年)**：
    *   引入AI大模型辅助，覆盖95%以上的复杂临床内涵规则。
    *   提供数据驱动的管理决策支持，帮助医院优化临床路径和成本控制。
    *   成为医院精细化管理的核心工具之一。

### **2. 用户画像与核心场景**

#### **2.1 用户画像 (Personas)**

*   **临床医生 (王医生)**
    *   **特征**：工作繁忙，诊疗压力大，对医保规则不完全熟悉。
    *   **痛点**：害怕因无意中开出不合规医嘱而被医保办通报、处罚；在开医嘱时反复查询规则手册，影响工作效率。
    *   **期望**：系统能在开医嘱时**快速、清晰、不打扰**地提示潜在问题，并给出明确的修改建议。

*   **医保办/质控科管理员 (李主任)**
    *   **特征**：负责全院的医保合规审核与管理。
    *   **痛点**：每月花费大量时间进行人工抽查病历，效率低下；发现问题时，诊疗行为已发生，难以追溯和纠正；缺乏有效的数据工具来定位高风险科室和医生。
    *   **期望**：系统能**自动化**完成大部分审核工作，提供**宏观数据看板**和**精细化分析工具**，让她能主动发现问题、精准管理。

#### **2.2 核心用户场景 (Scenarios)**

*   **场景一：医生开具药品医嘱**
    *   **流程**：王医生为一位18岁男性患者开具了“A药品”，该药品医保规则“限儿童使用”。
    *   **系统行为**：在王医生点击“保存医嘱”的瞬间，系统弹出提示：“【提醒】A药品限14周岁及以下儿童使用，当前患者18岁，医保可能不予支付。请确认是否继续？”
    *   **用户价值**：避免一次明显的不合规操作，为医生规避风险。

*   **场景二：医保办主任进行月度分析**
    *   **流程**：李主任登录系统后台，进入数据分析看板。
    *   **系统行为**：看板显示本月全院医嘱拦截次数Top 5的规则，其中“手术项目未按规定折价收费”排名第一。李主任点击该规则，系统下钻显示触发此规则最多的科室是骨科，相关医生是张医生。
    *   **用户价值**：精准定位问题，为后续的科室培训和管理提供数据支持。

### **3. 功能需求 (Features)**

#### **3.1 核心模块一：医生端实时提醒插件**

| **功能点** | **详细描述** | **优先级** |
| :--- | :--- | :--- |
| **3.1.1 医嘱实时捕获** | 在医生工作站（HIS/EMR）操作“保存”、“签署”医嘱时，能实时捕获医嘱内容、患者信息、诊断信息。 | **P0 (核心)** |
| **3.1.2 多级提醒机制** | **提醒**：轻微不合规或建议性规则，医生可确认后忽略。**警告**：中度不合规，医生需填写理由方可忽略。**拦截**：严重违规或支付政策红线，医生必须修改医嘱。 | **P0 (核心)** |
| **3.1.3 智能化提示界面** | 以弹窗或侧边栏形式展示，文案清晰易懂，明确指出“什么错了”、“为什么错了”、“建议怎么做”。 | **P0 (核心)** |
| **3.1.4 忽略理由记录** | 对于“警告”级别的提醒，提供标准化的忽略理由选项（如“患者病情特殊”、“上级医师已同意”等）及文本框，记录备查。 | **P1** |
| **3.1.5 规则知识库反查** | 在提示信息中，提供一个链接，点击可查看该条规则的原文依据和详细说明。 | **P1** |

#### **3.2 核心模块二：规则引擎与管理后台**

| **功能点** | **详细描述** | **优先级** |
| :--- | :--- | :--- |
| **3.2.1 规则数字化管理** | 提供后台界面，支持将`Markdown`格式的医保规则录入、解析并结构化为系统可执行的逻辑。 | **P0 (核心)** |
| **3.2.2 规则引擎服务** | 稳定、高效的后端服务，负责接收前端请求，执行规则匹配与逻辑运算，并在2秒内返回结果。 | **P0 (核心)** |
| **3.2.3 规则版本与生命周期管理** | 支持规则的新增、修改、停用、发布。所有规则的变更都应有版本记录和操作日志。 | **P1** |
| **3.2.4 规则测试沙箱** | 提供一个测试环境，允许管理员在规则发布前，使用模拟的病例数据对规则进行测试，确保其准确性。 | **P2** |

#### **3.3 核心模块三：数据分析与监控看板**

| **功能点** | **详细描述** | **优先级** |
| :--- | :--- | :--- |
| **3.3.1 宏观数据看板** | 展示全院维度的核心KPI，如：总审核医嘱量、拦截/提醒次数、违规率、预估节约医保金额等。 | **P1** |
| **3.3.2 多维度下钻分析** | 支持按时间、科室、医生、规则类型等维度对违规数据进行下钻分析和排名。 | **P1** |
| **3.3.3 违规详情追溯** | 提供违规事件列表，可查看每一次拦截/提醒的详细信息，包括患者脱敏信息、相关医嘱、触发的规则和医生最终操作。 | **P1** |
| **3.3.4 报表导出** | 支持将分析结果导出为Excel或PDF格式的报表。 | **P2** |

#### **3.4 核心模块四：系统集成与数据适配**

| **功能点** | **详细描述** | **优先级** |
| :--- | :--- | :--- |
| **3.4.1 HIS/EMR集成适配器** | 开发标准化的数据接口适配器，用于与主流HIS厂商（如卫宁、东软等）进行对接，获取所需数据。 | **P0 (核心)** |
| **3.4.2 医疗术语标准化** | 内置医疗术语（药品、诊断、手术）的标准化映射服务，将医院内部编码与国家标准编码进行对应。 | **P1** |
| **3.4.3 NLP服务接口 (远期)** | 预留调用外部AI大模型或NLP服务的接口，用于处理非结构化病历文本。 | **P2** |

### **4. 非功能性需求**

*   **性能**：医生端实时提醒的端到端响应时间必须小于2秒。
*   **可靠性**：系统服务可用性需达到99.9%。任何情况下不能阻塞或导致HIS/EMR系统崩溃。
*   **安全性**：所有涉及患者隐私的数据必须脱敏处理，符合国家《个人信息保护法》和医疗行业数据安全规范。
*   **可扩展性**：系统架构应支持未来规则数量的增加和更多医院的接入。

### **5. 产品路线图 (Roadmap)**

#### **第一阶段：MVP (最小可行产品) (3-6个月)**
*   **目标**：验证核心流程，上线确定性规则。
*   **核心功能**：
    *   完成**医生端实时提醒插件**的开发。
    *   完成**规则引擎与管理后台**，支持手动录入和管理“确定性规则”。
    *   **上线规则**：`第一批`（性别、年龄）、`第三批`（保险类型）、`第四批`（就诊方式）、`第五批`（机构级别）。
    *   **试点范围**：选择1-2个业务相对简单的科室进行试点。

#### **第二阶段：功能扩展 (6-12个月)**
*   **目标**：扩大规则覆盖面，上线数据分析功能。
*   **核心功能**：
    *   上线**数据分析与监控看板**。
    *   **上线规则**：`第二批`（手术折价）、`第六批`（简单疗程计算）。
    *   **试点范围**：推广至全院80%以上的临床科室。

#### **第三阶段：智能化升级 (12个月以后)**
*   **目标**：引入AI能力，攻克复杂临床内涵规则。
*   **核心功能**：
    *   对接**NLP服务**，开始试点需要从病历文本中提取证据的复杂规则（如重症判断、治疗失败等）。
    *   开发“事后AI智能审计”功能，对医生忽略的警告进行复核。

### **6. 成功指标 (Metrics)**
*   **业务指标**：
    *   医保报销申诉成功率提升20%。
    *   医保办人工审核病历所需时间减少30%。
*   **产品指标**：
    *   医生端提醒采纳率（医生根据提醒修改医嘱的比例） > 70%。
    *   产品用户满意度（NPS） > 40。
