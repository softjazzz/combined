## 概述

基于 PRD、技术选型与数据库设计文档，本开发计划采用 **Supabase BaaS** 为核心的技术架构，分阶段实现智慧医保临床实时质控系统。

### 核心约束
- 后端以 **Supabase 自托管**为核心（PostgreSQL、Auth、Storage、PostgREST、Edge Functions）
- 前端复用现有 `yibao-web`，通过 Supabase API/Edge Functions 交互
- 所有表启用 **RLS**，写操作通过 Edge Function 完成
- 目标性能：端到端响应时间 **< 2秒**

---

## 一、阶段规划与里程碑

### 第一阶段：MVP（3-6 周）
- 搭建 Supabase 基础设施与数据库 Schema（V1.1）
- 完成认证、规则管理 CRUD、规则测试沙箱
- 医生端提醒组件 Demo（本地模拟病例）、仪表板基础 KPI/趋势

### 第二阶段：功能扩展（6-10 周）
- 上线违规记录、审计任务、统计视图与报表导出
- HIS/EMR 适配器接口草案与联调演示
- 性能优化与追踪（端到端 < 2s）

### 第三阶段：智能化升级（>12 周）
- NLP/LLM 接口预研与 Beta 集成
- 复杂规则的证据链展示与复核工作流

## 二、详细任务分解

### 后端（Supabase + Edge Functions）

#### 环境与权限
- [ ] 初始化 Supabase 实例（自托管/云端）
- [ ] 设置环境变量：`SUPABASE_URL`、`SERVICE_ROLE`、`ANON_KEY`
- [ ] 开启 PostgREST、Storage、Auth，配置 CORS
- [ ] 配置 RLS 策略与角色：
  - `service_role`：读写删
  - `authenticated`：只读
  - `anon`：禁止

#### 数据库迁移（依据《数据库设计说明 V1.1》）
- [ ] **核心规则表**：
  - `yibao_rule_categories`、`yibao_rules`
  - `yibao_rule_triggers`、`yibao_rule_conditions`、`yibao_rule_actions`
- [ ] **业务主数据表**：
  - `yibao_drugs`、`yibao_medical_services`
- [ ] **违规与审计表**：
  - `yibao_violations`、`yibao_audit_tasks`、`yibao_audit_results`
- [ ] **视图与索引**：
  - 视图：`yibao_rule_statistics(rule_type, hits)`
  - 触发器：各表 `updated_at` 自动维护
  - 索引与约束：按文档添加
- [ ] **种子数据**：执行 `002_seed_minimal_rules.sql`

#### Edge Functions（TypeScript/Deno）
- [ ] **规则引擎执行器**
  - 输入：病例上下文 JSON + 规则 id/事件类型
  - 流程：读取规则 → 加载 conditions/actions → 计算命中 → 生成结果
  - 输出：`{ severity, messages[], evidence }`
  - 可选：采用 `json-rules-engine` 或自研轻量执行器
- [ ] **违规记录与审计**
  - 写入 `yibao_violations`、`yibao_audit_tasks`、`yibao_audit_results`
  - 只允许 `service_role`/EdgeFunction 持有的密钥写入
- [ ] **统计与报表**
  - 汇总规则命中趋势、TopN 维度（科室/医生/规则类型）
  - 提供导出 CSV/JSON 的 endpoints
- [ ] **规则测试沙箱**
  - 输入模拟病例 JSON，调用规则引擎，返回命中详情
- [ ] **统一错误码与审计日志**
  - 记录 function 入参、执行耗时、错误栈

#### 集成与适配
- [ ] HIS/EMR 接口契约草案（REST）
- [ ] 数据标准化：药品/诊断/服务项目映射存储与查询

### 前端（yibao-web）

#### 技术栈
- **框架**：Vue 3 + TypeScript + Vite
- **UI**：Ant Design Vue（现状使用）
- **状态管理**：Pinia
- **CSS**：TailwindCSS
- **数据**：`@supabase/supabase-js` + 约定的 Edge Function endpoints
- **路由**：Vue Router

#### 基础设施
- [x] Supabase Client 初始化与注入（已完成）
- [x] 错误处理与消息提示：统一 ApiWrapper（已建设）
- [ ] Auth 鉴权：Email/OTP 登录（MVP 可 Mock），路由守卫
- [ ] 角色/权限：前端仅控制导航展示，写操作由 Edge Function 校验

#### 页面模块
- [x] **登录与布局**
  - 登录页（支持 Mock），登录后进入 Dashboard
  - 侧边栏导航（已移植），面包屑与用户菜单
- [x] **仪表板**
  - KPI：总审核量、提醒/警告/拦截、违规率、今日新增
  - 趋势：`QCTrendChart`（Mock→真实数据）
  - TopN：科室/医生/规则类型
- [ ] **规则管理**
  - 规则列表/详情/版本/启停
  - 规则编辑器（Form+JSON 编辑），关联分类与触发事件
  - 条件/动作子表增删改查
- [ ] **规则测试沙箱**
  - 病例 JSON 输入，调用 Edge Function 预览结果
  - 命中详情与证据显示
- [ ] **违规与审计**
  - 列表/筛选/导出
  - 详情页：违规快照、命中规则、忽略/复核记录
- [ ] **系统设置**
  - Supabase 项目变量、Storage 桶、导入/导出配置

#### 医生端提醒组件 Demo
- [ ] 在 Web 侧模拟医生端弹窗/侧边栏提醒（多级提醒：提醒/警告/拦截）
- [ ] 忽略理由下拉与文本框，记录本地/提交 Edge Function

#### 体验与性能
- [ ] 页面骨架屏、加载态、错误兜底
- [ ] 指标采集与日志：前端埋点 + Edge Function 日志聚合
- [ ] 首屏加载与接口链路优化（目标端到端 < 2s）

## 六、关键风险与缓解措施

### 技术风险
1. **HIS/EMR 集成复杂度**
   - 缓解：早期与医院/厂商技术沟通，制定接口契约草案
2. **规则引擎性能**
   - 缓解：建立基准测试，优化 Edge Function 执行效率
3. **Supabase 自托管运维**
   - 缓解：准备云端 Fallback 方案，建立监控告警

### 业务风险
1. **规则复杂度超预期**
   - 缓解：MVP 阶段聚焦确定性规则，复杂规则后续迭代
2. **用户接受度**
   - 缓解：早期用户调研，快速原型验证
