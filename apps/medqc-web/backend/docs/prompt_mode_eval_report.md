# LLM 质控 Prompt Mode 评测报告

> 评测日期：2026-03-07 | 模型：qwen3.5-35b-a3b | 测试病历：入院记录 + 手术记录

## 结论

**推荐配置：分段模式（SegmentedQCPipeline） + plan_a**

---

## 一、测试背景

系统对病历文书质控有两个维度可调：

### 质控模式（架构维度）

| 模式 | 实现 | 工作方式 |
|------|------|---------|
| **快速模式** | `evaluate_document_fast` | 所有规则打包成 1 个 Prompt，一次 LLM 调用 |
| **分段模式** | `SegmentedQCPipeline` | 按文书类型切段 → 规则路由 → 每批 ≤15 条 → 并发 LLM 调用 |

### Prompt 模式（提示词详细程度）

以规则 SC-001（主诉书写规范）为例：

- **current**：仅告诉 LLM 规则名 + 描述（一句话）
- **plan_a**：额外提取【检查要点】（具体检查标准）
- **plan_c**：提取【检查要点】+【判定逻辑】（if-then 决策树）

## 三、为什么推荐分段模式

### 3.1 规则覆盖更全

| 文书类型 | 快速模式规则数 | 分段模式规则数 |
|---------|-------------|-------------|
| 入院记录 | 44 | 44 |
| 手术记录 | **20** | **77-78** |

分段模式通过 RuleRouter 的文书类型映射匹配到更多规则（如手术记录关联的术后病程记录、入院评估相关规则），覆盖面更广。

### 3.2 耗时更短（并发优势）

| 文书类型 | 快速模式耗时 | 分段模式耗时 |
|---------|-----------|-----------|
| 入院记录 | 33-39s | **17-21s** |
| 手术记录 | 18-25s | 30-38s（但评了 4 倍规则） |

入院记录 44 条规则：快速模式一次发送要 34s，分段模式 3 批并发仅 19s（**快 44%**）。

### 3.3 不受 max_tokens 限制

快速模式一次发 44 条规则，Prompt ~15000 字符，Thinking 模型需要大量 token 用于 `<think>` 推理。修复前曾因 `max_tokens=4000` 导致输出截断、全部降级为不合规。

分段模式每批仅 15 条规则，Prompt 短，不存在截断风险。

### 3.4 判定质量更稳定

LLM 一次处理 15 条规则比处理 44 条更专注，排在后面的规则不会因上下文过长而被忽略。

---

## 四、为什么推荐 plan_a

### 4.1 准确率最高

在所有测试场景中，plan_a 的合规率一致最高：

| 场景 | current | plan_a | plan_c |
|------|---------|--------|--------|
| 快速-入院 | 95.5% | **100%** | 95.5% |
| 快速-手术 | 100% | 100% | 100% |
| 分段-入院 | 100% | 100% | 100% |
| 分段-手术 | 96.1% | **98.7%** | 94.9% |

### 4.2 误报率最低

- **current** 缺乏具体标准，LLM 容易"过度联想"产生误报（如手术记录报了"经治医师签名"问题——但手术记录不需要经治医师签名）
- **plan_c** 给了 if-then 判定规则，LLM 反而过于机械地套用，在边缘情况下更容易报假阳性（如报"术后三天无病程记录"——只有一篇手术记录时当然没有）
- **plan_a** 给了检查要点但不强制判定逻辑，LLM 有适当的判断空间，平衡了精确性和灵活性

### 4.3 Token 消耗适中

| 模式 | 入院 Token | 手术 Token |
|------|-----------|-----------|
| current | 15154（最少） | 27850 |
| plan_a | 18355 | 29444 |
| plan_c | 18846（最多） | 30045 |

plan_a 比 current 多 ~20% Token，但准确率显著提升；比 plan_c 少 ~3% Token，且准确率更高。

## 五、配置建议

```python
# 推荐配置
pipeline = SegmentedQCPipeline(
    llm_client=service.client,  # 使用 qwen3.5-35b-a3b
    max_concurrency=3,           # 3 路并发
)
result = await pipeline.evaluate(
    document_id=doc_id,
    content=content,
    prompt_mode="plan_a",        # ← 推荐
)
```

### 后续优化方向

1. **增加更多测试病历**：当前仅 2 份，需要标注 5-10 份含已知问题的病历来计算准确率/召回率
2. **人工标注 ground truth**：请病案质控专家标注每条规则的正确判定，实现定量评测
3. **动态模式选择**：简单规则用 current（省 Token），复杂规则用 plan_a（提高准确率）
