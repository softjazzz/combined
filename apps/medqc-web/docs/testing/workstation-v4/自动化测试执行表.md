# Workstation V4 自动化测试执行表

本文档把 `workstation v4` 的自动化测试拆到“页面路径 + 测试动作 + 关键接口 + 关键表 + 预期返回”粒度，便于直接转成 API smoke、Playwright 用例或 SQL 断言脚本。

## 1. 使用说明

- 本表只覆盖 `workstation v4` 正式导航入口，不覆盖 `demo/test/debug` 页面。
- 优先把 `P0` 和 `P1` 变成自动化闸门，`P2` 作为增强。
- “关键表”写的是测试期望核验对象，不等于接口唯一读写对象。
- 某些页面当前仍含 mock 或 demo 逻辑，这类页面只建议做“页面可达 + 接口不报错”自动化，不建议当作数据库验收项。

## 6. 最小 SQL 断言建议

建议把以下 SQL 断言接进自动化执行链：

| 编号   | 场景           | 断言表                                 | 断言内容                                                           |
| ------ | -------------- | -------------------------------------- | ------------------------------------------------------------------ |
| SQL-01 | 登录后         | `sys_users`                            | `last_login_at` 是否更新                                           |
| SQL-02 | 首页草稿生成后 | `ai_frontpage_draft`                   | 指定 `visit_id` 是否新增或更新时间变化                             |
| SQL-03 | 首页质控后     | `qc_result`、`qc_results`              | 是否存在对应病历最新结果                                           |
| SQL-04 | 命中缺陷后     | `qc_defects`                           | 是否新增缺陷记录                                                   |
| SQL-05 | 文书质控后     | `medical_documents`                    | `qc_status/qc_score/qc_last_analyzed/qc_analysis_version` 是否更新 |
| SQL-06 | 通知操作后     | `notifications`                        | `is_read` 或新增记录是否变化                                       |
| SQL-07 | 同步操作后     | `sync_visit_status`、`sync_watermarks` | 状态或时间戳是否变化                                               |

## 7. 推荐落地顺序

1. 先把 `WV4-A01` 到 `WV4-A06` 做成最小自动化闸门。
2. 再补 `WV4-A07` 到 `WV4-A12`，形成首页与结算主链路自动化。
3. 然后补 `WV4-B01` 到 `WV4-B09`，覆盖规则、ICD、通知、系统配置。
4. 最后再考虑 `WV4-C*` 和 `WV4-D*`，它们更偏辅助验证，不是上线阻塞项。
