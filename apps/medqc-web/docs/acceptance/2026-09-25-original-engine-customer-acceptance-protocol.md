# 原始 LX0609 引擎：客户环境验收取证步骤

适用范围：原始 LX0609 引擎 A/B/C/D 整改。执行者为获授权的客户环境操作员和独立临床复核人；本任务不登录客户数据库，也不收集患者原文。开始前先选定本次验收的发布包、操作员、时间窗口及一条**在该发布包下新完成**的原始 LX0609 任务。旧三位编号任务和旧构建任务不能充当本次验收。

## 1. 固定实际运行版本

在客户机上，将 `$releaseRoot` 改为实际解压目录，执行以下只读命令。`build_id` 与 `git_commit` 必须在四处一致，后端 `started_at` 应晚于本次启动。若不一致，停止本次结果验收，先纠正启动目录或旧进程；不能仅凭 ZIP 文件名判断运行版本。

```powershell
$releaseRoot = 'D:\medqc\medqc-web-customer-Rxx'
$nonce = [DateTimeOffset]::Now.ToUnixTimeMilliseconds()
Get-Content -LiteralPath (Join-Path $releaseRoot 'frontend\dist\build-info.json')
Get-Content -LiteralPath (Join-Path $releaseRoot 'backend\app\data\runtime_build.json')
Invoke-RestMethod "http://127.0.0.1:3000/build-info.json?_t=$nonce"
Invoke-RestMethod "http://127.0.0.1:8001/api/v1/runtime-build?_t=$nonce"
```

只记录构建号、提交号、后端 PID/启动时间及实际解压目录。不要把 `.env`、Cookie 或授权令牌放进验收记录。

## 2. 同一保存结果的公开读取

操作员登录 V5，在客户样本验证或病历池选择上述任务和一份已完成病历，记下任务 ID、规则集键 `luxian_0609_qc_v1`、四段式规则编号和本轮任务状态；患者三坐标只保留在客户机。逐项核对：

1. 批量任务详情 `GET /api/v1/qc/sichuan/workspace/batch-jobs/{job_id}` 与单病历 `GET /api/v1/qc/sichuan/workspace/records/{visit_id}/latest-result?institute_id=...&patient_id=...` 指向本轮任务；单病历结果的 `data_origin` 为 `canonical_result_envelope`，不是上一轮任务或旧 `items_json`。
2. 打开运行/终末病历的质控抽屉，核对同一条规则的状态、原因码（若页面展示）、结论、建议和受控证据定位；`qc-detail` 不得额外出现未经发布的原始 0609 项。部分完成的任务须显示不完整，不得冒充全量完成。
3. 如该结果已有反馈，核对反馈绑定的任务、病历与规则编号，且原始结论仍与上述结果一致。没有反馈时记录“反馈联机未验证”，不要为取证擅自写入业务反馈。
4. 用页面正常导出该任务的 CSV、XLSX、HTML。在客户机内核对同一规则的状态、结论、建议、证据引用及总数；资料不足不能被重标为确定问题，三种格式不能出现详情与 latest 均没有的原始项。导出文件留在客户授权环境内，不上传到仓库或聊天。

若任一接口返回 404/409/5xx、字段冲突或任务来源不明，记录接口名、HTTP 状态、任务 ID、四段式规则编号及脱敏后的差异字段，停止将该例计为通过；患者原文和完整响应留在客户环境。一次已完成任务只能证明对应入口的联机交付，不能外推为三入口、全部规则或医学准确率。

## 3. B/D 恢复与费用边界

跨启动验收须由客户操作员在预定测试窗口使用本发布包的**正式新任务**完成：记录排队时的构建号/任务 ID，按客户现有启动流程重启同版本服务，确认只领取一次、任务最终状态与 Canonical 结果一致。不在客户临床环境人为切换版本；异版漂移只在隔离环境验收，未做时明确记为“客户机异版恢复未验证”。若未安排重启窗口，明确记为“客户机同版恢复未验证”。

取消或失败时只比较系统已观测的模型调用、Token、规则族、执行代次及 `usage_observation_complete`；供应商未返回的费用必须标为未知，不能填零。客户侧 PostgreSQL 竞争与 40 槽真实负载如未实测，也单独记为未验证，不能用本机两病例或隔离 PG 结果代替。

## 4. 独立临床保护集

独立复核人从现有候选台账中选择覆盖明确合规、不合规、资料不足、多事件及模型调用分支的病例，先保存独立业务判读，再与本轮结果逐项比较状态、原因、事实、证据及修改建议。签收记录须写明候选 ID、四段式规则编号、判读人/时间、接受或驳回及差异原因；病例原文、患者姓名和可逆标识只在客户授权位置保存。尚未签收的 `pending` 不能计为保护集通过。

验收交回本项目的最小信息：构建号与提交号、任务 ID 的不可逆代号、四个公开读取入口及三种导出的逐字段一致/差异结论、恢复/取消是否实测、临床签收数量与差异分类；不交回患者原文、完整导出、凭据。A/B/D 及整体目标只有在对应证据实际取得并复核后才能关闭。
