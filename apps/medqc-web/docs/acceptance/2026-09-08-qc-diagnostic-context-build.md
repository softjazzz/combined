# 执行上下文与发布版本绑定

## 已实现

仅有 EvidenceReadSession 不足以解释 prepare 额外收到的正文/结构化输入，且原打包脚本没有供客户运行端读取的版本声明。本批补齐这两个证据缺口。

1. prepare 在开始修改参数之前旁路冻结 `medical_text`、`evidence_payload`、`prepared_rules`、`source_schema` 及提供给它的 LX0609 运行配置。配置仅取 `LUXIAN_0609_` 前缀，排除密钥、令牌、密码、认证和端点字段；不遍历 LLM 客户端或完整全局设置。
2. 上下文作为固定独立内存字段，与材料/模型/结果共享总额度；单字段仍有 4 MiB 等既有限制。上下文超限不清掉已捕获的其他材料，不改变原质控结果；重复写入拒绝覆盖。
3. 若存在 source_gate_decisions，只记录其存在并明确缺项，不把未序列化的 gate 对象冒充完整上下文。这里记录的是传入配置，不宣称覆盖所有执行器内部另外读取的全局状态。
4. 正式打包结束前再次运行原源码门禁，通过后在目标包的 backend/app/data/runtime_build.json 写入 schema、实际 Git commit、build ID 和 inventory schema。复制阶段排除旧 runtime_build.json，避免把历史文件带入新包；AllowDirty 路径不生成正式版本声明。
5. 打包开始固定 Git HEAD，完成时验证仍为同一提交；期间提交变化、脏源码或其他门禁失败不写版本文件、不继续压缩成正式包。不使用 inventory 中可能过期的 git_head。
6. 客户运行时仅从固定路径读取最多 8 KiB 的版本文件，严格字段/类型/格式，拒绝重复键、BOM、超限及符号链接文件。无 Git、网络或源码扫描依赖。缺失/非法返回 build_version_unavailable，不回填当前开发机版本。
7. 每次采集创建时固定该版本声明，后续文件变化不会改写当次记录；没有版本仍是 partial。

此版本文件是发布声明，不是签名、安装目录防篡改证明或临床正确性证明。没有新增加密或重复内容摘要。
