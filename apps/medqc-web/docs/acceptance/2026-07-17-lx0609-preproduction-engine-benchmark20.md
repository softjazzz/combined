# LX0609 独立准生产质控引擎 20 例对比验收报告

日期：2026-07-17

范围：LX0609-001～LX0609-049

结论：**独立准生产 API 有条件 GO，默认关闭并进入人工验收；暂不接入任务主链或前端。**

## 1. 本轮交付是什么

本轮建立了一个独立、只读、无持久化的 LX0609 准生产入口，并在提交
`ea3c4b125` 增加独立 FastAPI 接口
`POST /api/v1/qc/luxian-0609/preproduction/evaluate`。调用方显式传入：

- running/final 场景与就诊三坐标；
- 49 个客户规则 ID；
- 冻结的 `evaluation_as_of_date`。

服务端只用固定17列、三坐标绑定和 `LIMIT 1` 读取已持久化病例包，再调用独立 runner。入口不调用四川旧服务、任务 API、workspace API 或持久化 API。返回对象只有有序的客户结果 DTO 和聚合运行指标。开关 `LUXIAN_0609_PREPRODUCTION_API_ENABLED` 默认关闭；现有客户主链没有切换。

这不是《LX0609 质控引擎渐进升级计划》的 Phase 6 完成声明。当前49点的内部成熟度为：

| 判定形态             | 规则数 |
| -------------------- | -----: |
| 统一 `RuleDecision`  |      8 |
| typed shadow adapter |      3 |
| legacy projection    |     38 |

因此，本轮交付应称为“49点统一编排的独立准生产入口”，而不是“49条判定核心全部重写完成”。

## 2. 测试方法

- 同一批20份本地真实病历；同一49规则目录顺序。
- 样本由既有固定10例和稳定补充10例组成。
- 模型配置相同，并发为1，缓存关闭。
- 新旧路径均不写数据库、不创建任务、不修改客户结果。
- 统一冻结评价日为 `2026-07-17`。
- 补充10例来自相对完整的0426病例集合；该集合普遍缺首次病程记录。
- 因首次病程缺失，依赖该文书的 LX0609-002、LX0609-016 共40条判断不纳入临床准确性结论，但仍纳入范围、性能和技术错误统计。

20例真实模型批次完成后，独立审查又发现并修复了 DTO 对“嵌入坐标、正文前缀和中间片段”的脱敏缺口。该修复不改变状态、模型调用或 token；修复后以冻结 case-02 进行零模型冷进程快检，49点完整调用为312.824ms、runner内部为236.009ms，未出现秒级编排退化。表中的真实模型耗时仍采用同一批20例实测值，未把单例冷进程数据外推为新的20例性能结论。

## 5. 人工核对和准确性

### 5.1 新旧差异

最终新旧状态相同896/980（91.43%），不同84/980。84条差异全部进行了结构化或正文人工核对：

- 60条：LX0609-001/005/006 缺权威入院时间，新引擎 `data_gap` 正确；
- 23条：LX0609-008/009 没有病重/病危初始触发，新引擎 `not_applicable` 正确；
- 1条：case-15 的 LX0609-046 存在逐份完整输血记录，新引擎 `compliant` 正确。

84条差异中，新引擎正确84条，旧引擎正确0条。

### 5.2 不合规精确率

- 新引擎：47/47 = **100%**；
- 旧引擎：47/52 = **90.38%**。

在本轮已确认的47个缺陷集合中，新旧引擎都命中47/47。这个数字只代表已核对缺陷集合，不代表980条总体召回率。

### 5.3 定向审计

定向审计共151条：84条全部差异、47条双方共同不合规、20条同状态合规抽样。

- 新引擎：151/151 = **100%**；
- 旧引擎：67/151 = **44.37%**。

该集合是“差异和不合规富集”的定向审计，不是随机样本，禁止把100%写成全部980条的总体准确率。

人工核对使用了本次运行中仅以内存保存的病例坐标，并只在报告中保留安全 case 标签和聚合计数。为避免提交患者索引，逐病例原始审计账本未进入代码仓库；因此后续独立审查可以复算本报告的计数和比例，但若要重新核对84条差异，必须用同一稳定选择器重新执行只读审计。

## 6. 稳定性和接口等价

- 独立旁路与同配置的新服务路径在同20例上状态 980/980 一致；
- 32/32 prompt hash 回放完整消费，接口形状和规则顺序一致；
- 最终版本相对前一版只有3条预期的 `non_compliant -> compliant`：case-12 的045/046和case-15的046；没有非预期状态漂移；
- 49条结果 exactly-once，目录顺序正确，技术错误为0；
- 基础 Python 路径由真值表和零模型断言覆盖。

本轮没有完成全部语义规则“同输入连续3次”的夜间稳定性门，因此不能宣称全49语义稳定性已达到正式发布标准。

## 7. 隐私和客户边界

最新准生产 DTO 已进行递归扫描：

- 不包含 institute/patient/visit 三坐标；
- 不包含病历正文、完整长文本或正文前缀；
- 不包含 prompt、raw response、SQL、异常文本；
- 不包含 `evidence_payload`、`fact_refs`、snapshot、documents、bundle；
- 不包含旧映射 ID 或 `mapped_rule_ids`、`primary_execution_rule_id`；
- 保留客户可读的安全 `evidence_items` 和受控来源名称。

真实 API 20例响应再次逐一扫描全部三坐标、病例正文24字符前缀和禁用内部字段，
命中均为0。关闭开关后，同一 checkout 的真实认证请求在120.636ms返回404；该
路径在认证存储、请求正文解析、病例读取、模型客户端和 runner 之前终止。开启、
关闭两个8002测试进程均已按PID停止，未触碰8001。

基础 settings 使用只读 overlay，不修改进程环境或持久化配置。基础设施异常会为所选规则返回安全 `technical_error`，不会回显异常。

## 8. 验收决定和剩余限制

### 有条件 GO

独立 API、默认关闭开关、20例真实请求、隐私检查和关闭回滚已经完成。前端人工试用
仍需满足：

1. 人工接受本报告的样本边界和 `data_gap` 增加；
2. 前端只消费准生产 DTO，不读取内部 trace；
3. 初始流量限定为内部人工验收，不回写客户正式结果；
4. 保留旧引擎作为一键回滚路径。

### 尚未完成

- 38条规则仍是 legacy projection；
- 所有 Golden gate 仍未达到全规则发布门；
- LX0609-009 的“病情变化时是否及时记录”语义子结论仍可能为 `data_gap`；
- 002/016 在本20例缺首次病程记录，不能据此评价临床准确性；
- 语义规则3次稳定性、全规则随机样本准确率和正式回滚演练仍属于后续发布门。

因此：**准生产旁路可以交给人工验收；当前不得宣称全新引擎完成，也不得自动替换正式客户主链。**
