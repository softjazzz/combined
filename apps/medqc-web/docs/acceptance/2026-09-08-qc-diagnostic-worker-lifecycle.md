# 单病例诊断跨 worker / commit 生命周期

## 原问题与最小方案

正式批量 worker 在单病例 observation context 内执行，结束后才统一提交 Canonical 结果。仅在病例执行外包 capture_scope 会过早释放材料；把整个并发批次包入一个 capture_scope 又可能串病例。

本批新增任务私有的 DiagnosticJobCapture，只有后续服务端授权入口可以构造并传给 worker；本批没有启用 HTTP 授权入口。对象限定一个 job_id 和一份病例三坐标，原件不进入全局注册表。

- 同一个对象只允许一个 worker 接管，重复派发不释放首个 worker 的材料。
- 仅选中的病例进入既有内存采集器；其他病例显式屏蔽继承的 context。
- 病例执行结束保留材料，批次提交时临时恢复同一采集器，消费上一批实现的正式提交回执。
- 同一病例被重复执行时拒绝交付诊断，避免“第一次输入＋后来结果”混包。
- worker 生命周期包装覆盖提前返回、异常及 CancelledError；提交材料存在时调用服务端提供的本地脱敏消费者，随后释放原件及内部病例坐标。
- 异步到期回调释放采集器，不等待下一次模型响应；不会取消正常质控。同步 CPU 长时间阻塞事件循环时不能保证计时回调准点触发，原采集器操作检查仍保留。
- 本地消费者失败只记录固定诊断错误，不回显异常正文，不改变正式质控状态。

所有匹配/释放职责在独立 job_capture.py；巨型 worker 仅增加可选参数、生命周期装饰和两个 scope 接线，不迁移规则、重写调度或加入诊断平台。默认参数为 None，关闭诊断不创建计时器或保留原件。

## 验证证据

先新增失败测试（模块不存在），再实现。追加“重复 worker 提前释放”测试先失败、修复后通过。

- 生命周期单测与正式 worker 集成：9 passed，6.20 秒。涵盖并发选中/非选中病例、取消、执行中到期、错误任务、重复病例、重复派发、消费者异常和 ambient context 隔离。
- 集成复用正式会诊三入口验收：运行真实 worker、prepare、会诊执行器及 Canonical 写入，仅替换医院资料读取和模型配置，写入临时合成 SQLite。原有单条、病历池批量、样本任务的状态/原因/事实/证据断言全部保留。
- 三个任务均收到选中病例的当次输入及对应已提交结果；两病例并发任务仅交付选中病例；所有采集器留存计数归零。此处 022 合成样例不需要真实模型调用，不能据此宣称会诊录制响应回放已完成。
- 诊断＋批量吞吐/取消回归：316 passed，1 deselected，14.02 秒；之后新增重复派发反证并再次运行上述 9 项聚焦检查。
- 被单独排除的 `test_create_workspace_batch_job_full_luxian_set_uses_current_customer_scope` 在原完整运行中失败：生产目录多出 076/077。将 worker 源码用 HEAD 版本在独立 Python 进程内恢复后，该项仍同样失败。未改测试预期或生产目录，不把该项算作绿色验收。
- check:encoding 通过但扫描 0 文件；另显式检查本批 UTF-8 无 BOM / LF。全局 lint 为 0 errors、677 条既有 warnings。前端未修改，未重复全量前端类型与单测。

未触碰客户数据库、未发送真实模型请求、未重启服务、未推送。临时 SQLite 保存的是原业务链的合成结果，不是诊断原件缓存。

## 仍待完成

这只是服务端内部生命周期接线，不是客户已经可以授权采集并导出完整材料。还需完整上下文/构建版本绑定、完整脱敏与硬性隐私/引用等价校验、管理员入口与并发资源总限额、受支持规则离线回放、实际客户包验收。

consume 是可信服务端本地处理边界，禁止提供客户自定义回调、写入原件或向网络发送原文；当前未连接生产消费者，所以仍没有原始材料的下载/落盘出口。
