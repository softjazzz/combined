# R01 068 未定时出院意见兼容路径验收

## 验收范围

本轮只修复 `LX0609-068` 在兼容调用没有 LLM 客户端时的错误状态，不改变 068 的规则口径、资料来源或正式批次输入。质控继续消费 Bundle/Evidence；CDM 原表不进入规则执行器。

## 问题证据与根因

冻结用例已证明：病程资料中存在可由确定性规则识别的“上级医师同意出院”意见，但文书时间缺失时，正确结果应为 `data_gap/authoritative_time_missing`。修复前执行器先进入语义回退；兼容调用没有传入 `llm_client` 时，语义抽取返回 `technical_error/model_transport_error`，覆盖了已经成立的确定性结论。

该因果关系由以下两条路径独立反推确认：

1. 执行器先构造 `undated_approvals`，旧分支仍无条件调用 `extract_discharge_approval`；后者在客户端为空时返回技术错误。
2. 同一输入在修复前的聚焦用例稳定得到 `model_transport_error`，修改分支门槛后稳定得到 `authoritative_time_missing`，且模型调用数为 0。

## 最小修改

语义回退现在只在“确定性路径没有结论且存在 LLM 客户端”时运行。已有确定性未定时意见直接进入 `authoritative_time_missing`；既没有意见也没有客户端时继续保持原有 `data_gap/source_empty`。

`native_extended_document_execution.py` 已超过 Python 文件预警线。本轮只修改既有 068 分支的一项进入条件，没有增加职责或生产代码块；为这一行逻辑建立新模块会形成转发壳，也达不到迁出至少 250 行完整职责的收益门槛，因此本轮不拆分文件。
