# 输血族选中文书证据修复

## 范围与结论

本闭环以 `47b7de7c2` 为基线，修复执行器只输出来源观察引用、客户证据依赖聚合器反查的问题。仅调整输血执行器内部来源保留与引用绑定，使用既有 Evidence Session、Binding 和公共文书投影。

- 041：选择输血同意书及输血触发记录，排除手术同意书。
- 044：结构化申请选择实际申请文书；非结构化评估保留原正文判定并记录命中来源。文书 ID 缺失不反向改变正文判定。
- 045：选择实际核对的专用输血记录，移除旧冻结结果中的无关日常病程。
- 046：合规时选择已核对记录，缺项时选择缺项记录。
- 047：在原有 assessment 中保留结束时间与所采用评价的文书来源；日常病程提供评价时可定位该文书，时限算法不变。

绑定按来源和既有身份字段精确匹配，同业务 ID 的多条材料全部引用；跨来源同 ID 分别保留。申请编号与文书编号不同仍可匹配。声明引用的控制字符在边缘空格处理前拒绝。无法绑定时为 `technical_error/snapshot_mismatch` 并清除客户事实；引用超过既有 128 条合同上限时为单规则技术错误，不静默截断。

## 改动规模与审核

生产修改仅为 `native_transfusion_execution.py`，本轮最终提交前统计为新增 341 行、删除 59 行。超过 200 行预警的原因是 044 正文判定和 047 时间判定必须在原判断位置同时保留来源；把来源事后交给新模块重算会再次形成事实所有者。其余私有助手只将已选身份映射为同一材料仓库的既有引用。未新增公共合同、DTO、注册表或投影组件。

原公开入口签名保持兼容；Prompt、临床状态判断和时间阈值保持原逻辑。证据集合纠错属于独立修复，不能计作结构迁移行为等价。后续迁移应以本修复提交重新冻结。

主协调审查并纠正了“按是否存在 ID 决定正文判定”、双编号匹配、观察引用丢失和引用上限隔离问题；独立审查核对了来源选择、时间算法与异常清理。
