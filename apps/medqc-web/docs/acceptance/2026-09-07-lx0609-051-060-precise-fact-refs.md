# LX0609-051/060 精确事实引用验收

## 旧问题

死亡文书规则的 Native 执行器能够确定 051 的最早死亡后讨论记录，但
`RuleDecision.fact_refs` 仍按来源类型纳入全部死亡讨论文书。聚合器因此需要
从展示事实中的私有 `source_document_refs` 再次选择客户证据，形成两个证据
所有者。060 也会把住院登记等来源级事实混入已确认死亡记录的证据集合。

## 本次收紧

- 051 仅将已裁决的死亡记录与最早死亡后讨论记录映射为同一 Evidence Snapshot
  中的 `fact_refs`；较晚或死亡前讨论不会进入引用集合。
- 060 仅将实际死亡记录映射为 `fact_refs`。
- 文书 ID 仅在执行器内部把已选行转换成 Snapshot 引用；不会新增客户字段、日志
  字段或摘要。

## 无文书 ID 的保守行为

若已判定的死亡/讨论行没有真实文书 ID，执行器保持既有来源级 `fact_refs`，不把
正常的资料定位不足升级为 `technical_error`。公共证据投影仍只展示能定位到真实
文书 ID 的证据，因此不会凭其他未选文书伪造定位。

## 不变项

本提交不修改死亡适用性、七日时限、`data_gap`/`not_applicable` 口径、Prompt、
来源目录、Renderer、数据库或 API。051 的未成熟窗口继续保持现有
`data_gap / evaluation_window_not_mature`，另行处理。

## 验收

在 `backend` 目录执行：

```powershell
py -3.10 -m pytest -q tests/unit/test_luxian_0609_native_extended_document_execution.py
```

结果：`247 passed`。其中包含 051 的最早死亡后讨论、死亡前讨论排除、无真实文书
ID 不伪造客户证据，以及 060 死亡记录缺失等回归形状。
