# PRD - 招标参数功能验收口径

更新时间：2026-06-08

## 1. 文档目标

本 PRD 用于统一招标参数对应的产品功能边界、验收口径和演示口径。当前阶段采用“最低基本要求”作为验收边界：每个条款需要有可演示入口、真实接口或本地数据源、结构化结果展示和只读/草稿安全边界；不要求达到医学专家金标准、全字段 100% 覆盖、医保正式一致率或多源证据闭环。

验收对象是系统是否按招标参数字面形成可演示功能闭环。不以静态页面占位替代功能，但允许能力以草稿、模拟、候选建议、待人工复核方式完成。

配套文件：

- `docs/acceptance/tender-coverage/coverage-matrix.md`
- `docs/acceptance/tender-coverage/coverage-matrix.json`
- `docs/acceptance/tender-coverage/demo-script.md`
- `scripts/acceptance/run_tender_acceptance.py`

## 2. 通用安全边界

- 自动生成结果只能进入草稿、预览、模拟或待人工复核状态。
- 不自动写正式病案首页。
- 不自动写正式医保结算清单。
- 不自动写正式 DRG/DIP 入组结果。
- 不向前端或报告暴露 `raw_response`、`medical_text`、`documents`、`record_content`、`internal_data`、`prompt`、`embedding`、`vector`。

## 3. 条款验收口径

| 条款  | 功能                     | 验收口径                                                                                                                                                                             |
| ----- | ------------------------ | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| 3.1.1 | 首页自动生成             | 能基于病历文书生成病案首页和医保结算清单草稿，并按患者基本信息、住院信息、诊断及手术操作信息、其他住院医疗信息、人员信息、费用信息展示提取结果或缺失状态；正式保存必须保留人工复核。 |
| 3.3.1 | 质控规则                 | 能对病案首页和医保结算清单执行字段完整性、格式规范性、逻辑性或一致性规则，并展示规则结果、问题明细和只读边界。                                                                       |
| 3.4.1 | ICD 编码规范内涵质控     | 能基于 ICD 编码规范，对诊断编码、手术操作编码、医保版/国临版映射、附加编码、病理编码和费用字段给出编码逻辑一致性问题或建议。                                                         |
| 3.4.3 | 诊断及手术操作完整性校验 | 能基于现有病历文书形成疾病诊断画像、手术操作画像、诊断发生发展时间轴和手术操作执行与否验证，并在病案首页页签旁提供“画像辅助”入口，作为首页书写或生成的辅助对照。                     |
| 3.5.1 | 智能编码                 | 支持国家医保局、国家卫健委相关 ICD 诊断和手术操作编码查询，返回候选编码、版本、映射、匹配方式和置信度。                                                                              |
| 4.1.2 | 病案问题概览             | 以消息列表或任务列表方式推送当天病案问题集中点，支持定位到病历和问题处理入口。                                                                                                       |
| 6.1.1 | 基于病历信息的自动化入组 | 能从病历信息抽取主诊断、手术、年龄、费用等入组字段，并生成 DRG/DIP 只读模拟入组推荐或待补充提示。                                                                                    |
| 6.2.1 | 预入组及修正建议         | 能提供 CHS-DRG 或 DIP 预入组结果；未入组或存在编码缺失时，返回编码修正建议，不自动写正式编码。                                                                                       |
| 6.2.2 | 分组器本地化适配         | 能使用本地化分组数据源、权重、分值或配置版本执行模拟分组，并保留配置来源或版本信息；一致率 95% 属于后续金标准样本验收。                                                              |
| 6.2.3 | 医保付费监测             | 能基于地方 DRG/DIP 付费标准进行模拟费用预判断，展示盈亏、支付率、费用异常分组或控费建议。                                                                                            |
| 6.3.1 | DRG/DIP 综合分析         | 能展示院级、科级、病区、主诊医师组、个人等至少一种或多种层级的 DRG/DIP 指标分析、盈亏分析，并提供导出入口或导出能力。                                                                |

## 3.1 当前阶段不纳入阻塞验收的增强项

以下内容属于后续增强，不作为当前最低基本要求的阻塞项：

- 首页和结算清单所有字段 100% 自动提取准确。
- 使用脱敏金标准样本证明医学准确率、字段召回率或医保一致率。
- 通过手术记录、麻醉记录、医嘱、费用和手术相关单据等多源证据严格证明手术是否真实执行。
- 自动写入正式病案首页、医保结算清单、正式 DRG/DIP 入组结果或正式质控结果。
- 对全部地区、全部医院付费方案完成生产级本地化适配。
- 对所有 DRG/DIP 指标、报告和导出格式完成生产级经营分析闭环。

## 4. 3.4.1 ICD 编码规范内涵质控专项定义

### 4.1 正向范围

3.4.1 只验收编码侧内涵，不验收普通病历书写质量。当前阶段最低要求是能在结构化样例或真实候选数据中识别或提示以下至少一类编码问题：

- 肿瘤主诊断编码与病理诊断编码、形态学 M 码之间的不一致或缺失。
- 病理编码存在时，病理诊断名称、病理诊断费和首页字段之间的不一致。
- 阑尾炎与腹膜炎同时出现时，是否需要按 ICD 规则合并编码。
- 冠状动脉支架置入术存在时，是否需要补充共同使用的附加编码。
- 诊断编码与手术操作编码不匹配。
- 医保版编码与国家临床版编码映射不一致。
- 编码问题对病案首页、医保结算清单、DRG/DIP 预入组结果的影响。

### 4.2 排除范围

以下内容不作为 3.4.1 的验收对象：

- 病程记录是否写得详细。
- 查房记录是否书写充分。
- 主诉、现病史、体格检查文字质量评价。
- 医生书写水平评价。
- 文书缺失、文书时限和文书格式问题。

这些问题分别归入：

- `3.3.1`：字段完整性、规范性、采集标准规则。
- `3.4.3`：疾病诊断画像、手术操作画像、诊断发生发展时间轴、手术操作执行与否验证，以及首页书写辅助对照。

### 4.3 结果卡要求

3.4.1 的演示结果应尽量展示：

- 当前诊断编码或手术操作编码。
- 触发的 ICD 编码规则。
- 编码依据和医学/规则解释。
- 推荐编码、合并编码或附加编码。
- 对首页、结算清单或 DRG/DIP 入组的影响。
- 只读提示：不写正式首页、不写正式结算清单、不写正式 DRG/DIP 结果。

## 5. 3.4.3 诊断及手术操作完整性校验专项定义

### 5.1 当前阶段最低要求

系统需要形成一个可演示闭环：

- 使用现有 `AIProfileDashboard.vue` 作为画像展示入口之一。
- 使用 `/api/v1/frontpage/profile/analyze` 或 `/api/v1/clinical-completeness/{visit_id}` 作为画像、时间轴或执行验证的数据来源。
- 页面明确展示四块内容：`疾病诊断画像`、`手术操作画像`、`诊断发生发展时间轴`、`手术操作执行与否验证`。
- 在病案首页页签旁提供 `画像辅助` 入口或提示区。
- 结果只作为病案首页书写或生成时的辅助对照，不写正式首页、结算清单或正式质控结果。

### 5.2 当前阶段不要求

- 不要求整合手术记录、麻醉记录、医嘱、费用、手术相关单据等全部证据源。
- 不要求证明每个手术“真实执行”的医学法证级闭环。
- 不要求自动判定全部首页诊断/手术漏填、错填或无依据。
- 不要求与正式病案首页字段做逐字段强联动写回。

## 6. 验收脚本

推荐总入口：

```powershell
python scripts\acceptance\run_tender_acceptance.py
```

前端截图证据可单独运行：

```powershell
npm run test:e2e:tender
```

验收通过只表示已经满足当前最低基本要求的可演示闭环。医学准确性、医保入组一致率、字段提取准确率和多源证据完整性仍需使用脱敏金标准样本集做专项评测。
