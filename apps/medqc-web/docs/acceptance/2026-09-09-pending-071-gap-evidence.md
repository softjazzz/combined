# 071 普通病程缺口的精确文书绑定

## 问题与方案

原排障包071：3份普通病程有document_id，快照和执行器事实各保留3条文书引用，但最终选中文书引用和客户定位均为0。两项真实native→binding→Finalizer测试复现缺签名、缺时间场景的同一遗漏（实际0，预期3）。

原因是bind_handoff_evidence仅选择交班/接班时间对应文书，入口也未传普通病程。最小方案在既有绑定器接收daily_course_rows，仅处理physician_signature_timeline_incomplete分支的既有source_document_refs，按明确来源与唯一ID找回已消费行，再复用现有快照绑定。不重新解释判定、不按时间或正文猜关联。

生产范围为continuity_evidence_selection.py及native_extended_document_execution.py的071调用点。巨型执行入口仅传递已有daily_rows，不增加独立职责；绑定职责继续留在既有证据模块。错源、不存在或重复ID沿既有binding_failed→snapshot_mismatch技术失败语义关闭；无可用引用不伪造文书定位。

## 验收目标

原病例定位从0恢复到3条，状态data_gap、原因required_field_missing、缺签名3份和0次模型调用保持；人工构造无关术后文书不得进入普通病程定位，错源及歧义引用不得误绑定。

## 范围限制

本轮只修既有普通病程缺口引用的搬运；不扩展其他经治医师变更分支，不改变文书筛选规则或引用数量上限。通用data_gap_details字段文案保持原合同。旧任务保存结果及客户部署包未自动更新。

## 实际验收

- 主协调复跑原包Provider→native071→binding→Finalizer，与固定旧版本56614f12b比较：客户定位0→3，选中文书引用0→3；三条均为daily_course_record并逐一对应原包三行。状态、原因码、缺项事实、客户文案逐字段一致；两边0次LLM调用。禁止网络连接，不访问数据库。
- 350项交接班、公共定位、事实映射及扩展文书执行回归通过（4.51秒）。新增绑定与完整链路测试、前轮文案测试共19项通过，覆盖无关术后记录排除、错来源、未知/重复ID、同ID跨源、非法引用、合法空引用及无标题场景不变成技术错误。
- 审查纠正了初版把空引用转为技术错的问题：合法空列表保留原判定且无定位；只有声明了无法可靠绑定的引用才失败关闭。
- ESLint 0错误、11条既有格式警告；未运行带--fix的lint。npm编码检查扫描0文件，另对本轮6文件严格验证UTF-8无BOM、LF及git diff --check。

本次确认的是最终结果中可供页面使用的三条精确文书坐标；未在客户机上点击验收，未重打发布包。
