# 正式保存结果与诊断采集关联

## 证据与实施边界

批量 worker 在单病例 observation context 内执行规则，但统一在所有病例处理后调用 complete_batch_job。执行器返回不等于数据库提交成功。本批补齐保存边界接缝，暂不启动客户侧采集。

- CanonicalResultStore 沿用原投影和原序列化，只在明确请求时返回与 INSERT 使用的同一 JSON 字符串及既有 CaseRef；不重复投影、不查询数据库复取结果。
- 默认不收集回执。提交前回执单独限制在 4 MiB 内，超限清空整组且继续原保存，诊断后续标记结果未匹配；不会持有部分回执并声称完整。
- complete_batch_job 仅在 commit 成功且任务完成 UPDATE 的 rowcount 为 1 时调用旁路。取消导致未更新、写入/提交异常时不通知成功。
- 采集器要求显式 job_id、已采集材料及可用病例 observation context；校验子任务 ID、根任务 ID 和原 snapshot 的 visit_ref，匹配结果必须唯一。缺失身份时不猜测。
- 结果与材料/模型共享采集器原 20 MiB 留存额度，作用域退出/过期后清空。结果始终仍是 partial，不把结果匹配等同于发布版本/回放完整性成立。

CustomQCWorkspaceService 已是巨型文件，本次仅修改保存接线与返回类型，未向其加入新业务职责；诊断匹配和生命周期仍在独立诊断模块。没有拆分原架构、增加保存字段或修改医学状态。内部写入方法由 None 返回改为可选收集的回执元组，原调用者可以忽略；对外 API/数据库合同不变。

## 验证

- 新测试先因缺失 capture_committed_results 失败，再实现：原写入 JSON 精确相同、关闭不留存、错误任务/病例拒绝、重复匹配拒绝、容量限制和提交/取消语义。
- 事务测试使用替身，明确核对事件顺序；没有真实数据库写入、真实模型调用或病历重跑。
- 完整诊断＋原 Canonical 交付/工作台记录＋LLM 客户端/观察日志：363 passed，9.04 秒，2 条既有 Pydantic 提示；随后新增 3 个容量/重复负例，新文件全部 14 passed。
- 前端无修改，最低编码和 lint 检查按本批提交执行；编码另显式检查本批文件 UTF-8 无 BOM、LF。未复跑全量前端单测或类型检查。

## 剩余项

保存接缝不代表客户已启用：仍需把授权选中病例的采集生命周期跨过 worker 的单病例执行与批次 commit，且不能让并发其他病例进入同一采集器。准确构建版本、其他执行上下文、完整脱敏/引用等价、客户入口及离线执行回放均未完成。

原件未新增文件/下载/网络出口，未增加加密。当前历史受限包能力不变，不宣称本批已实现完整诊断导包。
