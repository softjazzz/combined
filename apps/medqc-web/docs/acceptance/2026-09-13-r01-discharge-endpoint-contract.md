# R01 出院终点合同聚焦验收

## 验收范围

本轮只收口 `LX0609-061`、`LX0609-067`、`LX0609-068` 共用出院终点的问题，目标记录为 C03、C15。质控仍消费 Bundle/Evidence 资料链；CDM 原表只用于交叉核对，不作为规则旁路输入。

## 问题证据与根因

当前批次保存的逐病例冻结快照完整：C03 的权威出院终点为 `2025-08-13 09:27:40`，C15 为 `2025-08-09 08:42:53`。修复前，三条规则会在执行器内重新读取住院登记或出院记录字段，C03 实际使用 `2025-08-12`，C15 实际使用兼容字段中的 `2025-08-02 08:00:00`，造成窗口、证据及 061/068 状态分裂。

代码与真实批次反推确认有三个连续断点：

1. Evidence Provider 的评价终点规则集合遗漏 061、067、068，收到冻结快照后仍不生成 `evaluation_context.horizon`。
2. 061、067、068 各自调用本地出院时间 helper，没有共同优先消费冻结终点；出院记录回退还允许兼容时间覆盖标准日期。
3. 061 开始输出 `discharge_time_source=evaluation_context.horizon` 后，客户事实白名单未登记该来源，导致执行层成功结果被 Finalizer 改成 `technical_error/model_invalid_output`。

以上结论分别由批次 `0a35c448-580f-4cec-a811-ab19318c78ac` 的保存快照、批次 `aef28f85-8902-48d3-9637-5afa0a0cfd54` 的执行层/交付层差异和事实映射代码独立核对，不采用子代理未验证的因果推断。

## 实施范围

- Evidence Provider 为 061、067、068 生成统一的 `evaluation_context.horizon`。
- Source Registry 把该派生来源登记为三条规则的判定支持资料。
- Extended Document 执行器让三条规则优先使用冻结终点；只有兼容调用没有冻结终点时才回退原字段。出院记录同时存在标准日期和兼容时间时，以标准日期确定业务日，同日兼容时间只补充时分秒。
- 061 的客户事实合同接受 `evaluation_context.horizon` 作为合法时间来源。
- 冻结终点明确返回 `authoritative_time_missing` 或 `authoritative_time_conflict` 时，三条规则统一关闭为资料不足，不再回退到执行时读取的旧字段。

`native_extended_document_execution.py` 已超过 Python 文件预警线。本轮改动没有新增独立职责，只调整该文件中既有的出院终点 helper 及 061/067/068 调用点；拆成新模块会把一个既有小职责拆成转发壳，达不到 250 行职责迁出门槛，因此不在本轮做结构拆分。没有新增平台、状态机、Bundle 或回退资料链。

聚焦测试覆盖冻结终点生成、三规则消费、无效冻结终点禁止回退、标准日期与兼容时间优先级、061 客户事实合同以及既有扩展文书规则回归。
