# 排除文书更新时间冒充业务出院时间

## 根因与范围

RecordRepository.\_build_records_query 的出院时间表达式依次取首页 discharge_datetime、出院记录 discharge_date、出院记录 update_time。最后一项是文书元数据，导致只有更新时间的记录被选择为 final，且命中出院/就诊日期过滤，再经序列化进入逐病例任务冻结。

主协调亲读 SQL 查询、序列化和任务冻结链；独立只读审查确认按 ID 和按 CaseRef 的两个补锚点入口都不使用 update_time 回退出院时间。因此本轮只删除主查询的该项回退，不新增 discharge_time 来源、不改入院时间、排序或跨源优先级，也不改变缺少业务出院日期时既有 running 选择行为。

## 红绿与回归证据

使用 SQLite 内存库创建真实模型表与三组无身份样本，执行真实 query → serialize → build_record_evaluation_horizon_snapshot。仅更新时间的样本错误进入 final，错误命中出院日期过滤及就诊日期过滤；修复前 3 项失败、1 项合法业务日期优先级保护通过。删除错误回退后，与原记录查询、CaseRef、冻结 Provider 及真实入口回归合计 53 项通过（1.33 秒）。

合法首页出院时间仍优先，出院记录日期仍可回退；只有 update_time 的记录不再据此生成终末截止日。出院记录 discharge_date 在模型中为日期，既有查询按午夜呈现，本轮只保护原有表示，不宣称其有实际时分秒精度。

无真实数据库操作、无模型调用、未重跑保存任务或更新客户包。前端未修改，执行无自动修复 ESLint 与编码命令；编码脚本扫描 0 文件，另独立检查本轮文件 UTF-8 无 BOM/LF。短小的一行生产修复由主协调直接实施，独立代理核对其他入口与受影响筛选范围。

## 尚未解决

登记、首页及出院记录业务字段的跨来源优先级仍未统一。原排障病例仅 discharge_time 有值、discharge_date 为空，本轮没有擅自新增该字段为全局权威，也不据此宣称原病例场景已改正确。原任务结果与发布包未更新。
