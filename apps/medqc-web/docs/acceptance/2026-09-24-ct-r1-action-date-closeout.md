# CT/MRI重复检查日期归属 R1 代码收尾

基线：`ce1e125284a18193d1638879c08ca657e5f4a4c7`；规则：`LX0609-06-01-01`。本次仅修该规则在重复检查时把计划、报告和结果处理日期当作实际检查日期的错误合规。尚未作客户病例、真实模型或部署验收。

## 可复现的原问题

固定两条同名胸部CT医嘱及已执行检查，实际检查日分别为9月1日、9月3日。将一条格式合法的v3模型响应同时关联两次检查，病程正文为“9月1日完成胸部CT，拟于9月3日复查胸部CT”时，原代码只看日期后紧邻“复查胸部CT”，两条均输出合规。换成“9月3日胸部CT报告审核发布”或“9月3日胸部CT结果补录”也同样误判。这些句子只证明第一台检查已记录，不能证明第二台的执行记载。

修改前在当前真实`evaluate_ct_review`上，新增R1参数组为9失败、13通过；其中3项失败经过实际Evidence Session、`native_exam_lab_execution`与Finalizer，发布状态错为`compliant`。进一步验证发现，把限定词放到前一个日期之前，如“计划9月1日完成……，9月3日完成……”，如果以遇到新日期为作用域结束，第二台仍会被错误放行；名称后“完成报告签署／完成结果录入”也会被截取成“完成”。这两类随后加入红测，再修复。

## 最小代码边界

只改`ct_order_course_consistency.py`的`_unique_temporal_anchor`。实际日期仍来自检查事件，不采用最近时间匹配；先排除同日重复和缺少实际检查时间的候选，再检查日期所在句的前置计划、假设、否定或历史限定，以及日期后同一动作片段中是否存在明确检查实施表达。名称后的报告、结果、录入等文书动作和无关宾语不能证明检查实施。无法确认的原`consistent_description`响应落到既有`association_unresolved`，整条为`data_gap`；不新建状态、医学缺陷、模型请求或公共解析层。

此处为受控高精度表达，不是中文临床语义的全面识别。没有明确实施谓词、较自由的术式修饰、前一计划后同句另起实际检查等表达可能保守地落到资料不足，需以后续独立材料评估召回。报告日期、医嘱时间仍不能冒充检查实际时间。
