# LX0609 064/065/066 术后病程族精确证据坐标验收

日期：2026-09-07

## 范围

本闭环只收紧 native extended executor 中 `LX0609-064`、`LX0609-065`、
`LX0609-066` 的 `RuleDecision.fact_refs`。状态、原因码、展示 facts、065 的
72 小时评价终点口径以及 Aggregator、Finalizer、Renderer、API、前端均不修改。

## 证据坐标合同

| 规则 | 精确客户证据                                                              |
| ---- | ------------------------------------------------------------------------- |
| 064  | 每台手术事件、实际覆盖术后第 1–3 日的有效病程、实际命中术者查房判断的病程 |
| 065  | 每台手术事件、该事件结束后 72 小时内实际命中的上级查房病程                |
| 066  | 每台手术事件及其实际关联的首次术后病程；发生缺失时只保留未满足的手术事件  |

`evaluation_context.horizon` 仅参与 064/065 的窗口判定，绝不进入 `fact_refs`。
窗口未成熟、无触发或无逐行消费的资料缺口保留最小 snapshot 源级判定锚点；它不被
公共客户文书投影。任何已经消费的行若无法唯一定位为同一 snapshot 的逐文书引用，
Binding 必须归约为 `technical_error`，不能退回全量来源或伪装业务状态。

## 多事件关联

064/065 使用正式手术记录一行一事件；064 的每日覆盖和术者查房证据按当前事件的
术后日期收集，065 的查房证据按当前事件结束至 72 小时 deadline 收集。066 继续使用
既有“最近已结束手术”关联首次术后病程，缺失结论不顺带引用已满足事件的病程。

合法格式但不属于 snapshot 的精确引用被 Binding 降为 `technical_error`。
