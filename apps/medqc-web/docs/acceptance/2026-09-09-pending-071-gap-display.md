# 071 普通病程签名序列缺口提示

## 问题、根因与边界

原排障包071有3份普通病程，3份均缺结构化医师签名；不是缺普通病程正文。执行器已有总数、可识别普通病程数和缺标题/时间/签名计数，事实白名单也保留了这些数值，但客户Renderer没有处理 physician_signature_timeline_incomplete，最终结论泛称缺经治医师变更时间或交接班记录时间，未指出实际缺项。

最小方案仅补 customer_renderer.py 的现有071受控事实文案分支，以及 customer_remediation.py 的对应资料核对建议。不改执行器、事实合同、状态、原因码或Finalizer。Renderer已有同一规则族的受控文案职责，本次新增约16行同职责分支，无独立新职责，不以文件大小为由引入额外模块或拆分。

结论显示读取数、普通病程数和非零缺项计数；建议核对普通病程的源系统字段及同步映射，不要求据此补交接班记录，不用提交人替代医师签名。仍为 data_gap / required_field_missing。

## 验证

- 首次测试调用遗漏必填参数，补齐后四类场景均在具体文案断言处失败；修复后7项聚焦测试通过（0.20秒），覆盖签名/时间/标题/混合缺项及零计数不误报。
- 071判定、事实映射、Renderer、建议、Aggregator共1065项通过，1项失败（3.01秒）。失败为既有测试硬编码活动规则总数71，当前70。使用HEAD修改前的两个模块重新执行该单项，同样失败；未修改规则目录或放宽该断言。
- ESLint无错误、11条既有格式警告；不带--fix执行。npm编码检查扫描0文件，另对本轮文件严格核对UTF-8无BOM、LF及git diff --check。

## 剩余限制

本轮改善具体结论和核对建议，不宣称资料已补齐。通用data_gap_details/missing_fields文案仍沿既有合同；证据定位单独记录真实回放结果，不能用3条原始引用冒充3条最终可点击定位。

没有重跑保存的旧任务，也没有打包或部署客户机。待处理未全部解决。

## 原病例最终对照

主协调复跑原包 Provider → native071 → binding → Finalizer，并在同一输入下内存加载HEAD旧展示模块对照。旧结论泛称缺变更/交接班时间；新结论为“已读取3份病程记录，其中已识别普通病程3份；3份缺少医师签名，暂无法确认经治医师变更及交接班完成时限。”状态、原因码、六项事实不变；两边0次LLM调用，缺失来源保留不可用，未读数据库。

定位遗留：3行均有document_id、快照和执行器事实均有3个引用，但当前071交接班证据绑定只消费交班/接班行，没有绑定普通病程引用，最终选中引用及客户定位均为0。这是已定位的后续修复点，本次不声称定位已解决。
