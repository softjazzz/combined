# 015 培养结果识别修复验收

日期：2026-09-12。范围仅为已确认培养事件的结构化菌名识别及错误药敏前置提示，不修改 Bundle、时间窗口、状态映射或模型配置。

## 问题与依据

正式规则目录 015 及业务标准基线第 82 行要求：阳性菌结果后 24 小时内记录分析、临床意义或处理。原提示词额外要求“药敏待出时为 unknown”，项目合同没有该前置条件。本次修正不涉及判断感染或评价抗菌药物选择。

C01 的两个培养事件已有明确菌名，备选菌栏为空；原投影未把填名的结构化结果识别为阳性。主协调读取 Bundle 投影、报告和事件允许病程，确认没有针对这两个事件的分析。允许的首份后续病程均已超过 24 小时，且投影未截断、病程时间完整、观察截止已成熟。

仅改提示词仍不稳定：两模型各两轮中，Flash 有一次仍把已填写菌名判为 unknown。因此，可靠的结构化阳性由现有 Python `positive_hint` 提取负责，分析关联继续由既有链路完成。空备选栏不覆盖明确结果；非菌名、涂片和冲突结果不能强判阳性。

## 因果核对与边界

最终验证结果：

- 结构化菌名边界、提示词族隔离、native 执行器合计 209 项单测全部通过。主审发现初稿会将普通中文占位值当成菌名，已收窄名称形式并补充占位/不确定结果负例。
- Flash 与 35B 各两轮，更正后的生产提示词与实测提示词逐字一致；4 份真实回答进入当前完整解析与归约链，015 均为 non_compliant，三个事件阳性枚举均为 positive、positive、negative。只证明这个病例的本次四轮，不代表全样本稳定率。
- 最终 `n012-full30-culture015-full-after-private.json` 对比上述两个基线：仅 C01/015 从 uncertain 改为 non_compliant，其余 149 个完整保存项逐字段相等；C02 的已有不合格结论及证据未变。逻辑调用数 27→27，全部命中冻结回答，真实新增模型调用为 0。
- 该 150 项回放中无 uncertain/technical_error；015 分布为 2 不合格、2 数据不足、26 不适用。仍有资料不足，不将其自动算作已关闭。
- `npm run lint -- --no-fix` 通过。`npm run check:encoding` 仍因两个非本轮修改的前端文件含 BOM 失败：`src/services/semantic-rules-service.ts`、`src/views/medical-records/MedicalRecordsView.vue`。本轮文件单独检查 UTF-8 无 BOM、LF。

主协调直接读取旧冻结回答 `n012-freeze-before-r4/C01-00.json`：两个阳性培养事件的原始 `semantic_state` 已为 `absent`，但 `positive_state` 为 `unknown`。旧解析器因阳性未明将语义降为 unknown；补充可靠的 `positive_hint` 后，原有 absent 得以保留并由成熟窗口判不合格。这不是把任意模型 unknown 改成“未分析”。

独立审查还用合成投影发现初稿漏拦截“未培养出/未分离出/未鉴定/未确定”表达，以及同事件备注、主报告的阴性/污染冲突。主协调用实际投影函数独立复现后退回修正；同时避免宽泛的“无…菌”排除误伤真实菌名。这些是补丁边界反例，不能伪称为新增真实病例缺陷。

本补丁不关闭 012 等其他模型错误，不证明所有菌名格式均可确定性识别，不修改历史病例台账或页面已保存结果。未命中可靠结构化形式的结果仍走原事实提取路径。
