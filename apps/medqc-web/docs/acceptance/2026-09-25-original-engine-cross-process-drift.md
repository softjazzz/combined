# 原始 LX0609：任务运行身份跨进程漂移验证

日期：2026-09-25。范围：阶段 B 的任务接纳快照与跨启动前置门禁；全部为合成配置和隔离 SQLite，不访问客户数据库。

`backend/tests/unit/test_luxian_0609_task_restart_persistence.py` 在第一个 Python 进程通过正式 `CustomQCWorkspaceService.create_batch_job` 保存任务及设置/运行身份快照，在另一个 Python 进程读取同一任务表。第二个进程分别走直接 Worker 接管 `run` 与启动扫描重投 `recover`；其 `collect_records` 被设为若调用即失败，以验证漂移在病例读取前被拒绝。

本轮新增四种同构建号下的漂移输入：提交 SHA、首轮模型名、模型端点和有效规则设置。每种输入在 `run` 与 `recover` 两条路径均从持久化任务领取一个执行代次，最终落为 `failed`，保存相应“模型或实现版本已变化”或“执行配置已变化”原因；启动扫描只重投一次。原有同版/异版构建号、租约续约和启动监视测试继续保留。整份测试 `15 passed`，耗时 108.94 秒；Python Ruff 和差异检查另行执行。

此测试证明隔离 SQLite 上的跨进程冻结身份拒绝语义。它在运行身份门禁后故意停止，不证明完成医学执行、客户 PostgreSQL 多进程争锁、真实安装包恢复或配置管理端到端交互。因此 B 仍为局部验证，不将测试数等同于阶段签收。
