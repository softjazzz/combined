- 保留已有技术原因码和诊断信息；不把模型结构错误转换为临床资料问题。
- 拒绝用直接模拟执行器返回值替代真实非法模型响应测试；另保留明确命名的展示合同注入测试。
- 拒绝为扩展测试增加专用 runtime、身份白名单和 Binding 来源合同。测试仅替换最外层目录文件或病例资料输入，不绕过真实编译和来源判断。
- 冻结中发现 001 错借其他文书 ID，按“先修行为缺陷、后做等价迁移”单独处理，没有机械移除投影分支。

## 尚未完成的架构目标

1. 基础时限执行器仍引用来源快照；材料仓已有逐文书引用，但 Binding 尚不接受它作为 fact_refs。完整证据单所有者迁移未完成。
2. 多文书样本中 001/002 的客户证据仍可能为空；005 从日常病程选中文书时仍可能被标为上级查房来源。已如实记录，未把冻结现状当成正确定位。
3. master 除固定 001 至 075 外，还固定 active 数量；phase 再次固定同样范围。应由一个声明式目录定义范围，其他层校验一致性，不能靠测试专用执行链绕过。
4. 尚未完成三种业务入口的真实病例验收、两条获批新规则试点，以及真实模型预热后十次中位耗时比较。本轮 Stub Token 数不是实测性能数据。
5. 会诊候选范围不足仍存在历史 data_gap/uncertain 分支，本轮没有扩大临床口径修复。

## 后续建议

先单独确认并修正逐文书引用合同和 001/002/005 证据定位，再做行为等价迁移。
目录扩容应另做小范围合同修订，保留重复 ID、非法 ID、目录/phase/contract 不一致的失败关闭校验。
