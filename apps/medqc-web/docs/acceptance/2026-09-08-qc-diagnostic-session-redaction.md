# 当次 provider 材料与事实统一转换

## 本批边界

内部 `sanitize_execution_inputs` 将冻结资料复原后，使用同一个 PayloadSanitizer 对材料、事实内容、日期、匿名坐标和附带文本做一次身份收集。转换后的材料、来源引用、事实 ID、病例引用及快照由原引擎构造器重建，再经离线复原校验。

没有新增客户下载入口，没有修改正式 provider、执行器、保存或临床状态。新模块约 190 行，拥有完整的 session 转换职责；没有向引擎巨型文件加入诊断逻辑。

## 源码证据与取舍

- 独立只读核查确认正式 provider 的六类事实只含布尔或 horizon 数据，均无行级 `source_document_id`、派生 `extensions`。目前遇到这些未支持合同明确拒绝，不丢字段。
- 原冻结材料中可包含 `row_ref`。部分引用的原始计算字段已被正式 reader 裁掉，因此不能重新查库补齐或猜测原算法。统一将它当不透明身份替换，保留关联，再重建外层 document refs；没有引入另一套业务摘要算法。
- 64 位摘要状身份使用独立包内匿名 token，不保留客户摘要；新 token 只含 a-f，避免日期/手机号形状再次触发文本转换。
- 修正上批复原器对正式受控事实来源的判断：依据既有受控来源注册查询，这些来源本来不携带正文材料，不能一概按“available 必须有材料”拒绝。普通来源仍严格检查。
- 事实布尔值与 horizon 的 `basis` 必须不变；身份与业务枚举重叠时拒绝，而不是静默修改事实。
