# 人工质控报表实现假设

本批统计合同尚未获人工确认，不自行提升 PRD 55 覆盖状态。以下为可调整的实现假设，页面、响应及 CSV 均明示待确认。

- 范围：已保存任务人工缺陷，复用审核 owner 的唯一 `_manual_scope` 谓词；医院日历沿用 `Asia/Shanghai`，创建日期转库内无时区 UTC 后左闭右开比较。响应返回读取时刻 `as_of`，不是历史状态回放承诺。
- 录入数：日期窗口中的缺陷行数。当前审核 pending/approved/rejected/unknown 与现代整改 pending/submitted/approved/rejected/unassigned/unknown 独立分列；多次医生提交只按当前整改状态计一条，不将事件次数混入录入数。
- 院科：三坐标缺陷机构与已保存任务病例抽样科室配对。仅来源已核验时输出冻结抽样科室；未知不借用旧缺陷科室或同名跨院科室。科室筛选必须携带机构。
- 来源：唯一且录入人一致的 manual_create 历史、原 task_record/run、原 job 的场景和病例集合、原规则版本结果信封批量校验；不套用任务当前新轮。只有可信来源进入任务筛选，链条不全或错配时任务及科室未知。
- 整改：精确冻结八维 source 匹配现代独立 owner；不存在有效源链、出现其他轮或重复匹配均为未知。未派发仅在源链可信且现代整改确实不存在时成立，不读取旧 qc_defects 整改列。
- 批量：候选集合上限 10000，先全部聚合/筛选再分页；create 历史、病例、原 run、job、精确 job+三坐标信封、现代整改、人员及任务共八次批量读取，不逐例回退 N+1。来源故障返回不可用，不返回伪零。
- 权限：使用持久有效账号；管理员可跨院筛选，质控经理限本机构，普通质控员 API 限本机构本人录入。前端复用现有管理员/质控经理报告导航和页面 tab，不新建页面。
- 导出：同授权/过滤口径，完整病例三坐标、当前审核/整改、读取时间及待确认合同；防 CSV 公式注入。审计仅记录行数和筛选是否应用，不记录病例标识或正文。无正文、证据、快照字段输出。

验证仅使用合成 SQLite/Mock 数据，包括真实人工创建 owner fixture、跨日边界、权限、冻结错轮、批量调用数、分页与导出。未写业务库、未新增或执行迁移、未运行全量或类型检查、未进行真实病例/浏览器验收。
