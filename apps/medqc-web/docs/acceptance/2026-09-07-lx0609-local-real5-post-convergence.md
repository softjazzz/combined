## 真实数据发现及修复

### LX0609-019 客户结果合同缺失

真实任务首次保存时发现：019 在 LLM 判定为不合规时没有生成
`customer_display_facts`，保存层按合同拒绝交付。

修复后，019 的不合规路径输出受控的病理触发来源和已核对目标来源；没有放宽保存层校验。

### LX0609-065 合法资料缺口被映射为技术错误

065 执行器会输出 `postoperative_senior_round_window_unavailable`，但术后结果映射合同没有声明该合法类型，导致 Finalizer 将其转为
`technical_error/model_invalid_output`。

修复后，三份真实病例均稳定输出 `data_gap/source_unavailable`。

### LX0609-020/023 可选字段合同矛盾

二阶段 Prompt 声明 `execution_quotes` 为可选辅助字段，但解析器要求必须存在数组。模型省略该字段时会被错误判为非法输出。

修复后，省略该字段与显式空数组等价；字符串、对象等错误类型仍被拒绝，引用白名单、来源类型、时序和逐建议完整性校验均保持不变。

## 尚未通过的项目

`2496813` 的 020、023 在本次全量复跑中仍为
`technical_error/model_invalid_output`。受控结构采样表明，模型对同一组四至五条会诊建议偶发遗漏建议，或把病程引用放入结构化动作引用字段；独立复跑有时可进入
`uncertain/semantic_low_confidence`，但结果不稳定。

这两项技术错误没有被降级成 `data_gap`、`uncertain` 或临床缺陷，符合批准的失败语义。当前不得通过放宽逐建议完整性、引用来源或时序校验来隐藏问题，应作为独立的会诊语义稳定性缺陷处理。

另发现批量任务详情接口的顶层 `summary.status_counts` 与 360 条实际 Canonical 结果不一致；本记录中的分布取自逐规则、逐病例 Canonical 结果。该汇总问题不影响结果保存，但会影响任务总览，需单独修复。
