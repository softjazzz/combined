```powershell
pytest backend/tests/integration/test_luxian_0609_all_rules_three_entry_acceptance.py -m integration -q
```

覆盖口径：三个客户入口都验证正式客户交付集 70；工作台单例 A、工作台批量 A+B 的请求明确含完整 001--075，但正式持久化/交付必须剔除生产排除集。客户样本池 `/run` A 以正式交付集请求。交付集由生产 `get_luxian_0609_customer_delivery_rule_ids()` 提供后，按本验收批准范围与 master 001--075 取交集；测试再与生产 `LUXIAN_0609_CUSTOMER_EXCLUDED_RULE_IDS` 做不相交与全集闭包断言，因此不复制业务名单。空资料时所有非 `phase_1_target` 规则为 `not_executed/policy_definition_pending`，其余规则校验正式 contract 的 `executor_key`。三入口的 Canonical 状态、原因、客户展示事实、准则与无序证据坐标四元组（来源类型、文书身份、字段路径、记录时间）在共同交付的 70 条上相等，并明确证明排除集不落库。

会诊语义用稳定 LLM stub 仅覆盖确有语义 LLM 路径的 022；批量入口按病历归一调用数与 token，并比较 prompt 与 Canonical 结果。

当前已知主链阻碍：生产 master / phase scope / rule contract 现已延伸到 076--077。本验收明确只截取三份生产资料共同的连续 001--075 前缀，避免把未授权的后续点混入本轮。另，稳定 stub 的调用侧可观测到 `17/5` input/output token，但当前 worker 保存的 job summary 为 `0/0`；因此测试先比较每次真实 executor 调用返回的 token，不把未持久化的数值伪造为 summary。若发布门要求任务汇总 token，需另立生产修复任务。

033/034/035/041/042 是生产 `LUXIAN_0609_CUSTOMER_EXCLUDED_RULE_IDS` 中客户已确认的数据源排除项（缺同意书/收费来源）；这不是主链阻碍。测试不会将它们提交给 `/run`，而是以生产常量为权威精确断言它们不在客户交付集。

如果主链未能完成测试中的生产断言，应保留失败作为发布阻碍；不得用测试夹具伪造 worker 完成或修改生产路径来放宽该验收。
