# 当次冻结资料的离线结构复原

## 范围和结论

新增诊断内部模块 `session_restore.py`，将已冻结的输入重建为引擎原有 EvidenceReadSession。此模块不是下载接口，不做脱敏，不重新提取事实，不代表诊断 P0 已完成。

已有采集器保存完整事实及材料，但没有离线复原校验路径。当前复原只调用原有 FactV2、TimeValue、SourceObservation、Snapshot 和 MaterialStore 的构造器。就诊坐标由受信调用方显式传入，不从数据库补齐；未来完整导包须使用脱敏坐标及重建引用。

## 核心检查

- 类型与资源限制先于摘要算法，拒绝任意对象的 repr/回调；对可变输入做隔离复制。
- 按事实依赖重建，拒绝缺失、自引用、循环及重复事实；对正式序列化逐字段、逐类型比较，不能把 True 与 1 视为等价。
- 保留源行顺序、重复、None、空正文、截断、读取上限、查询错误和不可用状态。
- 原材料与来源引用、事实与来源引用、病例坐标与快照身份均须匹配。
- 临床文书引用必须与材料完整对应；唯一豁免为正式评价 horizon 常量所指的非临床上下文材料。
- 错误仅返回固定错误码，标准异常格式不得携带底层患者哨兵值。

独立审查复现并修复了“删去临床 document_refs 后重算合法快照 hash，结构复原仍通过”的缺陷；新增合法重算 hash 的反例，不仅测试随意篡改旧 hash。

- 新模块聚焦：24 passed。
- 全部诊断单测及三业务入口合成 worker 集成：282 passed / 11.30 秒，2 个已有 Pydantic 弃用警告。

测试失误记录：审查子代理执行聚焦测试时遗漏 `--noconftest`，导入 app.main 并触发演示 `demo_feedbacks.db` 的 init_db。只读核对其实现为 `Base.metadata.create_all`；无前后数据库快照，不能声明没有变化。已通知用户并停止该代理继续测试，未擅自删除、还原数据库。主线程测试均使用隔离参数，不将该次误执行作为无数据库证明。
