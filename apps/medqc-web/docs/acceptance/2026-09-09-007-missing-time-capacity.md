# 007：缺时间记录最有利放置后的确定性判定

## 问题、方案与范围

用户指出缺时不等于不可判定。旧007在发现可能超期且有任一缺时文书时直接data_gap，未判断这些文书是否有足够数量补齐间隔。

完整资料、稳定病情、入院及截止时间门控通过后，按已知查房时间分割区间。每个长度为D的区间至少需要max(0,ceil(D/72小时)-1)个补点，总和M与实质缺时记录数N比较：N>0且M>N时确定不合规，否则保持原逻辑。使用timedelta divmod避免浮点误差；不改变无缺时病例的既有判法。

每份缺时查房按一个潜在时点计入，重复行亦乐观计数，避免低估可补点数量。若来源合同允许单行代表多次独立查房，则必须先重新核对这一前提。日期截止仅取当日零点作为区间下界，不能冒充实际出院时刻。

文件范围为rule_007.py、course_quality_result_mapping.py、customer_renderer.py和两个聚焦测试。rule_007与renderer已有较多代码，本次仍是已有007判定与显示职责的小补丁，未增加独立职责或超过200行生产代码；计算集中于007私有函数，renderer仅转述已裁决事实，未新增全局注册/状态/回退来源。

展示单独使用course_interval_capacity_exceeded，显示已知时间点数、缺时份数、最少补点数和评价边界。明确“至少一处超过72小时，具体位置尚不能确定”，禁止沿用无缺时情况下的连续空白区间文案。文书定位沿原fact_refs传递。
