# LX0609 已知身份发送边界保护（2026-10-08）

## 本轮目的与结论

将“当前病例已知身份值不得残留”从人工检查变成发送前的强制检查。本轮只做离线实现与合成测试，没有外部模型调用、PG查询或数据库写入，也没有重启生产服务。

## 实现

- execution 在快照材料建立后构造病例专属 identity provider，收集明确身份字段和当前病例三坐标；每次发送重新核对材料归属，读取异常、快照失败或空上下文拒发。不会额外查询PG。
- llm_prompt_privacy 保留既有脱敏；脱敏后检查所有已知身份值，包括无标签姓名、请求参数、嵌套JSON与Unicode转义。发现残留只拒绝，不擅自改医学数字。
- 两个正式0609编排入口建立 ContextVar 作用域。内部清空 rule_set_key 的兼容调用继承同一范围；不同病例隔离，异常、取消及嵌套调用后恢复。
- SichuanQCLLMClient 每次 HTTP attempt（包括重试）在诊断捕获、观测记录和网络之前检查最终payload；不能只依赖第一次prompt包装。
- 异常只有固定提示，不含身份原值；provider与身份集合不进入对象repr，不新增持久化身份载体。
- 技术配置数值（例如temperature和真实JSON Schema位置的minItems）不当成病历身份；全部字符串、messages、metadata、未知字段以及schema的default/const/enum/examples仍检查。检查投影不改变实际请求。

## 验证

10个聚焦测试文件合计171项通过，含已有客户端/运行终末编排/适配器保护集；旧正则对照对合成无标签姓名发出1次委托，新保护为0次。合成HTTP替身验证正常请求可通过，残留请求在观测和transport之前拒绝；覆盖并发病例、嵌套异常、取消清理、每次重检、空上下文、编码残留和技术数字误拦。没有使用真实病例或真实HTTP作为本轮验证材料。

环境显式使用离线JWT占位值与空DATABASE_URL；首次未提供JWT时相关配置测试失败，补齐测试环境后通过，不把配置失败归为生产回归。

## 覆盖边界与未完成项

- 这是当前LX0609正式编排及其native/兼容客户端发送边界，不代表0916、智能助手或任意直接HTTP脚本自动获得同等保护。离线脚本应显式传入本次已知身份值或进入同样的受控边界，不得假设正则脱敏即已验收。
- 只保证检查当前上下文实际已知的身份。正常bundle的factory只保留masked身份，多数源投影不包含原姓名；无法逆推已经丢弃的原名，也不能把“未命中”当成所有姓名均已覆盖。后续如扩展原始patient_profile贯穿，须使用不序列化的内存上下文，不得把原始身份写回bundle/日志。
- 未做全项目隐私覆盖证明、真实模型回放、客户部署或前端浏览器验收。本改动不会撤回此前已经外发的材料。

检查范围：本轮Python聚焦pytest、Ruff、编码与ESLint；未重跑前端全量类型检查和全量单测（本轮未修改前端）。
