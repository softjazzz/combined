# LX0609-011/012 两阶段事实抽取小范围对照

日期：2026-09-13。代码时点：`c631cea3c`。结论：在固定四例、三轮实验中，“证据抽取一次并冻结，再由 LLM 判定”提高了状态表面的稳定性，但降低了事实正确率，也没有提高证据引用稳定性；当前方案不得进入生产。

## 问题证据与待验证假设

当前 011/012 已由 Python 拆分 CT/MRI 事件、裁剪可引用病程，再由一次 LLM 同时判断报告阳性、结果是否记录、异常是否分析及引用位置，最后由 Python 做状态映射。此前相同输入多轮运行出现语义或引用变化。

本 POC 验证三个假设：

1. 如果抖动主要来自模型同时“找证据并下结论”，固定证据后状态和引用应同时更稳定。
2. 如果第一次抽取遗漏或错误关联关键证据，冻结会产生稳定但错误的结果，正确率不会提高。
3. C12 第二事件的病程早于报告 88 秒，属于 Python 时间合同边界，不应计为两阶段模型能力收益。

## 试验设计

- 输入：正式 Bundle 主链冻结的 C05、C06、C08、C12，同一份当前生产提示词来源。
- 真值：9 个影像事件、18 条 011/012 事实及引用门槛；C05 第三个操作性事件保留在真实输入中，但不进入真值分母。
- 模型：`qwen3.8-flash`，`enable_thinking=true`，`thinking_budget=256`，temperature 0.2，top_p 0.9，最大输出 4096。
- 单阶段：当前生产提示词运行三轮，共 12 份回答；第 1 轮复用同一代码时点已保存回答，第 2、3 轮重新调用。
- 两阶段：第一阶段每例调用一次，选择由 Python 预先编号的报告/病程句子及事实类型；Python 校验事件、文书覆盖和句子编号后冻结。第二阶段只接收冻结事实，运行三轮，共 4 次抽取和 12 次判定。
- 技术失败按该病例对应的全部事实失败计算，不能以 HTTP 成功替代质控成功。

患者原文、请求和响应仅保存在 gitignored `.tmp/0910-full-audit/*-private`，不提交。

## 失败反推

两阶段的 15 个错误在三轮中完全重复，属于稳定错误：

- C05 每轮 3 错：事件 1 的 011/012 都引用了历史或其他检查文书；事件 2 的阳性报告被判为阴性。
- C06 每轮 1 错：事件 1 的报告同时含正常描述和明确异常，第二阶段仍判为阴性。
- C12 每轮 1 错：事件 2 的报告抽取结果全部标为异常，第二阶段仍判为阴性。
- C08 三轮 4/4 事实通过，但引用集合在轮次间仍变化。

主协调直接反查保存的第一、二阶段产物后确认两个根因：

1. 第一阶段虽然选中了稳定句子，却没有输出“该句与哪个具体检查事件相关”的受控关联事实。C05 的历史和本次材料一起进入冻结事实，第二阶段连续三轮全部引用。
2. 第一阶段已经把相关报告句标成 `abnormal`，第二阶段又重新判断阳性/阴性，形成重复事实所有者，并在 C05、C06、C12 各稳定判错一个事件。

因此，本轮只证明“冻结能固定输入”，没有证明两阶段能提高正确性。稳定性指标必须和真值准确率、引用一致性同时看；4/4 最终判定稳定不能作为上线依据。

## 收敛建议

下一版只保留一个小改动方向：第一阶段输出带事件关联的、由 Python 句子编号承载的证据事实；Python 校验事件白名单、报告后 24 小时窗口和引用位置。阳性分类只允许一个事实所有者，不能由第二阶段再次改写。第二阶段只判断“已验证的本次异常证据是否构成实质分析”，输出严格枚举；仍需同时验收正确率、状态稳定和引用稳定。

C05 是事件关联守卫，C12 第二事件是报告时间守卫；任何候选方案必须先通过这两例，再扩大样本。当前不新增缓存表、配置开关或生产调用。
