# 027 恶性诊断适用性不确定修复

## 证据与根因

原病例捕获模型已返回9条诊断分类，其中1条uncertain。MalignancyResolution只保存总状态，丢失该条来源定位；027把语义未知按data_gap输出，typed映射又压成required_field_missing，误导为治疗计划缺字段。

## 最小修复合同

沿原MalignancyFactResolver保存uncertain项的真实来源及原始行，只在内存传递；Prompt仍只有ref/source_kind/name/code，不增加坐标、正文输入、模型调用或缓存层。仅027的malignancy_semantics_uncertain映射UNKNOWN/CONFLICT/UNKNOWN及semantic_low_confidence，内部evaluation_unknown、客户uncertain。

受控展示事实只含malignancy_state=unknown、uncertain_diagnosis_count及固定类型。客户提示已有诊断恶性性质尚不明确、无法确定本条出院治疗计划质控是否适用，不再生成治疗计划missing_fields。其他肿瘤规则、明确阴性、明确阳性及技术失败状态不改。

## 真实定位边界

原包9条discharge_record_diagnosis各有diagnosis_id，却共用一个父document_id。只选择uncertain1行时原projector拒绝“同ID未全选”，因此合成单独document_id测试能过而原包定位为0。

不能为了通过投影选中其他8条诊断，也不能把未验证可打开的diagnosis_id冒充文书ID。实际文书查看链emr_view将出院诊断归并到discharge_record，assembly单篇读取按父文书ID定位。

因此本次仅对discharge_record_diagnosis明确parent document_id且同一冻结材料中存在唯一对应discharge_record的情况，允许投影到该真实父文书；内部fact_refs仍只选择不确定诊断行。父文书不存在、ID不匹配或重复时仍不生成猜测坐标。客户定位是承载诊断的出院记录，不宣称实现诊断行高亮。
