# LX0609-047 多次输血病程评价关联验收

## 问题与冻结反例

同一次就诊含多份输血记录时，047 原实现在扫描日常病程前即按任一未满足记录返回，无法将有明确时间的病程评价逐次关联；也不能证明笼统评价属于哪一次输血。

实现前新增的真实 typed EvidenceReadSession → 047 executor → Binding/Canonical 夹具为 RED：两次非重叠输血各有次日常病程评价仍返回 `non_compliant/requirement_violated`（首次运行 7 项中 5 项失败、2 项保留既有窗口优先级通过）。

## 本次口径

- 仅多事件分支读取 `daily_course_record`；单事件原算法不改，0 次 LLM 调用。
- 病程带完整结束时间锚点时只能关联该结束事件；锚点未匹配、同一病程匹配多个事件或含未解析独立结束标志，均不回退时间猜配。
- 无锚点病程仅在其权威 `record_time` 落入唯一一个 `[结束, 结束+24h]` 窗口时关联；窗口重叠的笼统评价返回 `data_gap/association_failed`，不能扇出。
- 关联以事件索引和文书身份为键；相同结束时刻的不同输血文书仍是不同事件。多事件均满足后，展示使用 `latest_end` 对应最早合格评价，材料置换不改变状态、关键事实或证据坐标集合。
- 未满足事件需要病程时，typed `daily_course_record` 查询错误为 `technical_error/source_query_error`；不可用或截断为资料缺口；明确评价时间不可用为资料缺口。技术/资料结果不投影为“评价缺失”的临床事实。
- 剩余事件仍沿既有窗口：成熟且无评价为不合规，未成熟为不适用。已有迟到同份评价不会阻断其后唯一及时病程评价；早于输血结束的病程时间不写成迟到评价。
