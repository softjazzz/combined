# 后续核实：正式失败重试与普通子集探针不同

在 `eccdfd144` 之后核对真实 Worker：`is_failed_rule_retry` 由持久化 `failed_rule_retry.schema_version` 识别；该分支的 `result_rule_ids` 取每病例 `active_rule_ids`，不是整个任务的 `output_rule_ids`。因此前述普通 `record_rule_map` 子集探针不代表正式失败重试会补出未选规则。

重新运行正式失败重试测试时，旧夹具先因缺任务配置快照而被门禁拒绝。仅在该夹具中补上正式 Settings 的接纳快照，并让 Worker 使用相同 Settings；未绕过门禁、未改结果断言、未改生产代码。真实 Worker 对两病例分别只执行各自失败的一条规则，合并保留原四条正常结果，最终六条、任务完成。该测试与失败范围/合并测试共9项通过。证据范围为真实 Worker + 替身质控服务/内存任务，不能升级为客户PG恢复或全入口任意子集均正确。

结论：不将普通子集探针的 `result_missing` 列为已确认的正式重试缺陷，不为它扩大生产修复。普通非重试子集是否可由真实创建入口产生，仍需独立核实。
