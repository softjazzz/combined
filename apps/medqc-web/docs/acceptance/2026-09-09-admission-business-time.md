# 入院业务时间修复与原病例验收

## 证据与方案

前次真实任务 `49837eef-8fe9-4d12-bfb0-80ec95555938` 冻结为 time_conflict。只读核验发现主查询使用 AdmissionRecord.update_time 代替业务入院时间，造成入院晚于出院；同一病例的登记表业务入院时间实际存在。

限定修改 RecordRepository 主查询：保留首页入院时间、入院记录业务入院时间的既有优先级，第三来源改为同机构、同患者、同就诊的入院登记业务时间。登记表三坐标为复合主键，精确外连接不增加结果基数。全部业务时间为空时留空，不回退更新时间或文书记录时间，不绕过已有时间冲突校验。

三个候选字段在本地 PostgreSQL CDM 均为 timestamp without time zone，已只读核验。修改不涉及数据库结构、Provider 状态解释、前端或暂停规则。

验收要求：原病例冻结截止恢复为 resolved；007、020/023 不再被假时间冲突阻断；保留真实缺失、真实冲突与跨病例隔离；以真实 API 新任务和保存结果复核，不以测试数量代替业务结论。
