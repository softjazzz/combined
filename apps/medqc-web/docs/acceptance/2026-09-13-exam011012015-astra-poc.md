## 2. 为什么（已用保存产物反推验证的因果）

### 2.1 C 修掉的两个确定性 Python 缺陷

1. **C12 整批不可交付（A 侧，三轮 3/3）**：模型三轮都把事件 2 的病程位置写成只属于**事件 1**
   白名单的病程。该越界在 `backend/app/services/luxian_0609/exam_lab_fact_extraction.py:1706-1717`
   的**预扫描循环**内直接抛出 `evidence_ref`，**不在**逐规则 `try` 内，因此
   `parse_exam_lab_fact_response_isolated` 的单规则隔离（提交 `507f20908` 引入）在这一条上失效：
   一条跨事件引用把整批两条规则打成 `technical_error`，单次重试后模型给出同样答案，仍然失败。
   验证方式：读取三轮原始答案的引用位置 + 逐事件白名单对照。
2. **C06#2 被 Python 改写（A 侧，三轮 3/3）**：`exam_lab_fact_extraction.py:1531-1549` 的
   present→absent 改写块把参考答案的 `present` 降为 `absent`。C 链路不经过该块，三轮均为
   `present`。验证方式：同一参考答案喂进真实 Python 链路的神谕测试（当前 HEAD 为 16/18，
   两项改写都在 C06）。

### 2.2 C 新增的错误合规（**未修复，是本轮主要负面结论**）

C 组三轮都把 C12 事件 2 判为 `present` 并引用了一份**精麻科查房记录的独立诊断列表**，
终态 `compliant`；正确答案是 `absent` / `non_compliant`。

- 事件 2 的报告是颅脑 CT 所见；被引用的病程全文是"诊断明确：1.…8.房性早搏，手术指针具备…
  于次日行椎体成形术"，**不含**该报告的任一所见，属另一次检查的独立诊断列表。
- 真正记录该报告结果的病程时间比报告时间**早 88 秒**，只属于事件 1 的候选集合，
  按冻结时间合同不能作为事件 2 的窗口内证据。
- 因此这是**模型的语义错误**，不是参考答案错误。C 合同只能证明"引用合法、字段自洽、时限成立"，
  证明不了"这段文字是否真的构成该事件的分析"——与方案 §4.2 和评审意见一致。

### 2.3 A 侧的语义不稳定

C05 012#2、C08 012#2 在 r1 与 r2/r3 之间翻转。相同输入、相同参数下 A 的语义结论不稳定，
