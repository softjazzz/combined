## 失败语义阻塞

当前实现不满足“模型/协议技术失败必须为 `technical_error`，语义未知必须可区分”的冻结验收：

1. 808 行 `llm_client is None`、828 行模型调用异常以及 835 行非法 JSON/未识别 state 都进入 `data_gap`；typed 转换（约 414–425 行）进一步统一为 `required_field_missing`。
2. `_llm_payload` 只解析 JSON object；随后只读取 `state`。`confidence` 不校验数值范围，`reason_code` 不校验字符串或枚举，二者也不参与决策。受控响应 `{"state":"present","confidence":"not-a-number","reason_code":[]}` 当前仍归约为 `compliant/requirement_satisfied`。
3. 急诊豁免的原生 facts 形状无法通过聚合器遗留 040 白名单，故完整公共投影当前直接异常；此问题同样阻塞迁移前的“冻结等价”。

因此本阶段状态为：**本地阻塞（失败语义）**。这不是迁移失败，也不能把现有 data gap 当作批准口径通过。

## 最小后续迁移建议（待独立授权）

先单列一个失败语义修复闭环，不提前迁移聚合器/Finalizer：在 MDT 执行器的模型响应边界区分“调用不可用/超时/异常”“协议非法”“合法 unknown”，分别映射到 `technical_error` 与 `uncertain`；保留已接入资料不足的 `data_gap`。本闭环仅校验实际消费的响应 object 与 `state` 枚举，不改变 Prompt，也不顺带收紧未参与判定的 `confidence`、`reason_code`；它们的约束另行评审。修复后重跑本冻结测试和现有 `test_luxian_0609_native_mdt_execution.py`，再决定急诊豁免 facts 缺陷与 040 所有权迁移。

当前 040 聚合器专属 facts 分支和 `mr_surgery` 证据白名单约为两个小型、单规则分支，明显不足 250 行；若后续迁移仅删除这两处重复所有者，收益是消除“执行器已判定、聚合器再解释”的唯一性冲突，而非为降行数拆分。不得在失败语义修复前新建生产 mapping 或接入 Finalizer。
