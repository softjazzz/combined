## 失败语义修复结果

本轮独立修复仅触及 `native_mdt_execution.py` 的模型响应边界：

1. 无 client 与生成异常归约为 `technical_error/model_transport_error`；非 Mapping 响应、无 JSON、非字符串或非枚举 `state`、以及非法 usage 都归约为 `technical_error/model_invalid_output`。
2. 合法 `unknown` 在来源完整时归约为 `evaluation_unknown/semantic_output_unknown`，公共客户状态为 `uncertain`。资料来源不可用会在模型调用前保留 `data_gap/source_unavailable`；模型技术失败不会被条件阻塞覆盖。
3. `_llm_payload` 仍只消费 JSON object 的 `state`。按本轮批准范围，`confidence` 与 `reason_code` 不参与判定，也未增加类型或枚举约束；受控 `present` 响应即使含这两个字段的异常类型仍保持合规。
4. 急诊豁免的原生 facts 形状仍无法通过聚合器遗留 040 白名单，故完整公共投影当前直接异常；此问题保持独立阻塞，未在本轮修复。

因此，**模型失败语义本地通过；急诊豁免 facts 投影仍阻塞 040 全量迁移**。

## 最小后续迁移建议（待独立授权）

失败语义已修复，不提前迁移聚合器/Finalizer。下一步仍应单列急诊豁免 facts 的公共投影缺陷，修复后再决定 040 所有权迁移。本闭环仅校验实际消费的响应 object 与 `state` 枚举，不改变 Prompt，也不顺带收紧未参与判定的 `confidence`、`reason_code`；它们的约束另行评审。

当前 040 聚合器专属 facts 分支和 `mr_surgery` 证据白名单约为两个小型、单规则分支，明显不足 250 行；若后续迁移仅删除这两处重复所有者，收益是消除“执行器已判定、聚合器再解释”的唯一性冲突，而非为降行数拆分。不得在失败语义修复前新建生产 mapping 或接入 Finalizer。
