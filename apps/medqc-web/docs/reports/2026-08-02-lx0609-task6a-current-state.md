# LX0609 Task 6A 基础时限与病程规则族现状

## 审计范围

Task 6A 当前覆盖 11 条规则：

- 基础时限：LX0609-001、002、004、005、006。
- 病程与严重程度：LX0609-007、008、009。
- 病历复制与主诉：LX0609-016、017、018。

本阶段只治理 Native 内部，不修改 Canonical Envelope、保存结构、单一结果 API
和前端状态解释。

## 当前生产调用链

```text
prepare_luxian_0609_execution
  → Runtime Manifest / typed rollout
  → Evidence Read Session（Snapshot + MaterialStore）
  → Luxian0609ExecutionEngine
  → basic_timeliness / course_quality executor
  → RuleDecision
  → decision reducer
  → Canonical Envelope
```

11 条规则已经具备 Typed Decision 路径，但两个执行器仍保留无 Evidence Session
时的旧投影或直接读取路径。当前技术债的核心是双路径和阶段职责混合，不是重新
编写 11 条医学规则。

## 已确认的主要技术债

### 基础时限

1. Typed 与 legacy 两套判定仍可由开关选择。
2. 同一函数同时负责资料状态、事实抽取、事件配对、适用性、Decision 和客户事实。
3. 入院锚点冲突时可能静默选择最早时间。
4. 004 没有统一使用权威文书完成时间。
5. 来源为空时，资料完整与资料未证实完整的语义没有完全分开。
6. 超时结果的实际间隔、超出时长和采用文书引用不一致。
7. 005、006 的医生职级仍主要依赖标题字符串，没有独立受控事实。

### 病程质量

1. 018 的运行实现违反合同：合同规定 `program_only / max_llm_calls=0`，当前代码
   仍会让 Pending 的诊断指向子判定调用 LLM 并影响最终状态。
2. 009 当前只允许每日病危病程子判定，但仍请求不参与该判定的检查、检验、用药
   和手术来源。
3. 007 只比较已有病程间隔，尚未完整表达住院首段和尾段评价窗口。
4. 008、009 尚无受控的病重/病危解除事件，不能自行推断 episode end。
5. 017 的相似度算法已经存在，但规则定义仍为 Pending，测试不能替代客户口径。
6. 主执行文件仍混合资料读取、事实、关联、适用性、判定、展示和 LLM。

## 数据读取现状

- Typed 主线复用同一个 Evidence Session，不需要规则函数再次访问数据库。
- legacy 分支仍可能直接读取病程资料，形成双路径漂移风险。
- 009 和 017 的来源集合包含当前正式子判定未消费的来源，会增加同步与 Snapshot
  成本。

## 当前验收覆盖

- 基础时限和病程两个聚焦测试文件审计基线：202 项通过。
- Task 5 矩阵目前只为这 11 条规则各绑定一个 v3 合规 Golden。
- 现有单测中已经存在大量问题、数据不足、不适用和边界 fixture，但尚未登记进
  规则验收矩阵。
- 007 缺少独立“恰好 72 小时”的验收绑定。
- 009、017、018 受 Partial/Pending 定义约束，不能按整条规则宣称验收完成。

## 真实病例能力

- 病历 208790 已有部分只读源真值：002、004、005、009 和 016。
- 病历 359787 尚无 Task 6A 的逐条真实源真值基线。
- 准生产评估接口可以只读执行当前代码，但不保存 Envelope。
- “当前代码执行 → 保存 Envelope → 单一 API 原样回读”需要运行正式任务，会写
  数据库，必须在执行前单独取得授权。

## 本批次最小实施范围

1. 基础时限先抽一个小型事实合同模块，不拆成多个通用层。
2. 先修冲突锚点、资料完整性、权威时间、阈值边界和客户证据事实。
3. 018 立即恢复为纯程序的已批准长度子判定，禁止 Pending 子判定影响状态。
4. 停止 009 当前判定未消费的额外来源读取。
5. 007、008、009 的窗口事实只在现有定义内收敛；不推断解除事件。
6. 016、017 不在本批次改变相似度医学定义。

## 停止条件

出现以下任一情况立即停止本批次：

- 需要自行定义病情变化事件、病重/病危解除事件或 017 相似度合同。
- 需要修改 Envelope、API、前端状态映射或其他规则族。
- 需要引入通用规则 DSL、全局事件图或第二套事实存储。
- 为通过测试而把技术异常降级成数据不足。
