## 背景

《病历内涵质控平台 V3.6 用户操作手册》描述的是一个成熟的病历内涵质控后台，覆盖工作台、病历质控、任务管理、统计分析、规则配置、质控点管理、文书管理和测试病历管理等完整业务闭环。

MedQC 当前已经具备 `dashboard` 管理端、`workstation-v4` 工作台、四川/泸县规则执行、病案首页生成、DRG/DIP 相关能力和部分质控任务链路，但整体形态更偏试点、演示和专项验证。本文档用于明确：

1. V3.6 手册全量功能应如何进入 MedQC 产品范围。
2. 当前 MedQC 已包含哪些能力。
3. 每个功能点还缺什么。
4. 后续开发优先级和验收口径。

## 目标用户

| 用户角色     | 核心诉求                                                               |
| ------------ | ---------------------------------------------------------------------- |
| 质控管理员   | 统一管理运行、终末、门急诊病历质控任务，审核缺陷、派发整改、追踪闭环。 |
| 质控员       | 处理分配给自己的质控任务，查看病历和缺陷详情，完成审核和复审。         |
| 医务管理部门 | 查看全院、科室、医生、质控员维度的质量统计和专项报表。                 |
| 规则管理员   | 配置评分标准、规则集、质控点、上线状态、测试病历和规则验证流程。       |
| 临床医生     | 接收催办、查看缺陷、完成整改或申诉。                                   |
| 系统管理员   | 配置权限、数据范围、任务队列、通知和审计。                             |

## 产品定位

MedQC 的内涵质控 V3.6 总需求定位为“医院病历内涵质控闭环平台”，而不只是单病例 AI 质控工具。目标是把病历数据、规则执行、缺陷审核、整改追踪、统计分析和规则生命周期串成可运营、可审计、可复核的后台系统。

本 PRD 不要求一次性实现所有功能。当前建议采用分阶段落地：

- P0：跑通病历质控主链路，包括工作台待办、门急诊/运行/终末列表、详情联审、催办、通过、存疑、重质控、任务创建和进度。
- P1：补齐整改闭环、筛选模板、自定义列、导出、任务分配和规则管理基础能力。
- P2：建设统计分析、质控员工作分析、专项报表、27 项指标、18 项核心制度。
- P3：完善高级规则编排、文书管理、测试病历场景化验证和运维治理。

## 数据、权限、状态、任务和报表要求

### 数据要求

| 领域       | 要求                                                                     | 当前差距                                                                              |
| ---------- | ------------------------------------------------------------------------ | ------------------------------------------------------------------------------------- |
| 病历主数据 | 统一登记号、流水号、病案号、住院号、患者、科室、医生、出入院时间。       | `records`、CDM、bundle 和历史 `medical_records` 存在多套来源，需要统一展示契约。      |
| 缺陷数据   | 缺陷需包含状态、严重程度、规则来源、证据、整改状态、申诉状态、操作历史。 | `qc_defects`、`qc_results`、`qc_remediation_tasks` 有基础，但状态闭环未全部接入页面。 |
| 任务数据   | 任务需包含类型、场景、进度、分配、抽样、期望完成时间、实际完成时间。     | `qc_tasks` 与 `qc_task_records` 有基础，复杂抽样和定时任务不足。                      |
| 规则数据   | 规则需支持评分标准、项目组、质控点、文书、生效科室、医生端生效、版本。   | `qc_rules`、`scoring_rules`、四川/泸县规则并存，需统一规则生命周期。                  |
| 报表数据   | 需形成运行、终末、门急诊、首页、质控员、专项指标的稳定聚合视图。         | 当前统计 API 偏概览，专题报表缺少数据集市和导出口径。                                 |

| 权限能力     | 要求                                                   | 当前差距                                                           |
| ------------ | ------------------------------------------------------ | ------------------------------------------------------------------ |

| 科室数据范围 | 质控员和医生默认只能看授权科室或个人相关数据。         | 数据范围设计有文档基础，页面和 API 过滤需逐模块校验。              |

| 状态域       | 要求                                                                                                                            | 当前差距                                                   |
| ------------ | ------------------------------------------------------------------------------------------------------------------------------- | ---------------------------------------------------------- |

| 缺陷状态     | 临床申诉、待整改、已整改、审核通过、审核存疑、催办状态需可追踪。                                                                | 缺陷状态有基础，但撤回催办、整改前后对比和申诉链路不完整。 |

### 报表要求

所有报表必须支持：

1. 时间范围查询。
2. 科室维度查询。
3. 任务维度查询。
4. 明细下钻。
5. 列表导出。
6. 指标口径说明。
7. 权限过滤。

当前 MedQC 需要优先补齐报表数据来源和指标定义，避免仅用前端模拟数据展示。

## 验收标准

### 文档级验收

- 本 PRD 覆盖 V3.6 手册的一级模块和主要二级功能。
- 每个功能点均标注覆盖状态、现有依据、主要差距、优先级和验收口径。
- 不把 mock、提示占位、未接后端接口写成已完成能力。
- 明确区分 `dashboard` 管理端能力与 `workstation-v4` 试点/工作台能力。

### 产品级验收

- 质控管理员能从工作台进入任务、缺陷、病历三个待办列表。
- 质控员能处理门急诊、运行、终末病历的缺陷审核和整改派发。
- 管理员能创建抽查任务、查看任务进度、重新质控并导出结果。
- 规则管理员能维护评分标准、规则、质控点和测试病历验证。
- 管理层能查看病历质量、质控员工作、专项指标和核心制度报表。

### 技术级验收

- 所有关键页面使用真实 API 或明确的不可用状态，不使用静默 mock 冒充数据。
- 所有批量操作具备权限校验、二次确认、操作结果和审计记录。
- 所有导出遵守筛选条件、导出上限、字段模板和权限范围。
- 任务、缺陷、整改、申诉、规则变更均有可追踪历史。
- 涉及真实患者数据时，导出和日志不得暴露敏感信息。
