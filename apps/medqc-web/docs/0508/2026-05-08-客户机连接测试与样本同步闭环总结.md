## 2. 本地 PG 启动问题

最初连接客户机本地 PG 时出现：

```text
connection to server at "127.0.0.1", port 5432 failed: Connection refused
```

排查结果：

- Windows 服务存在：`postgresql-x64-16`。
- 服务状态最初为 `Stopped`。
- 服务配置中的 data 目录为：

```text
C:\Program Files\PostgreSQL\16\data
```

- 该目录实际不存在。
- 真实 PostgreSQL data 目录通过 `PG_VERSION` 定位为：

```text
C:\pgdata\16
```

使用真实 data 目录手动启动成功：

```powershell
& "C:\Program Files\PostgreSQL\16\bin\pg_ctl.exe" start -D "C:\pgdata\16" -l "$env:TEMP\pg-customer-medqc.log" -w -t 20
```

启动日志显示：

```text
数据库系统准备接受连接
```

遗留问题：

- Windows 服务 `postgresql-x64-16` 仍指向错误 data 目录。
- 如果客户机重启，PG 可能再次无法通过服务自动启动。
- 后续应修复服务配置，使其指向 `C:\pgdata\16`，或由现场运维确认正式启动方式。

## 8. 当前遗留问题

### 8.1 本地 PG 服务配置错误

现象：

- 服务配置仍指向不存在的 data 目录。
- 需要手动用 `pg_ctl -D C:\pgdata\16` 启动。

风险：

- 客户机重启后服务可能无法自动恢复。

建议：

- 修复 Windows 服务 `postgresql-x64-16` 的 data 目录。
- 或明确由部署脚本/运维使用 `C:\pgdata\16` 启动。

### 8.2 `labtest_item_report` 剩余 6 个 visit 缺失

剩余缺口：

```text

2307530：源库 117，本地 0
```


已排除：

- `patient_id` 不一致。6 个 visit 在 `public.mr`、`cdm.mr`、`public.labtest_item_report` 中 patient_id 完全一致。
- `document_id` 合成冲突。`labtest_item_report_source_duplicate_candidate_keys.csv` 结果为 0。

- 客户机 env 中 `PG_LOCAL_TARGET_SCHEMAS=public,cdm`。
- 如果 `public.labtest_item_report` 和 `cdm.labtest_item_report` 同名表共存，同步可能优先写入 `public`，而审计和 bundle 优先读取 `cdm`。

## 10. 后续建议

### 10.1 代码侧

建议 CLI 下一步处理：

1. 修复 split schema 下 CDM 表写入优先级。
2. 当 `DB_SCHEMA_MODE=split` 时，CDM 同步表应优先写 `cdm`，避免被 `PG_LOCAL_TARGET_SCHEMAS=public,cdm` 误导写入 public 残留表。
3. 增加回归测试：
   - `public.labtest_item_report` 与 `cdm.labtest_item_report` 同时存在时，`upsert_to_local("labtest_item_report")` 必须选择 `cdm`。
   - `blood_application` 同理。
4. 保持 bundle/qc/sys/public 系统表兼容，不要把所有表都强行写入 `cdm`。

### 10.2 客户机开机后

建议执行：

1. 启动本地 PG，确认 5432 监听。
2. 查询 `public/cdm` 两边剩余缺失行分布。
3. 如确认写错 schema，调整同步 schema 优先级后重跑 `sample_full_domain`。
4. 重新刷新 bundle。
5. 再跑 `audit_sample_source_coverage.py`，确认：

```text
blood_application local_total_rows = source_total_rows
labtest_item_report local_total_rows = source_total_rows
bundle_status = covered
```
