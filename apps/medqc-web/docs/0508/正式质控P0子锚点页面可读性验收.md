## 页面展示位置

- 摘要卡片新增“专项检查项 X 项待复核”入口，仅用于查看顶层 `subitem_anchor_results`。
- 父规则问题卡片下方展示“父规则专项检查项”，作为父规则附属信息。
- 父规则详情弹窗中展示同一批子锚点，便于查看完整证据与判定原因。

## 误解风险检查

- 子锚点不计入“发现问题”数量，也不计入确认缺陷数量。
- 标签仅显示“专项检查项（待复核）”或“数据缺口”，未出现“确认缺陷”“系统确认缺陷”“建议重跑”等误导文案。
- `can_show_as_defect=false` 时前端不将子锚点作为缺陷计数；即使后端误传 `true`，计数工具仍返回 false。
- 缺少子锚点字段时页面不渲染子锚点区块，不报错。

## 可读性检查

- 子锚点证据与判定原因以父规则下的浅色附属块展示，不作为独立大卡片抢占主问题列表。
- 中文证据采用 `pre-wrap` 与 `word-break: break-word`，避免中文逐字窄列和横向溢出。
- 对较长证据摘要增加局部滚动上限：卡片内 120px，详情/弹窗内 240px，避免撑爆结果页，同时保留完整可读内容。
- 本轮未提交截图；使用组件级测试 fixture 验证页面文案、计数和误导文案风险。

## 自动化验收

- 新增组件级测试：`src/views/workstation-v4/components/__tests__/ContentQCTab.subitemAnchors.spec.ts`。
- 测试使用 `2311318` 的 SC-009/SC-070 子锚点形态构造最小 bundle 响应，不写正式业务结果表。
- 覆盖点：父规则附属展示、顶层专项检查项数量、待复核文案、判定原因可见、不出现确认缺陷/建议重跑文案。

## 结论

- 当前页面展示可进入“小范围内部验收/演示准备”，但仍建议对医生端正式发布时保留“待复核/数据缺口”分层。
- 不建议将子锚点纳入整改任务或确认缺陷统计，除非后续完成人工复核闭环和产品文案确认。
- Sheet2 回归需继续保持 `exact_confirmed=156 / blocked_with_reason=102 / skip=25 / needs_exact_review=0`。
