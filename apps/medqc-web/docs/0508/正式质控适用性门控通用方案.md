# 正式质控适用性门控通用方案

## 1. 目标与边界

本方案把 SC-083 的经验扩展为正式 `final fast_screen_full / sc_content_full_v1` 84 条规则的通用原则：先证明规则适用性，再做缺陷裁决。

本轮只做审计和设计，不接正式主链路、不改页面、不写数据库、不提交。

核心原则：

- 适用性成立不等于缺陷成立。
- 规则不适用时应 `rejected_by_system/not_applicable`，不是 `data_quality_gap`。
- 关键证据缺失时应 `data_quality_gap`，不是 `confirmed_defect`。
- confirmed 必须有触发证据、缺陷证据、可追溯 quote 和规则要件闭环。

## 2. 为什么 SC-083 不能只靠 LLM 直接判缺陷

SC-083 的判定至少包含两层事实：

| 层级     | 问题                                      | 证据                                                          |
| -------- | ----------------------------------------- | ------------------------------------------------------------- |
| 适用性   | 该病例是否确有四级手术                    | 手术编码 code_exact/code_normalized 命中手术分级 catalog 四级 |
| 缺陷成立 | 四级手术术前讨论是否缺少 MDT/相关专科意见 | 完整术前讨论正文、参与人员、讨论结论、客户确认的 MDT 口径     |

如果缺少第一层，LLM 会把名称相似、短片段或手术相关文本误当四级手术。如果缺少第二层，LLM 会把“未见 MDT 字样”误当缺陷。当前 `2142472`、`2214679` 已证明：四级编码成立，但只有参与人员片段，缺完整讨论正文和讨论结论，因此应为 `data_quality_gap`，不能 confirmed。

## 3. 三批随机 10 病历审计结论

三批正式原链路随机 10 病历中：

- first-pass confirmed_defect：36 条。
- 二轮 gate 后 confirmed_defect：5 条。
- 二轮降级 data_quality_gap：11 条。
- 二轮驳回 rejected_by_system：20 条。

first-pass confirmed 高频规则：

| rule_id | first-pass confirmed 数 | 二轮结果观察                                                |
| ------- | ----------------------: | ----------------------------------------------------------- |
| SC-015  |                       6 | 多数被驳回或降级，属于性别/病史字段适用性和证据完整性问题。 |
| SC-123  |                       5 | 需要先证明存在出院带药，不得把“无出院带药”当不详细。        |
| SC-118  |                       4 | 多数缺完整出院记录字段矩阵，二轮转 data gap。               |
| SC-097  |                       3 | 短字段片段不足以证明手术记录缺项。                          |
| SC-121  |                       3 | 需要完整出院记录与手术/病程对照。                           |
| SC-036  |                       2 | 需要异常报告和后续病程分析处理对照。                        |

data_quality_gap 高频规则集中在跨文书与结构化证据规则：SC-143、SC-038、SC-146、SC-118、SC-125、SC-046、SC-083、SC-100 等。

## 4. 84 条规则的适用性门控分组

### 4.1 手术等级 / 手术触发类

代表规则：

- SC-081、SC-083、SC-084、SC-085、SC-086、SC-092、SC-093、SC-094、SC-097、SC-099、SC-100、SC-101、SC-103、SC-105、SC-106、SC-108、SC-110、SC-113、SC-115。

门控证据：

- 是否存在手术：`mr_surgery`、`surgery_record`、`surgery_application`。
- 是否四级手术：手术编码匹配 catalog，优先 `code_exact/code_normalized`。
- 是否取材/送病理：手术记录、病理申请/报告、标本/快速病理结构化字段。
- 是否植入物/耗材：手术记录、耗材清单、费用、条码/追溯码来源。
- 是否有术前/术后/麻醉/安全核查文书：对应文书正文和结构化字段。

默认分流：

- 无手术触发：`rejected_by_system/not_applicable`。
- 手术存在但关键源表缺失：`data_quality_gap`。
- 名称候选、弱词触发、短片段：不得 confirmed。

推荐接入点：`evidence coverage flags` + `second-pass gate`，其中 SC-083、SC-099、SC-100、SC-101 应优先程序化 applicability gate。

### 4.2 诊断 / 病情触发类

代表规则：

- SC-010、SC-015、SC-019、SC-020、SC-047、SC-079、SC-125、SC-127、SC-138、SC-139。

门控证据：

- 诊断列表：入院诊断、出院诊断、术前/术后诊断。
- 病情触发：主诉、现病史、既往史、首次病程、检查检验阳性证据。
- 特殊人群或性别适用性：男性不要求月经史，儿科/新生儿规则需新生儿文书或年龄触发。

默认分流：

- 诊断/病情触发不成立：`rejected_by_system`。
- 缺诊断列表或关键病史字段：`data_quality_gap`。
- 只凭片段或泛化描述不得 confirmed。

推荐接入点：`postprocessor` + `second-pass gate`。诊断漏填类需要 evidence package 支持，不宜只靠第一轮 LLM。

### 4.3 医嘱 / 用药 / 出院带药触发类

代表规则：

- SC-070、SC-073、SC-074、SC-121、SC-122、SC-123、SC-143、SC-146。

门控证据：

- 医嘱存在性：药品医嘱、非药品医嘱、长期/临时医嘱。
- 执行闭环：执行清单、病程记录、会诊意见落实记录。
- 出院带药：出院医嘱中明确药品名称、剂量、途径、频次、天数。

默认分流：

- 不存在对应医嘱/出院带药触发：`rejected_by_system/not_applicable`。
- 缺医嘱、缺执行清单、缺出院带药段落：`data_quality_gap`。
- 不得把“无出院带药”判为“出院带药不详细”。

推荐接入点：`evidence coverage flags` + `second-pass gate`。SC-123 可先做程序化出院带药触发 gate。

### 4.4 检验检查异常触发类

代表规则：

- SC-036、SC-038、SC-140，以及与检查检验一致性相关的 SC-138、SC-139。

门控证据：

- 异常结果：检验/检查/病理报告，异常标识、参考范围或明确异常描述。
- 后续处理：病程记录、诊断、医嘱、复查、会诊。
- 时间轴：异常报告时间与后续病程/处理时间。

默认分流：

- 无异常结果：`rejected_by_system/not_applicable`。
- 缺报告单或缺后续病程上下文：`data_quality_gap`。
- 病程已有分析/处理意见时应 `rejected_by_system`。

推荐接入点：`targeted evidence package` + `second-pass gate`。SC-036 是 P0。

### 4.5 文书存在性 / 时效类

代表规则：

- SC-037、SC-050、SC-051、SC-055、SC-057、SC-058、SC-060、SC-063、SC-084、SC-085、SC-103、SC-105、SC-107、SC-118、SC-119。

门控证据：

- 文书是否应存在：病程、抢救、疑难、死亡、交接班、术前讨论、术后首次病程等触发事件。
- 时效证据：入院、手术、出院、抢救、死亡等时间点。
- 完整时间链：起止时间、缺失区间、文书列表。

默认分流：

- 触发事件不成立：`rejected_by_system/not_applicable`。
- 缺源文书、缺文书列表或时间轴不完整：`data_quality_gap`。
- 只有标题、记录时间或短字段空值不得 confirmed。

推荐接入点：程序化 gate 优先，其次 second-pass gate。

### 4.6 普适文书质量类

代表规则：

- SC-004、SC-007、SC-008、SC-009、SC-011、SC-012、SC-013、SC-014、SC-016、SC-018、SC-023、SC-024、SC-025、SC-026、SC-027、SC-032、SC-033、SC-035、SC-039、SC-040、SC-043、SC-044、SC-046、SC-066、SC-075、SC-076、SC-089、SC-091、SC-131、SC-134、SC-136。

门控证据：

- 目标文书正文完整可见。
- 相关结构化字段覆盖，例如入院记录 sections、首次病程字段、手术同意书字段。
- 规则特殊适用性，例如性别、年龄、文书类型、操作类型。

默认分流：

- 目标文书缺失或正文不可复原：`data_quality_gap`。
- 普适字段确实缺失且文书完整：可进入 confirmed 候选。
- 模板开头、短片段、字段名片段不得 confirmed。

推荐接入点：`postprocessor` 的 evidence coverage guardrail，必要时二轮 gate。

## 5. 每类门控证据模型

| 门控类型     | applicability_gate_name            | 适用性证据                                       | 不适用默认           | 证据不足默认       | confirmed 前提                          | 禁止 confirmed 证据                     |
| ------------ | ---------------------------------- | ------------------------------------------------ | -------------------- | ------------------ | --------------------------------------- | --------------------------------------- |
| 手术等级     | `surgery_level_code_gate`          | 手术编码 code_exact/code_normalized 命中 catalog | `rejected_by_system` | `data_quality_gap` | 四级编码 + 完整讨论/文书 + 缺失要件     | 名称候选、code_prefix_ext、参与人员片段 |
| 植入物       | `implant_material_gate`            | 结构化耗材/植入物记录或明确“植入/置入/使用+数量” | `rejected_by_system` | `data_quality_gap` | 植入物存在 + 条码/种类/数量字段缺失证据 | 单个“螺钉/钢板/骨水泥”弱词              |
| 病理取材     | `specimen_pathology_gate`          | 取材、送病理、快速病理、活检、标本证据           | `rejected_by_system` | `data_quality_gap` | 取材触发 + 手术记录/病理记录缺项证据    | 所有手术泛化触发                        |
| 异常结果     | `abnormal_result_followup_gate`    | 异常报告、参考范围、异常描述                     | `rejected_by_system` | `data_quality_gap` | 异常存在 + 后续无分析处理对照           | 只有报告存在、无异常证据                |
| 出院带药     | `discharge_medication_gate`        | 出院医嘱明确药品                                 | `rejected_by_system` | `data_quality_gap` | 存在药品 + 缺剂量/途径/频次/天数        | 无出院带药段落                          |
| 会诊落实     | `consultation_implementation_gate` | 会诊意见、执行医嘱、病程落实记录                 | `rejected_by_system` | `data_quality_gap` | 有意见 + 有对照证据证明未落实           | 缺执行表直接判缺陷                      |
| 文书时效     | `document_timing_gate`             | 触发事件时间 + 文书列表 + 时间区间               | `rejected_by_system` | `data_quality_gap` | 事件存在 + 时间链完整 + 缺失区间明确    | 只有记录时间或单条文书                  |
| 普适文书字段 | `document_field_coverage_gate`     | 完整文书正文/结构化字段                          | 通常不适用较少       | `data_quality_gap` | 文书完整 + 字段确实缺失                 | 短片段、模板标题、字段名                |

## 7. 哪些规则不适用时应系统驳回

- 无四级手术时的 SC-083。
- 无取材/病理触发时的 SC-099。
- 无植入物/耗材触发时的 SC-100/SC-101。
- 无异常检查/检验时的 SC-036。
- 无出院带药时的 SC-123。
- 无会诊意见或执行建议时的 SC-070。
- 男性病历中不应要求月经史。
- 非新生儿或无新生儿文书时的新生儿规则。

这些场景应 `rejected_by_system/not_applicable`，不是 `data_quality_gap`。

## 8. 哪些规则证据不足时应 data_quality_gap

- 已有四级手术编码，但缺完整术前讨论正文/讨论结论。
- 有植入物线索，但缺耗材/条码/追溯码来源表。
- 有异常报告线索，但缺原报告或缺后续病程上下文。
- 有会诊意见，但缺医嘱/执行清单/病程落实对照。
- 出院记录缺项类只有短片段，没有完整字段矩阵。
- 时间链规则缺文书列表或起止时间。

这些场景不能 confirmed，也不应简单驳回，应作为数据/证据链问题。

## 9. 可程序化与需 LLM 二轮 Gate 的边界

适合程序化：

- 手术编码匹配 catalog。
- 是否存在手术、会诊、出院带药、异常报告、医嘱、执行记录。
- 文书是否存在、时间差、字段是否为空。
- 性别/年龄/文书类型适用性。

适合 LLM 二轮 gate：

- 病程是否已经分析/处理异常结果。
- 会诊意见是否被实质落实。
- 出院医嘱是否足够详细。
- 讨论结论是否体现 MDT/相关专科意见。
- 诊断漏填是否由病史/检查证据充分支持。

不建议让 LLM 独立承担的内容：

- 判断手术等级。
- 仅凭手术名称判断四级。
- 仅凭弱触发词判断植入物/耗材。
- 仅凭短片段证明“全文缺失”。

## 10. 后续正式接入建议

建议分三步，不应一次性改全部 84 条。

第一步：只接 P0 的 applicability gate 和 data gap 分流。

- SC-083、SC-099、SC-100、SC-101、SC-036、SC-123、SC-118、SC-097。
- 输出 metadata，不改变父规则数量。
- confirmed 暂缓或必须过二轮 gate。

第二步：把 evidence coverage flags 纳入二轮 gate 输入。

- 让二轮模型看到触发证据、缺口证据和禁止 confirmed 条件。
- 技术上接在 `qc_result_postprocessor` 或 `qc_result_adjudicator` 前后均可，但不要改第一轮 pack。

第三步：规则族级回放验证。

- 对每个 gate 做只读回放。
- 确认 `confirmed_defect` 纯度提升、`data_quality_gap` 可解释、`rejected_by_system` 不误驳回后，再考虑 feature flag。
