# ADR-2026-08-19：离线产品激活码

## 状态

已接受，第一阶段实现。

## 背景

MedQC 只面向私有化部署，客户运行环境可能完全断网。因此授权不能依赖在线激活服务器、远程回拨或联网撤销列表；同时客户希望使用类似 Windows 产品密钥的“一次输入”体验。

## 决策

采用 `MQ1.<base64url JSON>.<base64url Ed25519 signature>` 格式的离线激活码：

- 发行方在受控环境使用 Ed25519 私钥签发；私钥不进入代码库、客户包或日志。
- 客户后端只内置公钥，在本地验证签名、产品、字段和有效期。
- 激活状态写入本地原子状态文件，不使用数据库表、不联网、不绑定机器。
- 产品正式包通过 `PRODUCT_ACTIVATION_REQUIRED=true` 开启门禁；开发环境默认关闭。
- 正式打包默认签发一份从打包时间起有效三个月的预激活状态。客户启动脚本仅在本机尚无激活状态时安装它，不覆盖客户后来导入的正式授权；发行方可在打包时显式关闭预激活。
- 缺失或无效授权只阻断新质控、样本池运行和数据同步；登录、授权页面、历史结果读取和健康检查保持可用。

激活码载荷只允许：`version`、`product`、`customer`、`edition`、`serial`、`issued_at`、`expires_at`。状态文件保存完整激活码，以便每次离线重新验签；它不是私钥，但仍属于受控授权材料，普通管理员不得读取或复制该文件。任何 API 都不得回显完整激活码。

## 未采用方案

- 在线授权服务器：与完全断网的私有化部署冲突。
- 内置共享密钥的短激活码：客户可从 Python 包中提取共享密钥并自行生成授权码。
- 首版机器绑定：增加换机、虚拟机和售后处理成本；后续可在明确需要时增加。
- USB 加密锁：离线安全性更强，但硬件、库存和售后复杂度不适合当前最小闭环。

## 风险与边界

客户拥有本机管理员权限且可以修改 Python 运行时代码时，任何纯软件离线授权都不能提供绝对防破解能力。本方案目标是正规授权、版本和期限控制，不宣称对管理员级篡改不可绕过。

后续若需要更强保护，应单独评审编译/签名的授权服务或硬件介质，不能把防护代码散落到规则执行器和全局中间件中。

当前同步只在公开触发入口执行激活门禁，尚未在同步 Service 内增加第二次校验。若未来新增绕过公开入口的同步调度器，必须先补 Service 级门禁及反例测试；本阶段不为尚未出现的内部入口扩展第二套授权机制。
