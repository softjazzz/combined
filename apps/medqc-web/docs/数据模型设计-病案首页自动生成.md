# 数据模型设计 - 病案首页自动生成功能

## 1. 概述

本文档定义了病案首页自动生成功能的完整数据模型，包括：
- TypeScript 接口定义（前端）
- PostgreSQL 数据库表结构（后端）
- JSON 数据格式（API 交互）
- 数据映射关系

## 2. 核心数据实体

### 2.1 病案首页自动生成任务（FrontPageGenerationTask）

用于跟踪整个自动生成流程的状态。

#### TypeScript 接口

```typescript
/**
 * 病案首页自动生成任务
 */
export interface FrontPageGenerationTask {
  task_id: string                    // 任务ID（UUID）
  admission_id: string                // 住院ID
  patient_id: string                  // 患者ID
  
  // 任务状态
  status: TaskStatus                  // pending | processing | completed | failed | reviewing
  started_at: string                  // 开始时间（ISO 8601）
  completed_at?: string               // 完成时间
  error_message?: string              // 错误信息
  
  // 进度追踪
  current_step: number                // 当前步骤（1-7）
  total_steps: number                 // 总步骤数（固定7）
  progress_percentage: number         // 进度百分比（0-100）
  
  // 分步结果
  extraction_results: {
    basic_info?: ExtractionResult<PatientBasicInfo>
    hospitalization?: ExtractionResult<HospitalizationInfo>
    diagnosis?: ExtractionResult<DiagnosisInfo>
    procedures?: ExtractionResult<ProcedureInfo>
    other_medical?: ExtractionResult<OtherMedicalInfo>
    staff?: ExtractionResult<StaffInfo>
    costs?: ExtractionResult<CostInfo>
  }
  
  // 生成结果
  generated_frontpage?: CaseFrontPage
  
  // 操作人
  created_by: string                  // 创建人
  reviewed_by?: string                // 审核人
  
  // 审计
  created_at: string
  updated_at: string
}

export enum TaskStatus {
  PENDING = 'pending',
  PROCESSING = 'processing',
  COMPLETED = 'completed',
  FAILED = 'failed',
  REVIEWING = 'reviewing'
}

/**
 * 提取结果包装器（带置信度和AI建议）
 */
export interface ExtractionResult<T> {
  data: T                             // 提取的数据
  confidence: number                  // 置信度（0-1）
  ai_suggestions?: AISuggestion[]     // AI建议
  extracted_at: string                // 提取时间
  extraction_time_ms: number          // 提取耗时（毫秒）
}

/**
 * AI建议
 */
export interface AISuggestion {
  suggestion_id: string
  field_path: string                  // 字段路径（如 "basic_info.birth_date"）
  suggestion_type: 'missing' | 'conflict' | 'alternative' | 'warning'
  message: string                     // 建议内容
  evidence?: string                   // 病历依据
  alternative_value?: any             // 建议值
  confidence: number                  // 置信度
  severity: 'info' | 'warning' | 'error'
  created_at: string
}
```

#### 数据库表结构

```sql
-- 病案首页自动生成任务表
CREATE TABLE IF NOT EXISTS frontpage_generation_tasks (
    task_id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
    admission_id VARCHAR(50) NOT NULL,
    patient_id VARCHAR(50) NOT NULL,
    
    -- 任务状态
    status VARCHAR(20) NOT NULL DEFAULT 'pending' 
        CHECK (status IN ('pending', 'processing', 'completed', 'failed', 'reviewing')),
    started_at TIMESTAMP WITH TIME ZONE,
    completed_at TIMESTAMP WITH TIME ZONE,
    error_message TEXT,
    
    -- 进度追踪
    current_step INT DEFAULT 1,
    total_steps INT DEFAULT 7,
    progress_percentage INT DEFAULT 0,
    
    -- 分步结果（JSONB存储）
    extraction_results JSONB DEFAULT '{}'::jsonb,
    
    -- 生成结果ID（关联到 case_front_page）
    generated_front_page_id INT REFERENCES case_front_page(front_page_id) ON DELETE SET NULL,
    
    -- 操作人
    created_by VARCHAR(50) NOT NULL,
    reviewed_by VARCHAR(50),
    
    -- 审计
    created_at TIMESTAMP WITH TIME ZONE DEFAULT CURRENT_TIMESTAMP,
    updated_at TIMESTAMP WITH TIME ZONE DEFAULT CURRENT_TIMESTAMP,
    
    -- 索引
    CONSTRAINT fk_task_admission FOREIGN KEY (admission_id) 
        REFERENCES admissions(admission_id) ON DELETE CASCADE
);

CREATE INDEX idx_fg_tasks_admission_id ON frontpage_generation_tasks(admission_id);
CREATE INDEX idx_fg_tasks_status ON frontpage_generation_tasks(status);
CREATE INDEX idx_fg_tasks_created_at ON frontpage_generation_tasks(created_at DESC);

COMMENT ON TABLE frontpage_generation_tasks IS '病案首页自动生成任务表：跟踪LLM提取的完整流程';
```

### 2.5 诊断和手术信息（DiagnosisAndProcedures）

对应 PRD 的 F3-F7 功能模块。

#### TypeScript 接口

```typescript
/**
 * F3-F7: 诊断和手术信息
 */
export interface DiagnosisAndProcedures {
  // F3: 急诊/门诊诊断
  ed_diagnosis?: Diagnosis[]          // 急诊诊断列表
  outpatient_diagnosis?: Diagnosis[]  // 门诊诊断列表
  
  // F3: 出院诊断
  discharge_main_diagnosis: DischargeMainDiagnosis  // 主要诊断（必填）
  discharge_other_diagnoses: DischargeDiagnosis[]   // 其他诊断列表
  
  // F6: 手术操作
  main_procedure?: MainProcedure      // 主要手术操作
  other_procedures: Procedure[]       // 其他手术操作列表
  
  // 损伤中毒外部原因
  external_cause?: Diagnosis          // 损伤中毒的外部原因（ICD-10）
  
  // 病理诊断
  pathology_diagnosis?: PathologyDiagnosis
}

/**
 * 基础诊断结构
 */
export interface Diagnosis {
  text: string                        // 诊断描述
  icd10?: string                      // ICD-10编码
  icd10_name?: string                 // ICD-10编码名称
  is_tcm?: boolean                    // 是否中医诊断
}

/**
 * 出院主要诊断（带入院病情）
 */
export interface DischargeMainDiagnosis extends Diagnosis {
  // F4: 入院病情推理
  admission_condition: '1' | '2' | '3' | '4'
    // 1-有 2-临床未确定 3-情况不明 4-无
  admission_condition_text?: string
  admission_condition_reasoning?: string  // 推理依据
  
  // F5: ICD编码推荐
  icd_candidates?: ICDCandidate[]     // Top 3 候选编码
}

/**
 * 出院其他诊断
 */
export interface DischargeDiagnosis extends Diagnosis {
  sequence: number                    // 顺序（1, 2, 3...）
  
  // F4: 入院病情
  admission_condition: '1' | '2' | '3' | '4'
  admission_condition_text?: string
  admission_condition_reasoning?: string
  
  // F5: ICD编码推荐
  icd_candidates?: ICDCandidate[]
  
  // 并发症标记
  is_complication?: boolean           // 是否为并发症（影响DRG）
}

/**
 * F5: ICD编码候选项
 */
export interface ICDCandidate {
  code: string                        // ICD-10编码
  name: string                        // 编码名称
  confidence: number                  // 置信度（0-1）
  reasoning: string                   // 推荐理由
  source: 'exact_match' | 'semantic_match' | 'knowledge_graph' | 'llm_inference'
  is_selected?: boolean               // 是否被选中
}

/**
 * F6: 主要手术操作
 */
export interface MainProcedure {
  date: string                        // 手术日期（YYYY-MM-DD）
  name: string                        // 手术名称
  
  // F7: ICD-9-CM-3编码
  code?: string                       // ICD-9-CM-3编码
  code_name?: string
  code_candidates?: ICD9Candidate[]   // Top 3 候选编码
  
  // 手术详情
  level?: '1' | '2' | '3' | '4'      // 手术级别（1-四级 2-三级 3-二级 4-一级）
  level_text?: string
  
  // 手术人员
  surgeon_name?: string               // 术者
  surgeon_code?: string               // 术者工号
  assistant1_name?: string            // I助
  assistant1_code?: string
  assistant2_name?: string            // II助
  assistant2_code?: string
  
  // 切口信息
  incision_healing_grade?: 'Ⅰ' | 'Ⅱ' | 'Ⅲ' // 切口愈合等级
  
  // 麻醉信息
  anesthesia_method?: string          // 麻醉方式
  anesthesia_method_code?: string
  anesthetist_name?: string           // 麻醉医师
  anesthetist_code?: string
}

/**
 * F6: 其他手术操作
 */
export interface Procedure {
  sequence: number                    // 顺序
  date: string                        // 手术日期
  name: string                        // 手术名称
  
  // F7: ICD-9-CM-3编码
  code?: string
  code_name?: string
  code_candidates?: ICD9Candidate[]
  
  // 手术详情（可选）
  level?: '1' | '2' | '3' | '4'
  surgeon_name?: string
  surgeon_code?: string
}

/**
 * F7: ICD-9-CM-3编码候选项
 */
export interface ICD9Candidate {
  code: string                        // ICD-9-CM-3编码
  name: string                        // 编码名称
  confidence: number                  // 置信度
  reasoning: string                   // 推荐理由
  source: string
  is_selected?: boolean
}

/**
 * 病理诊断
 */
export interface PathologyDiagnosis {
  text: string                        // 病理诊断描述
  icd10?: string                      // ICD-10编码
  pathology_no?: string               // 病理号
}
```

CREATE TABLE IF NOT EXISTS ai_suggestions (
    suggestion_id UUID PRIMARY KEY DEFAULT gen_random_uuid(),

## 4. 数据流转与映射

### 4.1 自动生成流程数据流

```
1. 用户触发生成
   ↓
2. 创建 frontpage_generation_tasks 记录（status=processing）
   ↓
3. LLM分步提取：
   - 步骤1: 提取 basic_info → 存入 extraction_results.basic_info
   - 步骤2: 提取 hospitalization → 存入 extraction_results.hospitalization
   - 步骤3: 提取 diagnosis → 存入 extraction_results.diagnosis
   - 步骤4: 入院病情推理 → 更新 diagnosis 的 admission_condition
   - 步骤5: ICD-10编码推荐 → 存入 icd_candidates 表
   - 步骤6: 提取 procedures → 存入 extraction_results.procedures
   - 步骤7: ICD-9-CM-3编码推荐 → 存入 icd_candidates 表
   ↓
4. 合并结果生成 CaseFrontPage 对象
   ↓
5. 保存到 case_front_page 表（status=draft）
   ↓
6. 更新 frontpage_generation_tasks（status=completed）
   ↓
7. 返回给前端展示
```

## 5. 数据模型设计原则

### 5.1 混合存储策略

- **关键字段单独存储**：便于查询、索引、统计（如 `patient_name`, `admission_datetime`, `primary_diagnosis_code`）
- **复杂嵌套数据用 JSONB**：灵活存储、减少表数量（如 `basic_info`, `hospitalization`, `costs`）
- **一对多关系用关联表**：便于精确查询和更新（如 `case_front_page_diagnoses`, `case_front_page_procedures`）

### 5.2 版本控制与审计

- 所有表包含 `created_at` 和 `updated_at`
- 关键操作记录操作人（`created_by`, `reviewed_by`, `handled_by`）
- 支持多版本（通过 `version` 和 `is_latest` 字段）

### 5.3 可扩展性

- 使用 JSONB 存储灵活字段，支持未来扩展
- 枚举类型使用 VARCHAR + CHECK 约束，便于添加新值
- 预留 `notes` 和 `metadata` 字段

### 5.4 性能优化

- 关键查询字段添加索引
- JSONB 字段使用 GIN 索引支持全文检索
- 分区表策略（按时间分区 `case_front_page`）
