# 原生扫码登录实施计划

**目标：** 接续`abd60ffb3`，补齐固定80项的01扫码认证缺口；账号、手机号密码登录保持原合同。

**架构：** 复用既有认证与角色落地，新增持久化、短时、一次性的浏览器授权会话。手机已有MedQC会话显式批准电脑登录，不将二维码本身作为Bearer凭据。原生方式已向用户询问；如指定第三方通道，调整接入方式，不将原生实现冒称第三方集成。

**技术栈：** 既有FastAPI、SQLAlchemy/Alembic、Vue及现有认证Store；二维码渲染复用已有库或成熟依赖。

## 原始范围

- PRD第98及426行要求账号密码、手机号、扫码三方式认证，没有指定短信或微信。第235行的外部通道阻塞属于历史实现判断，不能替代原始需求。
- 不扩展账户体系、其他认证整改或全仓安全审计；仅保证新增授权流程自身完整、安全且复用真实认证。
- 不运行本批数据库迁移；仅编写迁移并通过合成数据库测试。真实库与浏览器验收单独记录。

## 冻结接口与安全合同

- 创建时生成高熵session_id、browser_secret，返回短TTL（120秒）、电脑确认码。二维码只包含确认页面与session_id，不含secret、JWT或refresh token。
- browser_secret仅发起页内存持有，后端只存摘要，不进入URL、日志或浏览器持久存储。
- 扫码确认页必须经过现有认证；显示登录操作提示，要求校验电脑确认码并显式批准，不得自动授权。
- 状态pending、approved、consumed及取消/过期规则由持久化owner维护。批准与兑换均比较旧状态，重复、并发、超时或错误secret失败关闭。
- 轮询不返回身份信息或token；兑换必须持有browser_secret，消费授权前重新确认账户有效，签发沿既有token合同。
- 创建及确认需有界限流；确认码错误不得无限尝试。刷新或关闭电脑页面导致丢失secret时重新创建，不能恢复未知授权或盲目重放兑换。

接口统一前缀`/api/v1/auth/qr/sessions`，响应沿用auth的data envelope：

| 方法/路径 | 认证与输入 | 输出/行为 |
| --- | --- | --- |
| POST `/` | 匿名、IP限流 | session_id、browser_secret、verification_code、expires_at、poll_interval_ms |
| POST `/{id}/status` | browser_secret body | session_id、status、expires_at，无身份或凭据 |
| GET `/{id}/confirmation` | 当前认证用户 | 安全状态，不返回verification_code |
| POST `/{id}/confirm` | 当前认证用户、verification_code | pending比较更新为approved；错误码原子计数，最多5次 |
| POST `/{id}/reject` | 当前认证用户 | pending拒绝 |
| POST `/{id}/cancel` | browser_secret body | 发起端取消尚未消费授权 |
| POST `/{id}/exchange` | browser_secret body | approved单次消费，返回现有LoginResponse |

- 所有角色只能确认自己当前有效的持久化账户，session锁后查询并锁定SysUser有效性，不使用内存演示用户回退。先生成token，事务成功消费并提交后才返回。
- 状态固定pending/approved/rejected/cancelled/expired/consumed，不增加没有消费者的scanned状态。
- 手机页面`/auth/qr-confirm?session_id=...`，保护路由但不要求某业务菜单权限；二维码不含确认码。
- 新表沿sys_users权威schema；新增迁移71接70，仅代码与合成验证。新增服务承担状态，不扩大auth_store职责。

## 分工与验收

1. 后端代理核对现有签发、账户有效性、限流和迁移接入点；冻结合同后实现独立服务/模型/接口与聚焦测试。
2. 前端代理核对登录API/Store/路由与二维码依赖；冻结后实现登录页切换、二维码状态、已登录确认页和错误处理，不改后端契约。
3. 独立代理只复核新增认证流程的具体安全风险与反例；主协调亲验关键diff和合同测试，集中门禁并提交。
4. 测试至少覆盖过期、取消、错误secret/确认码、未登录确认、禁用账户、重复与并发批准/兑换、令牌不泄漏、轮询停止及迟到响应隔离。
5. 代码完成后才提升01状态；合成验证、非生产PG、业务部署、真实浏览器验收分别报告。
