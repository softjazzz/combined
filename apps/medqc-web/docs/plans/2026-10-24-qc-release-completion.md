# 质控功能收口与完整客户版发布 Implementation Plan

**Goal:** 将P0材料验收/失败恢复纳入正式项目，补齐两个抽取入口的事实冻结与已确认病例保护集，再从独立分支编译完整客户包。

**Architecture:** 沿用五类材料验收、正式失败配对合并和Canonical owner，不采用客户机源码节点补丁安装。只在已校验语义事实层增加冻结，命中仍走当前解析、判定及发布；材料、模型、提示词或协议变化失效。私有真实材料与录制应答留在临时目录，版本库保护集仅保留别名、业务裁定及去身份合成正反例。

**Tech Stack:** Python 3.10、现有LX0609执行/冻结/发布保存组件、隔离SQLite、Windows PowerShell客户包构建。

## 约束和验收边界

- C:/medqc-qc-source-fixes，codex/qc-source-completion-20261023；不改业务集成分支，不合并PR。
- 不调用真实模型，不重跑27例质控，不写本机/远端业务库；只读现有材料与既有应答。
