# 复用质控结果文书工作台

用户要求客户样本验证「查看病历」与质控结果文书展示统一，包括目录。现有只读查看使用编辑副本模板的只读分支，结果页使用QCRecordCompareWorkbench，存在两套正文与医嘱呈现。

最小方案：父页面只读分支直接使用QCRecordCompareWorkbench，新增documentOnly/providedDocuments配置既有展示职责。复用ReadonlyMedicalDocumentDirectory、分节正文、ReadonlyMedicalOrderTable；隐藏结果栏、结果移动切换、证据定位状态。默认入院记录，无入院按既有规则。

当前查看仍由前一任务current接口读取完整文书，再传入工作台，不发第二次摘要或render请求，不回退旧Bundle。历史质控工作台没有传入这些props，保持既有加载、证据定位和结果反馈。创建副本仍使用可编辑界面。

两个Vue文件均超过行数预警。本轮只接入已有组件及配置现有展示方式，不新增独立职责，不为少量配置迁出零碎模块。文件范围为父页面、工作台和各自聚焦测试；不修改后端或文书组装。

验收：默认入院、目录搜索/折叠/文书切换、医嘱表复用、无结果栏、单次current请求，历史工作台和编辑副本回归。使用本机100052查看并核对入院时间。

真实病例验收发现共用目录将正文“入院”等关键词混入文书身份，完整正文的查房、会诊和出院记录误入入院组。补充最小修复范围为 medicalDocumentTaxonomy.ts 和独立目录回归：已有明确身份先分组，仅未知类型回退正文；病程组保留原有医师角色细分。该修复同时适用于两个入口，不新增分类所有者。

验收完成：4 个聚焦测试文件 96 项通过（7.95 秒）；type-check、lint、encoding 通过。本机 100052 默认入院记录，目录为入院/首次病程 2、病程查房 5、会诊 2、医嘱 36、出院 2；点击医嘱显示共用表格，无质控结果列。后端日志每次打开只有 current 文书读取，切换医嘱未增加 summary/render 请求。未修改后端及质控判定，未打包。
