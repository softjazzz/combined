# 注册医生按主治医师姓名读取病历

用户确认：暂不用工号；本人名下病历沿用病历池的“主管医师”，对应病案首页 `attending_physician_sign`，不把住院医师、文书作者或任意签名算作主管医师。

## 本批实现

- 独立分支 `codex/doctor-name-case-scope-20261026`，不修改业务集成分支。
- 读取持久账号的已核定姓名、机构、科室，按机构、权威出院科室口径及主治医师姓名精确匹配。只清理姓名两端空白，不作模糊匹配或多人姓名拆分。
- 名下病例使用完整机构/患者/就诊三坐标；列表、计数、分页、主管医师选项及首页结果投影使用同一范围，SQL查询先限制范围再统计分页。无匹配返回空集合，不退回整科或演示数据。
- 正文、首页、诊断、手术、费用、结果及首页表单导出校验对象范围。跨院同号的旧单号入口拒绝含混身份；EMR完整三坐标入口可准确读取本人对象。
- 医生结果不读取旧的无机构缓存和legacy结果作为回退，Canonical读取失败保留失败状态。未接入个人范围的旧全院入口、通用表导出和客户样本池对普通医生返回403。
- 普通医生不能经个人资料接口修改用于授权的姓名或科室；管理员仍从原账号管理入口核定修改。管理角色及sync_admin保持原权限。
- 注册审批、通知和既有本人审核/申诉/整改/沟通沿用其持久申请人、收件人或显式任务责任人授权与CAS规则，不将这些对象授权扩为同科室读取权限。
- 缺姓名/机构/科室、账号失效、损坏角色配置或同机构同科室存在多个有效同名医生账号时失败关闭。无首页或主治字段缺失的病历不会自行推断归属。

## 验证及边界

121项相关测试通过，包含27项新增姓名授权测试。新增测试实际执行内存SQLite的账号和CDM SQL、HTTP路由及分页/导出，覆盖同科他人、跨科、跨院同号、住院医师误认、多人签名、旧public表、URL/参数/角色头伪造、自助改名、无匹配与失效账号。既有工作台SQLite夹具曾继承开发机split/cdm配置：改动前HEAD也复现28失败；明确夹具自身的默认schema后通过，另保留独立cdm与旧表隔离反例。

未运行全量前后端测试，未用真实医生账号进行浏览器验收；不调用模型、不重跑质控、不执行数据库迁移或修改既有账号授权。实现无需新增字段，以管理员核定的账号姓名为绑定值。姓名方案无法识别HIS实际存在但尚未对应多个账号的重名人员；此类身份歧义仍需管理员核实，后续可改绑工号。
