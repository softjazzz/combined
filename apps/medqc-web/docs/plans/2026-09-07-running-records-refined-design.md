# 运行病历质控页面精修

## 问题与方案

真实入口 `/workstation-v4/records/running` 使用 `QcRecordResultListView.vue`，不是病历池的阶段队列。1440px 浏览器截图确认：筛选控件的最小宽度与操作按钮争抢同一行，查询按钮被挤压；多层圆角卡片、装饰头像和重复蓝色按钮削弱工作重点。

采用与已批准病历池一致的克制医疗蓝方案：紧凑页头与视图切换、连续指标条、独立筛选行、列表标题/已选数量和操作行、清晰表格。相比只换颜色，此方案解决实际遮挡；不增加新的分析大屏或业务功能。

## 范围与所有权

- 主协调修改 `QcRecordResultListView.vue` 的模板呈现，新增运行页专属样式文件，保持查询和任务函数不变。
- 子代理仅修改 `QcRecordResultTable.vue` 的运行页呈现及对应测试，主协调审核。
- 不改变终末病历外观、共享指标组件、API、状态计算、导出范围和任务创建。
- 外层文件接近 1200 行预警线，本次新增完整的运行页视觉样式放入独立样式资源，不继续扩充内联样式。不拆业务函数，不新增组件转发层。

## 验收

- 1280/1440/1920px 下无页面横向溢出，查询及全部操作完整可见；表格必要时仅内部横滚。
- 查询条件、入院时间范围、分页、选择、导出菜单、查看结果和分析切换保持原语义。
- 运行/终末页面聚焦测试，类型检查、lint、UTF-8/LF 检查。
- 浏览器仅验证读取和界面交互，不启动真实质控或执行住院状态写操作。
- 保留资料不足、未知时间、加载失败的真实展示，不为设计编造数据。

## 剩余风险

共享页面与表格存在终末页消费者，因此所有新样式必须限定 inpatient；真实任务执行和导出文件内容不在本次纯视觉验收范围内。
