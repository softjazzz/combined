# 质控诊断证据包与开发机回放 Implementation Plan

> 状态：首批匿名展示回放及 T2 内部转换/文书引用基础已通过聚焦验收。完整脱敏/快照/模型等价验证、客户采集导出及百炼核查尚未完成；未运行模型或重跑客户质控。
> 长程授权：2026-09-08 用户要求设定长程任务并完成本计划，目标已在当前任务激活。正常批次通过主代理验收后连续推进，不再逐批等待确认；新外发权限、客户医学口径或不可代替的外部验收条件仍须询问。
> 执行时逐任务遵循 executing-plans；每个闭环主代理验收后单独提交，不扩大规则或临床口径。

**Goal:** 客户在已安装系统中选择疑点，导出脱敏且标明回放能力的诊断包；开发机 Codex 不依赖客户数据库、密钥和原始身份，即可核对证据、复现支持范围内的问题、建立失败测试并进行最小修复。

**Architecture:** 在现有后端增加独立的诊断证据模块，旁路消费当次已读取的 EvidenceReadSession、正式模型调用和结果。诊断数据不是临床事实的新来源，不改变规则执行、状态或保存合同。百炼辅助核查是后续可选功能，不是诊断包成立的前提。

**Tech Stack:** 现有 Python/FastAPI、LX0609 Canonical、严格数据模型、pytest、Vue/TypeScript、JSON/ZIP、项目既有客户打包脚本。

## 1. 已确认需求与不做的事

- 客户机不安装 Codex、Git 或开发工具；诊断能力随安装包部署。
- 所有对外诊断材料必须脱敏；原始身份映射、密钥、连接串不能导出。
- Codex 接包后先对齐代码版本、校验证据、离线回放，再写红测试和修代码。包中模型意见不是修改指令，也不是医学金标准。
- 包必须能够解释为什么不能回放：历史采集缺失、资料截断、脱敏破坏等价性、版本不匹配、未支持规则族等都显式展示。
- 不自动修改客户代码、升级软件、覆盖正式结果、重写原始病历；不开放远程终端；不导出数据库全库。
- 不重做聚合器，不新增临床判定引擎，不为诊断复制事实解析、规则注册表或资料Bundle。
- 本次计划不承诺3小时交付全部功能；按独立验收里程碑推进。P0优先，P1/P2不能挤占安全与回放验证时间。

## 3. ADR：选择当次受控采集＋脱敏数据包

**状态：已批准，按长程任务分阶段实施。**

候选方案：

1. 仅导出当前debug JSON：最快，但无法复现资料漏读、空正文和模型输出问题；只保留为历史受限包。
2. 当次受控采集＋离线回放：推荐。增加小范围存储/接缝，但证据时间和版本清晰，开发端可验证。
3. 客户机部署通用开发Agent或第二套全量判定引擎：拒绝。越过安装包维护边界、扩大隐私和架构风险。

代价：需要本地安全存储、清理策略、类型/引用重建及规则族回放验收；不得把它估作单纯“导出ZIP”。

## 4. 端到端流程与能力分级

```text
管理员授权诊断采集（选定任务/病例，明确资源上限）
  → 正式质控读取资料 → 旁路接收同一次读取的材料
  → 模型真实调用 → 旁路记录实际尝试与可解析业务响应
  → 正式结果保存 → 诊断材料关联该结果与版本
  → 用户选择规则疑点 → 本地脱敏/引用映射/一致性验证
  → 预览、检查通过 → 导出纯数据ZIP
  → 开发机inspect → 校验版本/包安全 → 离线replay → regression fixture
```

包内必须同时声明两种能力，避免混淆：

- **采集完整性**：complete / partial / unavailable，逐项列缺失原因。
- **回放能力**：render_only / executor_with_recorded_responses / unsupported。

旧任务没有录制时，允许生成明确受限的历史包，不补造模型响应。用户可显式发起新的“带诊断采集质控”，但这是新任务、新时间，不覆盖旧证据或暗中自动重跑。

P0覆盖：032/066展示回放；076空正文及029证据越界的确定性执行回放；020/022所在会诊族的固定响应回放，用于验证模型录制并发/重试机制。其他规则导出材料但未验收回放者必须标unsupported，不能宣称全引擎支持。

## 5. 数据包合同（纯数据，不附带可执行代码）

```text
diagnostic.zip
  manifest.json            包版本、构建/规则版本、场景、能力及缺失清单
  issue.json               用户描述、原结论、疑点；不把AI意见当预期真值
  inputs.json              脱敏材料、字段类型、来源读取状态、顺序及评价时点
  model-calls.json         去密钥请求、实际响应/安全失败、调用身份和attempt
  results.json             原结果、受控事实、必要阶段结果、引用
  privacy-report.json      转换类别、风险、能力降级；不含原始值和身份映射
  README.md                包内容及限制；只使用固定生成模板，不嵌入病历指令
```

manifest最小字段：schema_version、package_id、build_id、git_commit、release_inventory_version、rule_set_version、rule_ids、scope、capture_completeness、replay_capability、missing_components、redaction_policy_version、files。

- 复用既有source/artifact digest作来源与版本说明。脱敏后按现有EvidenceSession规范重建引用；旧摘要不冒充新内容摘要。不增加多套语义/请求摘要。
- 包完整性只用一份文件清单校验；哈希仅检测损坏，不宣称来源可信。包来源/身份仍按安全输入处理。
- 数值Decimal、datetime/date/time、时区、空值/空字符串/缺字段必须区分。顺序、重复文书与occurrence语义必须保留。
- 跨规则族共享一次模型调用时记录已有executor/logical_call_id/attempt关联；回放不能用简单全局FIFO。找不到唯一匹配时中止，不能偷调真实模型或复用其他病例响应。
- 保留实际执行参数及模型返回版本；模型别名不等于固定权重快照。脱敏请求/响应只是等价数据，不承诺重新调用模型可得到原答案。

## 6. 脱敏与回放等价性

### 客户本地

- 明确授权后才能启用正文诊断采集，默认关闭；普通质控不因诊断失败而失败。
- 原始诊断内容只进服务专用目录，不进入普通日志、数据库用量事件、浏览器localStorage或源码目录。
- 持久化必须采用经评审的本地加密和OS权限隔离；密钥不与包同存。实施前检查已有密钥设施；Windows DPAPI等方案须验证服务账号/重启行为，不临时自创密码学。
- 第一版建议保留7天、总量500MB、每包20MB作为待实测默认值，支持管理员降低；满额停止新采集并标partial，不阻塞质控。清理只能操作服务专用已验证目录，不执行用户指定路径。

### 对外转换

- 全字段允许清单＋已知身份字典替换＋本地格式识别；姓名/住院号/文书ID用包内一致随机编号，不保留首尾身份字符或低熵可猜测哈希。
- 正文、模型请求/响应、异常字段和用户描述一并处理；删除API Key、token、连接串、路径、机构/医务人员标识及其他不必要身份线索。
- 患者映射不导出。预览默认只呈现脱敏内容，不提供下载原始包的旁路。
- 时间按病例一致转换，不能破坏跨日/时间间隔、时区和评价窗口。主诉字数、相似度、年龄、特定日期等可能受脱敏影响，必须做规则相关等价验证；无法证明时降级回放能力，不能篡改原结论来伪造通过。
- 脱敏后模型引用必须仍指向脱敏原文。JSON中包含的文本和结构化字段同时转换；无法安全解析/脱敏的无效响应不能直接放入包，保留安全错误类型并标模型解析回放不可用。
- 扫描残留身份与密钥，命中/检测失败就禁止导出。人工确认不能绕过硬性风险；自由文本自动脱敏不宣称零遗漏。
- 后续发送给百炼的诊断输入使用同一脱敏出口，不把未脱敏文本发模型代为脱敏。

### 开发机安全

ZIP路径穿越、绝对路径、符号链接、重复名称、超大展开体积、过多文件、未知schema均拒绝。仅允许固定JSON/模板Markdown文件，不用pickle、eval、不运行包内脚本。

病历和模型内容是非可信数据，不能成为Codex操作指令。导入不得自动checkout/pull/安装依赖/访问URL/执行Shell。版本不符仅报告，由开发者选择受控工作树。

4. 双击/重试不重复创建采集和模型任务；取消/过期后禁止下载。
5. 入口可在单条结果“更多”中，不先建大诊断中心。复用workstation-v4样式。

### T6：发布与端到端验收（P0最后门）

1. 在没有Codex/Git/项目源码的干净客户运行环境启动安装包，完成授权采集、质控、预览和导出。
2. 开发机断网、无客户DB凭据，inspect/replay实际导出的匿名样包。
3. 从release inventory提取准确构建标识，禁止运行时依赖git命令；模块/依赖/schema随现有后端构建链交付，若存在动态导入需显式打包测试。
4. 继续执行现有发布门禁、排除字体。用户脏改未处理时只报告无法制作正式包，不用AllowDirty冒充可发布。
5. 提交前最低check:encoding、lint；共享TS/API闭环执行type-check和相关unit，交付前按项目条件执行完整test:unit。编码脚本扫描0文件时补显式UTF8/BOM/LF检查。

### T7：百炼辅助检查与批量抽样（P1，P0通过后再做）

- 手动反馈永远可以导包，不要求先跑AI。复用已脱敏材料与既有调用客户端，不另建LLM平台。
- 用候选模型对真实已知错误/正确结果/口径争议评测后确定默认配置；不能仅按模型排名指定。服务账号可用性和医院外发授权先确认。
- 输入限定规则要求、资料完整性、原结论和最小证据；输出疑点类型、原文位置、支持/反证及限制；引用真实性由程序检查。
- 与正常质控完全分离的疑点记录，不改正式状态。禁止执行文书中的指令，禁止自发联网搜索患者信息。
- 批量诊断复用已有任务基础设施，防重复、费用上限、并发、超时、取消；不使用诊断模型给自身结论作金标准。
- P1首批样例验证误报/漏报、引用有效率和成本后，再批准自动抽样；不在P0顺手实现。

## 9. 并行安排与验收责任

- 主代理先锁定包合同和捕获接缝；亲自审查模型实际输入、记录配对、脱敏引用及真实回放。
- 契约冻结后，代理A负责脱敏/安全负例，代理B负责离线回放及独立验收，主代理负责采集与API；同一文件禁止并发写。
- UI在API冻结后接线；发布验证最后统一进行。子代理测试通过不能替代主代理验收。
- 若只有3小时可用，优先T1/T2和032/066展示回放这一条完整纵向切片；禁止为宣称全功能交付牺牲脱敏、归属权限或离线边界。其余按实际完成度继续。

## 10. 总体验收与停止条件

- 手动选疑点，不依赖百炼，可导出声明准确的诊断包。
- 已验收规则族，开发机在无客户DB、无网络、无真实身份条件下复现既有缺陷，并生成可审阅的差异。
- 捕获开关、异常、清理均不改变原质控结果；不新增隐式资料源/LLM调用。
- 模型失败、历史缺证据、脱敏不等价、版本漂移、规则族不支持都拒绝冒充完整回放。
- 明确工程缺陷可进入自动修复测试；医学口径、资料载体、数据同步完整性未确认则停止该项并交人工决策。
- 每里程碑达到标准后提交并核验，再按长程授权推进本计划下一阶段；计划外扩范围仍暂停。整个功能验收通过再讨论更大自动化，不以剩余额度为理由持续新增架构。
