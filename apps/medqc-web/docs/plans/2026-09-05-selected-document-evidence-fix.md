# 基础时限规则：实际选中文书的证据闭环

## 问题证据与范围

前一轮多文书冻结用例表明：001/002 已选中有效文书，但客户证据为空；005 从 daily_course_record 选中查房记录，却投影为 senior_course_record。缺 ID 借用其他行的问题已单独修复，本轮必须保留这一安全边界。

根因是执行器只向 RuleDecision 提交来源级引用，丢失实际选中的材料行；现有逐文书引用已经存在，但 Binding 尚未接受其同源验证。不能在展示层按标题、时间或相似正文重新猜测。

## 最小实施方案

1. 独立红测试复现 001/002/005 的错误坐标。
2. 复用材料仓已有 document_refs，提供经过本次快照与来源校验的引用/原行配对。Binding 可选接收现有材料仓，仅接受规则允许来源的真实引用。旧来源级调用保持兼容。
3. 执行器在既有选择位置保留实际行及来源，追加该行引用；不重新选择事件，不改临床状态、时间算法、Prompt 或调用次数。005/006 共用的选择分支一起保持正确来源。
4. 现有公共证据组件负责把选中引用转换为真实文书坐标。存在逐文书选择时，它优先于旧 display facts 和来源级推测；即使选中行缺 ID，也不能重新借用其他行。
5. 聚合器仅增加通用投影调用，不增加规则号分支。主编排仅透传已有材料仓至 Binding。

## 文件范围与职责门禁

生产范围：evidence_material.py、decision_binding.py、native_basic_timeliness.py、customer_evidence_enrichment.py、execution.py、luxian_0609_result_aggregator.py。对应聚焦测试和本轮验收文档。

两个巨型文件只修改原有选择点和透传/装配调用，不新增独立规则职责，不开展拆分。材料引用校验留在已有材料仓/Binding，坐标生成留在已有公共证据组件。不得增加新 Bundle、Resolver、摘要算法、注册表、API/Canonical 字段或前端解释。

## 验收与剩余风险

- 相同输入下状态、原因码、客户事实、结论不变；精确证据改为实际选中行。
- 缺 ID、同 ID 多行、跨来源、跨快照、伪造引用不能输出错误定位。
- 004 原路径保持不变；原单文书路径和新多文书路径都验证。
- 使用现有生产 prepare 入口比较单规则与组合执行、确定性模型 Stub 的 Prompt 和调用次数。
- 本轮只证明冻结输入的实际后端执行链；真实客户病例、三种页面入口和真实模型十次性能验收仍需独立完成，不能以单测数量替代。
- 不修改用户已有前端改动，不重启服务、不写数据库、不调用真实模型。
