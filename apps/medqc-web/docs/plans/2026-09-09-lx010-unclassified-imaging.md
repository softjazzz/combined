# LX0609-010 未知类型放射检查处理

## 问题与最小范围

本机真实候选病例存在CT医嘱、放射科检查主记录及报告时间，但检查名称、类型、报告正文和直接关联缺失。既有执行器识别不到CT事件后返回不适用，将资料不明当成未实施。

仅调整 native_exam_lab_execution.py 的既有010结构校验：有效CT/MRI医嘱存在、未识别到目标主记录，但存在类型字段均空、执行科室为空或放射/影像、报告时间字段非空的主记录时，返回 data_gap / required_field_missing。不推定CT已经实施，不执行时差计算，不新增LLM、缓存或数据来源。明确非目标检查、只有计划的既有行为由回归验证。共享011/012判定不在本次修改范围。

文件超过长度预警，但本次仅向原有结构校验增加15行条件，不加入独立职责；不进行拆分或增加新分类框架。

- 162项既有及新增检查检验测试通过，1.05秒。新增六个参数组合覆盖放射科、医学影像科、未知科室和两种时间形式。
- 真实公开API重新执行：目标病例不适用变为数据不足，带3条医嘱证据；两个对照病例状态及原因码不变，均无模型Token消耗。
- 源库、临床CDM、Renderer、Finalizer、API与前端合同均未修改。未知检查记录的具体项目仍需数据对接补充，修复不等于可以完成此项质控。
