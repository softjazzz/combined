# 病理及死亡记录同步只读演练

本次覆盖已确认的两类缺口，不代表所有数据疑点均已排除：C23/C25 共5份病理报告在 homology 有完整诊断、clinical_data 没有诊断列；C02/C03/C04/C06/C09 共5份死亡记录在 clinical_data 有结构化章节，旧同步未完整组装正文。

入口为 `backend/scripts/verify_report_sync.py`。客户机旧后端不必先换整包：工具携带当前生产 `homology_sync.py`，仅在独立进程读取既有配置，病理适配使用当前生产模块；死亡正文组装使用从生产映射复制的章节定义，进程结束前恢复原映射。客户范围坐标及诊断包均放仓库外，不入库。

源连接使用 psycopg2 只读会话，本地连接设置只读事务。工具调用客户机真实入库函数，但 INSERT/DELETE 由预览会话截获到内存，仅允许元数据 SELECT 到达数据库。兼容旧入库入口缺少 required_columns 的签名，同时独立检查诊断/正文目标列、字段长度、保存条数及章节完整性。病理按完整病例坐标、申请号、病理号、报告时间和状态核对两库的同一报告。

输出只包含病例别名、条数、正文长度及受控错误类别，不输出病历正文、SQL参数或凭据；没有 apply 模式，不调用模型、不保存质控结果、不改配置文件。通过仅表示只读身份/投影/长度检查通过，不等于实际 INSERT 已成功，也不证明下游 bundle 或规则输入已补齐。

验证：新增14项及同源适配/死亡同步回归共59项通过，Ruff通过。包含旧死亡映射和旧入库签名演练、写SQL拦截、打包入口合成执行及敏感内容不输出检查。本轮无业务库连接/写入，无真实模型调用。客户真实只读结果待回传，后续实际定向补全和下游快照验收尚未执行。

本轮只有Python运维工具和文档变更。此前全量前端检查因虚拟内存不足中断，本轮不重跑无关的前端全量，提交前运行编码和不自动改文件的Lint检查。
