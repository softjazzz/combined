# V3.6 定时计划与执行回执

## 目标和边界

- 接续`cc0fa210f`，补43全部任务中的定时管理，不将基线未实现的39计入十项Goal。
- 计划定义与每次生成的单次任务分开保存。计划暂停/恢复不改变质控员处理状态；运行成功只表示抽样持久化完成，不表示人工任务完成或质控结果通过。
- 当前可证明完整抽样来源的运行中病历主链先接入；不以该范围替代原PRD全部场景，未完成范围继续保留，不提前提升43整项。
- 不引入新的Celery/RQ运行体系，不整改质控引擎。持久计划和执行回执承担恢复事实，既有detached runner只负责进程内派发。

## 创建与管理

- 独立计划表和运行回执表，新增迁移66；旧qc_tasks的scheduled任意JSON不再作为可执行计划。
- 创建引用已有空单次草稿ID和配置版本，服务端行锁、权限、CAS及完整配置校验后复制快照。源任务保持不变，新任务不跟随源任务后续修改。
- 创建必填Idempotency-Key，按创建actor与key唯一；相同源ID、配置版本和时间配置返回原计划，换载荷返回409。前端按actor与源任务持久保存未知请求，关闭重开不换key；明确冲突解除阻塞。
- 冻结scene、规则集key/version、抽样和分配配置；执行重验冻结版本，不换成最新版本。
- 周期计划使用动态活动病例范围，拒绝固定record_refs、旧record_ids、固定日期范围和截止时间，不静默删除这些字段。
- 支持once/daily/weekly，上海时区明确存储；状态active/paused/ended/cancelled独立CAS。恢复跳过错过的批次，不无限补跑。
- 管理员/质控管理员入口，稳定actor和对象权限在服务端核实；支持列表/详情、暂停/恢复/取消、立即运行、失败重试及运行历史。

## 到期执行与恢复

- 一次tick从数据库领取到期计划，行锁及唯一(schedule_id,scheduled_fire_at)保证并行扫描不重复派发。运行回执和next_fire_at在同事务提交。
- 回执使用稳定子任务身份，子任务仅one_time；重派、失败重试复用同一child，不重建重复任务。
- worker通过claim token、租约、心跳和CAS运行；过期运行可恢复，旧worker不能覆盖新worker状态。
- 抽样保存事务先锁定并校验运行租约，再写任务病历，防止失租worker迟到提交；进程内inflight集合抑制重复tick排队，Future结束或提交失败释放，跨进程仍以数据库领取为准。
- 复用现有TaskSamplingService及save_task_sample，成功必须有真实抽样持久化证据；异常保留失败回执，不伪装成完成。
- tick为可部署的one-shot命令，不把API lifespan中的计时线程宣称耐久调度。部署调用频率与非生产迁移另外验收。
