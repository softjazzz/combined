# 当前病历查看数据来源收口

## 已确认问题与范围

用户确认普通病历查看应使用当前 CDM，更新后重开即可看到新值，失败明确提示，历史质控保持不变。100052 本地登记时间有值但样本旧字段为空；旧 Bundle 文书47份，而当前六域组装50份。旧 Bundle 的结构刷新门槛无法识别正文更新。

本轮仅客户样本验证的「查看病历文书」只读入口。创建副本、结果对照、历史证据及质控执行继续原路径，避免改变旧任务语义。

## 方案选择与证据

1. 新增同步失效标记/数据版本平台：可缓存，但直接SQL修改绕过通知，且当前没有可靠完整的变更版本合同。
2. 每次打开按当前CDM现组装（采用）：复用 `_MaterialSnapshot` / `assemble_domain_bundle` / 文书投影，不读取持久化Bundle；无需刷新按钮、失效通知、迁移或额外digest。
3. 全局替换旧Bundle读取：会影响历史证据，拒绝。

100052只读实测六域现组装热加载0.059～0.062秒、50条SQL（含50份文书的来源表读取）；无共享物化时0.067秒、56条SQL。该收益支持先取消当前查看入口的持久化展示缓存。数据变化和组装版本变化均在下次打开自然生效，不靠TTL。

## 边界与文件

独立 `bundles/current_view.py` 隐藏当前读取、六域组装、入院时间投影与进行中请求合并。结束不保留缓存，后续请求必须重新读取；同进程并发同三元身份共享一次读取，返回深拷贝。已有assembly/emr_view保持组装算法和历史读取不变。新模块约80行不是搬迁拆分，而是独立当前查看职责，避免在巨型assembly/emr_view增加入口编排。

`emr_render.py` 为已有完整文书接口增加显式 `source_view=current`。默认 saved 不变；当前读取失败503，不回退旧Bundle，不写历史任务或持久化Bundle。当前模式仅full视图，summary/render历史对照不改。

前端只读控制器明确请求current，以同次响应 current_record.admission_time 构建顶部字段，不回退样本旧时间。入院时间复用既有纯函数extract_admission_anchor：登记优先、空时入院文书回退，冲突/都空不伪造，不用record_time。文书正文时间仍使用各文书字段。

## 验收

- 旧Bundle存在时，当前显示本地新正文和时间；SQL仅改正文不改update_time也能更新。
- 再次打开重新读取；并发同病例合并；错误之后能够重试。
- 登记优先/入院记录回退/缺失/身份隔离。
- 当前失败503，旧默认路由测试通过，历史数据未写入。
- 前端聚焦测试与真实100052页面验证；记录文书数和耗时。

## 限制

本轮不是所有页面全局迁移；不修改结果对照的summary/render。物化是请求级读取共享，非跨表事务快照；同步中的跨提交读取一致性不在此轮承诺。缺少可选源表按现有规则视为无资料，实际SQL失败明确拒绝返回旧文书。进程列元数据缓存需在数据库迁移后重启。大病历/多进程并发需后续真实测量，不以小病例证明整体性能。
