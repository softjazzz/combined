# 病历级材料快照实施计划

**Goal:** 新任务固定病历材料版本，Bundle、LX0609、补核及历史文书统一消费；目录状态/精度和只读预检不制造完整性。

**Architecture:** 在业务侧保存内容寻址、不可覆盖的病例材料文件及任务引用，不向任务items_json塞正文。短REPEATABLE READ只读事务一次捕获有界材料和既有受控读函数结果，事务结束后规则只回放捕获结果；来源绑定与材料指纹分别持有。历史无快照明确未留存，当前文书语义保持独立。

**Tech Stack:** Python3.10、SQLAlchemy、业务专属文件存储、PG原生一次性双库、Vue已有病历池。

基线998f7ac94，独立工作树D:/MedQC-worktrees/case-material-snapshots-20261104，分支codex/case-material-snapshots-20261104。不带入打包分支修改，不推送/合并/部署，不连接业务库或模型。

## 1. 不可变快照owner与保护测试
- 新增case_material_snapshot.py，规范化带类型值、内容指纹、任务引用、原子创建、校验及有界大小。
- 任务引用只允许新建，补核/失败重试读取同一原始任务引用，禁止重取当前材料冒充旧版本。
- ContextVar保存短事务连接和当前材料；底层读入口在固定材料存在时不得重新连接CDM。
- 新捕获使用病例三坐标、来源绑定、协议、投影、正文、文书ID、时间、状态、集合及查询完整性形成指纹；已有正确事实冻结继续使用原指纹。

## 2. 一次取材与实际执行入口
- Bundle表读和LX0609公共受控读函数使用共用短事务；捕获后回放，所有public源读取覆盖并拒绝未捕获查询。
- 组装当前文书的只读渲染结果也持久化，历史展示不再借用可变公共Bundle。
- worker在病例执行前绑定；模型、增量回写前结束源事务；取消/超限/损坏明确技术失败，不清除既有成功结果。
- 独立CDM初次捕获需要未过期的管理员受控窗口确认；这不是自动发布就绪协议，不解释epoch/operation为全接口完成。

## 3. Bundle复用与历史展示
- 缓存需同时匹配来源和当前材料指纹；CDM没有固定材料时不直接复用旧Bundle。
- job_id历史文书绑定任务材料，旧任务缺材料返回明确原因，禁止当前库补造。
- 原有源、三坐标权限、PDF业务库归属保留，业务写入owner不变。

## 4. 目录状态与日期精度
- 入院/出院精确时刻与日期分开，支持admission_date/discharge_date及精度元数据。
- 有出院日期可确认出院，无权威在院证据为unknown，不能用入院存在/出院空推断在院。
- 列表、筛选、计数和选样一致；未知状态不进入确认在院的任务范围。

## 5. 依赖合同与预检
- 从实际Bundle/规则源/展示读取维护固定表列依赖及显式诊断回退；不按可见表推断完整权限。
- 只读检查用pg_catalog定位、逐表SELECT核验，区分缺表/无权限/缺字段/空表；发布状态无证据明确unknown。
- API和独立DSH脚本共用合同，不自动授权、迁移或扩大临床投影。
