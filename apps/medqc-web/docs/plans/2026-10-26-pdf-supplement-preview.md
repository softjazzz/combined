# PDF 补全客户验证样本集实施方案

> **For Claude:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task.

**Goal:** 从 1022 的 27 例建立独立材料副本，按来源可追溯地补充客户授权 PDF；先提供只读逐例差异预览，确认范围后再开发和执行写入。

**Architecture:** 现有样本集不是病历版本隔离边界，Bundle 使用机构、患者、就诊三坐标。新集暂定“1026-PDF补全”，必须使用独立内部坐标和完整关系映射，不能让新集继续引用旧 CDM/Bundle 后再补原记录。本阶段只使用独立只读连接，在本地私有目录生成文书片段、对照及匿名汇总，不调用现有可能自愈写入的样本服务。

**Tech Stack:** Python 3.10、PyMuPDF、psycopg2、pytest；本地解析，不使用模型或云 OCR。

## 本轮执行：只读预览

文件：`scripts/qc/preview_pdf_supplement.py`，测试：`scripts/qc/tests/test_preview_pdf_supplement.py`。

1. 校验原盘点 manifest 与 ZIP 每个 PDF 的指纹；本地读取 1022 的持久样本三坐标，不能按姓名创建新匹配。
2. 单连接 `REPEATABLE READ READ ONLY`，短查询超时。仅显式读取 `qc` 样本表和 `cdm` 临床表；不加载应用、不执行建表或迁移。
3. 使用文字坐标顺序清除页面固定页眉、页脚，按明确标题与文书时间拆分跨页片段。未知标题、无法分界、身份不充分保留为待核对，不丢弃源片段。
4. 对比正文和已有分节内容，先找重复，再找内容对应；相同日期不足以证明同一份文书，不同日期也不足以证明新增。相似项只作候选，不能自动覆盖。
5. 输出匿名逐例统计、候选新增/补齐/重复/冲突/待确认清单；私有文件保留原 PDF、页码、正文和现库对应位置，均置于 `.tmp/0910-full-audit/*-private/`，不提交。
6. 本轮不提供 apply 开关、不创建新样本集、不刷新 Bundle、不运行质控。预览不是可直接执行的补数计划。

聚焦验证：人工合成 PDF 行覆盖跨页、页眉重复、历史日期不误分段、独立日期/标题、未知标题、分钟精度、签署不替代记录时间；正文精确重复、仅签名相似不误匹配、正文对应但记录时间冲突、原正文为空不误认为不存在；只读事务拒绝写入；真实 ZIP 页数守恒和 27 例清单完整。

6. 采用独立导入批次及逐例事务；数据提交后 Bundle 刷新失败需要单独重建，不重复插入；回退只撤销本批副本和附属产物，不能删除原数据。
7. 仅新坐标刷新运行、终末及领域 Bundle，核对“来源→新 PG→Bundle→规则输入”。材料变化必须使对应事实冻结失效，不能重用旧材料结论。
8. 验收旧 1022 和已有结果均不变、新集 27 例材料齐全、新旧坐标隔离、访问权限一致、普通业务池不含副本；不自动启动质控。

## 2026-10-26 细化预览：归类、正文排重及时间身份核对

增加离线脚本 `scripts/qc/refine_pdf_supplement.py`。输入上一阶段私有预览，原ZIP只用于核验未通过双标识的文件；没有数据库连接、写入、模型或 apply 入口。原始预览另用只读事务更新，排重范围扩至 CDM 内所有具备 `record_content` 的三坐标表，而非只查已归类表。

### 方法及界限

- 修正固定页脚“第(页码)页”的识别，且只在页面底部移除；明确标题时间行与页脚不算临床正文。剂量、小数点等不能作为格式噪声删除。
- 正文精确比较优先；包含及高相似只用于建议对应关系，多个旧记录使用相同正文时不按日期任选。小字段相同、签名相同或同一分钟均不足以认定同一文书。
- 只比较 JSON 的 `original_text`，不把元数据当正文。保留旧文书候选、来源PDF号、页码和内容指纹，另输出私有逐条CSV便于定位。
- 本机日常病程/上级查房的 `record_time`、`submit_datetime` 为 `timestamp without time zone`。只作明确标注的钟面比较；钟面不同列时间待核实，不能当作已确认时区冲突，更不能改写原时间。
- 相同正文但缺记录时间/明确签名，列为补字段候选；正文或非空字段不同，列为版本核对。所有候选均未获准写入。
