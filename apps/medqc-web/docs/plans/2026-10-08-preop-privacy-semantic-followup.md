# 术前脱敏与语义残留：离线修复边界

## 目标与顺序

先修复公共送模隐私器的已确认姓名格式遗漏，再处理 C12 暴露的抽取定义歧义。仅在 F 盘集成工作树实施；不调用真实模型、不写 PG、不改变既有冻结输入和原始响应。

## 方案

隐私部分复用正式 LX0609 执行入口的现有包装器。用人口学字段标签和有效性别值补齐姓名识别边界，保留姓名二次出现替换、医务人员姓名保护、JSON 可解析与幂等；不写入患者具体姓名、不以扩大中文匹配长度替代身份识别，不声称规则式处理能覆盖所有身份格式。通过实际 wrapper 捕获修复后的私有输入，原发送文件保持不动。

语义部分只澄清术前原子抽取 Prompt：完整核查后无内容与无法确定含义分开；签名和计划查看不等于术者已经查看患者；纯检查所见不自动等同医师当前术前诊断，但不要求固定栏目标题。Python 仍校验引用并按既有三态合同判定，不把 unknown 强改 missing，也不增加关键词式医学判定。

术前准备原有定义允许已完成或拟实施的检查与准备，继续保留。上一轮将计划性措辞单独列为问题过严，应核对其是否具体支持准备事实，而非要求所有准备已完成。医学争议不通过修改冻结答案解决。

## 验证与完成边界

先用合成反例证明隐私遗漏，再运行既有保护、变体、正式包装器和冻结输入离线回放。语义部分检查真实送模 Prompt 和输出合同，原 C12 unknown 响应仍应产生资料不足。离线测试不能证明模型在新 Prompt 下会判对；真实复验必须使用重新脱敏、重新冻结的输入，另记实际调用结果。本轮不追加外部调用。
