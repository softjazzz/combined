## 目标与边界

按手册补齐当前PG材料可支撑的检查；实际 `rule_id` 直接使用四段式，不增加永久编号映射。既有79条规则保留原判据。病案首页、编码、扣分分值不在本轮。目录接入不等于真实病例验收通过。

复用既有 `exam_lab`、`tumor_pathology`、`basic_timeliness` 执行族及同一证据会话。结构化关联、覆盖与最终判定由Python负责；正文内容仅在需要时受控提取原子事实。技术栈：Python、现有证据快照/RuleDecision、pytest、现有Vue规则目录消费接口。

## 已核实的数据边界

只读本地 `cdm` 的0910池30个唯一住院事件：影像主记录/报告各175条，培养相关报告14条，病理主记录10条/报告8条，抢救记录1条且有实质正文。数字是来源审计，不是临床缺陷数量。

- 影像主记录仅132条能用order_id关联本次住院医嘱；检验主记录order_id全空。不得用最近时间强行关联。
- 医嘱“新开”不证明已执行；未执行计划不能要求报告。报告缺失且执行/来源完整性不能确认时为资料不足。
- 病理两个主记录在本地CDM没有报告，但未核实源库，不能据此宣称临床漏报告。
- 拟诊讨论结构字段0/30、正文也空，诊断依据不得冒充拟诊讨论；该新增复制点暂不开发。
- 手术经过有14/15份实质正文，但术者、诊断、结束时间等字段全空；安全核查三阶段完整字段、输血单类型等尚未证实。不因“有表”直接上线完整性判定。

## 固定失败语义与验证

新规则交付仅允许合规、不合规、不适用、资料不足四态。来源不可用/覆盖未证明/模型输出不可验证不视为临床遗漏。完整范围内无触发事件才允许不适用；任何已证实缺陷不被其他事件的资料不足覆盖。每条保留逐事件依据和修改建议，前端不推断业务状态。

1. 每个实现先补聚焦回归，涵盖四态、多事件混合、重复键、歧义和失败隔离。
2. 使用同一输入、固定模型响应保护既有规则状态/原因/证据/调用量。
3. 使用只读PG快照逐例回放；区分固定响应、真实模型和源系统缺口。患者原文仅保存在 `.tmp/0910-full-audit/*-private.*`。
4. 主协调者检查关键diff、最终交付、目录选择与建议，再更新滚动清单并提交。未验证的规则不得写成已上线。

## 本轮实施结果

本轮已将以下四条规则接入正式规则目录、选择器、对应原生执行族、结果安全投影和客户展示：

- `LX0609-06-01-03`：CT/MRI 报告单完整性；
- `LX0609-06-03-02`：微生物培养报告单完整性；
- `LX0609-06-02-01`：病理报告单完整性；
- `LX0609-09-01-02`：抢救记录内容完整性。

其中前三条使用结构化来源和 Python 判定，不增加模型调用。抢救记录规则最多选择 8 份文书、合计 12000 字，单次受控调用只提取六类原子事实；Python 校验原文坐标、引文和带标签的抢救时间后再形成结果。来源不可用、范围不完整、关联不能证明或模型合同不可验证时统一返回资料不足，不生成临床缺陷。

`LX0609-06-01-01`（CT/MRI 医嘱与病程一致性）和 `LX0609-06-03-01`（培养医嘱与病程一致性）只进入规则总表并保持 `pending_definition`。当前 CDM 尚不能稳定证明检查已执行，培养主记录也缺少可靠医嘱关联键；在来源合同补齐前不得进入执行目录。

本轮未连接数据库、未调用真实模型，也未保存患者原文。受影响的 17 组单元测试共 1114 项全部通过，覆盖四态、多事件混合、重复业务键、缺失来源、模型失败隔离、安全投影和既有规则兼容。下一步需要在客户环境用 0910 样本或新的脱敏病例做真实来源回放，核对逐事件关联、资料不足比例、建议文本、调用量和耗时；真实回放完成前，代码完成不等同于客户验收完成。
