# LX0609 结果聚合器职责收口执行计划

> 2026-09-23：本文保留当时的整改范围与证据。当前引擎职责收敛任务以[新主计划](2026-09-23-lx0609-engine-boundary-refactor-master-plan.md)为接续入口；旧三位编号仅作为历史语境，不作为新运行身份。此说明不表示历史验收已全部完成。

## 决策

- 目标是消除结果聚合器的业务判断权，不以减少文件行数为目标。
- 执行顺序固定为：行为冻结、单规则族等价迁移、扩展成本验证。
- 不清理旧执行链，不修改数据库、API DTO 或前端结果合同。
- 技术失败、资料不足、语义不确定和不适用必须保持独立语义。

## 首个迁移规则族

选择 `basic_timeliness`：

- 规则：`LX0609-001/002/004/005/006`；
- 聚合器当前包含 26 处相关规则号引用；
- 同时覆盖结构化时限、资料缺口、不适用和 006 的受控语义补充；
- 已有本地权威时间、抢救事件和查房角色测试基础；
- 不依赖客户当前缺失的检查报告数据源。

未选择 `consultation_quality` 的原因：当前 020/023 对模型结构非法仍存在
`uncertain` 映射，与已批准的技术失败语义红线冲突。该问题必须作为独立行为修复，
不能混入首次行为等价迁移。

- `luxian_0609_result_aggregator.py`：6618 行；
- 近 90 天修改提交：105 个；

- 规则专属条件分支约 93 处；
- `safe_luxian_0609_customer_display_facts()`：第 491 至 4952 行。

### basic_timeliness 专属职责

迁移前必须冻结并逐项清除以下聚合器职责：

1. `001/002/004/005/006` 展示事实结构校验；
2. 时限事实的时间差、超时值和时间冲突复算；
3. `004` 抢救事件逐事件结构校验；
4. 时限客户结论的规则专属生成；
5. `004` 抢救记录及抢救医嘱证据生成；
6. `005/006` 查房文书证据来源选择；
7. 从 Reduced Decision 的 `fact_refs` 反查文书坐标时存在的规则专属来源过滤。

迁移后的“归零”只指上述业务职责和规则专属分支为零。通用排序、去重、结果装配、
Canonical Finalizer 调用可以继续保留。

## 证据职责

```text
规则执行器
  产生 RuleDecision、受控事实和 fact_refs

Decision Binding
  验证快照、允许来源和 fact_refs

公共证据投影职责
  将已验证 fact_refs 转换为文书 ID、字段路径和记录时间

Renderer
  根据已确定状态和受控事实组织客户文案

Aggregator
  装配、排序、去重和统计
```

首次迁移只移动现有投影算法，不改变证据选择口径，不给各执行器复制客户证据 DTO
拼装逻辑。

## 提交和验收

### 提交一：行为冻结

- 冻结五条规则的目录顺序；
- 冻结 `status`、`reason_code`、客户结论、受控事实和证据坐标；
- 只比较语义字段和来源定位，不断言具体 SHA；
- 冻结确定性路径 LLM 调用数和 Token 均为零；
- 冻结统一引擎启用时不进入兼容规则列表。

### 提交二：行为等价迁移

- 将完整的 basic_timeliness 展示事实校验和证据投影职责迁出聚合器；
- 保留 `aggregate_luxian_0609_results()` 公开入口；
- 不修改规则状态、原因码、客户文案和来源选择；
- 报告父文件、新模块和生产代码净行数变化。

### 提交三：扩展成本验证

- 使用一个结构化测试合同和一个受控语义测试合同验证现有扩展接口；
- 测试合同不得进入生产规则目录；
- 最终扩展能力结论仍需后续获批真实规则验证；
- 不允许为测试合同修改聚合器、保存、API DTO 或前端。

## 性能协议

- Stub 路径：调用次数、Prompt、输入 Token 和规范化 Canonical 结果一致；
- 真实模型路径：调用次数不增加，输入 Token 不增加；
- 输出 Token 允许自然波动；
- 相同环境预热后至少 10 次，比较中位耗时，回归阈值为 10%；
- 运行时字段、内部 trace、快照哈希和具体 `fact_refs` 哈希不参与普通语义断言。

## 停止条件

完成三个独立提交及对应验收报告后停止。其他规则族、旧链清理以及已发现的既有失败
语义问题均另立任务。
