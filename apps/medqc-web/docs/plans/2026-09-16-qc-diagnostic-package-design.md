# 质控诊断包入口设计

## 问题证据

- 批量质控任务已经保存执行状态、失败记录、规则进度和调试标识，但任务详情缺少稳定下载入口，排查人员只能临时查看页面或后台日志。
- 单病历完整结果页已有诊断包能力，运行病历与终末病历的复核预览没有入口，用户需要先进入更深层页面才能取得排障材料。
- 质控结果异常可能来自执行失败、模型输出校验、自动补跑或结果汇总。只保存页面截图无法区分这些阶段。

## 根因判断

现有数据链路可以支持排障，主要缺口是入口与安全导出边界。批量任务缺少一个只读取既有任务详情和调试快照的脱敏导出器；复核预览缺少对既有单病历诊断组件的复用。

## 实施方案

1. 在批量任务详情工具栏增加“下载质控诊断包”。运行中、失败和已完成任务均可使用。
2. 下载时刷新一次客户安全调试快照，导出任务状态、计数、失败阶段、原因码、规则执行状态、重试摘要和 trace ID。
3. 病历身份转换为包内临时别名；采用字段白名单，不写入病历原文、患者姓名、模型提示词、原始响应或访问凭证。
4. 在运行病历和终末病历共用的复核预览中复用 `QcDiagnosticExport`，保留现有“先预览脱敏摘要、确认后下载；必要时重新质控采集完整排障包”的流程。
5. 将原“诊断导包”统一命名为“质控诊断包”，使用轻量归档图标和次级按钮样式，与“查看完整质控结果”形成清晰主次关系。

## 文件范围与拆分判断

- 新增 `batchJobDiagnosticExport.ts`，完整负责批量任务诊断字段白名单、身份别名、凭证清理、文本结构和文件名。
- 批量任务抽屉及其控制器只增加触发和下载胶水代码。
- 单病历复核预览只保存已经加载的结果并组装诊断上下文；实际导出和排障采集继续由既有 `QcDiagnosticExport.vue` 负责。

`SemanticRulesBatchResultDrawer.vue` 与控制器已经超过巨型文件预警线。本次职责可以形成独立、可测试的导出模块，因此没有继续把诊断数据组装逻辑写入巨型文件。公开接口和后端契约不变。

## 验收指标

- 失败任务仍显示批量诊断包入口，并能生成 Markdown 文件。
- 导出内容包含失败原因码、失败阶段和 trace ID。
- 导出内容不包含测试样本中的患者姓名、就诊号、访问凭证、病历原文、模型原始提示词或响应。
- 单病历结果可用时显示“质控诊断包”，不安全状态和未运行状态不显示。
- 运行病历与终末病历共享同一实现，不新增接口分支。

## 剩余风险

- 批量包使用任务接口当前保留的数据；若后台已经清理某项执行明细，前端无法恢复该历史信息。
- 完整执行排障包可能包含医疗正文，仍需使用现有二次确认和人工复核流程；默认摘要包保持脱敏。
