## 实际断点与修改

1. 人工报表原来只有统计明细，没有进入现有整改弹窗的入口。仅在“已审核通过、来源已核验、完整三坐标及结果引用、运行/终末”的明细中挂接现有 `CaseRectificationCreate`；不新建页面，不复制整改状态机。
2. 人工报表的 `_source` 已核实冻结来源，但 API 原来不返回派发需要的 job/Envelope。现在额外搬运该同一来源的 `root_job_id/envelope_id`，来源无法核验时返回 NULL；不补猜当前任务或新轮结果。CSV 原有列和统计口径不变。
3. 派发弹窗原先只对自动缺陷校验所选信封，人工缺陷只筛 ID。现两种已指定目标均精确比较 job 和信封；缺引用、候选变更或换轮不能静默选择其他目标。服务端原有来源复核和重复派发约束不变。
4. 创建及嵌套整改动作成功后复用上一批的成功事件，重读人工报表原筛选/页码，并刷新同页工作分析；审核、整改、任务处理状态仍独立。

后端仅新增两项响应字段，不改读取规则、持久结构或旧迁移。旧 API 消费者可忽略新增字段；本批前端对缺失/损坏引用失败关闭，需要与本批后端共同交付，不能把旧响应当成可派发来源。
