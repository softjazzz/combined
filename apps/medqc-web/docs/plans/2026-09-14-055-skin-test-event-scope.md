# LX0609-055 皮试事件范围修复

## 问题证据与根因

0910 样本 C01、C02、C14 的正式 Bundle 医嘱均含 `drug_apply_method=皮试`，当前 055 结果的 `event_windows` 实际消费了这些医嘱。聚焦测试 `test_055_excludes_skin_test_order_from_treatment_event_windows` 在同一输入中放入皮试医嘱、真实静滴医嘱及静滴后 48 小时评价；修复前稳定得到 `non_compliant`，预期为仅保留静滴事件并判 `compliant`。

根因已由当前调用链验证：`native_extended_document_execution.py::_antimicrobial_orders` 只按抗菌药名筛选，055 随后为全部筛中医嘱建立评价窗口，没有排除非治疗性的皮试医嘱。错误发生在 055 事件范围，不在 Renderer、Finalizer 或结果映射。

## 最小方案和文件范围

- 在 `backend/app/services/luxian_0609/native_extended_document_execution.py` 增加 055 私有的治疗医嘱过滤，仅排除当前真实样本已证明的 `drug_apply_method=皮试`。
- 只把过滤结果交给 055 的空触发判断和事件建窗；054、057、058 继续使用原始抗菌医嘱集合。
- 在 `backend/tests/unit/test_luxian_0609_native_extended_document_execution.py` 固化混合输入，断言皮试不进入药名及事件窗口，同时真实治疗及评价仍保留。
- 用现有只读 0910 Bundle 回放 C01、C02、C14，核对皮试事件消失，并记录剩余治疗事件与终态。台账只在真实病例结果复核后更新。

生产文件超过 2000 行。本次不新增独立模块：过滤是 055 建窗入口的单字段事件资格判断，仅新增少量私有代码且没有第二个调用方；拆成模块会形成不足 250 行的转发边界，既不迁出完整职责，也不消除重复所有者。窗口计算和状态映射保持原位，本次不拆分文件、不改变公开接口。

## 验收指标与保护集合

- 新聚焦测试修复前红、修复后绿；既有 055 聚焦测试全部通过。
- C01、C02、C14 的 055 `event_windows` 不再出现皮试医嘱对应药物；真实治疗医嘱不得被误删。
- 状态、原因、事实引用仍由规则执行器单点产生，后续层不改写。
- LLM 调用数和 Token 不增加；本修复为确定性过滤。
- 保护集合为提交 `616f6e732` 时台账内全部“聚焦验收通过”“已关闭”“已关闭：复核通过”记录，以及本次 C01/C02/C14 的原始回放产物。055 的实际给药时间与评价关联仍是后续独立缺口，本任务不据皮试修复提前关闭这三项。

## 剩余风险

当前证据只支持精确的“皮试”途径值；不凭空增加“试敏”等同义值。055 仍以计划开始时间或医嘱下达时间代理实际执行时间，该合同冲突不混入本次最小修复。去掉皮试后，病例可能因其它治疗事件、评价关联或实际时间证据继续保持不合规或资料不足，这不表示本修复失败。

独立审查曾提出：纯皮试负向结论仍有一个 `fact_ref`，可能表示皮试行被消费。主协调反查 `_fact_refs` 后确认该值来自 `SourceObservation.snapshot_ref`，是证明 `inpat_drug_order` 来源完整读取的源级快照哈希，不是皮试行的逐文书引用；客户展示和客户证据均为空。测试已增加精确断言保留这一负向证据合同，未按错误假设删除来源完整性锚点。
