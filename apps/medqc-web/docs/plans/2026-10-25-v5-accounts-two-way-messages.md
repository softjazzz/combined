# V5 真实账号与双向消息实施计划

**Goal:** 复用现有 sys_users 与 qc.notifications，补齐管理员维护真实账号和医生回传到质控端的消息闭环。

**Architecture:** 管理接口只接受可信持久管理员，沿用 sys/public owner 解析；用户 ID 不变，机构、科室、角色由管理员维护。业务操作与通知同事务提交，消息列表、计数、已读、下钻再次核验持久账号及业务对象。沿用 V5 系统配置和统一消息面板，不新增聊天系统或 SSO。

**Tech Stack:** FastAPI、SQLAlchemy、Vue 3、V7.1 mq 组件、pytest、Vitest。

**本批交付:** 独立适配分支，起点 `3b9d67096`。代码及隔离合成验收完成；不是医院真实账号导入、业务库部署或全站权限改造。

## 约束与口径

- 只在独立适配分支开发；不推送、不合并、不写业务库。核心制度保持阻塞，80 项台账不因本批自动增计。
- 账号创建必须包含唯一用户名、邮箱、初始口令、显示名、机构、科室和明确角色；口令只保存哈希，不在响应或日志中返回。
- 维护支持查询、创建、修改角色/机构/科室及停用/启用，不物理删除历史账号；不允许管理员修改自身授权范围或停用自身。
- 编辑携带 updated_at 防止覆盖他人修改；失败不回退内存或模拟用户。
- 注册不得获取质控/管理员角色，个人资料不得自行变更科室授权。
- 医生提交/重提整改通知有效派发人；不可用则通知同机构有效质控主管。申诉提交/撤回通知同机构具审核权限的账号。无合法收件人时拒绝整笔操作，不静默丢失提醒。
- 消息已读不等于业务完成；支持旧历史、同院同科不同医生及跨机构反例。V7.1 既有保护集保留。

## 实现与入口

- V5 `系统配置 → 账号管理`，可直达 `/workstation-v5/system-config?tab=accounts`。只对管理员显示；后台再次检查持久管理员，不相信令牌传来的角色或演示账号。
- `/api/v1/account-management` 复用实际可见的 sys/public 账号 owner。支持真实列表、搜索、角色/状态筛选、分页、创建、修改绑定及启停；不物理删除，不修改用户名/邮箱/ID，不返回口令哈希。
- 已绑定机构的管理员只维护本机构；未绑定机构的持久管理员是全局维护者。创建四类业务角色，已有同步等专用角色拒绝覆盖，不能停用或修改自己的角色/范围。
- 账号维护写事务串行锁配合行锁及 updated_at 校验；登录更新过账号时间戳后，需刷新再维护，不能绕过409。
- 登录和令牌解析统一实际账号 owner；持久账号不存在、停用或数据库故障时，不回退到内存里的同名演示身份。注册不能选择质控/管理员角色；个人资料接口不能自行更改科室授权。口令及令牌调试输出脱敏，验证失败日志不含原始输入。
- 整改提交/重提通知有效原派发人；原派发人不可用则转同机构有效主管。申诉提交/撤回优先通知有审核权的原派发人，否则通知同机构有效主管；不会投给无申诉审核权的普通质控员。找不到合法收件人时整笔操作拒绝，通知失败事务回滚。
- `v5_qc_feedback` 与既有医生反馈来源分别校验，列表、概览、未读、单条及全部已读共用账号/机构/对象条件。复用原统一消息面板和整改/申诉精确下钻；已读不替代业务完成。
- 原共享外壳、图标、Token、助手面板和18文件保护集原样保留。系统配置仅追加页签与局部响应式布局；账号表格和弹窗使用V7.1公共类。
