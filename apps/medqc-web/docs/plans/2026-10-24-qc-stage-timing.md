# 单病历阶段计时与扩展文书调度

独立分支：`codex/qc-stage-timing-20261024`。不改集成分支、模型配置、规则族/HTTP 并发配置；不调用模型、不写业务库、不重跑27份。

## 设计与验证边界

1. 用请求内、线程安全的单调时钟收集器记录真实阶段，不从 Token 或平均分摊耗时推断。
2. 区分 Bundle 读取、证据快照、规则族排队与执行、HTTP 线程/槽位等待与请求、结果装配及写回。嵌套阶段和并行调用的累计时间不能相加当作墙钟时间。
3. 沿既有任务性能摘要保存安全阶段统计，白名单投影保持字段；最终提交耗时只能在返回后观测，使用脱敏终态日志保存，不能在提交前伪造完整计时。
4. 扩展文书只拆为抗菌药组和其他文书组。抗菌药理由/疗效/专家支持仍在同一所有者内共享事实；其他文书保留原有顺序。两组消费同一不可变证据会话，只让独立工作重叠，不提前触发原来不会调用的模型。
5. 合并时按原规则顺序恢复决策与展示事实，调用量/Token 按抽取结果归因求和；异常或取消必须清理兄弟任务。
6. 用固定应答/合成材料检查串并行状态、原因、事实、证据和用量等价，受控门闩证明实际重叠；测试超时/取消无遗留任务，HTTP 槽位不变；使用假时钟验证阶段边界及投影。

先跑新增及直接相关测试；不运行全量前后端检查，不以替身计时推算真实模型提速比例。

## 实现

- `core/execution_timing.py` 使用请求内 ContextVar、单调时钟与线程安全聚合；共享 HTTP 线程继承计时上下文，排队从提交开始，请求从拿到槽位开始。规则族排队和执行分别计时，独立文书组另有单位统计。
- 读取、证据快照、结果装配、进度/结果写回及最终保存接入真实所有者边界。最终保存前的 `summary.performance_profile.stage_timing` 明确为 `complete=false/before_final_save`；包含最终保存的脱敏 `qc_stage_timing` 日志在 worker 返回后输出。不额外更新数据库，不需要迁移。取消 await 后仍在途的阻塞 HTTP 计入 `pending_http_calls`，不声称观测已完整结束。
- 自动补跑等待和递归下一轮不计入上一轮墙钟；每轮收集器独立。保留旧性能字段的兼容值，同时标记 `allocated_or_reported_metadata` 和 `slow_rule_ranking_is_measured=false`，真实瓶颈应读取阶段统计，不能依赖旧慢规则平均分摊排名。
- 抗菌药组和其他文书组有限重叠。没有修改8/4规则族预算、HTTP预算、模型或提示词；抗菌药共享理由仍只抽取一次，组内原有步骤不变。结果按原选中规则的目录顺序装配，用量按抽取结果累计。
