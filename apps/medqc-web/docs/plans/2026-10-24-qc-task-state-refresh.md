# 质控失败状态与结果刷新 Implementation Plan

**Goal:** 运行、终末及样本结果页面按后台真实重试状态展示，任务部分失败后刷新已保存结果。

**Architecture:** 复用 batchJobStatus 的活动态判定，新增统一重试说明及终态判定；轮询 owner 在确认后台终态后发出 results-updated，completed 仍只表示成功。只调整前端搬运与展示，不修改后台重试策略、临床状态、资料或结果。

**Tech Stack:** Vue 3、TypeScript、Vitest、Vue Test Utils。

## 范围

- 独立分支 codex/qc-task-state-refresh-20261024，起点 b2bcae273；不改集成分支。
- 原有 index.prebuilt.css 改动排除；不调用模型、不重跑病历、不写业务库。
- 现有 API summary.automatic_failed_rule_retry 是自动重试状态来源；缺失、未知、明确停止时不承诺自动重试。

## 实施与验收

1. 在 QcRunSelectedControl 和实际结果抽屉补固定应答测试：部分失败、取消、自动补跑排队/执行、不可重试、次数耗尽、缺失/未知状态；先确认测试复现原问题。
2. 统一 batchJobStatus 展示和终态判定；等待自动补跑期间继续轮询，只有后台终态触发结果刷新；请求失败不冒充任务终态。
3. 运行/终末父页面及病历池状态条接收 results-updated；保留成功事件兼容，避免重复刷新。
4. 结果抽屉和状态条使用同一后台重试说明，保留成功项与失败项数量，不改临床结论。
5. 顺序执行定向组件/状态测试、改动文件只读 ESLint、编码检查；资源允许时做类型检查，不运行全量测试。记录实际验证和未执行项。

## 完成与验证

- QcRunSelectedControl 复用后台活动态判断；failed 首轮仍有明确 queued/running 自动补跑计划时继续轮询并禁用重复提交。后台终态发出 results-updated，运行/终末父页面刷新列表和预览并清理旧选择；completed 只在全部成功时发出，不重复触发刷新。
- 状态条、样本任务摘要及结果抽屉共用后台重试说明，区分排队、执行、次数耗尽、不适合补跑和计划未确认。成功或取消不受遗留重试元数据影响，读取失败不冒充任务终态；未知重试状态不承诺自动重试。全失败且补跑耗尽时不声称存在有效结果。
- 修改前的定向固定应答测试实际复现未发刷新事件、自动补跑中提前停止和抽屉固定承诺重试。最终六个相关文件104项通过，使用mock任务应答和定时器；两个父页面的刷新实际检查列表请求、预览刷新键和旧选择清理，不只验证子组件事件。
- 改动文件的只读 ESLint 零错误，已有风格警告未批量修复；保留V7.1模板与样式，不夹带全文件格式变更。全项目vue-tsc在1536MiB堆限制下内存不足，未完成；继承原tsconfig、包含全部改动源码/测试及原声明文件的定向vue-tsc检查通过。未运行全量单元测试。
- 本次不改后端重试策略、数据库、临床判定或历史质控结果；没有模型调用或27例重跑，没有打包、切换运行服务或操作集成分支。原生成CSS保持未暂存。
- 固定应答日志及定向类型检查配置位于忽略目录 .tmp/qc-task-state-refresh-20261024/，不提交。
