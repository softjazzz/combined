# Ubuntu22/Python310/PG16离线部署实施计划

**Goal:** 交付可离线安装的服务器依赖、前后端与80端口部署脚本，不影响同步和模型服务。

**Architecture:** 从07e62500b业务读取相同的0d3c17c44独立分支构建；Ubuntu22 runner生成完整wheelhouse、PG16便携客户端和独立启动脚本。新建业务库，默认仅展示1026；独立CDM尚未接入。使用独立venv及systemd账号，后端回环8001，前端80；端口占用则拒绝，不停止已有服务。

**Tech Stack:** Ubuntu22.04 x86_64、CPython3.10、PostgreSQL16、GitHub隔离runner。

## 步骤
1. 首先解析当前requirements并收集wheel，不以手工拼包替代完整解析。解析失败先修复冲突并记录。
2. 在断网命名空间中全新venv安装，pip check、模块导入、PG16迁移及合成账号/结果读取验证。
3. 收口服务器启动所必需的演示种子和无后台恢复启动边界，保留生产默认账号保护与PG持久认证，不修改医学判断。
4. 生成独立目录安装脚本、systemd服务、配置模板、建库/迁移/备份命令及回滚说明。脚本不直接操作Docker、同步库、模型或防火墙。
5. 构建、校验和下载交付物；患者材料和激活私钥不上传CI、不打入依赖包。

## 验收边界
不启动本机Docker；本机WSL丢失VHD，使用Ubuntu22.04 Actions环境。网络仅用于构建取依赖，安装/业务冒烟必须断网。测试只用合成数据库和固定响应，不调用模型；服务器安装由DSH另行执行。
