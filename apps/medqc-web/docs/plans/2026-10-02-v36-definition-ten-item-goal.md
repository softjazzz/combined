## 每项实施步骤

1. 读本工作树AGENTS.md与对应UI技能；检查工作区干净、当前分支和基线，不覆盖他人工作。
2. 只追踪本ID必需调用链，用一份清单标明已经具备/缺失动作；已具备能力保留，不重新实现。
3. 对真实缺口先补聚焦反例，复现失败；权限反例包括跨机构、非本人、状态过期、重复或迟到提交。
4. 最小修改接现有owner，运行聚焦pytest/Vitest及相关Ruff/ESLint。无DBURL下仅运行明确无真实库副作用的单元测试。
5. UI保持浅色工作台风格，列表、统计、分页、导出同筛选；未知状态不当0或成功；复杂动作放抽屉/弹窗。
6. 报告实际修改文件、测试命令/结果和未验证边界，中文小提交，仅暂存本线文件。
7. 主协调独立阅读关键diff、检查请求/状态/权限/调用量，选择提交集成到主线，再跑跨线聚焦回归。

## 验证与调度

- 轻量聚焦测试按线运行，重型全量Vitest、类型检查和全量ESLint由主协调集中，避免四工作树同时占满内存。
- Python：`python -m pytest <本项unit文件> -q`，`python -m ruff check <修改Python文件>`。具体文件由真实调用链决定后记录，不能运行会默认接业务库的脚本。
- 前端：`npx vitest run <本项spec> --maxWorkers=1 --minWorkers=1`；提交前编码检查和只读ESLint，主线统一`npm run type-check`及有条件的全量单worker单测。资源失败如实记录，不改超时/跳过/CI门禁。
- 四线各1-2个业务点一批提交，C线48/49后再50/51。空出槽位即启动D，禁止将“排队”报成“并发运行”。
- 每项保留四层：代码、本地/非生产验证、业务库部署、真实病例/浏览器。Goal代码收口不等于生产部署验收，不借旧隔离库授权写本批数据。
