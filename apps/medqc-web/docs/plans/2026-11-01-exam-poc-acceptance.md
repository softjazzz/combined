# 06-01-04 POC 验收补齐 Implementation Plan

> **For Claude:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task.

**Goal:** 复用既有六份合成应答，分别验收分类、事件引用、冲突、覆盖和升级，并经原正式结果链离线保存读取。

**Architecture:** 只增加实验验收与测试代码。专项核验仍由原解析器校验，医学结论仍由原 Native 执行器产生，经 Binding、Finalizer、Aggregator 和内存 SQLite 保存读取。分类期望与最终状态分别比较，Flash 不是金标准。

**Tech Stack:** Python 3.10、pytest、现有严格 OfflineIsolation、MockTransport、SQLAlchemy 内存 SQLite。

## 完成情况与证据

### 1. 验收字段

`scripts/exam_poc_acceptance.py` 使用真实专项解析器，单独保留六种原始分类、事件位置、内部事件引用、正式材料引用、源检查 ID、源文书 ID、引文、报告片段、记录引用、冲突引用、覆盖及输入截断标记。细分类期望来自合成材料，不以 Flash 应答作金标准。

请求归属按 case、arm、attempt 核对；旧报告仅允许既有案例顺序并按各 arm 的实际请求数分段，错序、漏项、多余应答、模型不符或显式归属不符均拒绝。协议重试与模型升级分别记录，协议失败原因再细化到漏项、错误事件、错误引用等。未来真实 POC 脚本也输出细项，并在分类待复核时返回验收未完全通过（退出码 3），不再只凭 recorded 布尔值返回通过。

### 2. 既有六份应答回放

输入为此前 `bailian-exam-poc-20261101T071228Z-private.json`，原始文件不改写。通过真实客户端、ASGI Gateway、MockTransport、Native 主抽取/专项核验、Binding、Finalizer、Aggregator、Canonical 内存 SQLite 保存与读取。没有真实 HTTP 请求。

原 POC 只录制专项应答，主抽取使用明确标注的固定“已记录”夹具。这刻意检验专项负面结论能否纠正主抽取。原材料没有评价截止时间，不从测试 Snapshot 的创建时间或其他字段推断一个上界。

| 合成材料 | 原始上下文：双模型均为 | 显式增加合成成熟上界：双模型均为 |
| --- | --- | --- |
| 本次结果的不同措辞记录 | compliant | compliant |
| 只有检查计划 | data_gap | non_compliant |
| 只有既往院外结果 | data_gap | non_compliant |

合计 12 次离线结果链保存读取：4 合规、4 资料不足、4 不合规。每个上下文内两臂的事件事实、冲突、最终状态、原因、展示事实和证据一致；热冻结均为零调用。客户投影将 `customer_evidence` 转为 `evidence` 并 HMAC 化来源，测试核对转换后的原文片段、时间、顺序和条数，没有放宽定位合同。

细分类仍有 1 处差异：院外既往场景 Flash 为 `other_exam`，35B 为 `none`；两者本次结果记录方向一致，分类差异保留人工复核标记。六份原应答没有发生升级，不能写成“真实升级成功”。

回放产物仅留在忽略目录：`backend/.tmp/bailian-exam-poc/acceptance-20261101-v2-private.json`，不提交原应答/产物。

### 3. 固定保护集

- 矛盾、左右侧、仅提及报告：专项分类及冲突经原正式链保存读取；矛盾仍按原合同提示，不另造医学状态。
- 重复相似检查：逐配对核对两个事件、各自源检查 ID 和两份文书，不能合成一个无身份 PASS。
- 既往检查被错误归为已记录：构造格式和引文都合法的错误应答，验收期望能标出语义差异；同时明确现有路由不会自动发现此错误，测试通过不表示模型质量通过。
- 长文尾部：超过既有 6000 字投影限制时不交候选模型，保留 `input_projection_limit`；验收显示输入不完整，不能用局部否定宣称全文核验完成。旧参考路径的输入限制仍是后续质量验收事项，本次不改 Prompt。
- 漏项、错误事件、错误引文、截断：候选拒绝后仍使用原始输入升级，复用原调用预算；升级再次失败保留专项不完整，整族结果不冻结。下一次离线执行仍发起固定请求，不复用失败冻结。
- 专项失败沿用既有主抽取事实的合同未变，不承诺全部变技术错误或资料不足；测试固定主抽取为 absent，核对其没有被失败专项覆盖。
- 升级 HTTP 错误、超时、取消：不接纳被拒候选；超时未知在途保留原 Gateway 隔离，不为测试清槽。原集合还覆盖预算不足、候选技术失败不自动升级、局部覆盖及跨分区冻结。
- 一份额外固定升级夹具走完整保存链，细化“漏项→升级→有效负面结论”的原因；这不是新增真实升级调用。
