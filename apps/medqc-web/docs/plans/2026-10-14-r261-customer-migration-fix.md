# R26.1 客户数据库迁移兼容修复

客户升级从 `20260915_000044` 到 `20261006_000047` 时失败，事务回滚到原版本。已成功生成客户机备份。客户只读查询确认只有 `public.visit_index`，三个同步字段均已存在且满足迁移合同；配置为拆分模式、`public,qc,sys,cdm,legacy` 搜索路径。

根因是 47 号迁移按拆分模式写死 `qc.visit_index`，而运行时按搜索路径解析该表。修复让迁移在当前事务设置应用的 `DB_SEARCH_PATH`，按 `to_regclass` 找到实际普通表或分区表，再执行原有字段类型、空值和默认值校验及缺列补齐。保留严格校验及自动降级禁止，不搬表、不建同名空表、不修改旧业务字段或行；45、46 号迁移仍按拆分模式创建 qc 表。

新增客户 public 表与自定义 schema 回归，修复前复现缺少 qc 表错误；修复后迁移及验收启动测试 109 项通过，Ruff 通过。补丁包只含修复后的 47 号迁移文件，旧交付 ZIP 保持不变。客户需应用补丁后重新执行正常 Alembic 升级，不能 stamp 跳过。

这是本地测试与补丁交付记录，尚未收到客户修复后升级成功的输出。未连接客户库或本地业务库执行迁移。
