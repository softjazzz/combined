# V3.6 任务内病例级重新质控合同（PRD 36）

## 1. 原文与现状缺口

- PRD 矩阵第 36 项要求“我收到的任务：重新质控”，包括单份或多份病例重新质控、查看进度和结果。
- 修改前，任务抽屉只有整范围“启动/重新质控”按钮，病例行只有查看本次结果和人工处理入口（`src/components/qc/TaskDetailDrawer.vue`）；`POST /api/v1/tasks/{task_id}/qc-runs` 也不接收病例集合（`backend/app/routers/tasks.py`）。
- 已有运行关联、job 进度和指定 run 的单病例结果读取可以复用；job 完成不等于任务病历人工处理完成，后者仍由 `task_record_completion_service.py` 独立写入。

## 2. 接口与范围

- `POST /api/v1/tasks/{task_id}/qc-runs?scope=all|assigned`
  - 无请求体：保持既有整范围运行。
  - 可选请求体：`{"task_record_ids": ["<UUID>", ...]}`，1–500 个，不接受重复、额外字段或非 UUID。
- `assigned`：运行人只能选择当前仍分配给自己的任务病历；服务端按任务关联和三坐标再次收窄，前端选择不是授权依据。
- `all`：任务创建人或 `admin` 可运行；管理员资格在 API 入口校验，并冻结进 job 过滤快照供 worker 二次核验。
- 选择集合只允许收窄既有 `run_scope`，不能新增病例或用旧病历号代替任务关联 UUID。

## 3. 并发、同步与结果

- 沿用任务行锁和全任务串行策略：该任务最新 job 处于排队、运行或未知状态时，新整批或病例级运行统一返回 409。相同病例重复、交叉子集和整批/子集竞争均不并发执行。
- 运行/终末远端范围任务仍要求最新同步快照的任务、场景及全任务三坐标与当前抽样完全一致；但逐例 `ready` 回执和 Bundle 版本/更新时间只要求覆盖本轮病例。无关病例同步失败不阻断合法子集，整范围运行仍自然要求全部病例成功。
- 运行历史由 `task_qc_runs` 回读身份，并从对应 workspace job 的冻结 `record_refs` 投影“整范围/所选 N 份”；job 不可读时显示“运行范围未知”，不伪造数量。
- 抽屉打开或显式刷新运行历史时，每个历史 run 最多读取一次对应 job 以投影范围；运行进度刷新只读取当前选中的一个 job，不重复轮询整段历史。当前没有自动轮询历史，避免随历史数量放大持续调用。
- 进度和成功/失败数只读取本轮 workspace job。单病例结果必须同时匹配 task、run、job、规则集与该 run 的冻结三坐标；病例不在本轮集合时返回 404“本次运行未包含该病历”，不回退到旧结果。
- job 完成只表示质控运行结束，不修改 `qc_task_records.status/completed_at/completed_run_number`；受领人仍须在结果完整后显式完成人工处理。

## 4. 前端交互

- 病历行提供“重新质控”，表格复选框支持多选后“重新质控所选”。不可执行或不属于当前受领人的行不可选择。
- 运行期间沿用现有禁用和 409 提示；历史行展示本轮范围，作业区展示本轮 job 进度，结果区只展示所选 run 的结果。
- 404“本次运行未包含该病历”只显示在该病例结果区，不影响任务详情、运行历史或其他病例结果。

## 5. 验收边界

- 不新增迁移，不改终末口径 B，不重写质控引擎，不写业务库或隔离库，不进行 LLM 外呼。
