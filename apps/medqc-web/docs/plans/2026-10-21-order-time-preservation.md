# 医嘱时间字段保存与规则读取定向补齐

## 范围与验收

仅在 `codex/safe-source-sync-20261021` 实现，不修改集成工作树、真实数据库、同步配置或运行服务，不调用模型，不重跑27例。

已有 ORM 及 `20261016_000049` 迁移包含计划结束、审核、执行、撤销时间，无需新增或执行迁移。此次补齐两张住院医嘱表的保存检查及规则白名单，保留字段独立含义，不把计划结束时间改名为实际停药时间。

## 实现步骤

1. 在真实 UPSERT 参数捕获和真实 native/snapshot SQL 选择处补回归测试，先复现有值时间被旧表结构过滤、药品及非药品读取遗漏的问题。
2. 药品补计划结束时间的既有同义字段映射；源端四个时间有值而目标列缺失时，在删除旧快照或写入前指出需要升级，不自动改库；源端空值允许旧结构继续读取。
3. native 与 snapshot 医嘱字段白名单保留计划开始、计划结束、审核、执行、撤销时间；仍只选择真实存在的列，不改变停药、撤销、实际执行及疗效起算的业务判定。
4. 用用户提供的 C17、C22 源端两条医嘱时间、状态结果，配合已冻结的对应源行做内存重放：homology 适配 → 实际 UPSERT 参数 → 实际 native/snapshot 读取。用户提供的补充值与旧冻结值分开标记，不冒称完整新源快照。
5. 跑相关同步、迁移 SQL 编译、证据读取及抗菌药时间回归；编码、Lint 等按资源完成。私有产物保留逐字段预期与实际、调用数和连接数，报告只证明保存和读取通路，不声称医疗结论或实际停药时间已验收。

## 隔离要求

新工作树不复制真实 `.env`，验证用模拟会话和禁止网络连接的离线执行器；不连接本机或医院 PG。复用原工作树冻结资料仅只读，不写回。现有 homology 总开关、快照替换策略及来源覆盖风险均不在此次改动范围内；不得因此建议启用整体切源。
