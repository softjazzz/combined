### R07 机制一根因确认：别名空间与候选下发不一致

进一步在越界分支采集模型返回的**原始别名**与“本条允许别名集合”，根因已经确定，并且不是定向复核缺失——定向复核路径早已存在（首轮低信心建议会用同一提示重问一次），而是**提示合同的别名空间本身不自洽**。

`_execution_prompt` 的别名按**全量候选**编号（`alias_by_ref` 由 `enumerate(candidates)` 生成），而 payload 里的 `candidate_documents` 只渲染各建议允许集合的并集，`allowed_candidate_refs` 因此是这套全局编号里的**稀疏子集**。实测证据如下（`allowed`为本条允许别名）：

| ------ | ------------------------ | ------------------ |
| C25 r1 | c13、c14、c7             | c6；以及 c3        |
| C26 r2 | c3、c4、c7               | c6                 |
| C26 r3 | c2、c215、c25、c26       | c1                 |
| C08 r2 | 12 个含 c2、c3、c10、c30 | c8、c9             |
| C04 r1 | 含 c2、c10、c11、c12     | 结构化字段返回 c69 |
| C11 r1 | c1、c3                   | 结构化字段返回 c53 |
| C21 r1 | 空集                     | c1                 |

这些别名在全局编号里都是合法候选，但不在本条建议的允许子集内，因此解析器只能按违约拒绝并降级为`unknown`；三次录制分别得到16、11、18条`unknown`，其中越界引用占13、10、15条。定向复核用的仍是同一套提示与别名（提交里复核入口复用`_execution_prompt`），所以重问会重复同一违约，无法收敛。

结论：修复方向不是继续加语义判断，而是让**别名空间与下发的候选一致**——把别名在“本次实际渲染的候选集合”上重新稠密编号，并把同一份别名映射从`_execution_prompt`传给`_parse_executions`，使提示与解析共用一套编号；逐建议范围校验保持不变，跨建议引用仍按违约失败关闭，不得因为改编号而放宽。验收要求：提示合同单测（允许集合与渲染集合一致、别名连续）+同输入A／B+30例聚焦回归。

### R07 机制二实验结论：未来计划判定不足以修复剩余记录

按“未来计划不算执行痕迹”实现候选守卫：对模型自选的执行痕迹原文做确定性核对，出现明确未来时点标记且候选原文没有任何明确完成或动作变更时，按“没有执行痕迹”处理。该守卫落在模型自选的候选上，不做跨文书推断。
