# V3.6 单任务分析合同

> 对应 PRD #43“全部任务”的任务分析子能力。本文只定义任务维度只读聚合，不改变任务执行、质控结果或病历处理完成的权威所有者。

## 权限与数据顺序

- 接口为 `GET /api/v1/quality-reports/tasks/{task_id}`，要求 `QC_TASKS.READ`。
- 对象权限与整任务进度一致：任务创建人、管理员或质控管理员可读；仅受领部分病历的质控员不能据此读取其他人的整任务聚合。
- 稳定账号 ID 和任务对象权限必须在读取 `qc_task_records` 前验证。无权请求不能触发任何任务病历聚合。

## 聚合口径

- 总数、处理状态和受领人统计只来自该任务的 `qc_task_records`，使用数据库聚合精确计数，不从分页列表或任务缓存字段推导。
- “处理完成”只认任务病历权威状态 `completed`，不以 QC job 完成、已有质控结果、病历审核或复审替代。
- 完成率为 `completed / task_records total`；空任务返回总数 0、完成率 0。
- 状态分布固定为待处理、处理中、已完成、已跳过和未知状态。未知数据库值只计入未知，不重判为其他状态。
- 受领人按稳定账号 ID 聚合；未分配单列。同一账号的姓名快照冲突时姓名返回 `null`，不猜测展示名。
- 评分与缺陷分别返回已知数与未知数。只要存在任一未知评分，全任务平均分为 `null`；只要存在任一未知缺陷数，全任务缺陷总数为 `null`。空任务的两项聚合值也为 `null`，不得用已知子集或 0 冒充全任务指标。

## 前端与错误

- 分析抽屉展示总数、完成数、完成率、评分/缺陷已知聚合与未知数量、状态分布及受领人完成数。
- 抽屉的“查看任务详情”只发出 `view-detail(task_id)` 下钻事件，由任务列表 owner 打开既有详情抽屉；分析层不新增执行动作。
- 迟到响应不得覆盖已关闭抽屉或另一个任务。服务端未知异常只记录异常类型，向前端返回统一不可用提示，不泄露 SQL、患者材料或三坐标。
