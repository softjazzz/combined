## 冻结所有者

创建/草稿编辑/模板的 `sampling_config.record_type_config` 存每机构危重、疑难各自的非空阳性码/阴性码数组。两集合不重叠。用户必须选择双阳性独立桶 `separate` 或明确危重/疑难先后顺序的 `priority`，没有默认。

任务抽样服务读取三坐标标志并产生唯一桶：危重、疑难、双阳性、双阴性普通；任一标志为 NULL/未知码、缺少机构字典时保持未知。按类型抽样遇到未知即明确失败，不跳过未知病例制造候选计数。普通桶仅双阴性，不是其他病例的兜底。来源异常同样失败，不返回空成功。

抽样保存层将分类结果写入 `qc.qc_task_records.record_type_snapshot`，并继续比较完整 sampling_config 防止查询期间配置变更。指定病例集合只允许全部进入与元数据分类，禁止二次筛选抽样。迁移81接80，仅编写；历史 NULL 不回填。

## 分配消费

按类型分配只读已冻结桶，不重查当前源事实。真实可分配账号仍由既有活跃质控员目录校验。每位选定质控员须显式选择可接收桶；桶内复用既有顺序与均分规则，未覆盖桶或历史未知快照使整个分配事务失败。单条与批量 UI 均传 `record_types`，不创建员工或推测账号。

自定义范围复用同一 `record_type_config.selected_buckets` 明确选择已知桶，无默认筛选。分类后先筛选再执行既有抽样。任何候选类型未知时失败，不把未知隐式排除后声称完整候选。指定病例集合禁止该筛选参数，仍可保存不含筛选的分类字典用于冻结分配。

本批验证为合成 HTTP 创建、抽样/保存/分配及前端单元回归；未执行数据库迁移、业务库部署或真实病例浏览器验收。完整院方类型目录仍待业务确认，不凭测试数量自动提升40–42整项。
