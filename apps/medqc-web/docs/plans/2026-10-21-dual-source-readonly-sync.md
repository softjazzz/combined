# 双源同步只读演练：27例及 C18 文书缺口

## 范围与决策

工作树 `C:\medqc-safe-source-sync`，分支 `codex/safe-source-sync-20261021`。
用户要求不改集成工作树、不写数据库、不调用模型。此次新增独立的只读规划入口；
没有切换运行中的同步来源，没有接入旧的整表替换写入口，也没有数据库迁移或部署。

单源替换无法满足已核实的互补数据：C18 的3份输血记录仅在 homology，1份出院记录仅在
clinical_data；旧导出包与本机两类记录均为0。具体旧同步遗漏环节尚未证实，不能仅凭现有
源端有值断言历史同步存在某个过滤条件。此次读取按患者、就诊坐标，不按日期、正文非空
或文书状态裁剪，因而不会排除无记录时间、分节有文但 record_content 为空的出院记录。

采用按稳定身份合并的内存规划器，替代“整表选一个来源”的实验设计。所有来源分别强制
REPEATABLE READ READ ONLY；两库快照不保证同一原子时点。连接失败、表不可读、字段缺失、
读取超时、超出条数上限与成功读取0行分开报告。主入口不导入旧应用，避免配置初始化副作用。

## 合并与字段所有权

- 显式核对来源机构映射、患者和就诊；同表稳定业务编号去重。缺号、重复号、机构不符、
  跨药品/非药品同号均显式列出，不模糊匹配或删除既有记录。
- 保留本地非空值；临床库、上游库仅补已确认同一记录的空字段。药品编码、病理关联号冲突
  阻止跨源补字段。非空冲突保留两份原始变体，不拼接不同来源正文，不按字数选择。
- 已验证的病理诊断、医嘱四类时间可以在内存候选使用 homology 优先级，仍记录冲突；
  不覆盖本地非空值，不把计划结束误作实际停止，不用提交时间代替记录时间。
- document_status、record_status、report_status 独立保留。Save 只是源原值，不翻译成草稿
  或已提交；上游独有文书仍进入候选目录，但正式有效性未据此认定。删除标记不用于删除本地行。
- 保留 record_content 和明确 JSON 原始文本路径、出院分节、签名及其原始字段。
  普通列与 JSON 不同也报告冲突；无效时间和 JSON 的原始值仍保存在内存变体中。
- 旧本地检验明细缺上游复合编号时，以既有 document_id 保留原行，标明无法跨源匹配；
  内部匹配键不冒充源编号，也不据此合并其他来源的明细。

## 下游保留验收

内存目标列投影显式报告无法映射的字段，不静默过滤后宣称就绪。旧客户库无时区时间列按医院
北京时间保留，目标文本时间保留时区信息。缺列不自动添加，状态不自动改写。

C18 专门核对用户已确认的3份输血和1份出院编号；该验收清单仅存在于演练工具，
通用策略没有病例特判。验收同时检查目标列投影后的真实文书组装。

在该闭环发现出院记录的 positive_assist_exam 未进入文书组装，已仅在本工作树补为可选章节。
入院情况、重要辅助检查、诊疗经过、出院情况、出院医嘱不依赖 record_content 非空。
这些结果不代表真实数据库或 Bundle 已更新；此次无持久化 Bundle 刷新。
