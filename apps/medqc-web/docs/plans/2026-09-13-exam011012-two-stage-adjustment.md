# LX0609-011/012 两阶段事实边界调整计划

日期：2026-09-13。

## 问题证据与根因

固定四例、三轮的 v3 POC 显示：两阶段使事实状态一致病例从 3/4 增至 4/4，但事实正确数从 46/54 降至 39/54，引用一致性仍为 2/4。C05 的历史检查证据被连续三轮当作本次检查证据；C05、C06、C12 各有一个明确异常事件被第二阶段重新判为阴性。

主协调已由保存的两阶段响应反推确认：

1. 第一阶段只选了句子和粗粒度类型，没有提供受控的“句子是否属于当前检查事件”事实，历史/其他检查与本次检查一起进入第二阶段。
2. 第一阶段已将报告句标记为异常，第二阶段又重新判断阳性/阴性，两个事实所有者给出冲突结论。

## 实施步骤

### 第一步：v4 私有 POC

- 输出：`.tmp/0910-full-audit/` 中新的 v4 脚本和 `-private` 产物，不修改生产代码。
- 第一阶段：Python 给报告、病程句子稳定编号；LLM 仅选择候选句并输出 `linked|historical_or_other|ambiguous` 事件关联。报告句保留 `abnormal|normal|uncertain|other`，阳性事实只由该阶段产生。
- 第二阶段：只接收第一阶段中已校验且与事件关联的病程句，逐句输出 `result_mention|analysis|both|neither`；不得输出规则状态、阳性分类或新的引用。
- Python：严格校验事件、文书、句子编号、时间白名单和完整覆盖；由唯一映射生成 011/012 的 `positive_state`、`semantic_state` 和引用。
- 测试：同一份 C05/C06/C08/C12 Bundle 输入，`qwen3.8-flash`、thinking budget 256；第一阶段每例一次并冻结，第二阶段每例三轮。沿用 9 个事件、18 条事实真值。

验收门槛：三轮事实正确率不得低于当前单阶段 46/54；状态一致至少 4/4；状态及引用一致高于单阶段 2/4；C05 不得引用历史/其他检查，C12 第二事件不得越过报告时间/事件目录。任一门槛失败即停止，不接入生产。

### 第二步：生产最小接入（仅在 POC 全部通过后）

- 新建一个 011/012 深模块，拥有句子编号、两阶段 schema、解析校验和 Python 状态映射完整职责。
- `native_exam_lab_execution.py` 只调用新模块并累计既有调用/Token/失败语义；不在超过 2000 行的执行器内继续堆放独立职责。
- `exam_lab_fact_extraction.py` 继续作为现有 010/014/015 及兼容链所有者，不复制 Bundle、事件拆分或状态映射。
- 新增聚焦单测，证明历史检查拒绝、报告前 88 秒拒绝、阳性事实不可被第二阶段改写、非法/缺失引用失败关闭、调用次数和 Token 准确。
- 使用冻结病例回放比较相同输入下的状态、原因码、关键事实、证据定位、调用/Token 和耗时；保护提交 `c631cea3c` 后已经验收的完整结果集合。

## 失败语义与风险

- 第一阶段缺项、重复、非法句子编号、事件关联不明确：不冻结，不输出确定性合规/不合规。
- 第二阶段缺项、重复、非法枚举或新增引用：受控失败，不能让一条坏事实污染同批其他规则。
- `uncertain` / `technical_error` 不得作为客户交付结果；生产接入前必须明确映射到该规则允许状态集合。
- 冻结键必须覆盖病例版本、事件/候选内容、schema/提示词和模型版本；本 Task 不新增持久化实现，先由 POC 证明业务收益。
- 最大风险是首次抽取稳定但错误。稳定性不得脱离真值准确率和证据定位单独验收。

## 巨型文件门禁判断

`native_exam_lab_execution.py` 已超过 2000 行。两阶段证据合同是可独立测试的完整职责，若进入生产必须放入独立深模块；现有执行器只能增加最小编排调用，不能在原文件新增 200 行以上逻辑。POC 未通过时不创建生产模块，避免为未证明收益的方案扩展架构。
