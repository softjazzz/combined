## 已实现的职责边界

- `agent-runtime/` 使用 DSH 公共服务和原生 AgentLoop，不在 Python 中新增模型循环。只适配现有供应商协议；会话恢复、停止与历史都来自 DSH 原生事件/JSONL。
- MedQC 新增 `/api/v1/qc-agent/business` 桥接入口，验证会话账号归属，固定页面上下文，向业务读取转发原 Bearer 身份。旧助手兼容入口保留。首页直接接管理助手，病历详情接医生助手；新入口不会挂载旧组件的 SQLBot 配置加载逻辑。
- 四个业务工具分别读正式保存结果、同一结果的保存证据、当前权威规则目录、既有 LX0609 结果分析接口。全部只读，不启动质控、不写 EMR、不启用规则、不分派或通知。
- 具体问题按任务＋病历引用＋规则绑定。最新任务变化返回 409，不能把旧“第二条”替换为新判定。点击问题和病例卡片传递本会话引用，服务端拒绝外来引用；界面只显示人能理解的问题。
- 管理查询的科室、在院/出院范围和完成日期固定在会话中，模型仅能细化规则/状态或翻页；正式指标与明细原样搬运，不自行聚合。统计引用打开时按同一条件刷新，并明确数据可能更新。
- 客户结论、建议、状态以正式结果卡片展示。生成解释不拥有判定权。无新工具来源的续问沿用 DSH 历史来源，并标注“未刷新业务结果”；不另建业务聊天历史。
- 前端用账号及语义上下文区分会话定位，切患者/范围时中止旧请求，代次校验丢弃迟到响应。引用打开同样隔离迟到结果。
- WeKnora 使用官方插件的搜索/原文读取，关闭 ask。知识库范围必须显式指定；名称命中文档与原文片段分开，截断/分页明确标识，读取文档前再次核对知识库归属。

## 真实模型＋合成业务接口

通过真实 Node 运行时、FastAPI 桥接和 HTTP 工具回调执行五轮。业务数据全部为手写合成病例/指标；规则目录读取是业务依据查询。没有上传客户病例或源码。测试病例故意使用合成字段，不能用来评价规则医学准确性。

| 合计                     |        9 |       12 |     26063 |      2287 |    49442 |

五轮全部 completed；恢复 API 回读到相应3/2轮。医生第二条绑定病例 A 的原问题与原摘录，管理下钻仍使用原日期/科室范围。未配置知识库时回答明确无法提供规范原文，没有伪造检索引用。

表中输入/输出为供应商返回的 prompt_tokens/completion_tokens 累计，未拆分缓存用量或估算费用。工具次数来自 DSH 原生调用事件；本表成功调用均执行了实际业务 HTTP 读取，预算拒绝场景另在确定性测试中核对实际读取不超过8次。

首次尝试仅用通用 LLM 字段出现五轮 HTTP401，未取得 Token 用量，不能按0计算。对照原服务的供应商配置优先级后已修复。另修复适配器精确模型元数据、DSH工具结果消息转换、中文跨字节解码，以及模型准备失败时原生事件投影不能丢失该轮的问题。

复核发现早期生成回答把目录空发布范围数组解释成判据缺失，并输出内部字段/表格；已在规则工具范围说明与系统指令中纠正，界面改为普通中文段落。停止后沿用已有来源却缺少引用卡片的情况也已修复为原生历史引用继承与未刷新标识。上述五轮表保留原测量，不把后续修正冒充当时已验证；最终界面和卡片绑定另做浏览器复核。
