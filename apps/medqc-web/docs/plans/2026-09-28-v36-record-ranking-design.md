# V3.6 质控病历排名收口

## 原合同

- PRD矩阵08明确要求真实审核量、复审量和角色数据，不以质控引擎调用次数或任务job完成数代替。
- 统计时间窗口内按审核人和病例三坐标去重计算总病历数；初审、复审分别按同一身份去重。同一病例可同时出现在两阶段，阶段数量不是总数的互斥组成。
- 场景代表已核实任务/质控结果的工作上下文，不从出院日期猜测归档状态。历史缺失场景只进入all，不分配到任意具体场景。

## 实现边界

- 提交审核时在权威校验及事务内冻结scene，来源只允许锁内任务或已核实质控结果，不信任客户端。
- 新迁移67给审核事实补场景字段及约束；不批量猜测回填旧记录，不执行真实迁移。
- performance_ranking_service负责筛选、三坐标去重和排序，前端仅搬运，不重新算名次或合计。
- 缺陷排名仍由其原owner维护；本次08不冒充07完成。具体场景可返回病历排名，同时保持缺陷排名不可用。
- 后续07独立批次按`2026-09-28-v36-defect-ranking-scene-plan.md`补齐人工缺陷场景；上述不可用描述保留为08批次边界，不代表07交付后的接口现状。
- 后端代理负责审核/排名服务及迁移/测试；模型由计划线唯一owner合并；主协调负责前端标签/合同测试和整项复核。

## 验证

- 同病例重复审核/多轮结果、同窗双阶段、跨机构同号、不同审核人、周月上海时区边界、历史NULL和各具体场景。
- 越权、场景来源不可核实、客户端场景注入、审核事务回滚及结果换轮。
- 代码、隔离数据库、业务部署、真实浏览器分别记录；未验证不提升业务验收状态。
