# V3.6 规则集版本 Excel 导入导出合同

## 1. 范围与权威所有者

本批补齐 PRD #62 在规则集版本生命周期上的 Excel 主链。工作簿只搬运既有规则目录中每个 `rule_id` 的版本状态，生命周期判定、草稿并发控制、发布校验和数据库事务仍由 `rule_set_version_service` 唯一负责。

Excel 不得创建新规则、修改质控点名称或来源文书，也不得导入条件、时效、提示词、Python/LLM 执行器或其他执行定义。评分标准 Excel 属于另一条主链，不在本文件范围内。

## 2. 固定工作簿合同

只接受 `.xlsx`，且必须恰好包含两个可见工作表：

1. `版本信息`：单行，固定字段为 `模板版本`、`规则集键`、`导出版本`、`导出状态`、`基础版本`、`基础内容摘要`、`草稿版本序号`。
2. `质控点`：固定字段为 `质控点ID`、`状态`、`质控点名称`、`来源文书`。只有前两列参与导入；后两列是便于人工核对的只读元数据，导入时必须与当前目录一致，不能借此改写规则定义。

状态仅允许 `active`、`paused`、`offline`。规则 ID 必须恰好覆盖该规则集当前目录全集、唯一且顺序不限。未知工作表、未知列、隐藏工作表、公式、宏、外部链接、加密文件及非标模板均失败关闭。

## 3. 冻结版本与摘要

- 导出内置、已发布或已下线版本时，工作簿是不可变版本快照。
- 导出草稿时，工作簿记录不可复用的 `draft:<uuid>` 身份、`base_version` 与 `version_seq`，三者共同防止删除后重建同序号的 ABA 覆盖。
- `基础内容摘要` 校验的是导出时冻结的基础版本，不是用户编辑后的 `质控点` 内容。用户可以修改状态；导入只要求基础版本仍可解析且其规范化摘要仍等于工作簿记录值。
- 已发布、已下线和内置版本永不被 Excel 覆盖。导入结果只能是草稿。

## 4. 导入语义与事务

解析和整文件预检必须在任何写入前完成：模板、资源限制、规则集、冻结基础版本、摘要、规则全集、重复项、状态、只读元数据、可执行性和至少一条 active 均须通过。

- 当前没有草稿：从工作簿冻结的基础版本创建草稿。
- 当前已有草稿：只接受由同一草稿导出的工作簿，要求 `draft:<uuid>` 身份和基础版本相同，并按工作簿中的 `version_seq` 做 CAS；普通冻结版本文件不得静默覆盖草稿。
- 写事务内再次锁定规则集，重新解析基础版本并复核摘要、草稿身份和 CAS，然后写入全部 entries 并在提交前回读 DTO。任一写入或回读失败整笔回滚。
- 导入不发布、不下线、不改变当前版本，也不自动运行质控。

HTTP 合同：权限限定 `admin`、`qc_manager`；合同错误返回带 `sheet`、`row`、`field`、`code`、`message` 的 422；并发或已有草稿冲突返回稳定 409 code；数据库失败脱敏为 503。网络异常、5xx、409 的执行结果视为未知，前端锁住同文件盲目重试，要求刷新版本列表核对草稿后重新选择文件。

## 5. 资源限制

- 上传压缩文件最大 2 MiB。
- ZIP 条目最多 32 个，解压总量最大 8 MiB，单个条目最大 4 MiB。
- 质控点最多 1000 行。
- 拒绝 ZIP 路径穿越、加密条目、宏、公式、外部链接和隐藏附加表。
- 错误和日志不得记录工作簿原文或数据库异常正文。

## 6. 接口与界面

- `GET /api/v1/rule-set-versions/{key}/{version}/export`：导出冻结版本。
- `GET /api/v1/rule-set-versions/{key}/draft/export`：导出当前草稿及 CAS 序号。
- `POST /api/v1/rule-set-versions/{key}/draft/import`：上传工作簿并创建或 CAS 更新草稿。

质控点管理页提供“导入草稿”，版本历史和草稿面板提供对应导出。导入抽屉展示文件限制、显式确认、逐行错误和结果未知提示。成功后刷新草稿及列表；同一文件成功或结果未知后均不可直接重复提交。

## 7. 验收

- 内置、已发布、已下线和草稿均可导出，内容与服务端详情一致。
- 冻结版本文件修改状态后可创建草稿；基础摘要只验证基础快照，不阻止状态编辑。
- 草稿文件只有在同一草稿、同一基础版本和相同 `version_seq` 下可覆盖；并发修改返回 409。
- 规则缺失/越界/重复、不可执行规则设 active、全无 active、元数据被改、摘要漂移、公式/外链/隐藏表/超限均零写入并可定位。
- 写入或事务内回读失败时不留下草稿或半批状态。
- 既有发布/下线版本、当前版本、历史任务和执行结果保持不变。

## 8. #64 / #69 边界

现有版本 entries 只拥有状态，不拥有可编辑或可删除的规则定义。把 `offline`、删除草稿或隐藏历史解释为业务删除会破坏生命周期合同；已发布和已下线版本必须保持不可变。因此 #64 的规则定义编辑/删除和 #69 的批量删除继续保留“部分实现”，本批不据此提升状态。
