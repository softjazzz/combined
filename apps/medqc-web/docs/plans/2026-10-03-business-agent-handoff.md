## 2. 架构总览

```
浏览器（Vue 3 + Ant Design Vue）
  └─ /api/v1/qc-agent/business/*        FastAPI 路由 business_agent.py
        ├─ 业务工具 BusinessTools（读正式接口、校验、写动作）
        └─ 模型运行时 agent-runtime（Node，DSH）
              └─ 通过工具回调到 FastAPI，模型只起草措辞
```

**核心原则（不能破）**：

1. **数字、状态、原因只来自正式业务接口，由 Python 判定**；模型只写措辞，且回答/草稿/报告里的数值要通过“来源核验”（归一化，09 等于 9；比较或因果措辞逐句拒绝，否定句豁免）。
2. **写操作必须“预览、用户点击确认、正式接口、回读”**，幂等靠 `qc_business_actions` 表和条件更新；模型没有确认工具。
3. **授权**：医生只能看被授权的病例，管理者限定在授权科室；会话绑定上下文，切换病例会重置。
4. **只读优先，写入开关在正式入口强制生效**（`business_write_switch.py`，每次请求读取环境变量，默认关闭，只有值为 `1` 才允许）：
   - `MEDQC_AGENT_FEEDBACK_WRITE_ENABLED` 控制实名异议反馈提交；
   - `MEDQC_AGENT_TASK_WRITE_ENABLED` 控制助手创建任务（动作预览与确认两处都拦）；
   - 关闭时返回 **HTTP 423**（与授权失效的 403 区分），前端给出明确提示，能力说明工具也会把对应能力列为“暂不可办理”；
   - 之前开关只在手动联调应用里生效、正式路由没有检查（合并审查发现，已修复并有测试覆盖）。

## 6.2 管理者入口四项残留修复（合并复核提出）

基线 `b3c759f79`。病例入口（病历池选中病例）下纯管理账号的助手有四处残留，根因都在对话组件对宿主范围的消费方式，本轮已修复；授权、写入开关与 423 行为未改动。

| #   | 问题                     | 根因                                                                                                 | 关闭方式                                                                                                                                                                                                          |
| --- | ------------------------ | ---------------------------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 1   | 在院范围没传到底         | `carePhase` 固定初始化为 `discharged`，不读宿主给定值                                                | 宿主固定管理者范围时用宿主的在院/出院范围，并禁用助手内的科室与范围选择；全局入口仍可自选                                                                                                                         |
| 2   | 跨科室切换仍沿用旧科室   | `selectedScope` 只在 `open` 变化时初始化；“唯一授权就选它”的回退会在宿主指定了科室时选到不匹配的科室 | 监听宿主科室实时同步；宿主指定了科室就只能用匹配的管理授权，没有匹配则报错“没有管理授权”，不回退到其它科室                                                                                                        |
| 3   | 同科室切换病例没重置会话 | 管理者上下文只有科室级，会话定位键不变                                                               | 病例入口新增“会话边界”（`caseKey`，机构+患者+住院号）：边界进入会话定位键，切换即停止旧轮次、清空展示与待显示问题、改用独立会话，迟到响应按代际丢弃；回到原病例按各自定位恢复。全局科室问数无边界，保持科室级会话 |
| 4   | 授权返回前仍激活会话     | `watch(context, …, { immediate: true })` 在授权前就调用 `activate`，可能 restore                     | 仅在“已打开、授权已读取且无授权错误、科室/病例已确定”时激活；授权读取中不做任何会话调用；授权失败清空旧范围并展示原因，不恢复旧会话                                                                               |

实现要点：授权范围、科室/病例选择和最终上下文抽成 `composables/useBusinessAgentScope.ts`（抽屉由约 1190 行降到约 1115 行）；`useBusinessAgent(boundary)` 增加边界与 `suspend()`；内嵌页签切换不再重置授权，进行中的对话不会因切页签中断。后端授权与接口**未改**。

**重要边界（如实说明）**：病例入口下的管理者对话是“科室范围问数”，会话按病例隔离，界面标注“来自病例 住院 X”；它**不会自动读取该病例的保存结果**。若要让管理者直接就该病例提问，需要后端在创建会话时校验并预绑定病例引用（沿用 `require_record` 的机构/科室/病例归属校验），本轮未做，见下方待办。
