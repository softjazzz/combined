# 06-01-04 百炼难例对照 Implementation Plan

> **For Claude:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task.

**Goal:** 在正式核验调用点上比较 Flash 与35B的真实难例应答，独立验收分类、事件/文书引用、冲突及完整性；不写业务库或运行患者质控。

**Architecture:** 使用原客户端、进程内Gateway、原Prompt和专项解析/接纳。先固定合成输入及参考答案；六类难例各两轮、交换调用顺序；另两次检查已知截断路径。候选升级保留每次原答，不能以参考模型恢复掩盖候选错误。正式保存读取另用本次录制应答在严格offline下复用，主抽取仍明确为固定夹具。

**Tech Stack:** Python3.10、原BailianPocTransport、httpx、pytest OfflineIsolation、Canonical内存SQLite。

## 范围和上限

- 使用既有部署配置的两个百炼模型 `qwen3.8-flash`、`qwen3.6-35b-a3b`，不访问患者库、客户机或Strata。
- 预计26次实际HTTP（6类×2轮×2模型组＋2次截断保护），硬上限32次；每次最多4096输出Token。串行单槽，不做压力测试，授权内不自动扩大场景或重跑失败整批。
- 禁止业务数据库连接；不写模型观测业务表。只读取显式指定backend/.env的凭据，不打印/保存凭据。
- 非实际35B调用（如输入触顶后程序选择Flash）单列排除，不冒充35B医学质量通过。
- 请求显式 `enable_thinking=false`，不将发送参数当作独立服务端证明。

## 调用前固定的参考场景

| 场景 | 预期 |
| --- | --- |
| 同次胸部CT左右侧写反 | result_conflicting，保留冲突，非已记录 |
| 明确另一项头颅MRI | other_exam，不绑定本次CT |
| 两次相似胸部CT、结节部位/大小变化 | 各自病程绑定各自事件；引用另一次结果不算本次 |
| 记录影像所见但临床解释不同 | result_recorded，临床判断不同不自动算报告矛盾 |
| 同次CT把报告阳性所见写为未见 | result_conflicting |
| 可读范围内长病程尾部记录结果 | result_recorded，不能漏读有效尾部 |
| 超出6000字后才有结果（单独保护） | 模型未收到尾部；局部否定不接纳、事件未核完，不计35B质量样本 |

## 执行步骤

1. 新增固定catalog、旁路评分和难例CLI；复用原真实POC运行时，默认预览。
2. 在严格offline下验证预览不读凭据、真实开关不能绕过网络隔离、场景Prompt/参考答案以及路由和评分边界。
3. 先提交固定输入/参考答案，再显式执行授权真实对照。结果完整保留到忽略的private报告，不按结果修改参考答案。
4. 复用录制应答走正式离线结果链，比较规则/事件/证据、冲突和保存。报告协议/引用失败、升级、分类差异、误报/漏报方向分开，不以Flash为金标准。
5. 如出现差异，逐项对照预设输入解释；不因此自动修改生产Prompt或医学规则，不追加未经说明的模型循环。

## 解释边界

六类是合成难例，重复两轮不是12例独立病例；只能提供先导质量证据，不能证明真实病历误报漏报不增加。时间记录含网络与排队；不外推本地量化、完整病历吞吐或GPU部署。报告实际Token与调用数，缺失费用数据不冒充零成本。
