# 06-01-04 百炼难例对照 Implementation Plan

> **For Claude:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task.

**Goal:** 在正式核验调用点上比较 Flash 与35B的真实难例应答，独立验收分类、事件/文书引用、冲突及完整性；不写业务库或运行患者质控。

**Architecture:** 使用原客户端、进程内Gateway、原Prompt和专项解析/接纳。先固定合成输入及参考答案；六类难例各两轮、交换调用顺序；另两次检查已知截断路径。候选升级保留每次原答，不能以参考模型恢复掩盖候选错误。正式保存读取另用本次录制应答在严格offline下复用，主抽取仍明确为固定夹具。

**Tech Stack:** Python3.10、原BailianPocTransport、httpx、pytest OfflineIsolation、Canonical内存SQLite。

## 范围和上限

- 使用既有部署配置的两个百炼模型 `qwen3.8-flash`、`qwen3.6-35b-a3b`，不访问患者库、客户机或Strata。
- 预计26次实际HTTP（6类×2轮×2模型组＋2次截断保护），硬上限32次；每次最多4096输出Token。串行单槽，不做压力测试，授权内不自动扩大场景或重跑失败整批。
- 禁止业务数据库连接；不写模型观测业务表。只读取显式指定backend/.env的凭据，不打印/保存凭据。
- 非实际35B调用（如输入触顶后程序选择Flash）单列排除，不冒充35B医学质量通过。
- 请求显式 `enable_thinking=false`，不将发送参数当作独立服务端证明。

## 执行步骤

1. 新增固定catalog、旁路评分和难例CLI；复用原真实POC运行时，默认预览。
2. 在严格offline下验证预览不读凭据、真实开关不能绕过网络隔离、场景Prompt/参考答案以及路由和评分边界。
3. 先提交固定输入/参考答案，再显式执行授权真实对照。结果完整保留到忽略的private报告，不按结果修改参考答案。
4. 复用录制应答走正式离线结果链，比较规则/事件/证据、冲突和保存。报告协议/引用失败、升级、分类差异、误报/漏报方向分开，不以Flash为金标准。
5. 如出现差异，逐项对照预设输入解释；不因此自动修改生产Prompt或医学规则，不追加未经说明的模型循环。

## 解释边界

六类是合成难例，重复两轮不是12例独立病例；只能提供先导质量证据，不能证明真实病历误报漏报不增加。时间记录含网络与排队；不外推本地量化、完整病历吞吐或GPU部署。报告实际Token与调用数，缺失费用数据不冒充零成本。

### 三次细分类差异

都发生在同一配对：`repeated_similar_events` 的事件1（10点胸部CT、左肺5mm结节）×文书2（14点复查、右肺12mm结节）。后者明确属于另一次检查，预设 `other_exam`；Flash两轮为 `none`，35B第一轮 `none`、第二轮 `other_exam`。

两类都映射为“未记录事件1的结果”，而事件1已由文书1正确记录，事件2由文书2正确记录。没有错误绑定为事件1的正面证据，也未产生错误冲突提示，故本轮最终方向一致。差异仍按原预期记录，不把它改成完全分类一致；35B两轮的变化说明温度0也不等于结果绝对固定。此小样本不足以判断哪个模型总体更好。

### 截断与技术失败

- 长文结果放在6000字之后的一次参考应答为 none，程序拒绝把它当完整否定，事件标未核完；离线正式链保留固定正确主抽取，保存compliant且不冻结。
- 该场景的cascade同样由程序选择参考模型，发生 ConnectError。它不是35B的语义失败，也不是新增临床结论；保持请求失败和原Gateway未知在途隔离，不强制清槽、不重试整批。
- 首次产物中 `complete=true` 仅因26组都已尝试，不能解释为全部成功。原始产物保持不改；后续入口已分开 `all_arms_attempted`、HTTP成功/失败和真正 `complete`，新增固定保护验证“最后保护请求失败不能报告执行完整”。本轮一律按25成功、1失败说明。
- 没有真实升级发生，不能据此说真实恢复已验收。

### 正式链离线复用

25份有效专项应答复用原客户端/Gateway固定传输→Native→Binding→Finalizer→Aggregator→Canonical内存保存读取，**25份完整性通过、0状态方向偏差**：13项compliant、12项non_compliant。另1份HTTP失败无应答，明确标不可回放，不冒充已验证。

主抽取仍是明确标注的固定夹具，成熟评价上界是合成上下文。这不是25次真实全病历质控。热冻结/来源HMAC及事件、文书、引文、冲突和保存读取沿原合同验证。

### Token和耗时

六类核心的12次请求：Flash共15014 Token、HTTP耗时合计62.98秒/P50 4.86秒；35B共14853 Token、合计38.73秒/P50 3.08秒。两轮交换调用顺序，仍只有少量短语义请求，不报告完整病例吞吐或统计显著加速。

连同额外截断保护，服务端成功上报的Token为：Flash19151、35B14853，共34004。那一次ConnectError没有服务端usage，不能算0 Token或据此推断账单金额；未取得实际货币计费。未独立证明服务端Thinking、权重/量化版本或缓存收益。
