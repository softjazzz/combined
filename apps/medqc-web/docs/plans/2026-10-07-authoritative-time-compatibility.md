# 权威时间时区兼容：最小修复与本机验证

## 问题与修复范围

候选包 `20b56036869da886b2c5651d3fb2a3ab4e6b6fec` 在授权开启后执行合成入院时效病例，实际得到 `data_gap / authoritative_time_missing`，人工预期为合规。

只读核对正式来源读取：入院锚点及正文均存在；PG 返回 `record_datetime` 为带时区 datetime（+08:00），而 `submit_datetime` 为无时区 datetime。现有字段优先级选取前者，基础时限解析器却拒绝带时区值。无时区输入经该 PG 字段回读也带时区，故不能靠修改输入回避。

只修改 `basic_timeliness_facts.parse_authoritative_datetime`：权威字段整值中的显式时区转换至 `Asia/Shanghai`，再与医院本地无时区时间比较。支持 datetime 及严格 ISO 字符串（含 Z、偏移）；无时区旧行为不变。缺失、无效日期、正文中的时间仍不作为权威时间。没有改变字段优先级、医学阈值、状态映射、保存合同，也没有增加模型调用。

该解析器由基础时限族共享，故验证同族事实、客户投影、证据及架构边界；不是只在 API 展示层改状态。
