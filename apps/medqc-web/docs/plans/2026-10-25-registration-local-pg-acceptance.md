# 本机注册、审批及登录实测

## 范围与授权

用户明确授权先备份本机 PG，再升级最新迁移，实际验证用户注册、管理员审批及审批后登录；另授权创建医院范围的临时验收管理员，完成后停用。不调用模型、不重跑质控，不改业务集成分支。

## 真实页面及接口结果

1. 注册表单从本机 PG 读取当前医院的 33 个科室选项。实际提交无邮箱、无手填机构 ID 的专用医生申请，HTTP 200；数据库邮箱为 NULL，账号停用、申请 pending。
2. 待审批时用正确账号口令正常登录返回 401。
3. 临时医院管理员通过正常口令登录，进入 V5 系统配置 → 账号管理 → 注册审批。核定机构、科室和 doctor 角色后，审批 HTTP 200。
4. 申请状态 approved，版本 2；历史 submit/1、approve/2 连续且审批人为临时管理员。通知与审批记录持久保存。
5. 医生通过实际登录页成功进入工作台，`/auth/me` HTTP 200，实际持久 ID、机构、科室和 doctor 角色一致。重新进入工作台恢复会话成功，刷新令牌及本人开通结果读取成功；登录外也可用原用户名及口令查询审批结果。
6. 医生读取管理员审批队列 HTTP 403；重复使用版本 1 审批 HTTP 409，不重复开通。
7. 实测发现无邮箱账号菜单只按邮箱显示，错误提示“未登录”。仅将账号展示文案回退到既有 `authStore.userName`，邮箱账号显示保持原样。22 项 V7.1 保护继续精确还原允许差异后核对旧基线，没有放宽导航、权限、确认弹窗或主题保护。

## 收尾及数据边界

- 管理员和医生两个临时验收账号均停用，保留测试申请、审批历史及通知。停用后新登录及既有令牌均 HTTP 401。
- 原有 326 个账号的全字段摘要一致，未改变既有管理员口令、角色或状态。
- 验收只向账号、注册申请、审批历史和通知写入本次测试记录；临床材料、既有质控结果和任务数量未变。
- 本轮 5 个前端聚焦文件共 57 项通过；其中含 21 项认证状态、22 项 V7.1 保护及 14 项注册 API/申请/审批面板。未重跑全量回归。
- 独立分支保存修复，不推送、不合并、不打包。验收进程禁止模型外联及质控执行、同步和无关写入；收尾恢复只读查看进程。

本次结论限于本机真实 PG 及当前分支，不能替代客户机部署验收。
