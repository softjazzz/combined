# 27例药品和非药品医嘱定向同步前预览

用户要求不部署新包，先只读比较 homology 与客户机 PG，确认后才备份补数。
实现仅在独立同步分支；本次只准备执行脚本，没有修改本机或客户机数据。

## 执行

执行包包含 preview_orders27.py、preview_order_time_fill.py、
preview-medqc-orders27.ps1 和既有27例的私有病例坐标文件 cases27-private.json。
坐标从用户此前导出包的 case_refs.json 原样提取，不包含患者/医生姓名，不提交。
客户机命令：

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass `
    -File 'D:\medqc\orders27-preview\preview-medqc-orders27.ps1' `
    -BackendPath 'D:\medqc\medqc-web-customer-R26.4\backend' `
    -OutputDir 'D:\medqc\orders27-reports'
```

凭据仅由客户机后端现有配置读取，不复制配置、不修改同步开关。
homology.graph3_homology 来源机构占位值与本地 cdm 的医院机构名按已验证口径映射。
两侧独立强制 REPEATABLE READ READ ONLY 事务；SQL 超时20秒、锁等待5秒。
跨库并非同一个原子快照，manifest 显式注明该限制。

## 比较口径

只读两张医嘱表，按同患者同就诊、完整机构坐标读取；若完整坐标0行而同患者就诊有行，
另标机构映射疑点。任何一侧两表均0行会标覆盖待查，不据此认定患者没有医嘱。
不筛掉停止、撤销、删除标记或重复编号；不擅自丢弃本地独有医嘱。

- 相同编号在药品与非药品表间交叉核对；跨表同号不直接算丢行。
- 同表同号必须两侧各唯一；空号、重复号、身份或时间冲突均待复核。
- 上游独有编号只称未匹配；仅提供“确切名称+开立时间”可能对应另一个编号的线索，
  不凭线索合并或认定缺失。线索数量包含所有候选，报告只列最多5个匿名标识。
- C17型通用名/商品名口径差异，须编码一致且名称确切交叉匹配才通过身份检查。
- 按显式别名比较开立、计划开始/结束、审核、执行、取消时间，不相互顶替；医院无时区时间
  按北京时间比较；未识别时间单列，既有非空不同值不自动覆盖，源空保留本地。
- 药品额外比较编码、规格、剂量/单位、途径、频次、剂型等；非药品比较名称、分类、数量、
  单位、频次、申请号等。分组、状态、删除标记按字段存在性分别报告。
- 未比较字段（包括正文、患者/医生身份及审计列）在 schema.json 明列，
  不宣称已完成全字段、正文或源库整体完整性验证。

## 交付报告

屏幕只显示范围、27例计数和最终路径，不输出逐条差异。
ZIP 内 manifest.json 记录汇总与限制；summary.json 为逐例逐表和逐字段计数；
schema.json 为列、类型、别名及未比较字段；differences.jsonl 为逐条匿名差异元数据，
只对时间字段输出两侧时间值，不输出姓名、药名、医嘱正文、凭据或原始病例/医嘱编号。
计数以病例及表为单位，跨类别同号可在两张表各出现一次，不冒充全局唯一事件数。

本脚本没有 Apply 参数、不发出 DDL/DML、不刷新 Bundle，不调用模型。
完成预览不表示两侧数据一致或可直接补数，需用户确认后另准备写入步骤。
