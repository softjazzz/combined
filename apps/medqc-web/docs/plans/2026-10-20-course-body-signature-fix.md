# 病程正文签名读取与两规则定向验证

## 范围与原因

用户要求仅解决签名读取，检查 `LX0609-10-01-01`、`LX0609-04-05-01`，复用1019样本集27例，不调用真实模型。其他业务判据和资料缺口留给Claude处理。

源端此前只读核查已确认日常病程结构化签名列为空；本机冻结资料191份日常病程中180份存在明确正文签名。原始表正文已保留，规则不能因结构化签名为空就忽略正文签名。实现基线 `ea3407499` 已有正文签名读取，但额外要求与提交人一致，且术者查房候选未纳入术后首次病程。

## 实现

- `course_record_signer` 优先使用结构化签名；为空时读取正文末尾独立“医师签名／医生签名”栏中的明确单一姓名。提交人不作签名成立的前置条件，也不独立作为签名来源。
- 普通正文提及、其他角色签名、多人未分角色签名和空签名不猜测为单一记录医师。
- 经治医师变更仍由原有稳定签名序列及交接文书时限判定；不因读到签名就直接交付合规。
- 术后24小时术者身份核对补读本人签署的术后首次病程，同时绑定对应来源及逐文书证据。术前查房条件、术后三日病程覆盖及原有时限保持原值。
