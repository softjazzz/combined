# 06-01-04双模型POC闭环验收实施与准入计划

基线：`3e46b6709d2caea4873bf3e6e0602bd7d9144538`；独立工作树初始干净，无CodeGraph索引。只改独立双模型分支，不推送、合并或部署。

## 最小设计

1. 保留现有待回答配对和输出协议；用默认关闭的 `LLM_EXAM_RESULT_CONTEXT_PROTOCOL=comparison_v1` 增加原文比较目录、报告来源引用及报告/记录/提交时间。`legacy`回滚原Prompt。比较目录不产生新待答项，未知时间保留null。
2. 比较目录在事件分批时继承全局稳定报告引用，不用子批答题位置冒充全局身份。同部位同模态重复检查与“较前片”关系明确写入指令；不强制分类，不使用最近一次启发式替代证据。
3. 保持成功配对不重判，失败只重试原范围；比较材料不随pending消失，升级只传原文与客观错误。超过现有Prompt预算失败关闭，不裁剪来造完整否定。
4. 新协议完整输入进入主冻结键，off参考路径也按模型/协议/实验分区。新协议与旧Strata prefix组合明确拒绝，不改变原prefix协议。

## 连续执行顺序

- A：核对已有请求、原答、保存链，查清首轮与补核的独立风险；实现上述最小设计。
- B：严格offline入口，固定合成材料与已有私有应答验证事件归属、时间、24小时边界、失败恢复、预算、冻结及Canonical内存保存读取。新增真实模型请求为0；自审后普通缺陷直接修。
- C：只在一次性授权后执行新实验，建议最多24次新增HTTP且包含失败/升级。请求前固定材料、参考、探索项、Prompt/模型身份、参数和账本；每次checkpoint。若现有固定范围缺少必要材料，不用重复请求补造证据或耗尽预算。
- 交付：分别报告工程安全、专项质量及有限灰度准入，不把保存通过、两模型共同错误或固定应答纠正当真实模型成功。

## 已知限制

现有5份9事件可拆6组，但实际模型可评分正例只有1个，且主要是重复报告中的摘录；其余9个正面配对由程序直接确认。真实冲突正例和6000字后尾部正例缺失。此范围足以验证C01改善或安全不完整，不足以证明广泛正例召回或35B平替。

旧私有投影时间为原始日期、正文已偏移，准备新协议时必须统一应用既有病例日期偏移，且只提供已批准事件范围的比较材料。不得直接将旧pickle原始日期外发。

比较输入会规范等价时区的datetime表示，但原来源投影对非+08时间仍按未知处理。本轮保留既有来源时间合同，不顺带改变培养规则；相应验收须分别说明序列化与来源可用性，不能笼统声称所有UTC来源均已贯通。
