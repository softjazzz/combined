# 特殊病历报表实施计划

> 使用 executing-plans 按独立业务边界实施，主协调集中审查与验证。

**目标：** 按原手册第62-63页实现第52项报表，并消费第60项已交付的专用标准绑定，不扩展其他PRD项。

**架构：** 出院范围沿用CaseScopeService医院时区和三坐标；新的报表服务只分类、汇总和搬运权威质控事实，计分复用scoring_service。不改执行器、历史分数或执行默认配置。

**技术：** FastAPI、SQLAlchemy、现有配置注册表、Vue/Ant Design Vue、pytest/SQLite、Vitest。

## 已确认合同

- 用户本轮“ok”采用八类可重叠、显式院方代码与实际实施来源、缺失未知；专用标准产生独立报表评分，标记版本，不覆盖历史结果。
- 类型为死亡、危重、疑难、会诊、输血、手术、三级及以上手术、四级及以上手术；按类型、科室、出院日期查询。
- 数量Top5按科室，等级分布与缺陷Top10；缺陷明细包含名称、提醒等级、大类、类型、文书、单否、数量和占比。病例下钻是补充，不能代替缺陷明细。
- 全部匹配出院病例构成候选队列，不用已有ready质控结果替代分母。缺来源、分类未知、无可用评分或结果须分别表达，不伪造0/满分。
- 查询、分页与导出同筛选口径；查询配置版本/标准绑定版本须可识别，错误、超限和并发变化明确返回。

## 来源核查

- 原始CDM工作簿“病案首页输血记录明细”第16行备注只有发血时间，禁止默认作实际输血依据。
- “病案首页医院自定义明细”第13行出院情况备注其他机构转入，禁止默认作本次死亡依据；第23/24行危重与疑难标志备注无数据，不能假定医院已供数。
- 真正死亡记录第31行和24小时入院死亡记录第38行提供death_datetime；输血记录第33/38行提供剂量和transfution_datetime。只读白名单结构化源字段，缺列未知，不从文书标题或全文猜测。
- 手术明细第12/17行提供手术级别与实际开始时间；会诊文书第25行提供会诊时间，接线须复核本地同步字段。
- 配置可复用qc.sync_config_registry表，但本模块持久CAS/审计和故障语义独立，不调用具有文件回退的公共配置读写方法。不新增真实库迁移或代填院方代码。
