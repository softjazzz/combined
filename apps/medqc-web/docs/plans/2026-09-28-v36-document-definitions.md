# V3.6 文书定义列表与导入实施合同

**Goal：** 收口PRD70文书定义列表、71文书定义导入；72名称搜索另批实现。

**Architecture：** 新建正式 `qc_document_definitions` 存储，仅管理类型名称和纯文本模板。不复用测试环境分类表，不接入患者文书、规则执行器或模板执行引擎。

**Tech Stack：** FastAPI、SQLAlchemy/PostgreSQL、openpyxl、Vue/Ant Design Vue、pytest、Vitest。

## 依据与边界

- PRD第300、301行要求查看已导入文书类型/模板，并可导入定义且校验字段；未约定外部模板格式。本批提供明确的本系统XLSX格式，不宣称兼容未知客户模板。
- 字段为文书编码、名称、分类、模板内容；四项必填。模板按纯文本显示，不执行HTML、公式、占位符或校验脚本。
- 全局编码唯一；只新增，不覆盖既有定义。批次ID、操作人和时间保留来源；不存原始文件名，不记录模板正文日志。

## 实施与验收

1. 后端新增定义模型、服务、Excel解析与路由，在主应用注册；迁移70接69，检查qc/public两schema新表约束。仅编写迁移并运行合成测试，不执行真实库迁移。
2. `GET /api/v1/document-definitions` 返回可信总数与分页列表，按创建时间倒序及编码稳定排序；管理员和质控经理授权，未知/故障不伪装空列表。
3. `GET /api/v1/document-definitions/import-template` 下载单Sheet“文书定义”的XLSX，表头为“文书编码/文书名称/分类/模板内容”。上传使用同前缀 `POST /import`，文件不超过2MiB、有效行不超过500；限制压缩包及解压资源并拒绝非模板内容。
4. 全文件解析校验后才开启写入事务；文件内重复、库内重复或并发唯一冲突均整批失败。字段错误返回Sheet/行/字段/错误原因；成功回执包含批次和准确新增数，不对未知提交结果建议盲目重试。
5. 前端新增V5“文书管理”入口、真实列表分页、纯文本预览与导入抽屉；模板下载、字段错误、忙状态、刷新及账号切换/卸载迟到响应均有测试。不做72名称搜索，也不添加编辑、删除或规则映射等范围外功能。
6. 主协调复核关键diff，集中跑相关pytest/Ruff、聚焦Vitest、type-check、只读ESLint、编码及暂存清单；通过后更新80项账本并单独提交。
