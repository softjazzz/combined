# 客户机前后端运行版本核对

## 目标与证据

用户需要排除旧后端进程、旧前端缓存造成的新旧混用。现有runtime_build.json是磁盘发布声明，按请求读取不能证明进程使用的是该版本；生产前端是静态文件，也不能依据服务器当前元数据判断浏览器已加载的JS。

方案采用编译内嵌前端身份+后端启动快照。静态版本文件单独展示无法识别旧进程；仅新增健康检查也无法识别旧前端，因此不采用这两种方案。

## 合同

正式客户构建将同一build_id和git_commit写入前端编译常量、dist/build-info.json及既有backend/app/data/runtime_build.json。前端展示只用编译常量；build-info文件供打包校验，不作为浏览器所加载版本的权威。单独customer Vite配置继承现有配置，不修改工作区已有vite配置改动。

后端启动时只读取一次发布声明，记录UTC started_at、PID，GET /api/v1/runtime-build只返回冻结安全字段并禁止缓存。接口不暴露路径、凭证或数据库内容，不查询数据库。文件缺失/非法时明确available=false，不推测Git版本。启动日志保留同样身份。

页面顶部简洁显示状态及前端短构建号，详情显示完整前后端构建号/提交、后端启动时间/PID和重新核对。两端build_id及commit均一致才显示一致；不匹配、旧后端404、不可连接、未标记构建和开发环境分别处理，不能错误显示绿色。定时仅可见页检查，切回页面/手动可刷新，请求有超时、防重入和销毁清理。

本次只验证浏览器与请求实际到达的后端，不能证明客户原本计划安装哪一个包；详情中的完整构建号仍需与交付包编号核对。多实例后端通过PID和启动时间可识别请求到达实例，不新增实例追踪平台。

## 范围与边界

后端新router+main注册/启动hook+公共路径；前端独立版本组件/service+WorkstationLayout两处接入；打包脚本/独立customer配置/plugin/聚焦测试。现有较长的main与layout仅作挂载，不放入新的独立业务逻辑。保留用户其他未提交修改。

-SkipBuild不再允许客户版本打包，明确拒绝并要求重新构建，不把新号贴到旧JS。AllowDirty仍可重新构建非正式包，不产生正式后端版本声明。新环境变量在build后恢复。

## 验收

- 旧后端启动后修改磁盘声明，接口身份/PID/时间不变；新实例读取新声明。
- 浏览器已加载A、后端B显示不一致；一致/缺标识/404/错误正确区分，错误不能保留旧绿色。
- 两端构建号与commit来自同次发布；实际构建输出包含编译身份且元数据相同。
- component/service聚焦单测、后端endpoint单测、打包契约测试、前端类型/编码/lint/单测；实际页面检查弹出详情与刷新。
- 不杀客户进程、不改客户数据库、不自行替换既有发布包。本次功能须重新构建部署后才能用于客户机。

## 完成验证

前端全量 933 项单测、类型检查和无自动修复 ESLint 通过；后端启动快照 3 项测试、打包身份 3 项测试通过。实际 customer 构建成功，验证 JS 内嵌身份与 build-info 完全相同，测试产物不作为正式发布包。14 个任务文件独立通过 UTF-8 无 BOM/LF 检查；既有编码脚本扫描 0 文件，因此未依赖其空扫描结论。浏览器验证顶栏入口与详情：本地开发环境正确显示开发标记，仍运行的旧后端返回缺版本接口时明确提示“后端尚未提供版本信息”，无错误绿灯。
