# V5 用户管理入口

用户需要管理员查看和管理用户列表。既有账号服务已具备持久账号列表、搜索、角色/启停筛选、分页、编辑及注册审批，本次只补齐可发现的独立入口，复用原有 owner。

## 改动

- 侧栏“数据与配置 → 用户管理”，直达 `/workstation-v5/users`。新页面复用 `AccountManagementPanel`，同时保留用户列表及注册审批。
- 菜单按路由 meta 权限过滤；仅 admin/sync_admin，医生、质控员及质控主管不新增管理权限。服务端仍按持久账号角色、启停和机构范围授权。
- 列表展示姓名、用户名、机构/科室、角色、启停状态及最近登录；搜索、筛选、分页和编辑继续调用原有 API。
- 无邮箱注册账号的 DTO 如实允许 NULL；打开编辑时转换为空表单值，不强制新增邮箱，也不在修改账号请求中补写邮箱。
- 账号列表、注册队列和申请详情采用不加行锁的持久管理员校验，使只读查询不再执行 `SELECT FOR UPDATE`。创建、修改及审批仍保留默认的管理员行锁、写锁和版本检查；权限判据不变。
- 旧 `system-config?tab=accounts` 及带 `registration_id` 的通知深链继续有效，未改 V7.1 Layout、图标、主题或全局 CSS。

## 验证与边界

- 5 个前端文件 50 项通过：独立入口与角色过滤、旧链接、账号空邮箱编辑、注册审批、旧导航及 22 项 V7.1 保护。
- 后端账号管理及注册 45 项通过，全部采用合成 SQLite；增加 PostgreSQL 方言 SQL 编译检查，确认列表无行锁、创建仍加管理员行锁。
- 聚焦 ESLint、Ruff、编码和类型检查在交付前执行；不重跑全量质控。
- 不写本机业务库，不新建/启用管理员、不调用模型。上一轮验收的临时管理员及医生保持停用；本轮没有有效管理员登录，因此未宣称完成新入口的真实管理员浏览器验收。
- 沿用独立注册分支，不改业务集成分支、不推送合并、不打包。页面的实际维护操作仍受当前只读启动方式限制。
