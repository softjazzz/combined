# 质控结果区紧凑工作台设计

## 背景与目标

当前单病历质控结果已经通过 `CanonicalQcResultEnvelope` 直通前端，但结果区仍采用多层卡片和纵向堆叠布局。规则数量达到 49 条时，用户需要频繁滚动，折叠态也难以快速判断问题。

本次仅重构整个质控结果区，包括顶部统计、状态筛选、结果列表、展开详情和证据入口。病历目录、任务信息、后端接口和 Canonical Envelope 均不在改动范围内。

## 设计原则

- 一个连续工作台承载统计、筛选、结果列表和详情，不使用卡片套卡片。
- 保留医疗中后台所需的信息密度和可扫描性。
- 风险颜色只用于真实风险、数据不足和技术异常状态。
- 前端只渲染后端结果，不重新计算、推断或改写业务结论。
- 所有状态均可展开，证据定位事件保持兼容。

## 信息架构

### 顶部工具栏

左侧展示“质控结果”和总数，右侧使用紧凑分段筛选展示全部、不合规、数据不足、技术异常等状态及数量。筛选只控制可见项，不改变结果内容。

### 折叠结果行

结果行使用双层结构：

1. 第一行展示状态标识、规则编号、规则名称和展开按钮。
2. 第二行展示后端结论，最多两行。

状态颜色只出现在小型状态标识和左侧细线。结果行之间使用弱分隔线，不把每一条结果做成独立悬浮卡片。

### 展开详情

展开区域使用一块连续表面：

1. 顶部为判定摘要。时限类问题优先横向展示规定时限、实际间隔和超出时限。
2. 中部使用双栏布局。左侧展示判定事实、判断标准和数据缺口；右侧展示核对文书、关键证据和定位入口。
3. 底部展示处理建议。模型分析仅在存在内容时出现，并降低视觉权重。
4. 窄屏自动降为单栏，不隐藏业务字段。

## 视觉与交互

- 页面底色沿用 `#f5f5f7`，结果区使用白色或低透明度白色主面板。
- 工具栏高度约 48px，状态筛选高度 30–32px。
- 折叠行内边距约 12px 14px，规则标题使用 14px/600，结论使用 13px。
- 规则编号使用中性灰标签，所有可见枚举翻译为中文。
- 展开态使用浅灰背景和左侧蓝色强调，不增加多层边框。
- 时限类指标带展示“规定时限 / 实际间隔 / 超出时限”。超出时限使用风险红，其余指标保持中性。
- 时间点使用“起算时间 → 记录时间”的紧凑时间轴表达。
- 证据使用列表行，展示文书名称、字段或摘要和“定位原文”动作。无定位能力时不展示伪交互。
- 只使用轻量 CSS 过渡，不引入动画依赖。

## 数据边界

数据链保持：

`CanonicalQcResultEnvelope → 数据库原样保存 → 单一结果 API → 前端结果模型 → 只渲染`

本次不新增 DTO、状态映射或前端二次结果投影。字段顺序、结论文本、状态、事实、证据和 `locate-evidence` 事件参数保持不变。

缺少单个事实字段时仅隐藏对应指标。时限字段不完整时回退到普通事实列表。数据不足和技术异常不进入风险指标布局。折叠态限制结论行数，展开后展示完整内容。

## 验收标准

- 顶部统计和状态筛选合并为紧凑工具栏。
- 结果折叠态可在两行内识别状态、规则和结论。
- 时限结果正确展示 `8 小时 / 448.6 小时 / 440.6 小时`。
- 事实、标准、数据缺口、证据和建议使用连续详情布局。
- 全部状态仍可展开，证据定位事件参数不变。
- 现有组件测试保持通过，并增加布局与交互断言。
- 完成功能闭环后集中执行组件单测、编码检查、lint 和类型检查。
- 不使用浏览器进行验收。
