# CT 纯引导操作项目的结果规则边界

## 证据、假设与定位

基线 aa0ca649d。C05#3 的冻结报告只含“CT引导下操作。”；同一 EvidenceReadSession/MaterialStore 的当前只读核对也只有同检查号的一条主记录及一条报告，身份字段为空，record_content/impression 仅含该项目标签。读取时点保存在忽略目录 c05-scope-20260914/c05-scope-read-private.json，不声称新读取与旧 snapshot 完全相同。

已运行最小真实投影调用：主记录与报告仅含上述标签，仍生成 target_confirmed=True、result_text_available=True、positive_hint=unknown。断言“纯操作项目不能自动成为确诊断结果事件”失败。这说明候选关键词识别范围大于011/012诊断报告结果规则范围；尚不能据此排除所有引导或介入检查。

原有三个待验证假设为：操作项目误入诊断结果范围、诊断报告未同步、模型误读。保存正文和字段缺省情况不支持直接认定模型误读。拟采用可证伪的最窄分类：只有已提供正文完全等于纯引导操作标签，且无冲突检查名称、无任何额外结果内容时，标记为 guidance_only。其他情况均维持原行为。

## 业务依据与适用边界

011/012以客户正式目录中“影像报告结果”及“阳性结果”为对象；010检查前原因不是本轮改动范围。国家卫健委《放射诊疗管理规定》将介入放射学与X射线影像诊断分列，并定义影像引导操作：[官方来源](https://www.nhc.gov.cn/wjw/bmgz/200601/bcd50643d52643c5b669062484f9398e.shtml)。这支持区分操作角色和诊断结果角色；**官方文件没有逐项规定本项目011/012的排除算法**，以下为结合客户规则对象作出的工程口径推导。

仅“CT引导下操作。”纯标签不提供诊断结果，按明确操作性项目处理，011/012对此事件不适用；不将它分类为“阴性”。任何独立诊断所见、普通CT检查名、非空附加结果或诊断报告缺失的普通检查，均不适用这个例外。010保留其原检查前原因判定。所有原事件和文书位置保留，不删除事件或重排编号。

## 验收与停止条件

先红后绿：纯操作项目011/012不适用且不调用模型；同一业务键出现真实结果时不得豁免；仅检查名而无报告时不得豁免；跨业务键诊断报告不受影响；010事实及终态保持原值。非法模型字段仍是执行失败，不能以角色例外吞掉任意坏JSON。

审查后的明确约束：同事件必须存在exam_item_report来源且该来源正文满足纯标签条件，主记录即使有同标签结果字段也不能单独豁免。纯操作事件的course_doc_positions必须为空，非空按value失败进入既有恢复，不静默删除引用后记成功。012输出schema继续使用unknown表达没有阳性判定，内部事实因角色明确归一为not_relevant，绝不归为negative。

真实C05从同一当前MaterialStore构建前后投影并比较；其余事件的业务键、坐标、允许病程、时间和正文零变化。保护集合为上一轮18个事件规则金标对，基于8d8a1460c冻结输入，及aa0ca649d下当前读入资料的改前投影；不混淆不同资料时点。此次先不迁移单事件LLM合同，C06/C12模型改造沿原隔离实验继续验收。

风险：标签不是诊断结果，但可能反映上游接口只同步了操作项目；遇其他正文、缺失来源或冲突字段不得沿本例泛化豁免。若真实当前资料不再满足纯标签条件，停止该例分类而非扩大匹配词表。
