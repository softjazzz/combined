# 双临床数据源并存 Implementation Plan

**Goal:** 保留原数据源，在系统后台配置旧源及已有独立CDM，设置默认源，运行/终末病历列表按源切换；既有任务、结果和1026材料不串库。

**Architecture:** 在最新业务d0dd97c73的独立工作树中承接Linux交付6206eef96（含PR34/35前置），复用双链路9a0bce6ac。业务engine/SessionLocal固定；临床读取通过显式source_id和绑定版本选择旧业务CDM或独立只读CDM。默认只影响新选择，任务持久记录来源，PDF副本继续使用业务登记及材料schema。

**Tech Stack:** FastAPI / SQLAlchemy / PostgreSQL、Vue3 / TypeScript / Ant Design Vue；隔离固定应答及两个一次性PG数据库。

## ADR与边界

- 不将DATABASE_URL改为临床库，不将业务迁移应用到同步库；不重建抽取服务，不启用定时、模型或实际质控。
- 数据源设置与原抽取链路控制分工：保存/默认切换不提交同步或质控。既有源默认启用、默认选中；独立CDM在配置与只读检查后由管理员明确启用。
- 持久管理员可配置；连接凭据独立保护、不返回浏览器或日志。源不可用显式失败，不读另一库或内存。
- 病例列表、详情、Bundle、任务读取使用一致来源；缓存及最新结果不能将两源同三坐标病例混用。老任务明确兼容为旧源，不通过当前默认重新解释；1026材料固定业务库。
- 两个真实独立PG测试库放同键异值材料，源账号写入拒绝，业务缓存/结果写入仅在业务库。无MR首页但有其他文书的病例需能发现；无权威出院信息不伪造终末状态。

## 实施步骤

1. 新建独立分支并保留原改动；复用9a0bce6ac，逐文件解决与P5-B、Linux及既有规则/PDF边界的冲突，不整文件覆盖。
2. 核对services/data_pipeline_settings.py、database/clinical_connection.py及读取入口，补数据源配置owner、默认源、请求/任务固定来源和缓存绑定。测试配置失败关闭、凭据不泄漏、旧配置兼容。
3. 核对routers/records.py及病例池实际查询，复用取材/权限过滤，增加按源列表和详情；补同键异值、缺首页、权限/缺表/断连与真零行差异测试。
4. 核对workspace任务创建、执行入口及Canonical读取，持久传递来源；默认切换不改旧任务。保留PDF材料、历史选轮和失败结果行为。
5. 复用后台面板，补数据源配置、启用/只读检查/默认选择及运行/终末列表选源；补定向组件/API测试、类型和只读lint。
6. 使用本机独立原生PG集群的两个一次性数据库和合成数据验证正式公开读取入口、业务缓存写入及源只读；阻断外部网络、拒绝业务端口/目录。当前不部署、不写真实业务库、不连接模型或重跑病历。
7. 提交本地独立成果，汇报基线/依赖、验证命令、通过/跳过/未覆盖及后续DSH接入要求。本轮未授权推送、PR或部署，不自动执行。
