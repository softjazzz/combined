# 演示账号仅展示确定问题

## 用户确认与范围

用户明确选择“只保留确定问题”。在独立 `codex/demo-qc-result-visibility-20261025`（基于f05b1e892）实现账号驱动的结果面板展示，不改集成分支、质控执行器、持久化结果或业务数据库。模型调用与质控重跑均为零。

## 展示策略

- 认证账号具有sync_admin、super_admin或developer角色时显示完整结果。此优先级必须高于is_demo_account：内置sync_admin账号同样带演示标记。
- 非开发角色的演示账号只显示canonical non_compliant“确定问题”。合规、不适用、待处理、资料不足、暂停和技术失败详情不进入分类、列表或临床计数。内部条目不展示。
- 明确非演示账号保持原完整视图。认证未就绪或缺演示标记时默认只显示确定问题，防止加载时闪现完整结果。
- 任务排队/运行/部分失败/失败等执行状态保留。单病历技术失败有独立提示，不把无确定问题写成“全部通过”。
- 单病历平铺、分组视图、原文对照及批量按病历视图共用展示策略；分类、摘要计数、原文定位条目同步过滤。保留原输入及规则身份，分组不重新编号。
- 演示结果面板隐藏高级视图、诊断包和完整结果导出入口，避免从这些按钮重新展开隐藏结果；开发账号保持原有功能。导出/诊断处理函数也检查当前展示权限，异步返回后再检查。

## 实现边界

这是UI展示限制，不是新的后端数据授权边界。服务端原有机构/对象/角色授权及结果查询合同保持不变，完整结果仍存库，开发账号可读取；本次不改API响应、不改变质控状态或重算数据。已登录账号信息来自现有auth/me；不依赖前端账号名称判断开发身份，不修改账户角色。

Auth API用户角色类型补入既有sync_admin字面量，个人资料角色展示同步适配；保留原UserRole枚举和旧权限映射不变，不授予其他业务操作权限。
