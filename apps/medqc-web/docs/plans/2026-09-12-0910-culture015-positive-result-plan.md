# 015：备选空菌栏不得覆盖已填写菌名

## 目标、证据与待证伪假设

2026-09-12，主协调核对正式目录 015 原文与业务基线第 82 行：已有阳性菌结果后 24 小时内记录分析、临床意义或处理；不要求等待药敏齐全。现有提示词却写“阳性但药敏待出时015为unknown”，与该规则要求不符。

真实 C01 Bundle 投影中两个已绑定培养事件的 `item_name=细菌结果（质谱法）1：`、`result` 为已填写菌名，其他菌栏为空；允许病程位置分别为 2/6，主协调逐份阅读，未见针对这两个培养事件的结果分析。不能用另一标本的处置替代。本轮仅评价是否记录分析，不诊断感染、不评价用药是否正确。

原始输入保存在 `.tmp/0910-full-audit/culture015-source-input-private.json`；固定回答回放 `n012-full30-culture015-counterexample-private.json` 仍为 `uncertain/semantic_output_unknown`。反例命令使用 `n012_full30_replay.py culture015-counterexample --freeze-from culture015-policy-after-qwen3.7-flash-r2-private --cases C01` 后断言 015 为 non_compliant，已运行并失败。

根因假设：可靠的结构化菌名格没有转为已有 `positive_hint`，模型又可能受空备选栏/等待药敏指令干扰。仅纠正提示词的 4 次实测仍有一次 unknown，故不能单靠提示词宣布解决。子代理必须独立证伪此假设。

## 最小实施

文件白名单：`backend/app/services/luxian_0609/exam_lab_fact_extraction.py` 与新测试 `backend/tests/unit/test_luxian_0609_culture_identified_organism.py`。

1. 在现有培养 `positive_hint` 所有者处识别同一已绑定培养事件里的可靠结构化结果：仅处理“细菌结果”含可选方法括号/编号/冒号的项目名，结果为非空中文菌名称值；排除否定、不确定、未填写、正常菌群/混合菌群等含混描述，不扫描病程或任意检验值，不硬编码院内 item_code 或本例菌名。其它结果继续受控模型判断。
2. 结构化阳性与明确阴性/污染/待排信息冲突时保持 unknown，不能把冲突强判阳性。注意主栏与备选栏的含义，不因空备选栏把已填写菌名降级。
3. 不改变现有事实解析、窗口、最终状态或原因码；可靠阳性只填既有 positive_hint，由既有 Python 校验覆盖模型阳性枚举。分析/处置关联仍由原路径负责，不凭菌名捏造分析。
4. 纠正提示词的药敏前置条件，说明已明确菌名与备选空栏；不得把未出结果或污染可能当作阳性。

生产文件本轮不增加独立职责，仅补足现有结构化阳性事实提取，预计增量小于 60 行；不引入新 Bundle、模型层、注册表或状态所有者。巨型 native 文件不修改；新增边界测试单独成文件。
