# V3.6 PRD 28 病历详情缺陷分区合同

## 1. 范围与结论

本批只补运行/终末病历详情的五个缺陷查看入口，不修改质控执行器，不新建第二套缺陷判定，不修改数据库。

五个入口为：全部缺陷、单否、人工、编码、核心制度。“全部缺陷”严格指本次 LX0609 Canonical 结果经客户投影后 `is_confirmed_issue=true` 的确认缺陷，不把技术异常、资料不足或 AI 建议重判为缺陷。

本批不交付两项能力：

- 核心制度分类：规则目录与结果 DTO 没有权威归类，页面固定显示“未接入（缺核心制度归类）”。
- 精确命中片段定位：现有 evidence 只能支持已授权的文书/字段级依据核对；片段或偏移需要执行器输出，属于质控引擎范围。

因此 PRD 28 仍为部分实现，不能整项提升为完成。

## 2. 单一事实 owner

| 分区     | 权威来源                                                               | 本层职责                                            |
| -------- | ---------------------------------------------------------------------- | --------------------------------------------------- |
| 全部缺陷 | LX0609 Canonical 客户投影 `is_confirmed_issue`                         | 只按 `rule_id` 装配本次结果条目                     |
| 单否     | 场景默认评分标准的 `scoring_service.score_case().deductions[].is_veto` | 只搬运同一 `job_id` 的单否规则                      |
| 人工     | `list_case_manual_defects` / `GET /api/v1/manual-defects/case`         | 预览最近 200 条并保留精确 total；既有审核页入口不变 |
| 编码     | 现代结果 `source_key=coding_qc` 的最新结果及 `current_result_defects`  | 预览本次前 50 条；既有编码质控入口不变              |
| 核心制度 | 尚无权威分类 owner                                                     | 明确未接入，不按规则名称猜测                        |

## 3. 接口

`GET /api/v1/qc/sichuan/workspace/records/{visit_id}/defect-partitions`

参数：`institute_id`、`patient_id`、可选 `scene=running|final|outpatient`。病例身份始终为机构、患者、就诊三坐标。权限与 LX0609 单病历最新结果一致。

响应回显三坐标和非空 `job_id`。前端只有在三坐标及 `job_id` 与当前详情完全一致时才展示 Canonical/单否分区；ready 结果缺少 `job_id` 时两区均不可用，空字符串不得互相匹配通过。病例或结果切换后丢弃旧请求的迟到响应。

`confirmed.source=luxian_0609_canonical_projection`，`veto.source=scoring_deductions`，`core.source=core_system_classification`。本接口不代理人工和编码 owner。

## 4. 无结果与失败语义

| 情形                       | 展示                                         |
| -------------------------- | -------------------------------------------- |
| Canonical 确认缺陷为 0     | 当前分区暂无缺陷                             |
| 未配置场景默认评分标准     | 未配置评分标准，不显示 0                     |
| 单否分区可用               | 显示默认评分标准名称，避免与列表另选标准混淆 |
| 人工缺陷查询成功且 total=0 | 当前病历暂无人工缺陷                         |
| 无最新 `coding_qc` 结果    | 未做编码质控，不显示 0                       |
| 最新编码结果缺陷为 0       | 本次编码质控未发现缺陷                       |
| 任一 owner 读取失败        | 该分区独立显示失败和重试，不拿空数组冒充成功 |
| 核心制度                   | 未接入（缺核心制度归类）                     |

后端底层异常统一脱敏；不得返回连接串、SQL 或患者正文。

## 5. 前端交互

五分区使用紧凑分段控件，计数不可用时显示 `—`。人工或编码结果超过本批只读接口上限时明确标为预览，既有完整业务入口保持不变。Canonical 条目只显示既有来源文书名；人工、编码条目不伪造定位能力。快速切换病例时，旧请求不得覆盖新病例。

## 6. 验收边界

- 后端：权限、来源、同结果绑定、未配置标准、无结果、局部失败和脱敏错误测试。
- 前端：五分区切换、各 owner 来源、未配置/未质控/错误、身份错配、迟到响应和角色挂载测试。
- 不写业务库、不执行迁移、不调用 LLM。
