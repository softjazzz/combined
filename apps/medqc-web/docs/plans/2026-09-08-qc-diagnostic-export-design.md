# 诊断包增强：保存结果的批量核查

## 问题与范围

客户反复复制单条规则，难以比较同一病例全部规则的原因码、事实和证据。网页实际入口为 QCRecordResultComparisonDrawer → QcDiagnosticExport → buildQcResultDebugText，输入为 latestResult.items。后台历史受限 ZIP 只支持 032/066 文案投影，不能把它当作全部规则执行回放。

本次复用网页已有的全部已加载结果与脱敏器，增强同一个 Markdown 下载文件。正文仍可人工阅读，末尾增加 JSON，包含结果白名单字段、按状态/原因分组的规则索引、按来源类型区分的证据引用计数。文本与 JSON 同次脱敏，下载与确认预览使用同一快照。

不重新读取数据库来替代当次输入，不新增第二套材料来源。未采集的执行输入、源读取状态、模型请求响应、执行版本明确列为 missing_components，replay_capability 为 manual_review。证据引用数量不能当作查询返回行数。完整性同时核对本包数量、不同规则数、任务数量、缺失/冲突标记，不能把筛选后的单条结果称作全量。

## 文件与验收

- qcResultDebugExport.ts：可选诊断包输出；普通复制保持原格式。
- qcDiagnosticSummary.ts：只汇总已脱敏结果，不解释业务状态。
- QcDiagnosticExport.vue：启用增强输出，保留人工确认和 2 MiB 上限。
- 聚焦测试：72 条结果、子集与重复规则、不同源同引用、日期间隔、脱敏白名单、确认后的下载快照。

## 剩余限制

这次增强改善批量核查和本机解析，但不能仅凭导出的结果还原 CT/MRI 医嘱与检查主记录的匹配过程。源读取状态和关联候选的执行时采集需要另一个明确的业务闭环；旧任务没有采集的信息不能事后伪造。此次无数据库迁移，无新增 LLM 调用，不构建客户发布包。
