发现业务缺陷时固定反例，另立修复提交。

- 事实验证集中在 2232–2592，规则专属证据策略还分散在文件开头、4507–4569、
  5014–5032 和 5253–5256。

### 首批候选：人工问题分类与规则推荐

**选择依据：**

- 主要逻辑是确定性纯函数和受控 LLM 输出合同，不共享数据库 session、同步水位或行锁。
- 现有单测从约第 188 行到 1133 行集中覆盖各类问题文本、会诊/入院 LLM 推荐和候选规则。
- 该职责被创建样本、刷新分类、fallback 候选及展示读取复用，修改时容易与同步和 CRUD
  同文件冲突。
- 迁移可显著减少样本池服务的概念数量，同时不触碰高风险同步事务。

**拟迁出的完整职责：**

- 问题文本规范化和各问题族识别；
- 确定性分类、动态候选规则合并和白名单；
- 入院一致性、会诊族受控 Prompt、输出解析和规则推荐；
- 构建样本项分类更新；
- 分类专用规则元数据加载。

远端连接错误分类、Excel 读取、匹配评分、住院状态和同步签名不进入该模块。

**建议文件范围：**

- 新增 `backend/app/services/sample_issue_classification.py`；
- 修改 `backend/app/services/custom_qc_sample_pool_service.py`，保留已被外部导入的兼容名称并
  委托新模块；内部消费者直接导入新模块，避免两套实现；
- 新增 `backend/tests/unit/test_sample_issue_classification.py`；
- 更新 `backend/tests/unit/test_custom_qc_sample_pool_service.py` 的服务集成测试；
- 仅当路由直接导入分类函数时修改对应 import，不改变 API DTO。

**冻结基线：**

- 空文本、内在质量默认分类、首次病程/查房/会诊/手术/输血/交接班/复制问题；
- 入院一致性和会诊族 LLM 正常、部分、非法 JSON、越界置信度与未知规则；
- source table 动态候选、规则白名单和候选顺序；

**规模门禁：** 预计迁出 1200–1900 行完整分类职责；兼容导出只允许薄别名或显式 import，
不得保留第二份实现。生产代码净增应接近零，新增行主要来自模块头部和明确接口。父文件
目标减少相同量，但验收以单一实现和回归等价为准。

**主要风险：** 现有测试和路由可能从原模块导入函数；分类依赖规则元数据和 LLM 调用协议；
不正确的拆分会改变候选顺序或 Prompt。先建立 import/caller 清单，并固定输出顺序。

**回滚：** 保留 `CustomQCSamplePoolService` 公开类和路由 API。若任何冻结分类或 Prompt
漂移，整结构提交回退；不得用两套实现或运行时开关维持兼容。

## 排期与停止条件

1. 当前会诊族验收补齐完成后，先实施检查检验客户投影迁移；它直接减少聚合器的重复业务
   所有权。
2. 检查检验结构提交全绿后，再实施样本问题分类迁移；两个大文件不能同时改，便于归因。
3. 每个结构提交完成即暂停审核，不连续迁移下一个规则族或同步模块。
4. 若冻结测试发现旧缺陷，保持结构前行为完成迁移，随后另立最小缺陷修复；安全漏洞除外。
5. 若首批候选实际迁出少于 250 行、需要新增第二套状态机/注册表、或必须修改 API/数据库
   合同，停止实施并重新评审边界。
