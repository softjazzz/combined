# V3.6 病历能力整项收口依赖（PRD #21/#24/#25/#27/#28/#29）

> 2026-09-27 只读核对结论。本文只说明代码收口边界，不代表非生产验证、业务库部署或真实病例验收完成。

## 结论

这六项当前没有可在不改变 PRD 口径的前提下快速升为“代码完整”的整项。共同根因是运行病历范围尚不能可信识别“出院未归档”；不能用当前在院子集冒充完整运行范围。

`#25 病历列表批量操作` 最接近完成：当前在院列表已能按三坐标创建四川 workspace 任务、轮询并展示进度、完成后刷新。但 PRD 的模块范围仍要求完整运行病历，且全局验收要求所有批量操作具备权限校验、二次确认、结果和审计。因此只能保留为部分实现，不能因当前在院子视图可用而升整项。

## 可信范围证据

- PRD 将运行病历定义为“入院到归档”，明确包含当前在院和出院未归档；运行病历查询验收要求可查询完整运行范围（`docs/PRD-内涵质控V3.6总需求与差距矩阵.md:151-165`）。
- CDM 模型虽有 `cdm.mr.archive_sign`，但仅注释为“归档标志”（`backend/app/database/models/cdm.py:218`）；仓库未找到该字段的 ETL 映射或院方确认值域。
- 既有只读数据核对中，`cdm.mr` 482 行有 481 行 `archive_sign` 为空；191 行已出院中 190 行为空、仅 1 行为“是”。空值不能解释为未归档，出院时间也不能解释为已归档（`docs/plans/2026-09-23-task-scene-candidate-source-audit.md:10-19`）。
- `CaseScopeService` 只提供 `active`、`discharged`、`active_and_discharged`，按入院/出院事实分类，不读取归档状态（`backend/app/services/case_scope_service.py:15,600-606`）。因此现有接口只能可信区分在院/出院，不能构造“出院未归档”。

## #25 现有实现的准确边界

- 前端 `src/views/workstation-v4/components/qc/QcRunSelectedControl.vue:262-274` 只允许 `carePhase=inpatient`，提交完整 `institute_id/patient_id/visit_id`，创建 `scope=running` 任务；`214-250` 轮询并反馈完成/失败。
- 后端 `backend/app/routers/qc_sichuan.py:1969-2048` 具备产品激活校验、创建者所有权、运行中幂等复用，并对归档未核验范围失败关闭；成功创建路径没有显式 `audit_event`。
- 触发按钮直接调用 `startSelectedQc`（`QcRunSelectedControl.vue:3-8`），当前没有二次确认。PRD 全局验收要求见 `docs/PRD-内涵质控V3.6总需求与差距矩阵.md:415`。
- 病例操作时间线会合并质控运行、审核、人工缺陷和任务完成事件（`backend/app/services/case_operation_timeline_service.py:283-314`），但任务事件不能替代操作接口自身的成功审计。

## 后续解阻条件

1. 医院确认归档状态的来源表/字段、全量覆盖率和值域，并给出已归档、未归档、未知的明确映射；未知必须失败关闭。
2. 产品/医务确认五类缺陷的规则到分类权威映射；执行器输出稳定的文书标识及命中 snippet/offset。
3. 缺陷整改、申诉复核分别由既有权威 owner 输出规范状态，运行缺陷列表只搬运，不重判。
4. 确认医生身份到系统用户/通知通道的映射，以及单病例评分标准调整的权限、版本与审计合同。

在这些条件满足前，可继续交付各自独立子能力，但覆盖审计必须维持“部分实现”。
