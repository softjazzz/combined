# 注册表单精简与本地科室目录

用户决定：注册不再填写工作邮箱、申请机构 ID，科室必须从本机 PG 已有数据选择。

## 实现边界

- 独立分支 `codex/registration-department-20261025`，基于合并后的 `b34f539cf`；不改业务集成分支。
- 新增公开只读、限流的科室目录接口，仅投影科室名称、选项标识和显示标签，不返回患者、文书或账号数据。
- 临床读取复用 Bundle 的 `clinical_read_schema`，split 模式固定 `cdm`，不回退 `public` 同名旧表。从首页、入院登记、出入院记录提取实际存在的机构/科室配对，去重并排除空值和已删除记录；同名跨机构选项分开展示。
- 新表单仅提交科室选项标识；后端重新读取目录，解析机构与科室，拒绝失效选项或与显式机构文本混传。旧客户端的显式申请字段保持兼容，均只是待审批申请，不授予业务权限。
- 部署可以通过 `REGISTRATION_INSTITUTE_ID` 限定注册目录，未设置时复用 `HOMOLOGY_TARGET_INSTITUTE_ID`，均为空才展示多机构选项；不接受公开接口传入机构范围。当前只读查看进程限定泸县人民医院，排除本机历史测试机构，未修改业务库或原 `.env`。
- 邮箱可空，不生成虚假邮箱，不要求迁移。旧账号继续使用邮箱令牌，新注册无邮箱账号通过既有持久账号 ID 解析链登录和刷新。
- 审批、机构范围、停用、版本冲突和通知事务保持原 owner。待审批账号仍不得登录。
- 科室加载、空目录、读取失败及重试有明确状态；目录不可用时禁止提交，不伪造科室或成功结果。

## 定向验证

- 注册申请/审批 HTTP 链：22 项通过（含无邮箱申请、待审批禁登录、审批后登录/me/刷新、驳回重提、失效选项及机构混传）。只用合成 SQLite。
- 临床 owner 保护：1 项通过，`cdm`/默认同名表内容不同时只读取 `cdm`，跨机构同名选项保持独立。
- 前端申请、API、审批面板：3 文件 14 项通过。
- 本机真实 PG 只读目录核对：113 个非空选项，`sys_users.email` 在 sys/public 均允许 NULL；未修改业务数据或结构。
- 类型、暂存文件编码、聚焦 ESLint/Ruff 通过（ESLint 无错误，保留既有 Vue 模板格式警告）；没有重跑全量质控或调用模型。

本机仍为只读查看模式，注册审批表缺失的问题不通过本次改动规避。正式注册/审批持久化仍需后续按已有迁移升级，不能把表单可见当作客户机闭环验收通过。
