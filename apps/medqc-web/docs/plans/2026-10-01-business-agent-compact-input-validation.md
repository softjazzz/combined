日期：2026-10-01。独立分支 `codex/medqc-business-agent`，基线 `8c7162218`。沿用既有 qwen3.8-flash、每轮60秒/最多8次实际工具读取，不扩 SQLBot、写操作或模型范围。只读连接确认 `transaction_read_only=on`，没有启动 Worker、迁移、写共享 PostgreSQL 或操作主3000/8001。

同病例、同五个原问题、同会话分组的最终重放全部完成。输入 Token 降低85.1%，两轮列表查询从停止变为完成；解释追问仍有额外读取与事实表述风险，不能据此批准答案质量或客户部署。实际医生/科室管理者身份与真实 WeKnora 验收仍缺。

## 改动与事实边界

- DSH `output.render` 接收模型用的纯投影，`presentationMeta` 保留完整卡片与分页范围，由原生 JSONL 持久化和恢复。没有第二套历史、结果副本、缓存或摘要压缩。
- 保存结果默认索引，每页最多10条，状态筛选支持全部原状态；需要正式结论/建议时使用有界 `saved_text`。完整卡片不截断，证据保留否定条件且只进模型一次。规则只发送标题、口径及实施范围，统计仅给指定数量的排序概览，原指标与完整展示资料仍可回读。
- 后续页必须携带已看到的 `expected_job_id`，任务或病例保存引用变化409，未见版本404；每次仍走授权检查。空筛选不继承旧轮卡片冒充当前结果。
- 页面显示类别、页号、返回/匹配/保存总数及全状态计数；索引与卡片共用稳定 ID 和位置。“第二条”快捷追问显式绑定同页稳定 ID。
- 本轮优化改变的是业务工具给模型的读取范围，正式保存结果/统计接口合同没有改。首次默认返回75条的旧工具调用已改为分页；客户端必须查看范围，不能把第一页作为全量。

## 正式事实核对与未通过项

- 每轮后重新读取正式保存结果，所有返回卡片的状态、结论、建议、job_id、record_ref逐项一致；两份病例列表的三条不合规沿用保存顺序。单问题证据不裁剪、不复制第二份给模型。每轮原生会话恢复与返回轮次完全一致。
- 管理回答的范围病例/可用/不可用数量、全状态分布及前三规则计数与正式输出一致；下钻沿用统计返回的病例引用，第一条正式结论的时间值一致。没有重新计算医学判据或正式指标。
- 卡片一致不等于自由文本正确：两轮列表改写了部分保存文字，不能称回答逐字保留；虽卡片原文可查，回答使用“正式原文”措辞仍有风险。
- 两轮列表及解释轮把 `is_complete=false`、missing_rule_ids推断为“任务尚未跑完”，工具没有提供这种任务运行事实。缺少保存项不能推断任务仍运行。
- 解释轮读取目标问题/规则之后，又尝试3次医生会话不适用的统计查询（422），并读取额外 data_gap问题；共6次工具，耗时53.750秒。原授权边界拒绝成功，但工具选择和追问范围仍需修正。
- 解释文字根据截断摘录提出对已完成事件的口径疑问；正式状态没有被改，但这种重新判断式表述超出“搬运已保存事实”。它说明保存摘录不是完整当前文书，实际没有读取当前文书，不能把该回答当作原文核对完成。真实 WeKnora仍未配置，未提供规范原文引用。

因此本次交付是输入体积、分页/引用合同和列表完成率的改善；答案质量验收继续未通过。下一轮应先限定医生可见工具、说明结果完整性字段的含义并减少解释偏离，在另行明确的真实调用预算内复测，不换模型或放宽60秒。
