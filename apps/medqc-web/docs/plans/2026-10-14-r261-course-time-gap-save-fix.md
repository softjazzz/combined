# R26.1 病程时间资料不足结果保存修复

本方案已由 [统一结果保存边界](2026-10-14-r261-optional-result-facts.md) 替代。
以下保留首轮定位记录，不再按单规则原因逐个增加例外。

客户日志确认保存失败组合为 `LX0609-02-01-03 / data_gap /
authoritative_time_missing / facts=missing`。执行已完成，保存层的病程事实合同
拒绝该组合，导致整个任务失败，并非已证明病程记录缺失就是直接原因。

用合成病历复现：入院时间 2026-01-01 08:00，无病程，评价截止仅知
2026-01-04 日期。执行器不能确定是否已满 72 小时，返回上述资料不足组合；
原保存层抛出与客户相同异常。入院当天评价则正常返回尚未到检查时限。
客户实际缺少哪个时间字段尚未确认，不能把此合成触发条件当作客户事实。

修复只允许该规则的 `data_gap + authoritative_time_missing` 在展示事实为
None 或空字典时保存；原状态、原因和说明不变。不接受非空非法事实，不放行
其他规则或合规、不合规结论。数据库结构、模型调用、业务判定均不改变。

验证：新增 9 项回归，修复前其中 3 项复现异常；修复后 9 项全通过。
病程合同及保存边界 68 项、原生病程执行及 canonical 交付等 422 项通过，
合计 490 项。新增保存回读测试使用内存 SQLite，不连接业务库，不调用模型。
Python Ruff、编码检查、ESLint、类型检查通过；前端 147 个文件共 1333 项测试通过。

客户补丁仅包含 `backend/app/services/luxian_0609/course_quality_result_mapping.py`。
安装前备份原文件，覆盖后重启服务，再对原失败单份病例验证。旧失败任务不自动
恢复；没有中间结果可复用时需重新发起。保留诊断补丁以定位潜在后续错误。
