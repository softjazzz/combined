# LX0609 核心引擎分阶段本地验收与最终客户验收计划

**Goal:** 完成核心聚合器剩余规则族职责收口，逐阶段本地验证、审核和提交，所有阶段完成后统一在客户环境验收。

**Architecture:** 沿用统一执行链及现有执行合同。执行器判定并选择 fact_refs，Binding 校验引用，规则族映射校验事实，公共组件投影证据，Renderer 组织文案，Aggregator 装配结果。复用现有模块，消除重复业务所有者。

**Tech Stack:** Python 3.10、FastAPI、pytest、PostgreSQL、Vue 3、现有 unified engine。

执行时使用 executing-plans 工作流；本文是 2026-09-06 经用户确认的验收节奏修订，优先于旧计划中“客户验收完成后才能继续下一规则族”的规定。

## 4. 每阶段的实际执行步骤

### A：定位和冻结

1. CodeGraph 定位实际入口、执行器、绑定、聚合及保存链；索引定位后再核对源码。
2. 列出本阶段全部专属分支，包括间接族调度和来源白名单，不只统计规则号。
3. 建立“规则 × 可达状态 × 资料形状”矩阵；不可达状态注明原因。
4. 用相同输入冻结状态、原因码、customer_display_facts、criterion_results、fact_refs 语义来源、客户文案和证据坐标集合。
5. 聚焦测试通过后独立提交 A，只含测试和基线。不得使用 xfail/skip 冒充归零守卫。

发现已知业务错误时，先独立记录反例、最小修复、测试和提交，再以修复后的行为冻结。已批准且含义明确的缺陷可直接处理；新的临床口径必须明确后才实现。

### B：等价迁移

1. 先迁完整事实验证职责至所属模块，再移除聚合器原实现。
2. 执行器选择真实引用，Binding 校验，公共投影生成坐标；不复制第二套证据 DTO 构造。
3. 添加立即绿色的该域聚合器所有权守卫；同时审查间接族分支，防止只删除字面规则号。
4. 对冻结输入差分，状态、原因码、事实、文案保持一致；customer_evidence 比较去重后坐标集合和数量。
5. 聚焦及公共边界影响测试通过后独立提交 B；本地失败先修复，不继续叠加下一域。

### C：本地入口验收、审核和继续

1. 用独立测试数据库运行单病历单规则、病历池批量、客户样本验证三个正式 API 创建入口。
2. 只替换外部资料和模型响应时明确记录替换点，实际任务派发、执行器、Binding、保存均使用生产代码。
3. 检查 unified=true、实际 executor_key 一致、无异常回退，核对落库 Canonical 和 API 返回结果。
4. 主协调 Agent 亲自审核关键 diff、模型输入、技术失败映射和定位结果，独立审查人员负责证伪。
5. 记录本地结果和待客户项，提交 C。通过后继续下一阶段；无需等待客户环境。

分类清楚：合同/执行器/非法输出/超时为 technical_error；必需资料缺失为 data_gap；事实具备但语义不可靠为 uncertain；无触发或未成熟依批准规则进入 not_applicable。不能用空集合代表“来源已完整同步”。

## 5. 本地验证协议

每个规则覆盖真实可达状态，家族整体覆盖适用性、明确合规、明确违反、资料缺口、关联歧义、语义未知和技术异常。重点覆盖边界前/恰好/边界后、单事件/多事件及已删除/取消事件。

资料分层：

- 本地真实病历：验证实际资料映射，记录安全引用。
- 固定脱敏资料：填补本地缺失形状，经正式链验证；不声称真实源库完整。
- 受控 Stub：冻结语义输出，比较 Prompt、调用次数和输入 Token。
- 真实模型：同一脱敏输入、模型配置和评价时间，基线与候选在隔离环境预热后交替运行至少 10 对，报告中位耗时；结构迁移门为回归不超过 10%，调用数及输入 Token 不增加。

与该族无关的测试无需每次重跑。公共 Binding/Finalizer/投影改变时扩展影响测试；最终阶段运行完整 LX0609 回归。纯 native 路径明确记录调用数 0→0。

已确认的业务修复允许反例结果按批准口径改变；其余冻结结果应保持。新增语义调用或输入扩大不得混入结构迁移，必须有独立成本与准确性证据。

## 6. 并发、审查及回滚

- 主协调 Agent 先确定根因、文件白名单、输出不变量和验证方案。
- 实现代理处理当前域；验证代理可独立跑基线/接口/性能；下一域代理只读审计。
- 聚合器、Finalizer、公共投影同时只允许一个写入者。后续域的生产迁移必须在前域本地通过后进行。
- 每阶段提交 A/B/C；发现缺陷另立提交，记录顺序依赖。
- 回滚按依赖逆序进行并重跑受影响测试，不能假定删除任意中间提交都能独立工作。
- 全程精确暂存；不提交 dist、临时病历、日志或已有无关前端修改，不自动 push。

### 6.1 2026-09-06 并行执行决策（已按用户要求启用）

背景：输血族结构提交 `938497a57`、本地入口提交 `42c92fc79` 已完成。剩余族有独立执行器，但共同修改聚合器与 Finalizer；多个 Agent 同时修改共享文件会污染行为对照和回滚边界。

决策：**族内独立工作并发，共享边界接入串行**。主协调负责架构判断、共享文件的唯一写入者调度和最终验收，不让实现者自行选择迁移边界。

| 本批任务                              | 并行写入白名单                   | 暂不允许                                   |
| ------------------------------------- | -------------------------------- | ------------------------------------------ |
| surgery_presence：030/032             | 独立 presence 冻结测试与验收文档 | 生产逻辑、共享测试、聚合器、Finalizer      |
| surgery_gate：003/024/025/028/031/033 | 独立 gate 冻结测试与验收文档     | 同上；不得误迁 029/034–040                 |
| surgery_mdt：040                      | 独立 MDT 冻结测试与验收文档      | 同上；不得调整急诊豁免、模型输入与失败状态 |

每族冻结通过并经主协调核对后，才允许在各自文件白名单准备独立的生产职责迁移；同一时刻最多一个族接入聚合器、Finalizer 和公共证据组件。每次接入前以最新提交复跑该族冻结，对共享差分重新审核，不能以不同旧基线各自通过代替合并后通过。040 可提前冻结，但不自动提前改变原计划的生产接入顺序。

保留 A（冻结）、B（迁移）、C（本地入口）独立提交；发现缺陷另立修复提交。低于 250 行的职责必须证明消除重复所有者的实际收益，禁止为了“多族并行”预建转发壳或通用框架。

收益是并行消化资料形状和测试工作；代价是共享接入仍须排队，且需要重新核对基线。未采用“所有族同时改公共文件、最后一次验收”，因为冲突消解不能证明业务等价；也未采用完全串行，因为独立冻结不需要等待公共文件写入。

客户策略保持不变：被排除或冻结的规则验证拒绝/不派发，不在测试中解禁。固定脱敏资料、真实本地病例、模型 Stub、真实模型与客户验收分别记账。

## 7. 最终本地收口与客户验收

阶段 6 逐一确认已无调用者的遗留函数后才删除。仍有客户调用的历史入口必须明确隔离；若仍承载规则专属判断，记录为未完成职责，不得宣称聚合器完全收口。不可通过把整段旧聚合器改名搬走完成验收。

阶段 8 将全部待客户矩阵统一验收：

1. 确认部署进程来自候选目录、前后端版本和数据库预检结果一致。
2. 选择每条变更规则的真实适用病例，补齐各族矩阵；病例数量由覆盖决定。
3. 同一资料和评价时点分别经三个入口重新创建任务；运行期间资料变化须记录并排除差分干扰。
4. 对比状态、原因码、关键事实、executor_key、客户文案、证据坐标并实际点击定位。
5. 区分源数据缺失、部署差异和代码缺陷。缺陷独立修复，本地回归后复验受影响矩阵。
6. 所有必须项通过后报告最终完成。客户不可达时保留“本地通过、客户待验收”，不得伪造 PASS。
