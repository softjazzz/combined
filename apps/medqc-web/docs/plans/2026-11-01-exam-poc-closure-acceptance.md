## 阶段A：根因与最小改动

### 首轮和补核是两个独立问题

1. 首轮已经同时给了C01三个报告，两模型仍将后一次病程挂到前一次事件。因此不能把全部错误归咎于补核缩上下文。
2. 原Prompt只有事件位置、报告正文及病程引用/正文，缺少报告时间、病程记录/提交时间、稳定报告来源身份。未明确同部位同模态不同次，以及“较前片”只表示比较对象而非当前报告ID。
3. 定向补核缩为E002后，程序仍用全投影报告校验，模型却看不到E003报告。新的Flash补核只修正报告片段位置，仍误挂事件，被`quote matches other report`拦截。
4. 正式执行按事件分批会缩小`imaging_events`，直接遍历子批不足以保证全病例比较。实验还存在旧正文日期已偏移而投影时间未偏移的问题，新协议不能直接外发旧pickle的原始时间。

### 实现与职责

- `exam_result_context.py`组织输入协议，不判断临床结果。
- `comparison_events`保留全局只读报告目录，正式子批继承，身份使用原报告引用而非子批编号。
- `comparison_context_refs`只限制外发比较目录，不缩小程序的独有句/跨报告比较。真实POC只允许原批准9事件，不能因属于同一患者而外发其他报告。
- 待答集合仍为`events[*].course_doc_refs`；比较事件不新增输出任务，已成功配对不重判。
- 新Prompt明确不同次检查、“较前片”、一份病程可记录多次、概括表达以及时间未知。没有最近一次关联、强制other_exam、逐字缺失即否定或裁剪错误引文。
- 升级与补核沿用原材料和客观错误，不传候选结论作事实。现有两次/批、八次/专项预算不变。
- 时效由原Native和时间owner判定，Binding/Finalizer/保存层不重判。早期失败/晚期成功不能覆盖原及时引用；完整确认仅晚期仍判超时。

### 开关、冻结与回滚

`LLM_EXAM_RESULT_CONTEXT_PROTOCOL=legacy`为默认值；`comparison_v1`为实验协议`exam-result-comparison-v1`。双模型路由仍默认关闭，未修改部署配置。

新协议实际专项Prompt、比较材料及时间纳入主冻结键。新协议下route off参考路径也按参考模型配置和外层实验分区；cascade/shadow保留候选/参考模型、修订及实验隔离。未改旧冻结文件。

回滚设置为`legacy`，恢复旧Prompt路径，保留v5身份安全校验；v4错误冻结自然失效，不删除新旧实验冻结。`comparison_v1 + Strata prefix`显式拒绝，避免悄悄复用旧前缀协议。
