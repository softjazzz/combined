# 单病例规则验收实施记录

目标：人工预期编辑/回读→冻结到一次运行→正式结果比较→人工复核追加保存。

架构：复用样本 raw_payload_json，增加 rule_validation 元数据；不增加表、不修改执行器。专用验收接口调用现有单病例样本运行入口，模型只接收原有运行参数。结果通过现有正式API读取，禁止绕开Canonical校验。

实施步骤：
1. 新建 test_case_validation.py：并发修订校验、冻结预期、运行绑定、纯比较和复核追加；SQLite持久化测试。
2. qc_sample_pools.py 增加验收接口：仅自建测试池、一份病例、当前可执行规则；访问控制及失败处理。
3. 新建 RuleValidationDrawer.vue 和服务：编辑预期、明确启动、刷新结果、保存人工意见；客户样本页入口。
4. 测试保存回读、修改后历史预期不变、失败/缺结果/重复结果不误报一致、跨用户禁止、意见追加、答案不进入运行请求。
5. 聚焦测试后运行编码、lint、类型和单测；记录真实模型及客户PG未执行范围。

边界：只冻结预期与样本身份/来源修订，实际材料沿用正式任务已有读取机制，不声称实现了全病历不可变快照；不自动上线。旧编号预期明确要求重建，不静默映射。第一版每病例最多50次验收记录，到限提示，不自动删除历史。

进度：代码与隔离端到端验证完成，浏览器冒烟未完成，尚未合入日常分支/推送/部署。

实现位置：
- `backend/app/services/test_case_validation.py`：复用样本JSON，修订冲突检查、预期冻结、运行绑定、状态差异和人工意见追加。
- `backend/app/routers/qc_sample_pools.py`：验收API复用原运行和正式Canonical结果读取；只传病例坐标与规则ID，不传答案。
- `src/views/workstation-v4/customer-sample-validation/RuleValidationDrawer.vue`：自建测试池单条样本的“规则验收”入口，编辑依据/预期、运行、刷新、证据建议入口、人工复核。

## 第二阶段：固定实际执行材料与版本

第一阶段“材料未冻结”限制已补齐：入口保存病历包，正式执行会话构建时保存实际读取的有界CDM资料；已有任务重试复用同一材料，禁止回退实时读取。复用诊断材料freeze/restore类型合同；context作用域仅验收存在，普通执行直接走原builder。执行器业务判据没有修改。任务入队前完成run与job绑定，避免Worker先启动读不到所属运行。

新增共享边界仅：样本入口内部request.state携带服务端引用、Worker材料读取与调用作用域、execution会话构造包装、样本序列化排除验收私有材料。所有普通入口无验收引用时保持原行为；HTTP请求体没有新增可注入材料引用字段。

复核绑定原任务已有代码/模型/评价参数快照。缺执行材料或版本的旧运行只能记录不通过；本地process版本UI标明需固定构建后复验。发布仍按设计文档第10节人工记录并提交release_scope，无在线发布状态机。

容量为每run5MiB、每病例20MiB、50runs；入队前超过上限返回明确错误，执行时超过上限拒绝当前验收，不允许回退实时材料。未实现自动清理。快照只在受控样本存储内；API列表不返回材料或其他用户复核，普通日志不写原文。

验证：后端101/101通过（本模块、样本入口、两规则真实Worker链路、原三入口验收）；Ruff、类型检查、npm run lint、git diff --check通过。前端全量1136通过、2个路由加载超时；两失败文件及新抽屉重跑9/9通过，新抽屉共4项。未连接客户PG、未调用真实模型、未启停3000/8001。当前子代理无浏览器工具，浏览器验收仍待主代理接入可用工具后完成。
