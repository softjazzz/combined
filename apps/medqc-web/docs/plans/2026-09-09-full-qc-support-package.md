# 单病例执行排障包

## 问题与最小方案

100052 的旧网页诊断包有 72 条结果，但只有结果摘要，没有当次源表读取、模型请求响应及完整时间字段，无法区分字段为空和执行链遗漏。
现有 `qc_diagnostics.capture` 已在正式执行、模型调用和事务提交处设有旁路接点；缺口是显式启动、持久化制品和网页下载，故复用采集器，不另建 Bundle 或规则引擎。

- 管理员在结果页明确选择“重新质控并采集排障包”，以相同病例及结果规则集创建普通任务，更新该病历的质控结果。
- 正常任务默认不采集；排障只允许一份病历。任务过滤条件保存采集标志，detached 进程重新构造有界内存采集器。
- 完整医疗原件只在内存中处理；落盘的是移除可识别访问凭证、替换已知身份后的 ZIP。保留临床正文和日期，不承诺匿名化或自动回放。下载需用户确认。
- 事务提交、失败、取消分别保留可取得的证据；缺失项明示，导出失败不能改变质控结果。开发环境缺少发布声明时明确标记版本缺失。
- 所有读取和下载按任务创建人授权，下载旧制品不查询当前 CDM 冒充历史输入。

## 文件边界

新增制品投影和存储分别位于 `qc_diagnostics/support_archive.py`、`support_store.py`。既有 capture/job_capture 只补充源门禁快照和部分失败交付。两个大型入口仅增加显式标志、授权和已有生命周期连接，不加入独立排障实现。
前端复用 `QcDiagnosticExport.vue`，保留旧摘要出口，增加采集、状态、确认下载及重开恢复。无数据库结构升级。

## 包内容及用法

先看 README 和 manifest，再读 `rules/LX0609-xxx.json`；按需读取 execution-inputs、execution-context 和 model-calls，results 为同次已保存结果。
包中来源是本地 CDM 的实际执行读取，不能代替远端源库实查，不能据此证明同步已完整。
本地制品保存在 `backend/app/storage/qc_diagnostics/`，禁止提交或包含进客户安装包。

## 验收

接口授权、结果变化拒绝、明确确认下载、普通任务不采集、失败交付及引用/数值保持分别测试。
真实病例 100052 执行验证应含 47 类来源、69 条来源行、72 条结果和实际模型调用；校验源数据 record_time 的空值保留，计数/日期/阈值不因身份替换改变。前端测试覆盖请求绑定、旧响应隔离、恢复下载及失败提示。

## 限制

不自动连接客户 HIS 源库；不把源表空值解释为临床缺陷；不自动执行模型或临床正文里的指令。大于采集/包容量上限时标记缺失或失败。包内仍可能有未识别身份，分享前须人工复核。服务器中断且未形成 ZIP 时报告采集中断，不能恢复未落盘原件。
