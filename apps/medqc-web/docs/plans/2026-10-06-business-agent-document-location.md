## 冻结证据与根因

修复前正式医生接口返回 `200 / quote_not_found`；当前正文与前轮失败记录中的正文一致。冻结保存结果的任务和规则版本、证据全文及字段、来源类型/身份、会话引用、实际 SQL 和参数、原始正文、前端未匹配提示及截图。

原来源为 `senior_course_record` 的单条 `record_content`，保存摘录长 273 个 Unicode 字符，当前正文长 345 个；差异只有签名区域多出的 72 个空格。保存证据生成器 `_excerpt()` 先执行 `re.sub(r"\s+", " ", value).strip()`，当前文书装配则保留原排版。对原正文重新执行既有 `_excerpt()`，能完整复现保存摘录；字符级差异及 SQL 均私有保存。

原定位器直接用 `content.find(quote)`，未对应保存摘录的空白压缩合同。因此文书身份能确认、正文能打开，却找不到包含连续空格的原句。此次不是选错文书、多字段摘录拼接或非空白文字变化。摘录对应成功不证明整份文书的版本未变化。

## 调用链与身份核对

1. 保存证据：`customer_evidence_enrichment.py::_excerpt` 生成摘录；源身份通过 `emr_render.py::_project_customer_safe_source_refs` 投影，保留具体文书映射。
2. 助手来源：正式会话保存 `reference_id` 到该病例保存结果的关联，证据读取检查保存任务版本与病例归属。
3. 文书查询：`business_agent.py` 的 `evidence-document` 路由从本账号会话和服务端保存证据取得病例三元组；客户端只提交引用和证据序号。`require_record` 重新检查医生精确授权。
4. 正文装配：`load_current_documents` → `_assemble_current_documents` → 当前源表读取及文书投影。原反例实际 SQL 包含 `institute_id`、`patient_id`、`visit_id` 三个过滤条件，参数与冻结病例一致；投影中只有一个与该 `source_ref` 及来源类型对应的文书。没有根据标题或相似正文选文书，也没有回退到旧文书。
5. 定位与展示：`business_documents.py::locate_document` 先确认来源身份和类型，再匹配该文书正文；`BusinessAgentDrawer.vue` 只按后端 Unicode 码点坐标切片高亮，不独立猜测原句。前端主体无需修改。

这项 SQL 结论限于本次实际源表和病例，不将共享装配器的其他兼容源表路径一并宣称通过。

## 最小修复

仅修改后端 `business_documents.py` 的摘录定位：将连续空白折叠为一个分隔符，用映射表把唯一匹配范围换回未经改写的原正文坐标，`matched_quote` 返回该原始切片。空白分隔符没有删除；数字、单位、文字、标点和零宽字符不做近似处理。

精确文字与空白变体一并计数；同文书出现重复句仍返回 `quote_ambiguous`，不给猜测位置。既有 300 字截断摘录只能按原合同标注“前缀定位”，字面省略号完整匹配优先。缺正文明确说明未提供正文。身份不符、正文实质变化或不连续拼接仍展示保存摘录及来源，并保留未匹配提示。
