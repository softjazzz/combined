# LX0609 三个独立闭环

## 批准范围与执行方式

用户批准按三个闭环推进，由 Terra high 实现，主协调 Agent 独立审核。每个闭环单独验证、提交，不混入前端已有修改，不推送、不修改客户数据库。

## 一：会诊技术失败语义

- 已确认：生产 episode 执行器将结构非法映射为 evaluation_unknown，typed 决策又改写原因码；聚合器对非法会诊展示事实改写为 data_gap。
- 修改：结构非法使用现有 technical_error 合同；合法语义 unknown、真实资料不足、有效临床结论保留原语义。缺少模型客户端不得解释为临床资料缺失。
- 文件：native_consultation_episode_execution.py、聚合器会诊非法事实隔离块、对应测试和验收说明。
- 验收：一/二阶段非法结构、非法引用、合法 unknown、技术异常；二阶段失败不污染 021/022；聚合后的 Canonical 保持技术错误；Prompt、重试和调用次数不增加。
- 不做会诊族架构迁移。

## 二：基础时限证据归口

- 已确认：basic_timeliness_customer_projection 仍由聚合器调度；目前决策引用来源快照，部分精确文书 ID 另从 display facts 生成。
- 先冻结完整事实、证据坐标和来源语义，不只检查规则号字面量。
- 复用现有引用和材料仓，先证明逐文书绑定可表达，再迁移公共投影；不能删分支导致证据缺失，也不能复制 DTO 拼装到各执行器。
- 不改变临床状态、原因码、Prompt 和 Canonical 外部合同。需要超出既有合同的公共边界改动时先记录证据与方案，由主协调审核。
- 验收覆盖多文书、缺 ID、外部/伪造引用，以及单规则、批量、客户样本入口；未实际执行的真实模型性能验收不得宣称完成。

## 三：生产编排扩展边界

- 已确认：原测试手动注册和构造执行批次，不能证明生产准备入口可扩展；phase_scope 仍固定 001 至 075。
- 使用测试专用 native 和受控语义合同，通过实际加载/计划/准备/执行/绑定链验证；不得绕过引用真实性检查，不创建虚假生产规则。
- 生产新规则的临床验收仍需获批业务定义。测试合同验证与真实模型十次性能验证分开报告。
- 如真实编排无法表达测试合同，记录最小公共边界阻碍，不借机新增框架或静默 fallback。

## 审核门禁

主协调亲读关键 diff、复跑聚焦测试，记录失败与未完成项。每个闭环通过后单独中文提交；三个闭环完成后停止，不扩展到其他规则族。

## 本轮调查后的范围调整

1. 会诊失败语义按原计划修复。
2. 基础时限冻结发现真实安全缺陷：选中文书无 ID 时，来源级引用会借用同来源另一条记录的 ID。依照“结构提交不混入行为修复”的门禁，本轮先独立修复这个错误兜底并建立完整基线，不宣称完成职责迁移。迁移还需解决当前 Binding 不接受材料仓已有逐文书引用的问题。
3. 生产 master 与 phase 编译器固定要求 75 条。先新增真实加载器拒绝扩展的可复现测试，以及既有 001/006 单选/组合的真实编排一致性验证。不增加测试专用 runtime、可信身份或来源白名单，以免用第二套合同掩盖阻碍；两条真实新增规则扩展验收仍未完成。

三个提交的边界因此是：失败语义修复、证据定位安全修复与冻结、生产扩展门禁验证。它们不等于原先完整架构目标全部实现，后续汇报必须保留这个区别。
