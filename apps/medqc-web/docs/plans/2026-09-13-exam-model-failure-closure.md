# 检查检验模型失败隔离与验收计数修复

## 问题与证据

主协调已用正式执行器、裁决和聚合链复现：持续返回跨事件病程引用，调用两次后 011 为 `data_gap / required_field_missing`，012 保持合规；非法枚举 `value` 的测试不能覆盖这条路径。首答使用隔离解析器，整批重试使用公开解析器，后者会把引用无效转换为 unknown。评分器的事件分母已修，但缺失规则仍退出规则级分母且按事件重复计分。

任务持久化、API 和页面是否已识别失败项仍是待验证假设，只读定位后决定最小改动，不以存在失败文案推断交付已被拦截。

## 范围与责任

- 主协调：检查检验解析/恢复、聚焦生产测试，复核任务链并确定任务交付改动。
- 评分器代理：仅 POC 评分器和自检；规则按病例、规则、轮次计一次，缺失规则留在可评分母。
- 任务链代理：先只读定位，确认文件白名单后才能实现。
- 不改 C06 汇总优先级、临床语义关键词或生产模型 schema；不扩大 015/26 例试验。

## 失败语义与最小方案

首答与唯一一次恢复使用相同严格隔离合同。可归属的跨事件引用登记为失败规则，保留其他有效规则事实；恢复仍失败不得转成资料缺失。真实缺字段、时间冲突继续按已有资料合同处理。资料齐全时模型未能判定不冒充缺字段。

任务执行失败信息与客户临床结论分离；完整有效的其他规则结果保留，有失败的任务不得显示全部完成。复用现有任务状态和元数据入口，禁止增加第二条保存/聚合链。三项比例分别记录明确分子分母：首答有效规则/请求模型规则、恢复有效规则/重试规则、最终失败规则/请求模型规则，零分母用 null。

## 任务边界定位与实施补充

主协调已核对 `sichuan_workspace_batch_worker.py`：规则结果允许 `technical_error` 进入 items，而最终统一调用 `complete_batch_job`。`custom_qc_workspace_service.py::complete_batch_job` 固定保存 completed；canonical store 拒绝失败结果会回滚整次写入，不能用它代替任务失败处理。

实施范围为上述两个文件、独立的任务执行失败分离 helper、现有任务状态展示 `batchJobPresentation.ts` 及对应测试。任务数据库状态复用 failed，summary.execution_status 区分 failed/partial_failed；合法结果保留，失败规则进入执行失败列表，不写入临床结果集合。前端仍按既有终态停止轮询，不新增数据库枚举或第二个任务入口。

统计复用 `FamilyUsageAttribution` 及统一/兼容适配器：`execution_contract.py`、`executor_registry.py`、`execution.py` 仅透传安全计数与比例。现有共享合同无法搬运新统计，是本次跨层字段改动的具体依据；不更改裁决状态。任务按病例累加计数后计算比例，范围明确为检查检验模型调用，不冒称全部质控规则准确率。

补充验收：持续执行失败任务状态 failed、有效结果仍可读取；部分失败不得显示全部完成；失败规则不进入 canonical store；实际资料缺口仍正常交付；父任务不能因子任务存在有效结果而变回 completed；API投影和页面用相同summary含义。
