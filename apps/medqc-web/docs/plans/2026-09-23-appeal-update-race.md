# 申诉更新终态竞态小闭环

## 业务问题与证据

`PUT /api/v1/appeals/{id}` 先查申诉人和 `pending`，再仅以 id 更新；适配器的两次 `execute()` 是独立事务。审核/撤回可能在其间提交终态，导致终态后的理由、证据、优先级或备注仍被改写。独立审查已复核这一调用链。实库只读核对 `qc.qc_appeals` 与 `public.qc_appeals` 同名；当前实际 `evidence` 为 JSONB，其余本批更新字段为 text。

## 最小合同

- 查询与最终更新均明确指向权威 `qc.qc_appeals`，不依赖默认 search_path。
- 最终 UPDATE 同时要求 id、申诉人和 `status=pending`；零行不得报成功，预读存在而状态变化返回 409。其他用户 403、不存在 404、无身份 401、空更新 400、数据库故障 503 且不回显异常或患者原文。
- 保留 `AppealUpdate` 原有字段，不改创建、列表、审核/撤回状态映射。与审核/撤回并发时，先完成更新则随后审核读取新内容；先完成审核/撤回则更新被数据库最终条件拒绝。
- 权限/身份、请求校验和 OpenAPI 仍可读；任何非法正文的错误响应不得回显理由或证据原文。
