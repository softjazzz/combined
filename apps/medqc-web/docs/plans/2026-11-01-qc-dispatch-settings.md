# RabbitMQ显式开关与后台设置范围

## 本批决定

从业务线d2a94df3b建立独立功能分支，不直接改集成分支。系统配置增加“质控运行”页签：明确的RabbitMQ开关、当前新任务模式、配置来源、Publisher/Worker近期就绪状态、检查与保存。默认仍legacy，不自动安装服务、迁移数据库、启动进程或调用模型。

开关只影响新建正式LX0609任务；已入队任务以原持久化mode运行，关闭不停止既有Worker或重投任务。新任务路由与持久化使用同一个配置owner，提交前重新校验，避免检查后切换导致创建未校验的MQ任务。

沿用系统已有文件持久化设置的部署方式，但新增owner使用跨进程写锁、修订号CAS、原子替换及损坏失败关闭；不向.env写入。部署可通过QC_DISPATCH_STATE_DIR指定共享持久目录，同主机Web多进程、Publisher和Worker必须共享；多主机必须显式共享目录，未共享时看不到匹配就绪信号、不能从页面启用。设置只含模式、版本和操作人，不含凭据。地址、密钥及服务安装仍归部署配置。

现有M2没有服务心跳，必须补齐Publisher/Worker成功启动后的轻量心跳，匹配Broker及数据库部署身份，失联/停机/未知不显示就绪。开启时核对新鲜心跳、既有迁移启动检查、Gateway只读健康和鉴权资源接口；不发模型请求或任务。没有MQ配套服务时，开关不能保存为开启，关闭仍可保存。GET失败不按零或关闭伪装成功。

界面复用现有工作台V7.1公共类，限管理角色且演示普通账号不可修改；服务端再次授权。账号切换、卸载、晚响应和保存失败都不能错误展示已生效。

- 已有后台：模型/Provider、Temperature/Top P/Max Tokens、病历/规则族/HTTP并发、首页抽取与数据同步策略。复用现有入口，不重复实现。`src/components/LLMApiConfig.vue`的`buildCustomParameters`及`buildExecutionConcurrency`是现有保存入口；Thinking目前没有独立页面开关，不能误列为已完成。
- 适合后续新增：调用观测开关、有限重试预算/退避、任务超时/队列容量、Outbox保留期及告警阈值。须沿各自owner同步Worker和Web，并区分立即生效与重启要求；本批仅建议，不顺手放开。
- 暂保留部署配置：Broker/Gateway地址及凭据、PG连接/模式、服务实例安装、模型物理资源与部署容量、迁移/恢复命令。

## 部署、生效和回滚

1. 配置保存在`QC_DISPATCH_STATE_DIR/settings.json`，未配置时回退`backend/data/qc_dispatch_control`。文件存在后优先于环境默认值；每次新建正式任务读取，不需要重启Web。`revision`防止旧页面覆盖其他管理员保存。
2. Web部署默认保留`QC_TASK_DISPATCH_MODE=legacy`。独立Worker进程仍需通过自身的`QC_TASK_DISPATCH_MODE=rabbitmq`启动校验（可用该进程的环境覆盖）；不要为了预启动Worker而先把Web的环境默认值改成rabbitmq。Publisher不读取页面开关，关闭后继续发布已持久化的Outbox。
3. 三种进程共用数据库/Broker配置和同一可写持久目录，服务完成迁移检查且连接可用后每5秒写心跳，30秒失效。多机共享目录必须可靠支持文件锁及原子替换；未部署共享存储时不启用后台MQ切换，不宣称支持任意多机部署。
4. 点击“检查配套服务”仅GET Gateway的`/health`及带鉴权的`/v1/llm/resources`。启用保存会重新检查，失败不保存；关闭无需依赖MQ/Gateway可用。检查通过不保证服务之后不宕机，持久任务沿用租约、失败及恢复合同，不静默改走另一执行方式。
5. 回滚首先在页面关闭，让新任务回到Web，再等待MQ已有任务收尾，最后停止独立进程。不要以删除开关文件作为普通回滚：删除后会重新采用环境默认值。不会改写已有任务mode、结果或失败范围。
