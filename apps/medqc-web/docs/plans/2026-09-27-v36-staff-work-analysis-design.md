# V3.6 质控员工作分析合同（P2-R2）

## 范围与边界

- 本批交付全场景人员工作分析，复用现有事件，不修改质控引擎、不新增迁移。
- 运行与终末无法完整归属：workspace 审核未保存场景，申诉仍关联旧结果；不能把全场景数据贴上运行或终末标签。这两个筛选返回不可用，统计值为 null。
- 仅 admin/qc_manager 读取；沿用工作台全院数据范围守卫。不增加患者正文、病例下钻或个人绩效评分。
- 本批不把功能代码或单测通过视为真实病例、浏览器验收，不提升 PRD 严格覆盖状态。

## 事实与指标

| 指标 | 权威来源 | 时间与归属 |
| --- | --- | --- |
| 初审、复审次数 | qc_record_reviews.stage | created_at / reviewer_id |
| 审核病历数 | 审核事件内完整三坐标 | 窗口内去重；全局与每人分别去重 |
| 人工缺陷录入数 | manual_create 创建历史及人工缺陷来源 | 创建事件时间，核对创建人 |
| 人工缺陷审核通过、驳回次数 | qc_defect_history 的 manual_review_approved/rejected | created_at / actor_id |
| 申诉通过、驳回次数 | qc_appeal_reviews 的 approve/reject | created_at / reviewer_id |

- 人工缺陷限定现有任务人工来源谓词，不把自动缺陷算作人工工作。
- 初审、复审统计的是决定次数，同一病例多轮结果不等于多份病例。
- 缺陷被驳回数（创建者队列当前结局）与执行驳回数（审核者事件）不同，本批只统计后者。
- 活跃人员为本期任一上述动作的去重人员；实际审核人员只包含有病历审核事件的人。
- 人均审核病历数 = 各人员去重病历数之和 / 实际审核人员数；多人审核同一病例分别计个人工作量，全局病历数仍只计一份。零分母返回 null。
- 统计完整人员集合，不从首页前十名排名反推总数；姓名缺失显示人员 ID，不构造示例姓名。

## 时间与失败语义

- 复用 performance_ranking_service.compute_window：医院时区 Asia/Shanghai，本周、上周、本月，左闭右开，查询时转换为库内 UTC。
- 对比创建、审核和申诉的各自事件时间，不以当前状态或缺陷更新时间替代。
- 非法参数 422；无权限 403；读取失败脱敏 503；不可归属场景为显式 unavailable，不伪造零。
- 有效空窗口返回空明细、零计数及 null 人均；前端请求竞态不得覆盖新筛选结果。

## 职责与验收

- 服务负责 SQL 事件聚合、去重和指标；接口只负责权限、参数和响应；前端只展示，不重算业务事实。
- 读取接口为 GET /api/v1/quality-reports/staff-work，参数 period 与 scene；页面为 /dashboard/qc/reports/staff-analysis。
- 新页面复用统计报表布局，按筛选、总览、人员明细分区；不扩展旧排名入口和旧统计服务。
- 测试覆盖跨院同号、同病例多轮、不同创建人与审核人、周期边界、超过十人的全量统计、未知场景与读取异常、权限及前端旧请求失效。
- 隔离库仅做只读冒烟；若无非空数据，明确记录未完成正向真实病例验收。数据库写入另按本批授权执行。
