# 2026-10-03 业务助手 M2/M3 外部依赖对接清单

本清单把已评估为“缺外部条件、助手侧不能自行补齐”的事项集中列出，写明缺什么、建议由谁提供、验收标准和助手侧接入后的工作。所有结论来自源码核查，详细依据见各专题记录；提供方是按职责的建议，具体人选由项目方指定。

## E1 整改分派

- **现状**：助手通过 `read_action_capabilities` 说明不能分派，不会称已分派。
- **缺什么**：
  1. 保存的质控问题到缺陷记录的权威映射（现无可靠对应关系）。
  2. 责任科室/责任医生目录。
  3. 逐病例、逐科室的授权校验（现有 `/api/v1/remediation` 创建入口只校验登录与对象存在）。
  4. 原子幂等：同一动作重复提交不产生重复记录（唯一动作键）。
  5. 期限合法性与状态机（待分派、已分派、已整改、已关闭）。
  6. 逐条成功/失败明细与审计。
- **验收**：用一个授权科室的 2 条保存问题分派，返回逐条结果；重复提交返回同一记录；越权科室被拒绝；审计可追溯到操作人。
- **助手侧接入**：沿用“预览、用户点击确认、正式接口、回读”的既有模式（与复检任务同一套 `qc_business_actions` 幂等表），预计 1 个预览工具加确认分支加回读，不新增架构。
- **注意**：前端 `src/api/rectification.ts` 声明的 `/api/v1/rectifications` 后端没有实现，需确认是废弃还是待建。

## E2 催办

- **现状**：`/api/v1/qc/defects/{id}/urge` 只更新缺陷状态并写历史，未调用任何通知投递。
- **缺什么**：真实通知投递（站内消息/企业微信/短信等其一）、投递回执、失败重试与频率限制（防止刷屏）。
- **验收**：催办后医生端“消息”页签收到一条可追溯的消息；回执能区分已送达/失败；一天内重复催办有限制提示。
- **助手侧接入**：与 E1 同一批做；助手只能在回执为“已送达”后才说已送达，否则说“已提交，送达状态待确认”。

## E3 医生本人趋势

- **缺什么**：登录账号与医生工号的授权映射；正式统计接口按医生过滤的合同（口径、归属规则：主治/经管/书写者）。
- **验收**：医生账号只能看到自己名下病例的趋势，换账号看不到他人数据；与管理者看到的科室合计可对账。
- **助手侧接入**：复用 `trend_statistics` 的结构，把范围从科室换成医生，工作量小，难点全在口径。

## E4 EMR 内嵌浮窗与写回

- **缺什么**：目标医院系统与版本、受信身份/SSO、机构-患者-住院号映射、来源页面白名单、上下文消息协议（打开病历、切换患者、注销）、只读还是允许回写的权限决定。
- **验收**：在 EMR 里切换患者，助手上下文同步切换且不串患者；注销后助手清空；跨域仅限白名单来源。
- **助手侧接入**：助手面板已是可嵌入的独立面板，需新增消息通道和来源校验；**写回电子病历属高风险，建议首版只读**。

## E5 主动订阅与定期推送

- **缺什么**：调度能力、投递目标（谁收、通过什么渠道）、失败重试、暂停/取消语义、订阅的授权归属。
- **现状补充**：通知收件箱已由 `query_followups` 只读覆盖，缺的只是“主动推”。
- **验收**：配置一条“每周一汇总外一科不合规排行”，周一按时收到；暂停后不再收到；失败有记录。

## E6 自由问数出图（SQLBot/ChatBI）

- **现状**：项目已 vendored `third_party/sqlbot`，旧版面板里有 iframe 入口；本机没有运行服务。第一版图表只画有正式统计来源的趋势折线和规则排行条形，不依赖它。
- **缺什么**：
  1. 部署（独立服务、登录态打通）。
  2. 只读数据源与表级授权，保证不越过医生/科室范围。
  3. 图表卡必须标注“由问数工具生成，非正式质控统计口径”，不得与正式统计混用。
  4. 许可证评估：上游为带附加条款的 GPLv3，要求保留 Logo 与版权信息。
- **验收**：授权范围外的数据问不出来；生成的图能追溯到执行的查询；界面有口径标注。
- **助手侧接入**：作为独立入口接入，不改变正式统计的“数字由 Python 判定”原则。

## E7 编码建议与 DRG 入组

- **现状**：前端默认走 Mock；应用编码属于写语义。
- **缺什么**：正式确认流程（谁确认、可撤销、留痕）与真实分组器数据源。
- **助手侧接入**：只读解释可做，应用编码必须走确认流程，暂不接入。

## E8 完整联调环境

- **现状**：本机只有只读业务助手后端（8003），病历池页面读不到病历列表，因此合并后的智能助手在真实病历池页面没有端到端验收；e2e 用例已改名但未运行。
- **缺什么**：一套完整的测试后端（病历池、文书、质控结果、通知）及测试账号，数据为合成或脱敏。
- **验收**：在该环境运行 e2e 与人工走查病历池、病历详情、管理首页三个入口。

## 对接时的统一约定

- 助手只搬运正式接口的结果，不自行判定状态、原因或数值。
- 任何写操作必须“预览、用户点击确认、正式接口、回读”，并有幂等键。
- 外部接口异常时，助手用中文如实说明未完成，不得把“已提交”说成“已完成/已送达”。
- 真实患者数据不进入文档和提交；联调用脱敏或合成数据。
