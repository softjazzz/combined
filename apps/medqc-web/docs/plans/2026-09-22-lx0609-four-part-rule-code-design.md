> 日期：2026-09-22
> 决策更新：2026-09-22，依据用户希望长期只有一套编号的要求，采用四段式 `rule_id` 全链路迁移方案，取代此前永久保留三位 `rule_id` + 四段 `rule_code` 的双身份设计。当前在独立分支 `codex/lx0609-rule-identity` 实施，旧双身份与CT草稿保留在原工作树。编号迁移与业务扩展分开验收，目前尚未完成迁移验收。

## 1. 编码结构

```text
LX0609-大类-子类-质控点
```

示例：`LX0609-06-01-03` 表示“LX0609规则集—检查检验—CT/MRI—报告单完整性”。

- `LX0609`：规则集代码。当前仓库、接口和历史结果使用0609，未取得正式更名依据前不得改成0619。
- 大类：两位稳定代码，只表达业务文书或诊疗领域。
- 子类：两位稳定代码，表达同类文书或同类诊疗事件。
- 质控点：两位稳定代码，只在所属子类内连续增长。

四段式编码直接作为唯一 `rule_id`，贯通目录、执行器、模型输出、结果保存、API、前端和导出。不表达执行依赖，不允许从编号推导执行器、数据源或最终状态。发布后身份稳定；展示分组、排序调整不引发重新编号。

## 4. 唯一规则身份与历史边界

1. 生产规则目录直接保存四段式 `rule_id`，例如旧010迁移为 `LX0609-06-01-02`。执行、查询、反馈和展示都使用相同身份，不保留三位编号驱动运行的通道。
2. LX0609 专用合同不再引入另一套 `rule_code`。公共 API 若受其他规则集约束暂需保留该字段，只能是与 `rule_id` 完全相等的兼容字段，不能承载第二身份；须盘点消费者后明确去留。
3. 三位旧编号只保留在迁移清单、旧版规范/报告、冻结验收产物和原始历史归档中。历史业务表采用一次性迁移，禁止用常驻转换服务维持双编号。
4. `family_key` 和 `executor_key` 继续决定执行归属。四段式编码不形成父子规则，不新增中央门禁或聚合层。
5. 去掉目录强制001到079连续及按数字区间推导规则族的假设，改为显式成员、唯一性和合同覆盖校验。新 CT 规则直接使用 `LX0609-06-01-01`、`LX0609-06-01-03`，无需分配080/081。
6. 历史任务选择、子任务、结果 JSON、独立结果表、反馈关联及必要校验值必须同时处理。旧版只读归档保留，不能把重命名后的副本冒充原始冻结产物。

## 5. 事实共享原则

同一子类优先共享事件事实，但是否共享由事实合同决定，不由编码字符串决定。

以CT/MRI为例，`exam_lab`规则族一次建立影像检查事件：

```text
医嘱 → 执行/检查主记录 → 报告 → 对应病程窗口
```

- Python一次生成医嘱、执行、检查、报告、时间和关联事实；
- 必要时一次抽取检查原因、结果记录和阳性结果分析等原子语义事实；
- 五条CT/MRI规则分别读取所需字段；
- 纯结构化规则不因为语义抽取失败而失败；
- 不允许按规则重复提交相同病历文本给模型。

## 6. 分阶段实施与验收

1. **固定基线并分离草稿**：工作树基线为 `9a29f46b2dd395343abb187421590de3dd8e396d`。先核对主工作区未提交的前序0609修复，形成实际验收基线；保存现有草稿后将 CT 新规则及010报告缺失所有权调整移出编号迁移补丁。
2. **盘点与冻结**：复核79条对应关系；盘点源码常量、正则、动态编号生成、目录/合同、模型响应、结果与反馈、前端路由/缓存/测试和发布配置。源码已确认位置见迁移盘点文档。
3. **代码迁移**：沿现有链路替换身份与格式约束，保留判据、来源、适用性、语义提示内容、调度和全局40槽位设置；不得顺带重构规则族或调整业务标准。
4. **历史迁移演练**：先对数据库副本只读盘点和 dry-run；迁移程序须检查版本、未知编号、重复身份、孤立引用，并具备幂等和回滚方案。迁移时停止旧版本接纳/写入任务，确保代码与数据切换一致。客户库实际写入应在演练验收和明确发布授权后执行。
5. **行为等价**：固定同一输入和已保存模型响应，仅在回放副本中转换身份位置。状态、原因码、事实、证据定位、调用及重试次数必须一致；模型响应里的患者原文和非身份字段不做全局替换。判定或反馈校验值若包含规则编号，按原算法重建并验证绑定，不要求字节相同，也不能直接绕过校验。
6. **端到端验证**：新任务、历史详情、反馈、统计下钻、重试、导出都使用同一四段式身份；新主链旧编号残留为零，归档及迁移资产明确白名单。固定回放不能证明新编号对真实模型完全无影响，还须另跑受控模型回归，报告变化。
7. **独立交付**：编号迁移形成可单独审查/回滚的提交并验收后，再开发两条 CT/MRI 新规则。010所有权更正属于第二阶段的明确业务变化，不能混入第一阶段的等价声明。
