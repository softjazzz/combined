# 2026-10-03 业务助手 M3 科室质量分析报告草稿（M08）

## 结论

新增管理者工具 `compose_quality_report`：标题 + 纯文本正文（≤1500字），来源默认取本会话已读的统计/趋势卡片；Python 校验正文数值必须出现在来源当前文本中，并按句拒绝比较/因果措辞（含否定的免责说明除外）。报告卡复用草稿卡（可复制），附来源与口径、数据限制，注明不是正式报告、导出发布走既有流程；回读重取来源，数值不再一致时 409。

真实验证 6 轮迭代，第 6 轮完成（5 工具、6 模型、55.1 秒）：报告含口径、结果分布、问题集中规则、趋势不可比说明、讨论要点与限制，数值均来自正式来源，未写病例标识或因果结论。

## 迭代中发现并修复

| 轮次 | 现象                                                                        | 修复                                                 |
| ---- | --------------------------------------------------------------------------- | ---------------------------------------------------- |
| 1    | “2026年9月1日”被判来源未出现（来源为 09/01）                                | 数值按值比较（去前导零），草稿校验同步               |
| 2    | 模型把分节对象数组写成带杂字符的 JSON 字符串；预算中止显示“[object Object]” | 运行时按声明类型还原数组字符串；中止转为明确中文原因 |
| 3    | 参数错误只回“不符合合同”，模型无从修正                                      | 422 返回字段路径与错误类型（不回显值）               |
| 4    | 免责句“未作……比例或增长率”被误判比较；模型写入住院号与自算合计              | 比较措辞按句判断并排除否定句；说明禁止病例标识       |
| 5    | 状态分布计数（如不适用164）被判来源未出现                                   | 统计卡片文本补“规则结果条数”；422 列出具体违规数值   |
| 6    | 一次违规（10、75）按提示删改后通过                                          | —                                                    |

另将报告合同由“分节对象数组”简化为“标题 + 正文”，避免模型生成嵌套参数失败；系统提示更新为“复检/专项任务只生成预览由用户确认”。

## 检查

后端业务 224、运行时 59 通过。私有证据 `m3-report-chat-1..6-private.json`。

## 限制

报告生成接近 60 秒编排预算，若再出现一次违规重写可能超时；“讨论要点”属模型组织的建议性文字，未做语义校验，仅数值与比较措辞受控。
