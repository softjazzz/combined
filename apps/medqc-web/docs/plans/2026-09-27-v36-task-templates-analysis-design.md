# V3.6 任务模板与任务分析合同

> 对应 PRD #43“全部任务”。本文只定义创建参数复用和任务维度只读分析，不改变任务执行、抽样、分配或质控结果的权威所有者。

## 1. 任务模板

### 1.1 边界

- 模板是当前用户私有的任务创建参数快照，不是任务，也不产生任务编号或状态。
- 保存、更新、删除、套用模板均不创建任务，不自动抽样、分配、调度或执行质控。
- 模板只保存当前已接通的配置：`scene`、`rule_set_key`、`date_range`、`department_filter`、`sampling_method`、`sampling_config`、`assign_method`、`assignee_config`。
- 模板不保存 `task_name`、`deadline`、`record_refs`、旧 `record_ids`、任务 ID/编号/状态/进度、受领人或任何运行结果。套用后，任务名称和截止日期等动态内容由用户本次填写。
- 套用只填充创建抽屉。提交任务时仍完整经过当前规则集目录、场景、抽样参数和分配策略校验；过时、损坏或当前不可用的模板不得绕过创建门禁。

### 1.2 权限与并发

- 所有模板读写都以当前稳定账号 ID 作为 `owner_id`；管理员也不能读取或改写其他账号模板。
- 同一用户最多保存 20 个模板，模板名称在该用户内唯一。
- 更新和删除必须携带 `version`，服务端使用 CAS；冲突返回 `version_conflict`，前端刷新后再操作。
- 存量模板配置读出时再次逐字段校验；损坏配置返回不可套用状态，不伪造成空配置。

### 1.3 接口与验收

- `GET /api/v1/tasks/templates`：列出本人模板。
- `POST /api/v1/tasks/templates`：保存一个创建参数快照。
- `PUT /api/v1/tasks/templates/{template_id}`：CAS 更新名称或配置。
- `DELETE /api/v1/tasks/templates/{template_id}?version=`：CAS 删除。
- 创建抽屉可选择并套用模板；模板管理支持保存、套用、编辑和删除。
- 账号切换、迟到请求和失败响应不得把上一账号模板或配置写进当前抽屉。

## 2. 任务分析（预留）

任务分析是单个任务的只读下钻，不复用全局任务状态统计冒充任务维度分析。其权威数据来自该任务和 `qc_task_records`：任务总数、各处理状态、完成率、按受领人计数与完成数。`score`、`defect_count` 缺失时分别计入未知数量并保持 `null`，不得显示为 0，也不在聚合层重判质控结果。

任务分析沿用任务详情/整任务进度的对象权限；只提供下钻和返回任务详情，不新增执行动作。本节由独立实现线补充接口与页面细节。
