# V3.6 列表所选病历批量质控收口

## 范围与证据

- PRD25验收为“批量重新质控后生成任务并展示进度”；通用批量操作要求权限、二次确认、结果及审计。
- 当前`QcRecordResultListView`已接`QcRunSelectedControl`，通过三坐标调用既有workspace batch job并轮询，完成时刷新结果。账本“仅依赖已有任务ID”的描述滞后。
- 本批只完善该既有链，不新建任务表或执行器。完整运行病例集合仍由21负责；终末归档未核验仍禁止执行，不以本批提升21/31等行。

## 实施

1. 后端创建入口同时校验既有病历ANALYZE权限与工作台数据范围，创建及幂等复用记录无患者正文的审计；保持prepare的精确病例集合校验、owner隔离及执行合同。普通质控员虽有ANALYZE动作权限但无全院工作台范围，不允许绕过列表提交任意病例；受领任务专用执行链不变。
2. 前端二次确认所选数量和现有LX0609规则集，冻结完整三坐标；非法或数量不符不得静默丢弃后执行。创建、轮询、恢复按账号/角色/场景/生命周期隔离，校验回执job身份，不把失败或未知终态当作完成。
3. 复用进度条及父列表刷新，终态完成只触发一次；账号变化清理选择。保留真实服务错误，未确认创建结果不建议盲目重复提交。
4. 聚焦HTTP权限/owner/审计测试和组件确认/精确请求/进度/失败/迟到/恢复测试；主协调复核diff并跑类型、Lint、编码及相关测试后提交。

## 交付层次

不执行真实数据库写入、迁移或质控作业。合成接口和组件测试只证明代码合同；隔离PG、真实病例和浏览器验收、业务部署另列。

- 后端7文件131项、前端列表/控件/状态条3文件66项通过，Ruff与独立复核通过。

- 代码完整不等于隔离PostgreSQL、真实病例、浏览器或部署验收；这些层次本批未完成。
