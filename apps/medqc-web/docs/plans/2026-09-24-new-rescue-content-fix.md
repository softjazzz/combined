# LX0609-09-01-02 抢救内容原子定位与时间角色修复

## 边界与证据

仅修改新增抢救内容规则执行器及其专属测试。原始 004 时效规则、公共编排、Finalizer、Store、API、前端和模型调用配置不变。基线 `775c17ede`；R01 唯一一次固定模型响应的六项引文均在各自绑定正文唯一逐字出现，六组坐标均错误。脱敏前后本次正文同为 765 字且相同，故本次失败不能归因于脱敏位移。离线回填后现有解析器接受坐标，唯时间项因不含“抢救时间：”标签降为 unknown，最终仍为资料不足。

R01 时间引文含有效时分，形式是“于[日期时分]予以…”，紧邻模型的措施引文，属于实际处置叙述候选；文书还包含入院和既往叙述。当前证据没有独立临床审阅，不能将其标为合规金标准。

## 原子合同

- 六字段及 `present/absent/unknown`、输出 schema、文书绑定和单次有界模型调用不变。`present` 仍须非空、至多 160 字的原样引文。
- 原坐标为整数且非布尔、区间合法且逐字对应时原样保留，即使同一引文在同文书重复。原坐标不准确但类型仍正确时，仅在绑定文书中引文**恰好一次**逐字出现时由 Python 回填。零次、两次（包括重叠）、跨文书、类型错误均拒绝整份模型响应；不做裁剪、标准化、模糊或最近位置匹配。
- `absent` 仍须全文 `[0, len(body))`；`unknown` 仍须三个空值。文书、字段或原子结构错误仍整批拒绝。这与现有 `model_invalid_output → data_gap` 的公开失败语义一致，不做字段级容错。
- 时间标签的 Python 直接提取保持既有优先级。无标签时间仅作为模型给出的 `rescue_time` 候选，经 Python 检查有效时分、实际动作关系及同文书措施证据；记录/签字、既往、计划等语境不算抢救时间。不确定降为 `unknown`，其余已验证字段仍保留，最终状态由现有 `_result` 判定。

## 验证与限制

先冻结合成正反例：原准确坐标、错误坐标唯一引文、重复及重叠引文、脱敏差异、无匹配、注入文本、明确标签、实际处置叙述、多次抢救、记录/签字/入院/既往/计划时间、缺时间及缺字段。随后使用 R01 同一 Evidence Session 和**原保存响应**离线回放，核对坐标、六事实、状态、原因、调用量；不再请求模型或写数据库。聚焦 pytest、Ruff、编码和 diff。真实样本只有 R01，无法证明泛化准确率或临床验收通过；保护集也无临床签收基线。
