# LX0609 两份真实病例数据不足与误判收敛计划（修订版）

**目标：** 以冯丽平（`208790` / `2496813`）和李孝西（`359787` / `2465281`）为真实病例，严格区分三类结果：

1. 当前资料源与 MaterialStore 都不存在必要资料：保留 `data_gap`，列入同步/接口补数清单；
2. 资料已沿唯一主链读到，但 Native 事实提取、字段映射或事件关联错误：以单规则 TDD 最小修复；
3. 资料来源间互相冲突或口径尚未确认：先冻结来源合同，只读审计，不靠猜测修规则。

本计划替代原“连续修复出院终点、055、任务摘要”的版本。已接受的评审结论是：原 Task 1 错把任务快照当作 Provider 的唯一资料来源；原 Task 2 不能宣称 055 已完成整个时限判定；原 Task 3 的规则数和状态汇总在当前服务中无法稳定复现。

**固定边界：**

```text
源 PG / 已加载 Bundle
→ Source Reader
→ EvidenceSnapshot / MaterialStore
→ Native 规则
→ RuleDecision
→ Canonical Envelope
→ 数据库 / API / 前端原样展示
```

- `EvidenceSnapshot / MaterialStore` 仍是唯一资料链；不增加 Bundle、Snapshot、Resolver、事件平台、LLM、Prompt、配置开关或数据库 schema。
- 规则执行器拥有业务判断；Renderer 只组织文案；Finalizer、Aggregator、Envelope、API、前端不得重判状态或原因码。
- 一个 Task 只处理一个已证明的根因，完成后独立提交、独立审核并暂停；不得连续自动进入下一项。
- 本计划不以降低 `data_gap` 数量为验收目标，更不能把真实缺失伪装成合规、不合规或不适用。

## 3. Task B：LX0609-025 植入物资料已存在时的事实提取闭环

## 9. 成功定义

本计划成功不是“所有数据不足消失”，而是：

- 055 不再使用不可能的负时间间隔；
- 025 不再忽略已读取的植入物事实；
- 064–066 不再把操作目录行误称为独立手术事件，且不会在关联口径不明时乱判；
- 终点评价与任务元数据不再基于未经确认的来源假设；
- 对资料确实缺失的规则，客户能看到具体缺什么资料，而系统仍保持保守结论。
