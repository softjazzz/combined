# 质控规则示例病历编写指引

为确保质控规则测试演示具备足够的说服力，示例病历需要做到“结构完整、要点突出、可复现质控结论”。编写和维护示例时请参考以下规范：

## 1. 基本原则

- **真实性**：示例应基于真实临床流程，描述必须符合常见诊疗场景，但不得包含任何真实患者隐私。
- **针对性**：每条示例都要明确指出触发或满足质控点的关键语句，并在 `focusPoints` 字段中列出。
- **结构化**：按“主诉 / 现病史 / 查体 / 诊断 / 处理”等段落拆分书写，方便前端展示与阅读。
- **长度要求**：建议单条示例正文控制在 **600~900 字**，正例与反例都应覆盖关键要点；必要时通过新增段落或提示扩展，但总字数不宜超过 2000 字的输入限制。
- **易维护**：使用 `apps/medqc-web/src/data/qcRuleCases.ts` 中的结构化字段，按需添加提示或评估结果。

## 2. 字段说明

| 字段 | 说明 | 示例 |
| ---- | ---- | ---- |
| `ruleId` | 质控规则编号 | `SC-007` |
| `documentType` | 对应文书类别（中文） | `入院记录` |
| `positive` / `negative` | 正例 / 反例，使用结构化对象 | — |
| `title` | 示例标题，便于快速理解 | `具备完全民事行为能力患者自行记录病史` |
| `summary` | 1-2 句概述示例要点 | `由患者本人叙述病史，记录清楚...` |
| `sections` | 段落数组，每段包含 `heading`、`content`、`hint` | — |
| `focusPoints` | 质控关注点列表，在 UI 中展示为标签 | `["病史陈述来自患者本人", ...]` |

## 3. 编写流程

1. **确认质控点**：阅读四川省住院病历质量评定标准（2023 版）原文，搞清楚判定依据。
2. **准备素材**：从匿名化案例或公开示例中选取素材，必要时自行撰写虚构场景。
3. **拆分段落**：按照病历文书格式拆分段落，并在 `hint` 中说明与质控点的关联。
4. **标注焦点**：将质控要点写入 `focusPoints`，保持 3 条以内的精炼描述。
5. **自检**：确认示例长度、中文标点和段落对齐；确保反例准确反映违规点。
6. **测试**：在前端质控规则测试弹窗中切换正例/反例，核实文本展示正常。

## 4. 维护建议

- **版本控制**：每次调整示例请在 PR 描述中附带修改原因和截图。
- **扩展覆盖**：优先补齐缺口多、反馈频繁的质控点；推荐按文书类型批量维护。
- **Review 清单**：
  - 是否写明病史提供者及行为能力（适用于 SC-007 等规则）。
  - 是否包含必要的时间节点（24 小时、术前/术后等）。
  - 是否提供触发规则的关键语句（反例必须可被运行规则准确抓取）。
  - 是否给出与质控点无关的冗余信息？如有，应当精简。

## 5. 后续工作

- 持续扩展 `qcRuleCases` 中的规则覆盖范围。
- 结合 LLM 真实评估反馈，迭代示例文本的可读性与判定准确度。
- 未来可考虑将该数据迁移至后端，由运营或质控人员在 CMS 中维护。当前阶段使用前端文件以保证迭代效率。
