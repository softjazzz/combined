# 四川省病历质控系统 - 佐证依据功能使用指南

## 📋 功能概述

佐证依据功能为四川省病历质控系统的每个质控规则评估结果提供详细的支撑证据，包括从病历原文中提取的相关文本片段、评估逻辑说明和改进建议，大大提高了质控结果的可信度和可解释性。

## 🎯 核心特性

### 1. 智能证据提取
- **自动识别**: 从病历原文中自动提取支撑质控结论的关键证据
- **多格式支持**: 支持单一文本、分号分隔、JSON格式等多种证据格式
- **位置标注**: 精确标明证据在病历中的具体位置

### 2. 原文高亮显示
- **实时高亮**: 点击"定位原文"即可在病历中高亮显示相关证据
- **导航功能**: 支持在多个证据片段间快速导航
- **上下文展示**: 提供证据的完整上下文信息

### 3. 详细评估说明
- **评估发现**: 详细说明为什么该规则合规或不合规
- **评估逻辑**: 解释质控结论的推理过程
- **改进建议**: 为不合规项目提供具体的改进建议

## 🎮 使用指南

### 第一步：启动质控评估

1. **打开病历详情页面**
   - 在病历列表中选择要评估的病历
   - 点击进入病历详情页面

2. **启动四川省质控**
   - 点击页面右上角的"四川省病历质控"按钮
   - 在弹出的模态框中选择质控模式

3. **选择多文书模式**（推荐）
   - 开启"多文书模式"开关
   - 多文书模式能提供更精准的证据定位

### 第二步：查看佐证依据

1. **等待评估完成**
   - 系统会自动分析病历内容
   - 显示各文书类型的质控结果

2. **展开佐证依据**
   - 在每个质控规则结果下方找到"查看佐证依据"按钮
   - 点击按钮展开详细的证据信息

3. **浏览证据内容**
   - **评估结论**: 显示合规状态和置信度
   - **评估发现**: 详细的评估说明
   - **支撑证据**: 从病历中提取的具体证据片段
   - **评估逻辑**: 质控结论的推理过程
   - **改进建议**: 针对不合规项目的改进建议

### 第三步：定位原文证据

1. **点击定位原文**
   - 在证据片段旁边点击"定位原文"按钮
   - 系统会自动在病历原文中高亮显示该证据

2. **查看高亮内容**
   - 页面会自动显示"病历原文 - 证据标注"区域
   - 相关证据会以黄色背景高亮显示
   - 当前查看的证据会以橙色背景突出显示

3. **导航多个证据**
   - 使用"上一个"/"下一个"按钮在证据间导航
   - 查看证据计数和当前位置
   - 点击"清除标注"可清除所有高亮

## 🔍 功能详解

### 证据类型识别

系统支持多种证据格式的自动识别和解析：

#### 1. 分号分隔的多个证据
```
主诉：反复胸闷气短2年;体格检查：双下肢水肿;辅助检查：BNP升高
```
- 自动分割为3个独立的证据片段
- 每个片段都有独立的位置标注

#### 2. 单一长文本证据
```
患者2年前开始出现活动后胸闷气短，休息后可缓解。1周前症状加重。
```
- 按句号自动分割为多个证据点
- 保持语义的完整性

#### 3. 结构化JSON证据
```json
[
  {"text": "心界向左下扩大", "location": "体格检查心脏部分"},
  {"text": "射血分数35%", "location": "超声心动图"}
]
```
- 支持复杂的结构化证据格式
- 包含精确的位置信息

### 高亮显示功能

#### 高亮样式
- **普通高亮**: 黄色背景，用于标注所有相关证据
- **当前高亮**: 橙色背景，突出显示当前查看的证据
- **动画效果**: 平滑的高亮切换动画

#### 导航功能
- **自动滚动**: 点击定位时自动滚动到证据位置
- **循环导航**: 到达最后一个证据时自动回到第一个
- **位置指示**: 显示当前证据在所有证据中的位置

### 评估逻辑说明

系统为每个质控规则提供详细的评估逻辑：

#### 合规情况
```
根据质控规则"SC-001 主诉记录完整性"的要求，通过分析病历内容，
发现主诉记录完整且符合规范要求，包含了症状、持续时间等关键信息，
因此评估为合规。
```

#### 不合规情况
```
根据质控规则"SC-002 现病史逻辑性"的要求，通过分析病历内容，
发现现病史记录中时间顺序不清晰，缺少症状发展的逻辑关系，
因此评估为不合规。
```

## 🔧 技术实现

### 前端组件架构

```
MedicalRecordDetail.vue (主页面)
├── EvidenceViewer.vue (佐证依据展示)
│   ├── 证据解析逻辑
│   ├── 评估信息展示
│   └── 高亮请求处理
└── HighlightedText.vue (原文高亮)
    ├── 文本高亮渲染
    ├── 导航功能
    └── 滚动定位
```

### 数据流程

1. **后端LLM评估** → 返回结构化证据数据
2. **前端证据解析** → 解析多种格式的证据
3. **用户交互** → 点击查看佐证依据
4. **高亮请求** → 点击定位原文
5. **原文标注** → 在病历中高亮显示

## 🚀 最佳实践

### 使用建议

1. **优先使用多文书模式**
   - 多文书模式提供更精准的证据定位
   - 每种文书类型都有专门的证据提取逻辑

2. **逐个查看证据**
   - 按规则逐个查看佐证依据
   - 重点关注不合规项目的证据和建议

3. **结合原文验证**
   - 使用"定位原文"功能验证证据的准确性
   - 查看证据的完整上下文

4. **关注改进建议**
   - 对于不合规项目，仔细阅读改进建议
   - 结合具体证据制定改进措施

### 性能优化

1. **按需加载**
   - 证据面板采用懒加载方式
   - 只有点击时才解析和显示证据

2. **智能缓存**
   - 已查看的证据会被缓存
   - 避免重复解析和渲染

3. **响应式设计**
   - 支持移动端和桌面端
   - 自适应不同屏幕尺寸

## 🔍 故障排除

### 常见问题

1. **证据显示不完整**
   - 检查后端LLM返回的evidence字段
   - 确认证据格式符合解析规则

2. **高亮功能不工作**
   - 检查证据文本是否在原文中存在
   - 确认文本匹配的准确性

3. **导航按钮无响应**
   - 检查是否有多个证据片段
   - 确认高亮组件正确初始化

### 调试方法

1. **查看浏览器控制台**
   ```javascript
   // 查看证据解析结果
   console.log('解析的证据:', parsedEvidence)
   
   // 查看高亮文本列表
   console.log('高亮文本:', highlightTexts)
   ```

2. **检查网络请求**
   - 确认API返回的数据结构正确
   - 验证evidence和evidence_locations字段

3. **测试不同证据格式**
   - 使用测试脚本验证证据解析
   - 确认各种格式都能正确处理
