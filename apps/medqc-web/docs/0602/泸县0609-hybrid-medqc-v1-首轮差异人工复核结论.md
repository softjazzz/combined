## 复核结论

`hybrid_medqc_v1` 当前不建议迁入主干。它降低了规则混杂度，但在触发条件门控上变弱，容易把“无当前手术、无输血、无病危/病重、缺少触发事件”的规则判成缺陷或不确定。

首轮 23 条差异中：

- baseline 更可信：14 条
- hybrid 更可信：6 条
- 两者都需要修正为“不适用/数据不足/证据不足”：3 条

这说明当前主要问题不是 pack fallback，而是规则触发条件与证据门控。继续扩大样本前，应先把 `hybrid_medqc_v1` 增加硬门控，否则会扩大误报。

## 对 hybrid_medqc_v1 的修正要求

### P0：增加触发条件硬门控

这些规则必须先确认触发事件存在，否则不得交给 LLM 自由推断为缺陷：

- 手术相关：`LX-019`、`LX-022`、`SC-082`、`SC-087`、`SC-096`、`CL-208`
  - 必要触发：本次住院有效手术名称、手术时间、手术记录或手术医嘱。
  - 空壳 `surgery_record` 不算有效手术事件。
- 输血相关：`LXE-52`、`SC-073`、`SC-133`、`SC-134`
  - 必要触发：输血医嘱、输血记录、输血申请或血制品费用。
- 病危/病重相关：`CL-231`、`SC-051`
  - 必要触发：病危/病重医嘱、病危/病重告知书、病程中明确“病危/病重”状态。
- 病理相关：`SC-037`
  - 必要触发：病理申请、病理报告、手术取材记录。细菌培养不能作为病理触发。

### P1：把“空壳文书”识别为数据不足

`surgery_record` 虽然存在，但内容全为空字段，不应作为“有手术记录”或“缺手术记录”的直接证据。需要在 bundle 构建或规则执行前做文书质量标记：

- `empty_shell_document=true`
- `has_effective_content=false`
- `trigger_eligible=false`

### P1：证据引用要精确到字段

hybrid 有几条方向正确，但证据太粗：

- `CL-248` 应引用“已遵会诊意见”及是否有具体执行措施。
- `SC-068` 应引用 `医生签名:` 为空的会诊记录。
- `SC-048`、`SC-049` 应引用入院记录时间和查房记录时间，而不是只引用医生签名。

### P2：时间源优先级

这份病历存在 `record_time=2026-03-29` 与结构化诊断时间 `2026-04-19` 冲突。时限规则需要固定时间源优先级：

1. 入院记录 `record_time`
2. 住院主表入院时间
3. 文书 `sort_time`
4. 结构化诊断时间仅用于诊断条目，不得覆盖入院时间

## 策略结论

`hybrid_medqc_v1` 的分桶思路可以保留，但不能按当前版本上线。下一版应改为：

1. 先运行程序化触发条件门控，过滤不适用规则。
2. 对有明确触发事件的规则再进入 hybrid 小包 LLM。
3. 对缺关键触发表字段的规则输出 `data_gap`，不进入缺陷判断。
4. 对 LLM 结果增加“证据必须包含触发事件”的后校验。

只有完成以上门控后，再追加外科/内科各 1 份病历做第二轮 POC。
