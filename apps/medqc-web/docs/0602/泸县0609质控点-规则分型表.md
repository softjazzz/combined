## 2. 分型定义

| 分型         | 定义                                                                   | 执行原则                                          |
| ------------ | ---------------------------------------------------------------------- | ------------------------------------------------- |
| Trigger Gate | 判断规则是否适用于当前病历，例如是否有手术、输血、会诊、病危病重医嘱。 | 程序化优先；无触发事件返回 `not_applicable`。     |
| 程序化规则   | 时限、存在性、数量一致性、字段完整性等可由代码或 SQL 确定的规则。      | 不交给 LLM 直接裁决；必须输出阈值、实际值和差值。 |
| 跨文书规则   | 需要比较多份文书或同一业务域文书。                                     | 构建 rule-level context bundle，输出证据矩阵。    |
| 跨表联查     | 需要医嘱、检查、检验、输血、费用等结构化表。                           | 数据不全返回 `data_gap`，不能判合格。             |
| LLM 语义规则 | 需要判断分析是否充分、会诊意见是否明确、文本是否复制等语义问题。       | LLM 只处理语义部分，并强制引用原文证据。          |

## 3. 当前总体判断

当前 49 条规则不是全部可正式验收：

- `formal_ready`：3 条，具备候选条件但仍需真实 golden answer 验证。
- `ready_with_data_gap`：3 条，规则逻辑可定义，但当前客户样本池缺关键结构化时间或正文。
- `needs_evidence_hardening`：10 条，已有执行基础但证据字段、客户口径或阈值需增强。
- `needs_cross_document`：14 条，需要跨文书 bundle 或多文书比对逻辑。
- `needs_data_linkage`：15 条，需要医嘱、检查、检验、输血、费用等结构化数据联查。
- `needs_rule_implementation`：4 条，需要新增专项规则。
