# 泸县0609质控点-测试计划

更新时间：2026-06-13

## 目标

本测试计划用于验证 `luxian_0609_qc_v1 / 泸县0609质控点验证 v1` 是否达到客户样本验证和现场演示可接受的质控效果。

测试目标不是证明 49 条规则“能跑”，而是证明规则能稳定输出以下五类可解释状态：

- `non_compliant`：确有缺陷，必须有证据和建议。
- `compliant`：符合规则，必须说明关键满足点。
- `not_applicable`：触发事件不存在，例如无本次手术、无输血、无病危病重。
- `data_gap`：数据不足，不能判定，例如缺医嘱、费用、报告时间、出院记录。
- `uncertain`：模型或规则无法稳定判断，需人工复核。

禁止把 `data_gap` 统计为合规；禁止把无触发事件的规则交给 LLM 自由判断后输出严重缺陷。

## 测试范围

本轮只验证泸县 0609 客户专项规则集：

- 规则集 key：`luxian_0609_qc_v1`
- 客户质控点：`LX0609-001` 至 `LX0609-049`
- 映射底层规则：按 `backend/app/data/luxian_0609_rules_v1.json`

本轮不扩大到 SC 全量规则，不直接改主干 `QCRuleOrchestrator`，Trigger Gate 仍作为旁路能力验证。

## 测试阶段

### 阶段 A：单病历机制复核

默认样本：`visit_id=2313364`

目标：

- 验证无手术、无输血、无病理、无病危病重时，相关规则被拦截为 `not_applicable`。
- 验证 `data_gap` 不再被标记为 `is_compliant=true`。
- 输出 `baseline_current` 与 `trigger_gate_baseline` 的差异。
- 人工复核所有差异，确认 Trigger Gate 是否误拦。

通过标准：

- 手术、输血、病理、病危病重规则无误报。
- `data_gap` 不被统计为合规。
- 仍进入 LLM 的规则结果有可定位证据。

### 阶段 B：触发族小样本测试

选 6-8 份真实样本，优先覆盖：

- 无触发综合样本：验证 `not_applicable`。
- 真实手术样本：验证手术、术前、术后、手术安全核查。
- 麻醉或术前讨论样本：验证麻醉同意、访视、麻醉记录、MDT。
- CT/MRI 阳性样本：验证报告记录和阳性分析。
- 细菌培养阳性样本：验证培养记录和阳性菌分析。
- 会诊记录丰富样本：验证会诊目的、意见、执行和照抄。
- 出院记录样本：验证恶性肿瘤出院后治疗计划。
- 如有条件，补充输血样本：验证输血同意、评估、病程、费用一致性。

通过标准：

- 有触发事件规则误拦率为 0。
- 无触发事件规则误报率低于 5%。
- `uncertain` 占比低于 20%。
- 每条结果必须有证据、建议、触发依据或数据缺口说明。

### 阶段 C：49 条规则逐条复核

对每条客户质控点建立人工复核记录，字段见：

- `docs/0602/泸县0609质控点-人工复核表.csv`

通过标准：

- 49 条规则均有至少 1 条可复核记录。
- P0 高风险规则人工一致率不低于 90%。
- 全部规则人工一致率不低于 85%。
- 严重缺陷误报率不高于 5%。
- 不允许出现“有缺陷却显示符合规则要求”的状态反转。

### 阶段 D：客户样本验证页面演示测试

在 `/workstation-v4/customer-sample-validation` 选择 `泸县0609质控点验证 v1`，跑 10-20 份客户样本。

记录：

- 任务创建耗时。
- 首条结果出现耗时。
- 总耗时。
- fallback 率。
- parse error 数。
- 每份病历命中数。
- `not_applicable / data_gap / uncertain / non_compliant / compliant` 分布。

通过标准：

- 页面无全局异常。
- 任务创建成功率 100%。
- 结果详情可打开。
- 10 份样本中至少 8 份返回完整可读结果。
- `data_gap` 明确说明缺少什么数据。
- 不暴露 `prompt`、`raw_response`、`embedding` 或内部链路文本。

## 满意效果定义

达到以下条件才算满意：

- 49 条规则全部有测试记录。
- 人工复核总体一致率不低于 85%。
- P0 高风险规则一致率不低于 90%。
- 无触发事件规则误报率不高于 5%。
- 有触发事件规则误拦率为 0。
- `data_gap` 不被算作合规。
- 严重缺陷不能出现状态反转。
- 结果必须有证据、建议、触发依据或数据缺口说明。

## 问题分级

- P0：状态反了、误拦有触发规则、无触发却报严重缺陷。
- P1：证据引用错、时间源错、文书类型错。
- P1：fallback 或 parse error 导致规则缺结果。
- P2：建议文案不专业、UI 标签不清晰、结果可读性差。
