# 泸县0609质控点-执行依赖矩阵

> 目标：把客户第一批 49 条质控点从“规则描述”拆成可执行依赖，明确哪些可以单文书判断，哪些必须跨文书比对，哪些必须联查医嘱、检查、检验、费用等结构化数据。
>
> 关联文档：
>
> - `docs/0602/客户第一批质控点-语义规则覆盖矩阵.md`
> - `docs/0602/泸县0609质控点-病历书写规范依据映射表.md`
> - `docs/0602/医疗机构病历书写规范（2026年版）_合并.md`

## 判定口径

| 判定类型   | 定义                                                             | 实现方式                                        |
| ---------- | ---------------------------------------------------------------- | ----------------------------------------------- |
| 单文书     | 只依赖一类文书的存在、时限、字段完整性或语义内容。               | 可直接走现有语义规则或确定性规则。              |
| 同域多文书 | 依赖同一业务域内多份文书，例如多篇病程记录、术前小结和手术记录。 | 需要按 `visit_id` 聚合同域文书。                |
| 跨文书     | 需要比对不同文书域，例如会诊记录和病程记录、手术记录和麻醉记录。 | 需要构建规则级文书 bundle。                     |
| 跨表联查   | 需要联查医嘱、检查、检验、费用、输血等结构化数据。               | 需要新增或复用 `qc_context_bundle`。            |
| 语义判断   | 需要判断内容是否明确、是否分析、是否照抄、是否有治疗计划。       | 需要 LLM 或规则加语义判断，且必须引用原文证据。 |

| 入院记录     | `admission_record`                                        | 基本满足                 | 支持入院记录内容、记录时间、结构化字段和全文。                 |
| 首次病程记录 | `first_course_record`                                     | 基本满足                 | 有记录时间、诊断依据、鉴别诊断、诊疗计划等字段。               |

| 检查结果     | `exam_master`、`exam_item_report`                         | 部分满足                 | CT/MRI 需检查项目、报告时间、结果摘要。                        |

| 输血         | `bloodtrans_record`、`blood_application`、`mr_bloodtrans` | 部分满足                 | 需和医嘱、手术记录、麻醉记录、费用明细联查。                   |
| 费用         | `mr_cost`、`medical_insurance_settlement_cost`            | 部分满足                 | 输血医嘱与收费一致性需要明细级费用项目。                       |

## 规则实现分层

### v2：优先补齐文书类和跨文书类规则

这些规则可以在现有文书数据基础上完成，不依赖费用或复杂医嘱明细：

- `LX0609-007` 病情稳定患者 3 天无查房病程记录
- `LX0609-020` 有会诊记录单无请会诊执行记录
- `LX0609-022` 会诊意见不明确
- `LX0609-023` 会诊执行记录照抄会诊意见
- `LX0609-024` 恶性肿瘤手术记录未写淋巴结清扫情况
- `LX0609-025` 手术植入物信息不完整
- `LX0609-027` 恶性肿瘤出院后治疗计划缺失
- `LX0609-031` 手术记录非手术者签字
- `LX0609-035` 麻醉知情同意签名或时间不规范
- `LX0609-036` 麻醉术前或术后访视缺失
- `LX0609-037` 麻醉访视内容不规范
- `LX0609-038` 麻醉记录单缺失
- `LX0609-044` 输血前评估缺失或不完整
- `LX0609-046` 输血病程记录不完整或不规范

### v3：补齐跨表联查规则

这些规则必须有稳定的 `qc_context_bundle`，把同一 `visit_id` 下的文书、医嘱、检查、检验、费用和输血明细聚合到规则输入中：

- `LX0609-008` 病重患者 2 天无查房病程记录
- `LX0609-009` 病危患者每日病程记录或病情变化记录缺失
- `LX0609-010` CT/MRI 检查前病程记录或原因缺失
- `LX0609-011` CT/MRI 报告后 24 小时内未记录
- `LX0609-012` CT/MRI 阳性结果未分析
- `LX0609-014` 细菌培养报告后 24 小时内未记录
- `LX0609-015` 细菌培养阳性菌未分析
- `LX0609-026` 化疗记录与医嘱不一致
- `LX0609-028` I/II 类切口预防抗菌药物使用超时
- `LX0609-043` 输血前常规检查不完整
- `LX0609-048` 术中输血多文书记录不一致
- `LX0609-049` 输血医嘱与收费不一致

## 需要补的基础能力

1. **规则级上下文聚合**
   - 输入：`visit_id`、规则 ID、规则集 key。
   - 输出：该规则需要的文书、结构化数据和时间轴。
   - 不应把全病历无差别塞给 LLM。

2. **统一文书时间轴**
   - 至少覆盖入院时间、出院时间、记录时间、报告时间、医嘱开始时间、医嘱停止时间、手术时间、输血时间。

3. **医嘱分类器**
   - 识别病危、病重、手术、化疗、抗菌药物、输血医嘱。
   - 区分治疗性抗菌药物和预防性抗菌药物。

4. **检查检验分类器**
   - 识别 CT、MRI、病理、细菌培养。
   - 识别报告时间、异常或阳性结果。

5. **跨文书字段抽取**
   - 手术记录、麻醉记录、术后首次病程记录中的输血成分、输血量、输血时间。
   - 手术记录中的植入物、术者、签名、淋巴结清扫情况。

6. **费用项目映射**
   - 输血医嘱与费用明细项目映射。
   - 至少支持血液制品、配血、输血相关费用的演示口径。

## 结论

当前项目的文书类型和基础 CDM 表总体覆盖客户第一批质控点，但“规则执行链路”还没全部接通：

- v1 已可演示已有可执行规则。
- v2 应补齐文书类和跨文书类规则，重点解决客户肉眼能验证的病历书写问题。
- v3 再补跨表联查规则，重点解决医嘱、检查、检验、费用与文书一致性。
