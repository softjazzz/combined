# 泸县0609质控 POC 有效能力迁主干方案

## 背景

泸县 0609 质控集当前通过旁路脚本验证以下能力：

- Trigger Gate：先判断业务触发事件是否存在，避免无手术、无输血、无病危病重等场景被 LLM 误报。
- 状态归一化：把 LLM 或 gate 结果统一为 `non_compliant / compliant / not_applicable / data_gap / uncertain`。
- 客户点聚合：以 49 条 `LX0609-xxx` 客户质控点为主体，聚合底层 `SC/LX/CL/LXE` 执行规则结果。
- 结构化事件信号：从 PG/CDM 表读取手术、麻醉、病理、化疗、输血、检查检验、费用、出院记录等触发事实。

已完成真实 LLM 验证的合成样本：

| 样本             | 场景               | Golden 命中 |
| ---------------- | ------------------ | ----------- |
| `LX0609_SYN_001` | 基础时限缺陷       | 4/4         |
| `LX0609_SYN_002` | 基础时限合规       | 4/4         |
| `LX0609_SYN_003` | 病重/病危查房边界  | 3/3         |
| `LX0609_SYN_004` | 抢救记录时限       | 3/3         |
| `LX0609_SYN_005` | CT/MRI 与细菌培养  | 3/3         |
| `LX0609_SYN_006` | 复制病历与诊断逻辑 | 3/3         |
| `LX0609_SYN_007` | 会诊质量           | 3/3         |
| `LX0609_SYN_008` | 手术麻醉           | 4/4         |
| `LX0609_SYN_009` | 肿瘤病理化疗       | 4/4         |
| `LX0609_SYN_010` | 输血               | 4/4         |

合计：`35/35` 条 golden answer 与系统输出状态一致。上述结论来自旁路 POC，不代表 49 条规则已全部生产可上线；它证明的是 Trigger Gate、状态归一化、结构化事件信号和客户点聚合这套机制可以作为迁主干候选。

本轮真实调用模型的关键观测：

- 10 份合成样本均 `provider_error_count=0`。
- `LX0609_SYN_006` 出现 1 次 parse/fallback，但最终客户质控点聚合结果正确。
- `LX0609_SYN_009` 出现 2 个 fallback pack，但最终客户质控点聚合结果正确。
- 剩余命中依赖的 POC override 主要覆盖确定性时限/状态规则：入院记录 24 小时、首次病程 8 小时、72 小时高级职称查房、病重/病危边界、抢救 6 小时。这些不能以脚本硬编码迁入，应转为正式结构化规则或程序化 gate。

## 迁主干目标

把旁路验证有效的机制迁入正式质控链路，但不把 POC 脚本里的临时硬编码直接搬进生产。

迁入后应满足：

- 正式批量质控结果以 49 条客户质控点为主体展示。
- 无触发事件的规则返回 `not_applicable`，不进入 LLM。
- 缺关键数据的规则返回 `data_gap`，不伪装为合规。
- 有触发事件的规则才进入 LLM 或程序化规则判断。
- 结果中保留证据来源、触发事实、底层规则映射和聚合来源。

## 建议迁入模块

### 1. Trigger Gate 服务

新增服务建议：

```text
backend/app/services/luxian_0609_trigger_gate.py
```

职责：

- 输入：`visit_id`、客户规则目录、结构化 bundle。
- 输出：每条 `LX0609-xxx` 的 gate decision。

核心输出：

```json
{
  "rule_id": "LX0609-041",
  "gate_family": "transfusion_event",
  "action": "not_applicable",
  "status": "not_applicable",
  "reason": "未发现本次住院输血事件，输血规则不适用。",
  "evidence": "未见输血医嘱、输血申请、输血记录或输血费用。"
}
```

Trigger Gate 不应调用 LLM。

### 2. 结构化事件信号加载器

新增服务建议：

```text
backend/app/services/luxian_0609_event_signal_loader.py
```

从以下数据源读取触发事实：

- 文书：入院记录、首次病程、日常病程、查房记录、会诊记录、抢救记录、出院记录。
- 手术麻醉：手术记录、术前小结、术前讨论、手术安全核查、麻醉记录、手术申请、手术知情同意。
- 检查检验：`exam_item_report`、`labtest_item_report`。
- 病理：`pathology_exam_master`、`pathology_exam_report`。
- 医嘱费用：`inpat_drug_order`、`inpat_nondrug_order`、`inpat_bill_item`。
- 输血：`blood_application`、`bloodtrans_record`。

输出应包含：

- `event_flags`
- `evidence_quotes`
- `data_gap_reasons`
- `source_tables`

### 3. 状态归一化

新增统一状态枚举：

```text
non_compliant
compliant
not_applicable
data_gap
uncertain
not_executed
technical_error
```

规则：

- `data_gap` 不得算作 `compliant`。
- `not_applicable` 表示触发条件不存在，不是“质控通过”。
- `uncertain` 必须进入人工复核队列。
- `technical_error` 与业务不合规分开统计。
- 反例有缺陷却显示“符合规则要求”属于 P0。

### 4. 客户点聚合器

新增服务建议：

```text
backend/app/services/luxian_0609_customer_result_aggregator.py
```

聚合规则：

1. 优先使用 `primary_execution_rule_id` 的结果。
2. 如果 primary 不存在，再使用 `mapped_rule_ids` 中的可用结果。
3. `non_compliant` 优先级最高。
4. `data_gap` 高于 `compliant`。
5. `uncertain` 不得被其它 compliant 结果覆盖。
6. 如果映射到底层不可执行规则，应标记为 `not_executed` 或 `data_gap`，不能静默通过。

### 5. 规则目录映射校验

新增启动或测试期校验：

- 每个 `LX0609-xxx` 必须有 `primary_execution_rule_id`。
- `primary_execution_rule_id` 必须存在于当前规则集执行规则中。
- 如果不存在，必须在规则目录中标记 `implementation_status=待补规则` 或 `data_status=待数据联查`。

当前已发现的问题：

- `LX0609-027` 映射到 `SC-116/SC-124`，但这两个底层规则不在当前 59 条执行规则中。旁路 POC 用客户点级校正跑通，但正式主干应补对应可执行规则或调整规则集。

## 不建议直接迁入的内容

旁路脚本中的 `_apply_luxian_poc_customer_overrides()` 属于 POC 校正，不应原样进主干。

迁主干时应拆成：

- 可解释的结构化 gate。
- 规则级 prompt 优化。
- 客户点聚合策略。
- golden case 回归测试。

## LLM 安全运行要求

真实 LLM 验证必须满足：

- 使用 `workspace-write` 文件权限。
- 不使用 `danger-full-access`。
- LLM 调用走受控本地代理或网络 allowlist。
- 真实病历不得直接发往未受控外部模型。
- POC 可优先使用 `LX0609_SYN_%` 合成样本。

安全运行配置见：

```text
docs/0602/Codex最小权限LLM运行配置方案.md
```

## 当前结论

可以迁主干的不是“某几个样本的临时 override”，而是以下工程机制：

- 先 gate，再 LLM。
- 先判断触发事实，再判断缺陷。
- 明确区分 `not_applicable` 和 `data_gap`。
- 客户点聚合优先 primary rule。
- 底层规则缺失必须显式暴露。
- LLM 调用必须经过安全出口。
