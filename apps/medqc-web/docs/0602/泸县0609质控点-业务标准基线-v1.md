## 3. 状态定义

| 标记     | 含义                                                            |
| -------- | --------------------------------------------------------------- |
| 正式     | 属于当前67条正式规则，可依据现行规范或客户明确口径验收          |
| 临时     | 属于经批准的8条临时规则：050、054、055、056、057、059、063、075 |
| 已确定   | 业务标准足以实施；数据缺失应返回数据不足，不得重新解释标准      |
| 部分确定 | 已确定子判定可以实施，未确定子判定不得影响最终状态              |
| 待确认   | 不允许输出确定问题或合规结论，只能说明缺少的标准或资料          |

正式/临时是产品发布属性，已确定/部分确定/待确认是标准完整性属性，两者不能混用。

## 10. 当前仍需院方确认的最小清单

本基线生效后，不再向客户重复询问已经由2026规范或客户补充确认的问题。剩余问题压缩为：

1. 010：CT/MRI检查前病程的有效时间窗、一次病程对应多次检查的关联规则和急诊例外。
2. 017：70%相似度算法、文本预处理、最短长度，以及“两次以上”到底指两份还是至少三份。
3. 023：如仍要求单独判断“照抄”，需确认相似度算法和允许重复范围。
4. 024：必须记录淋巴结清扫的癌种—术式目录、例外及未清扫原因要求。
5. 028：允许预防用药延长至48小时的特殊情况清单，以及预防/治疗意图权威字段。
6. 049：医嘱—实际输注—收费业务键、退费、补录和拆分收费规则。
7. 056：“重点抗菌药”是否等于限制使用级加特殊使用级。
8. 059：如需扩大到“缺诊疗医嘱”，需提供分病种或分操作必需医嘱目录。

## 11. 引擎落地要求

1. 标准先写入版本化 Fact/Decision 合同，再修改 `phase_scope`；不得先改标签制造已完成假象。
2. 已确定规则缺少源数据时返回具体数据不足，不得降级成不适用。
3. 部分确定规则只能执行已列明子判定；未确认子判定不得影响最终状态。
4. 确定性存在性、时间和数值计算使用Python；语义判断仅接收最小必要上下文，并输出受控事实枚举。
5. 每条规则至少有合规、不合规、不适用和数据不足验收样本；不具备某状态的规则应在合同中明确。
6. 每族完成后使用至少两份真实脱敏病例核对 Native、Canonical Envelope、数据库保存和单一结果API。
