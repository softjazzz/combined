# 病案智能助手 PRD 差距审计

日期：2026-06-07

## 审计结论

病案智能助手已从单一“质控助手”扩展为同一对话面板中的四类能力入口：质控、编码、DRG/DIP 入组模拟、SQLBot 问数。其中质控、ICD 编码查询、当前病历编码建议、DRG/DIP 模拟入组已经接入受控 `qc_agent` 工具链；SQLBot 问数完成源码内嵌、配置接口和前端入口，但第一版仍是独立 iframe 嵌入，不把 Text-to-SQL 结果转换为本系统结构化结果卡。

整体安全边界保持为只读分析：不写正式病案首页、不写医保结算清单、不写正式 DRG/DIP 结果、不写正式质控结果表；敏感字段继续通过后端 `assert_no_sensitive_output` 和前端 `sanitizeQcAgentPayload` 过滤。

## PRD 条目对照

### 1. 质控

已完成：

- 对话式输入、右侧抽屉聊天流、用户消息/助手结构化结果分离。
- 单病历只读上下文定位，支持 `visit_id`、候选病历确认和文书选择。
- 质控结果卡展示发现问题数、高风险数、执行规则、未执行规则、证据摘要和处理建议。
- 不支持写入、保存、提交、导出等危险意图，返回 `unsupported`。

未完成或部分完成：

- 批量正式质控任务创建和进度追踪未接入该聊天面板。
- 病案首页质控、医保结算清单质控在聊天面板中仍以受控拒绝或待扩展为主。
- “查看执行计划”等下一步动作目前只填充输入框，不自动执行，符合防误触设计，但还不是完整任务编排。

### 2. ICD 编码查询

已完成：

- 自然语言识别 ICD 查询、诊断编码查询、手术操作编码查询。
- ICD 候选卡展示查询词、编码类型、版本、候选编码、置信度、匹配方式和医保/国临映射。
- 不展示原始 ICD 大表、向量路径、embedding 或 raw response。

未完成或部分完成：

- “复制编码”等卡片内动作目前是展示按钮，未全部接入剪贴板和后续入组链路。
- 尚未提供编码召回率、准确率和地方医保映射覆盖率审计报告。

### 3. 当前病历编码建议

已完成：

- 支持 `给 visit_id=xxx 推荐诊断和手术编码`。
- 展示病历摘要、主要诊断候选、手术/操作候选、置信度、来源和低置信度提示。
- 明确“仅为编码建议，不写入正式首页或结算表”。

未完成或部分完成：

- 目前偏规则/结构化字段抽取，不等价于完整医学知识图谱推理。
- 未提供编码员确认、采纳、驳回和审计留痕功能。
- 未写入正式病案首页，也不应在当前只读助手中直接写入。

### 4. DRG/DIP 入组模拟

已完成：

- 支持通过主诊断、手术、年龄、住院日、费用等参数触发 DRG/DIP 模拟。
- DIP 卡展示城市、主诊断编码、DIP 编码、DIP 名称、病种类型、入组路径和费用/住院日摘要。
- DRG 卡展示主诊断、其他诊断数量、手术操作数量、ADRG/DRG、权重、模拟支付、盈亏风险、映射信息和降级提示。
- 外部服务失败时返回受控 fallback，不暴露 `raw_response`。

未完成或部分完成：

- 未把未入组原因转成系统化编码修正建议闭环。
- DRG/DIP 本地化适配、一致率统计、支付标准和费用极高/极低组监测仍需接入正式指标服务。
- 结果为模拟结果，不写正式 DRG/DIP 结果表。

### 5. SQLBot 问数

已完成：

- `dataease/SQLBot` 源码快照放入 `third_party/sqlbot/`，与主 `src/` 和 `backend/app/` 隔离。
- `third_party/sqlbot/UPSTREAM.md` 记录来源、commit、快照时间、拷贝排除项和许可证/品牌保留要求。
- 新增 `GET /api/v1/sqlbot/config`，默认未启用返回 `enabled=false`，已配置时返回不含密钥的嵌入配置。
- 智能助手新增“问数”能力 chip 和“统计今天病案问题集中点”建议 chip。
- 未配置时显示 SQLBot 未配置/待接入；已配置时打开 iframe。

未完成或部分完成：

- SQLBot 服务部署、连接数据源、指标语义层、只读库权限、行列级权限控制均不在本次代码内完成。
- 第一版不把 SQLBot Text-to-SQL 结果转成本项目结构化结果卡。
- 问数能力不进入 `/api/v1/qc-agent/chat`，避免破坏现有受控 Agent 边界。

## 安全边界审计

| 安全要求                                                  | 当前状态 | 证据                                                                                    |
| --------------------------------------------------------- | -------- | --------------------------------------------------------------------------------------- |
| 不写正式病案首页                                          | 已满足   | `qc_agent` 工具均注册为 `writes_db=False`；聊天面板仅调用只读工具                       |
| 不写医保结算清单                                          | 已满足   | SQLBot 文档明确禁止；助手未接入结算清单写入动作                                         |
| 不写正式 DRG/DIP 结果                                     | 已满足   | DRG/DIP 仅模拟返回，工具注册为 `writes_db=False`                                        |
| 不暴露 `medical_text` / `documents` / `record_content`    | 已满足   | 后端 `assert_no_sensitive_output`；前端 `sanitizeQcAgentPayload`；单测覆盖              |
| 不暴露 `raw_response` / `prompt` / `embedding` / `vector` | 已满足   | 后端敏感字段过滤；SQLBot 集成文档列入禁止字段；单测覆盖                                 |
| SQLBot 不返回密钥                                         | 已满足   | `/api/v1/sqlbot/config` 仅返回 `enabled/base_url/embed_url/app_id/display_mode/message` |
| SQLBot 需要登录态                                         | 已满足   | 主应用全局 `enforce_default_auth`，`/api/v1/sqlbot/config` 不在公开路径中               |

## 下一阶段任务

1. 部署 SQLBot 独立服务，配置只读分析库或只读视图，禁止连接生产病历全文表。
2. 为 SQLBot 建立病案指标语义层：病案问题集中点、科室风险排行、缺陷趋势、处理闭环、编码/入组异常统计。
3. 为问数入口增加配置页或环境检查页，显示 SQLBot 服务可达性、应用 ID、数据源只读状态。
4. 将 SQLBot 查询结果限定在指标/统计维度，禁止返回病历全文、文书正文和可识别敏感字段。
5. 补齐质控助手中的批量任务入口：只允许创建受控后台任务，危险写入或导出必须二次确认。
6. 补齐编码建议的确认流：采纳、驳回、备注、审计留痕，但仍不能直接写正式首页。
7. 补齐 DRG/DIP 修正建议闭环：未入组原因、可选编码修正、模拟前后差异和风险说明。
8. 建立验收脚本，分别覆盖质控、编码、入组、问数四类任务的 UI、API、安全过滤和权限边界。
