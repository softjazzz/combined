# 泸县0609真实样本GoldenSet建设计划

更新时间：2026-06-16

## 1. 建设目标

建立一套由真实客户样本病历构成的 golden answer，用于验证泸县0609质控点在真实病历上的准确性、证据完整性和数据接入覆盖情况。

合成样本用于验证机制，不能替代真实 golden set。真实 golden set 才能支撑：

- 规则是否真实有效。
- 误报、漏报、状态反转是否可控。
- 证据链是否能被质控员复核。
- 哪些规则因数据缺口不能验收。
- 是否具备进入受控试点的条件。

## 2. 样本规模和分层

第一阶段目标：20-30 份真实客户样本病历。

按规则族分层：

| 规则族           | 建议样本数 | 样本要求                                                         |
| ---------------- | ---------- | ---------------------------------------------------------------- |
| 基础时限类       | 3-5        | 覆盖入院记录、首次病程、主治查房、高级职称查房、抢救记录。       |
| 病重病危类       | 3-5        | 至少包含病重或病危医嘱，能复核查房/病程记录间隔。                |
| 检查检验类       | 3-5        | 包含 CT/MRI、阳性检查结果、细菌培养或阳性菌结果。                |
| 会诊类           | 3-5        | 包含会诊申请、会诊意见、后续病程执行记录。                       |
| 手术麻醉类       | 5-8        | 包含手术记录、术前小结、术前讨论、安全核查、麻醉记录和访视记录。 |
| 输血类           | 2-4        | 包含输血申请、输血医嘱、输血记录、输血后评价和费用。             |
| 肿瘤/化疗/病理类 | 2-4        | 包含恶性肿瘤诊断、手术、病理、化疗或出院治疗计划。               |

如果真实样本不足，应记录为 `sample_gap`，不能用合成样本替代真实准确率统计。

## 3. 样本入选条件

必须满足：

- 来自客户样本池或经授权的脱敏真实病历。
- 已关联系统病历主索引。
- 文书可读取。
- visit_id、科室、出入院时间、文书范围可追溯。
- 不进入正式生产统计、归档、结算或绩效扣分。

优先选择：

- 非 Demo 病历。
- 文书类型较完整的病历。
- 覆盖手术、会诊、检查检验、输血等关键场景。
- 已有客户指出问题的病历。

排除：

- 仅有少量空文书的病历。
- 无法定位 visit_id 的病历。
- 未脱敏且不允许用于验证的病历。
- 数据来源不明或无法复核的样本。

## 4. Golden Answer 字段

每条 golden answer 以“规则 + 病历 + 证据”为最小单位。

```json
{
  "golden_id": "LX0609-GOLDEN-0001",
  "visit_id": "2313364",
  "sample_pool_id": "customer-pool-id",
  "qc_point_id": "LX0609-003",
  "rule_name": "手术记录：手术后24小时内是否完成",
  "rule_family": "手术麻醉类",
  "trigger_exists": true,
  "expected_status": "non_compliant",
  "expected_hit": true,
  "trigger_facts": [],
  "required_sources": [],
  "evidence_fields": [],
  "human_reason": "",
  "reviewer": "",
  "review_status": "pending",
  "reviewed_at": null
}
```

字段说明：

| 字段               | 说明                                          |
| ------------------ | --------------------------------------------- |
| `golden_id`        | 唯一编号。                                    |
| `visit_id`         | 病历 visit_id。                               |
| `sample_pool_id`   | 样本池 ID。                                   |
| `qc_point_id`      | 规则 ID。                                     |
| `rule_family`      | 规则族。                                      |
| `trigger_exists`   | 触发事件是否存在。                            |
| `expected_status`  | 人工期望状态。                                |
| `expected_hit`     | 是否应命中缺陷。                              |
| `trigger_facts`    | 触发事实，例如手术、输血、会诊、报告时间。    |
| `required_sources` | 判断依赖的数据源。                            |
| `evidence_fields`  | 人工复核证据字段。                            |
| `human_reason`     | 质控专家判定理由。                            |
| `review_status`    | `pending/accepted/rejected/needs_more_data`。 |

## 5. 期望状态口径

| 状态             | 标注标准                                       |
| ---------------- | ---------------------------------------------- |
| `non_compliant`  | 人工确认存在缺陷，证据充分。                   |
| `compliant`      | 人工确认符合规则。                             |
| `not_applicable` | 无触发事件，例如无手术却测试手术规则。         |
| `data_gap`       | 有触发可能，但缺关键文书、表或字段，无法判断。 |
| `uncertain`      | 证据矛盾或专家无法稳定判断。                   |

禁止：

- 把 `data_gap` 标为 `compliant`。
- 把无触发样本标为缺陷。
- 用合成样本统计真实准确率。
- 只有模型结果、没有人工理由。

## 6. 标注流程

1. 从客户样本池筛选候选病历。
2. 按规则族自动生成候选样本清单。
3. 信息科确认数据源是否存在。
4. 质控专家逐条标注 expected_status。
5. 第二人抽样复核高风险规则。
6. 写入 golden answer 文件。
7. 跑系统结果与 golden 对比。
8. 输出误报、漏报、状态反转和证据错误。

## 8. 评估指标

规则级：

- TP / FP / TN / FN / Unknown。
- precision。
- recall。
- data_gap_rate。
- not_applicable_rate。
- evidence_complete_rate。
- technical_error_rate。

规则族级：

- 基础时限类准确率。
- 手术麻醉类准确率。
- 检查检验类准确率。
- 输血类准确率。
- 会诊类准确率。
- 病重病危类准确率。

全局：

- 严重缺陷误报率。
- 严重缺陷漏报率。
- 状态反转数。
- 证据错误数。
- 可解释结果比例。

## 9. 通过标准

受控 POC 建议门槛：

- 20-30 份真实病历完成标注。
- 每个主要规则族至少有 2 份可复核样本。
- 高风险规则召回率目标不低于 95%。
- 可行动问题精确率目标不低于 85%。
- 严重漏报为 0。
- 证据完整率不低于 90%。
- `data_gap` 不计入合格。

试点前建议门槛：

- 确定性规则 controlled case 100% 通过。
- 语义规则精确率不低于 90%。
- 证据完整率不低于 95%。
- 技术错误率低于 1%-2%。
