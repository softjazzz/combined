# LX0609-023 会诊执行记录 口径标准与分歧处置清单

更新时间：2026-09-11
适用范围：0910 样本库、LX0609 正式质控链（CDM → Bundle → 规则执行器 → 保存/API/页面）
文件性质：**我方口径裁定**。客户目前的反馈无法覆盖以下判据，为避免质控结果长期停留在“不确定”，由我方按病历书写规范与可复核原则制定标准；客户仅需知晓，不阻塞开发。

## 一、结论摘要

1. 023 是“**有执行记录但写得是否规范**”的质量分级规则，不是“有没有记录”的是非题；这条性质决定了它无法像 020 那样退化成确定性问题。
2. 客户原文本身包含**三个并列缺陷**（照抄会诊意见／未进行归纳总结／未明确具体执行情况），现行实现把三者压进同一个状态码，判据互相打架，是当前不稳定的第一主因。
3. 规则档自身已标注缺口：「**照抄阈值和执行动作识别需定义**」。在口径未定义的前提下，任何模型判的都是它自己的理解。
4. 实测证据：同一份代码、同一批 12 例、各 3 轮，DeepSeek flash 与 qwen3.7-flash 对 023 的**系统性偏向相反**——前者偏“具体”、后者偏“笼统”，准确率几乎相同（16/22 对 17/22），只是判错的记录互相错开。**这说明分歧来自口径模糊，不是模型强弱。**
5. 处置方式：按本文第四节把 023 拆成三条子判定并冻结判据，把判断从模型下沉到确定性校验；023 不再产出“不确定”。

## 三、分歧点清单

### D1 一条规则压了三个缺陷

客户原文里“照抄会诊意见”“未进行归纳总结”“未明确具体执行情况”是三件独立的事：第一件是文本相似度，第二件是写作完整性，第三件是信息充分性。现行实现只输出一个枚举，三者信息被合并丢失，判据之间互相覆盖。

### D2 照抄没有阈值

规则档明写“照抄阈值需定义”。现实中存在连续谱：整句照搬 → 改写措辞 → 只保留关键词 → 写出针对本患者的独立描述。没有阈值就无法区分“合理复述”和“照抄”。

典型反例：C30 的病程复述了会诊意见“建议 2 周后复查尿常规，肾内科门诊随访”，人工判**照抄**；而 C19 的病程写“建议行神经阻滞治疗，配合针灸理疗”，人工判**尚未发生**（与照抄无关）。两句都是“建议…”，判据完全不同。

### D3 同一种表述算不算执行，取决于建议类型

| 病程原文                               | 建议类型   | 人工判定                   |
| -------------------------------------- | ---------- | -------------------------- |
| 建议患者对症康复锻炼，加强下肢功能锻炼 | 康复锻炼类 | 具体（写下锻炼要求即落实） |
| 遵会诊意见执行                         | 用药调整类 | 笼统（无实际给药事实）     |

差别不在语言特征，在临床口径；纯正则或纯关键词无法表达。

### D4 模型的系统性偏向相反

DeepSeek flash 倾向把同一句话判成“具体”，qwen 倾向判成“笼统”，两者各错一半。在口径明确的前提下，同一批数据上两个模型不应出现这种对称分歧。

### D5 “不确定”无法交付

023 判不准时系统只能退到 `uncertain`，在交付上等于没有结论：台账不能关闭、客户看不到判定。判成不符合会引发医院申诉，判成符合会漏检，因此技术上的退回是正确行为——问题在上游口径。

### D6 建议粒度未冻结

系统把长句会诊意见拆成原子建议后，各建议共享同一句原文。C27 的“给予红光照射以促进伤口愈合、CPM 治疗、关节松动训练、体适能训练”被拆成 4 条，人工冻结为 4 条但计数口径未冻结；C19 人工冻结 6 个细项、系统抽取 1 条。粒度为 1 时，“具体/笼统”的判断对象都不明确。

## 四、我方制定的判定标准（冻结项）

以下为标准正文，全部按可复核、可复现、可用 Python 判定的原则制定。

### S1 023 拆成三条独立子判定

| 子判定                   | 判据来源 | 命中结果   |
| ------------------------ | -------- | ---------- |
| 023-A 照抄会诊意见       | S2       | 023 不符合 |
| 023-B 仅笼统遵嘱、未归纳 | S3       | 023 不符合 |
| 023-C 未写明具体执行情况 | S4 + S5  | 023 不符合 |

三条各自输出命中状态与证据位置；023 最终为“任一命中即不符合”，全部未命中且证据充分时为符合。**理由**：与客户原文一一对应，判据互不覆盖，命中原因可分别展示。

### S2 照抄判定阈值（可算，不交模型）

满足以下两条即判 023-A 照抄：

1. 病程中与会诊建议原文的**连续重合片段 ≥ 12 个汉字**；
2. 该重合片段长度 ÷ 建议原文长度 **≥ 50%**。

不判照抄的反例：仅重合通用词（复查、治疗、会诊、建议）；重合片段 < 12 字；病程在重合片段之外另有针对本患者的独立描述（症状、体征、处置或时间）。

**理由**：可用现有引文落地校验加文本比对精确计算，阈值可复现、可审计；12 字（约两个临床短句）足以排除通用词巧合，50% 排除局部引用。

### S3 笼统遵嘱清单（命中即判 023-B）

命中清单且**同句内不含任何具体措施、药物、检查、时间或科室**时判笼统：

> 遵会诊意见执行／按会诊意见处理／已按建议执行／遵嘱执行／嘱执行／已遵医嘱／继续原方案

不判笼统的反例：同句出现药名、检查名、时限、科室或具体动作（例如“遵会诊意见今日加用头孢呋辛”，属具体）。

### S4 按建议类型的执行判据表（核心）

| 建议类型                   | 视为已落实的最低证明                                             |
| -------------------------- | ---------------------------------------------------------------- |
| 用药／调整用药             | 有实际给药、加用、停用或换药事实（医嘱执行记录，或病程明确写出） |
| 检查／检验                 | 写明已完成并有结果时间，或有明确预约时间                         |
| 康复／理疗／护理／功能锻炼 | 病程写明已开展，或已向患者指导并记录                             |
| 转科／转诊／转运           | 有实际转出或接收事实                                             |
| 随访／复查                 | 写明随访时间，或已预约                                           |
| 风险沟通／告知             | 写明沟通对象与内容                                               |
| 会诊／请会诊               | 有新的会诊申请或会诊记录                                         |

**理由**：这是把“同一种表述算不算执行”从语言问题转成查表问题；表一旦冻结，模型只负责抽取“建议类型 + 处置事实 + 原文引文”，判断由 Python 完成。

### S5 具体性分级

| 级别     | 定义                                                   |
| -------- | ------------------------------------------------------ |
| specific | 满足 S4 且能在病程原文中逐字定位到该措施               |
| generic  | 只有类别或笼统表述（如“继续康复治疗”），未写明具体措施 |
| copied   | 满足 S2                                                |
| no_trace | 会诊后病程在该建议对应来源内没有任何相关记载           |
| unknown  | 仅当受控来源不可用时使用（由 data_gap 单独承接）       |

### S6 判罚范围与“不确定”的归口（023 不再产出 uncertain）

1. **023 只评价已找到的执行痕迹**：已找到的痕迹中存在笼统或照抄 → 不符合；已找到的痕迹全部具体 → 符合；
2. 没有任何已找到的痕迹（该建议在会诊后病程中无记载）→ `not_applicable`，**不判罚**；
3. 必要文书缺失或来源不可用 → `data_gap`；
4. 模型未给出可落地引文或引文落地校验失败 → 该建议不进入“已找到的痕迹”，按第 2 条处理，同时标记“需人工复核”。

**理由（2026-09-11 修订）**：初版曾规定“判据不足即按未落实判不符合”。实测否定了该归口——按初版实现会让 C08、C11、C21、C23、C25、C26 六条人工预期为“符合”的记录被判不符合（12 例对照中 023 仅命中 3/11）。改为“只评价已找到的痕迹”后同一批数据命中升到 5/11，且无记录从正确变为错误。这与 020／023 的冻结合同一致：020 管有没有痕迹，023 只管已找到的痕迹是否规范；无法判定的条目返回 `needs_manual_review`，不计入不符合。

### S7 建议粒度冻结

同一句会诊意见拆成多条原子建议时，每条建议的“覆盖度”与“具体性”**只判本条动作**，不得对整句判断；一句话被拆成多条时，系统展示的建议条数以抽取结果为准，并在台账中记录“人工冻结条数与系统条数不一致”的差异项，供客户核对，不作为判定依据。

## 六、影响评估

- 已关闭的 020 相关记录不受影响（020 侧判定链不改动）。
- 023 未关闭记录按 S1—S6 重新判定后，预期可给出确定结论；判定方向以 S2/S3/S4 的确定性判据为准，不再受模型偏向影响。
- C30/023 需要按 S4 复核一次：现系统认为存在具体执行痕迹，人工判为照抄意见；该条差异按 S2 直接计算文本重合即可定论，不需要模型介入。
- 建议粒度差异（S7）只记录不判罚，避免把粒度问题混入状态判定。

## 七、验收方式

1. 用已冻结的 12 例（C02、C08、C11、C17、C18、C21、C23、C25、C26、C27、C29、C30）跑 3 轮，要求每例 3 轮状态与原因码完全一致；
2. 逐条核对 023 的命中原因（023-A/B/C）与证据定位，不只看最终状态；
3. 核对客户展示事实中的建议条数、具体／笼统／缺失计数与关系状态；
4. 确认 020 侧与已关闭记录零回退；
5. 若第 1 项仍有抖动，按“抖动发生在抽取还是判定”分别归因，抽取侧问题另行处理，不得用重复调用掩盖。
