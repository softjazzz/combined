# 客户机交付包编译打包指南

本文用于在开发机上生成客户机可部署的 MedQC Web 交付包。默认输出到 `D:\LLM\LX888\release`，并排除 ICD 向量索引、embedding、运行日志、本地密钥和临时数据。

## 适用目录

在开发机进入项目目录：

```powershell
Set-Location -LiteralPath "D:\LLM\LX888\apps\medqc-web"
```

## 构建方式

打包脚本会以本次构建身份重新编译前端，并核对前后端构建号。可以先运行 `npm run build` 检查本机依赖，但正式打包仍会重新构建；构建失败时应修复原因后再打包。

## 打包到 release 目录

在开发机执行打包脚本：

```powershell
powershell -NoProfile -ExecutionPolicy Bypass `
  -File scripts\package-customer-release.ps1 `
  -OutputRoot "D:\LLM\LX888\release"
```

脚本会生成：

```text
D:\LLM\LX888\release\medqc-web-customer-YYYYMMDD-HHMMSS
D:\LLM\LX888\release\medqc-web-customer-YYYYMMDD-HHMMSS.zip
```

`-SkipBuild` 已被脚本拒绝，不能用旧 `dist` 冒充本次构建。

正式打包默认使用仓库外的发行方私钥：

```text
D:\LLM\LX888\secrets\medqc-offline-activation-private.pem
```

脚本会在客户包中生成一份从打包时间起有效三个月的预激活状态。客户首次使用标准后端启动脚本时，该状态会安装到本机授权目录；如果客户机已经存在激活状态，则绝不覆盖。私钥和签发脚本不会进入客户包。

需要指定其他私钥或客户名称时使用：

```powershell
powershell -NoProfile -ExecutionPolicy Bypass `
  -File scripts\package-customer-release.ps1 `
  -OutputRoot "D:\LLM\LX888\release" `
  -ActivationPrivateKeyPath "D:\secure\issuer-private.pem" `
  -BundledActivationCustomer "某某医院" `
  -BundledActivationMonths 3
```

只有明确需要生成“未预激活包”时才传入 `-SkipBundledActivation`。该参数不会关闭客户包的激活门禁，客户启动后仍需在系统设置中手工输入有效激活码。

交付包还会包含只读数据库预检工具：

```text
tools/customer-db-preflight.ps1
```

## 客户机数据库部署闭环

部署新包必须按以下顺序执行。后端 `/docs` 可以打开，只代表 Web 进程存活，不代表 PostgreSQL 可连接或业务表结构正确。

### 1. 启动 PostgreSQL

先确认 PostgreSQL 服务已启动且配置端口可连接。默认端口示例：

```powershell
Test-NetConnection 127.0.0.1 -Port 5432
```

如果客户环境使用其他地址或端口，以客户机 `backend\.env` 中的 `DATABASE_URL` 为准，不要为了通过检查临时改连接配置。

### 2. 数据库备份

在覆盖代码或执行迁移前，由客户数据库管理员完成数据库备份，并记录备份文件、数据库名称和备份时间。没有可恢复备份时，不得执行数据库结构升级。

### 3. 运行只读预检

在解压后的交付包根目录执行：

```powershell
powershell -NoProfile -ExecutionPolicy Bypass `
  -File .\tools\customer-db-preflight.ps1
```

预检会脱敏显示数据库地址，并检查：

- PostgreSQL 是否可以连接；
- 当前数据库、用户、schema 和 `search_path`；
- 工作台、通知和客户样本池依赖的核心表及关键字段；
- `alembic current` 与 `alembic heads`。

预检事务固定为只读模式，不会建表、补列或执行迁移。出现 `MISSING_TABLE`、`MISSING_COLUMNS`、`database_unavailable` 或版本不一致时，应停止部署并保留输出。

### 4. 人工确认并执行迁移

仅在 PostgreSQL 正常、备份完成且已确认 `current` 落后于 `heads` 后，由获授权的部署人员进入后端目录执行：

```powershell
Set-Location -LiteralPath .\backend
python -m alembic -c alembic.ini current
python -m alembic -c alembic.ini heads
python -m alembic -c alembic.ini upgrade head
```

`alembic upgrade head` 会写数据库，预检工具不会自动执行这条命令。

### 5. 重启并执行核心接口烟测

迁移成功后重启后端，使用已登录浏览器或获授权的 API 客户端检查以下接口。目标是业务响应正常且不返回 HTTP 500：

```text
GET  /api/medical-records/workstation
GET  /api/v1/notifications?page_size=30
GET  /api/v1/qc/sample-pools?page=1&page_size=50
POST /api/v1/qc/sample-pools/import-upload
```

最后一项需使用合法客户模板实际上传一次。若 `/docs` 正常但上述接口返回 500，优先检查数据库服务、迁移版本、schema/search_path 和后端首次异常日志，不应先归因于模板格式。

## 排除内容

打包脚本会排除以下内容：

- `backend\.env`
- `backend\data\vector`
- `backend\data\manual_qc_runs`
- `backend\data\sample_pool_uploads`
- 本地 SQLite/demo DB 文件
- 后端测试目录、缓存、临时脚本、运行日志
- ICD 向量索引和向量构建脚本
- `.pyc`、`.pkl`、`.log`、`.faiss`、`.index` 等运行或向量相关文件
- 全部前端字体文件（客户机使用系统字体回退）

## 检查最新压缩包

打包后检查最新 zip：

```powershell
$zip = Get-ChildItem "D:\LLM\LX888\release" -Filter "medqc-web-customer-*.zip" |
  Sort-Object LastWriteTime -Descending |
  Select-Object -First 1

$zip.FullName
```

检查压缩包中是否误带向量或 embedding 文件：

```powershell
Add-Type -AssemblyName System.IO.Compression.FileSystem
$archive = [System.IO.Compression.ZipFile]::OpenRead($zip.FullName)

$archive.Entries |
  Where-Object {
    $_.FullName -match 'vector|embedding|faiss|\.npy$|\.index$|\.bin$|backend/data/vector'
  } |
  Select-Object FullName

$archive.Dispose()
```

如果没有输出，说明没有发现上述向量相关文件。
