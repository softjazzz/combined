## 2. 首个真实失败与本次最小修复

### 2.1 失败证据

修复前，运行页与终末页均显示同一批 454 份病历；同一脱敏病历同时出现在两个范围。源码已生成 `hospital_status`，但调用 `ApiService.getRaw` 时又把参数包装为 `{ params }`。`getRaw` 的第二参数本身就是查询参数，所以真实请求没有把顶层 `hospital_status` 传给后端。

- `usePatientRecords.fetchData` 改为 `ApiService.getRaw(url, params)`。
- 对应公开 composable 回归改为断言真实 `getRaw` 调用合同。
