# 质控首页与病历池准商用收尾审计

日期：2026-08-08
范围：全院统一范围的质控首页、病历池、最新 LX0609 Canonical 结果投影及旧 Dashboard 首页入口。
边界：本审计不记录患者姓名、住院号、病历正文、原始三坐标或模型输入输出。

## 已完成的交付合同

| 能力           | 交付事实                                                                                                                           |
| -------------- | ---------------------------------------------------------------------------------------------------------------------------------- |
| 演示隔离       | 生产环境无论配置如何均不返回演示病历；开发环境演示能力保留。                                                                       |
| 病历身份       | 内部始终使用 `institute_id + patient_id + visit_id`；页面键为可逆 JSON 三元数组，重复 `visit_id` 不串值。                          |
| 访问范围       | 当前按已登录的全院质控科统一范围查询；未实施机构、科室或角色分级授权。                                                             |
| 病历池质控摘要 | 只读取完成根任务的当前规则版本 Canonical Envelope；跨创建人选择唯一最新结果，冲突、缺失或无效 Envelope 均失败关闭。                |
| 同步与运行状态 | 没有权威来源时均明确为 `unknown`，不从文书数量、Bundle、`data_gap` 或遗留队列推断。                                                |
| 在院/出院      | 由权威出院时间在服务端筛选；列表、总数、科室统计与质控摘要使用同一筛选范围。                                                       |
| 首页           | 仅消费同一三坐标范围的 `clinical_qc`；高风险只来自 `non_compliant`，技术异常只在数据运行状态；没有真实时间序列时不显示趋势或环比。 |
| 旧入口         | `/` 与 `/dashboard` 单向跳转 `/workstation-v4`，保留 query/hash；不再加载旧静态 Dashboard 首页。                                   |

## 已验证的真实数据基线

只读验收报告见 [record-pool-real-data-acceptance.md](/D:/LLM/LX888/apps/medqc-web/docs/audits/2026-08-08-medqc-record-pool-real-data-acceptance.md)。

- 当前开发进程中有 454 条真实 CDM 三坐标；病历池接口返回 456 条，额外 2 条为开发演示病历。
- 真实三坐标投影结果为：5 条 `ready`、220 条 `not_run`、229 条 `canonical_envelope_missing`。
- 分页间 `qc_summary` 一致；`source_state` 与运行态均如实为 `unknown`。
- 当前全量 Canonical 摘要读取约 9.2 秒，接口第 1/2 页约 9.0–9.8 秒；这只是开发环境基线，不满足“P95 小于 2 秒”的准商用性能目标。

## 上线结论：暂不签发准商用通过

以下事项必须在发布前闭环或得到业务方明确豁免：

1. 用 `ENV=production` 重启后端，并通过真实认证 HTTP 入口复验：病历池不得混入演示病历，数据库 count、接口 total 与首页 KPI 必须对账。
2. 单独追查并补齐或重新生成 229 条历史完成任务缺失的 Canonical Envelope；病历池当前正确显示为“结果校验异常”，不得降级成“未质控”。
3. 基于生产同条件样本测量病历池与首页 P50/P95；当前基线约 9 秒，未达到 2 秒目标。先定位 SQL/批量摘要读取，再决定是否需要优化；不得以缓存或前端当前页统计掩盖。

以下是当前已知且按合同展示的能力边界，不应被误报为医疗质控缺陷：

- `source_state=unknown`：暂无权威的逐病历同步状态；
- `running_task_state=unknown`：遗留任务持久化只有 `visit_id`，不能安全投影至三坐标病历；
- 全院统一范围：这是当前业务授权，不等同于未来多机构/科室隔离能力。

## 回归与审核范围

本轮实现保持既有 CDM、任务、Canonical Envelope 与工作台接口主链，未新建 Bundle、结果表、统计平台、规则执行器或 LLM 调用。上线前的独立审核应以 `db9ada121` 之后的提交为范围，并同时复核本报告列出的三项阻断条件。
