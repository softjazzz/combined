# DG-5：LX0609-018 验证数据合同闭环

## 结论

本次修复只收敛 v3 验证数据生成合同，不修改 LX0609-018 执行器、Prompt、Canonical Envelope、API 或前端。

审核指出，上一版生成器会因源入院记录时间落在合成窗口外而删除已有记录，再按诊断关键词合成主诉。这会造成“用生成数据证明生成数据”的自证循环，上一版 018 的 10 条不合规不能作为金标准结论。

当前生成器已改为：

- 已有非空 `admission_record.chief_complaint` 时保留源记录的主诉、正文和诊断依据；
- 只将记录时间字段重基准到 v3 当前住院窗口；
- 仅在源记录确实缺失或主诉为空时，才按已有第一诊断补写受控记录；
- 不新增第二套 Bundle、Snapshot 或资料来源。

因此，当前任务中的 018 状态只能作为“修复后执行分布”记录，不能把 10 条不合规自动宣称为已验证的临床金标准；除已有冻结金标准病例外，仍需人工复核主诉与第一诊断。
