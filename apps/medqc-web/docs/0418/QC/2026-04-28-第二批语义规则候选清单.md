# 2026-04-28 第二批语义规则候选清单

## 1. 文档定位

本文档只服务于**客户样本验证页**的第二批语义规则候选梳理，不修改主线后端执行逻辑，不替代主线实施计划。

输入依据：

- `sheet2_rule_mapping_seed.csv`
- `sheet2_rule_mapping_seed.summary.json`
- `2026-04-28-客户样本验证质控点实施计划.md`
- `2026-04-28-质控点测试遗留问题清单.md`

输出目标：

- 给出第二批语义规则的高优先级问题族
- 明确每个问题族的主规则、是否需要新规则、实现方式、风险与前置依赖
- 为主线后续“收窄规则集 -> 固定回归矩阵 -> 扩第二批语义规则”提供侧线输入

## 2. 筛选原则

进入本清单的问题族，需同时满足以下条件中的大部分：

1. 属于 `Sheet2` 高频或高风险问题。
2. 不属于当前 `sample_programmatic_gate_v1` 已稳定承接的程序硬门槛。
3. 第一批语义规则未完全覆盖，或现有规则命中不稳定。
4. 已有规则库存在可复用主规则，或新增规则的边界已经足够清晰。
5. 对客户样本验证页的验收价值高，能直接提升 `exact_hit / same_family_hit`。

不优先纳入本批的类型：

- 纯程序时间一致性问题
- 纯缺文书存在性问题
- 仍停留在 `manual_review` 且问题边界不清的零散文本

## 5. 建议优先级

建议第二批语义规则按下面顺序推进：

1. **会诊记录内容质量 / 复制粘贴 / 结论不足**
   - 原因：这是当前清单里边界最清晰、遗留问题文档已明确点名、且现有 `SC-069` 明确处于 `todo_semantic` 的问题族。
2. **上级查房复制粘贴 / 身份异常 / 疑似代写**
   - 原因：高频、用户感知强，且第一批规则只能打到“内容空洞”，还原度不够。
3. **会诊意见已写遵执但实际未落实**
   - 原因：真实样本已有命中，但 `SC-070 / LX-016` 边界不一致，先收口能明显降低结果噪音。
4. **危急值记录不完整 / 处理不充分**
   - 原因：已有 `SC-039`，实现成本相对低，但依赖 bundle 证据组织。
5. **诊疗医嘱与病程记录不一致**
   - 原因：覆盖面大，但天然依赖跨文书一致性，比单文书语义规则更容易受证据拼装影响。
6. **上级医师查房缺失 / 未及时书写**
   - 原因：临床价值高，但属于混合型问题，更适合在时间轴层稳定后补。
7. **四级手术未 MDT / MDT 不能被普通会诊替代**
   - 原因：价值高但前置依赖重，需要先把 MDT 文书识别口径说清。
8. **围术期手术记录缺项 / 逻辑矛盾 / 签名异常**
   - 原因：规则库已有，但强依赖围术期文书全量证据，适合放到第二批后段。

## 6. 建议实施顺序

为避免第二批再次做成“大而散”的语义规则堆叠，建议按下面顺序实施：

### 6.1 先做“已有规则 + 明确边界”的问题族

- `SC-069`
- `SC-070`
- `SC-039`
- `SC-146`

目标：

- 先把已有规则真正收口到样本验证链路
- 先做出一批稳定 `exact_hit`

### 6.2 再做“必须补子口径”的问题族

- 查房复制粘贴 / 身份异常
- 会诊记录复制粘贴 / 结论不足

目标：

- 明确哪些问题适合继续复用原规则
- 哪些问题必须拆新增子规则

### 6.3 最后做“强依赖证据层”的问题族

- MDT / 四级手术
- 围术期跨文书一致性
- 输血链

目标：

- 避免在证据层尚未稳定前，把问题都归因到 prompt 不准
