## 4. 逐条分析

## 4.1 被入口错误挡掉的 8 条

以下 8 条规则本身没有问题，问题在执行入口：

- SC-023
- SC-024
- SC-025
- SC-026
- SC-027
- SC-032
- SC-033
- SC-036

它们的共同点：

- 执行域：`course`
- 适用文书：`首次病程记录` / `日常病程记录`

但当前 `final bundle -> SichuanQCService.evaluate_running_final_bundle_input(...)` 这条链路里，适配器固定写死：

- `scene=final -> document_type=出院记录`

所以这些规则在进入编排器之前，就被文书类型守卫判为：

- `规则适用文书类型 ['首次病程记录'/'日常病程记录']，当前文书为 '出院记录'`

因此本次 P1a 暴露的核心问题是：

> `sc_content_v1` 虽然是终末病历首批内涵规则集，但其中包含 8 条病程类规则；而当前终末批量入口还是“单 document_type=出院记录”的执行模型，二者不匹配。

这说明下一步不是先调 prompt，而是先修正：

- 终末 bundle 评估入口必须支持 **按文书类型拆分执行**
- 或者先把 `sc_content_v1` 再拆成：
  - `sc_content_final_terminal_v1`
  - `sc_content_final_course_v1`

否则这 8 条规则上线后会长期“看起来已执行，实际上未评估”。

## 4.2 有效命中的 4 条

### SC-121 诊疗经过不全面、不详细

当前结果：`non_compliant`

判断：

- 方向上合理，系统抓到了“诊疗经过不够细、关键检查结果与药物描述不够规范”的问题
- 但当前 findings 扩散到了：
  - 药理描述是否准确
  - 单位书写是否规范
  - 其他格式问题

这说明该规则在精审阶段的证据边界仍偏宽，容易把“医学书写质量”与“记录是否完整”混在一起。

建议：

- 收紧 SC-121 的证据范围
- 只围绕：
  - 主要药物名称是否明确
  - 与主要诊断直接相关的重要辅助检查结果是否明确
- 不把药理学解释、格式小错误混进主结论

结论：**保留上线候选，但需要收敛 prompt / evidence 策略**

### SC-122 无出院医嘱或出院医嘱不全

当前结果：`non_compliant`

判断：

- 命中合理
- 证据明确
- 建议可执行

主要问题点：

- 出院医嘱有随访和一般注意事项
- 但没有明确的出院带药指导

结论：**可作为首批上线规则保留**

### SC-123 出院带药不详细

当前结果：`non_compliant`

判断：

- 命中合理
- 证据干净
- 建议明确
- 该条是当前 12 条里最稳定的一条

结论：**可作为首批上线规则保留**

### SC-125 出院诊断或死亡诊断错填、漏填、顺序错误

当前结果：`non_compliant`

判断：

- 方向合理，模型识别到了：
  - 出院诊断栏不清晰
  - 主次诊断顺序可能不规范
  - 文书内部存在病史逻辑矛盾
- 但当前一条规则里混入了三类问题：
  - 出院诊断栏缺失/不完整
  - 诊断顺序问题
  - 其他病史逻辑矛盾

这会导致这条规则过重，后续不利于业务解释和整改。

建议：

- 业务上优先把它当成“需要人工复核”的规则
- 后续如果规则治理允许，最好拆开：
  - “出院诊断缺失/不完整”
  - “出院诊断顺序不规范”

结论：**可保留，但建议作为待复核优先规则，而不是硬判定规则**
