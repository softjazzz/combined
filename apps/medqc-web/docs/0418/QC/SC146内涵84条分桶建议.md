> 基线来源：`apps/medqc-web/sichuan_rules_146.json` + `apps/medqc-web/backend/app/data/sc_rule_family_map.json`

## 1. 结论摘要

- 当前仓库中，**SC146 内涵规则共 84 条**。
- 判定口径为以下 3 个 `rule_family`：
  - `content_completeness`
  - `consistency_cross_doc`
  - `procedure_order_linkage`
- 当前仓库里 **尚未实现** `sc_content_full_v1` 或 84 条固定分桶版本。
- 按“`target_document_type` + `rule_family` + 少量人工拆分”建议，**推荐总桶数为 20**。
- 本建议稿中：
  - **每个桶都 <= 10 条**
  - **无重复、无遗漏**
  - **无 >10 条大桶**

## 4. 建议优先人工拆分点

以下桶虽然已经满足 `<=10`，但实现时建议优先保留人工拆分，不要再合并：

### 4.1 首次病程记录

- `first_course_features`
  - `SC-023`
  - `SC-024`
- `first_course_reasoning`
  - `SC-025`
  - `SC-026`
  - `SC-027`

原因：

- 这组规则已在真实病历验证中证明，`SC-023~027` 不适合 5 条混跑。
- `2 + 3` 的拆法明显优于 `5 条一包`。

### 4.2 手术/麻醉相关规则

- `operation_preop`
- `operation_anesthesia_intraop`
- `operation_postop_followup`

原因：

- 虽然都属于 `operation_record + procedure_order_linkage`，但时间阶段不同：
  - 术前
  - 麻醉/术中
  - 术后
- 如果直接合并成一个大桶，会降低 prompt 聚焦度。

### 4.3 日常病程内容完整性

- `daily_course_core`
- `daily_course_quality`
- `rounds_rescue_discussion`
- `handover_communication`

原因：

- 这 21 条原本都落在 `progress_note + content_completeness`
- 但实际涉及：
  - 日常病程分析
  - 上级查房
  - 抢救记录
  - 疑难/死亡讨论
  - 交接班
  - 告知记录
- 若混成一个桶，语义跨度过大。

### 4.4 检验/检查报告

- `exam_report_quality`

原因：

- 目前为了便于落地，把 `SC-138/139/140` 合成了一个小桶。
- 若后续发现这 3 条稳定性不足，优先拆成：
  - `exam_report_consistency`: `SC-138`, `SC-139`
  - `pathology_report_linkage`: `SC-140`
