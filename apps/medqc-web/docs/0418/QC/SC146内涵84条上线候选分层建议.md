# SC146 内涵 84 条上线候选分层建议

> 日期：2026-04-24  
> synthetic 基线：`apps/medqc-web/backend/data/manual_qc_runs/sc146_intrinsic84_qwen3.6-35b-a3b_20260424_frozen_v8.json`  
> 前提：84 条规则已完成规则级 synthetic 验证，当前文档解决的是“怎么上线”，不是“是否已收平”。

## 1. 结论

- `SC146` 内涵规则共 `84` 条，synthetic 基线已冻结。
- 这 `84` 条不建议一刀切同策略上线。
- 更合理的落地方式是按风险分三层：
  1. `A` 级：可直接上线
  2. `B` 级：建议灰度上线
  3. `C` 级：需真实病历重点观察后再放量

当前建议分布：

- `A` 级：`37` 条
- `B` 级：`38` 条
- `C` 级：`9` 条

## 2. 分层原则

### 2.1 A 级：可直接上线

满足以下特征：

- 主要依赖单文书内部完整性
- 缺陷边界清晰，synthetic 中 `pass/defect` 对立明显
- 对客户书写风格、路径配置、医嘱系统耦合较低

上线策略：

- 可直接进入默认启用名单
- 真实病历联调时重点看误报率，不必先做人审拦截

### 2.2 B 级：建议灰度上线

满足以下特征之一：

- 依赖跨文书一致性
- 依赖时序闭环，但仍可通过文书链路稳定判断
- 对医院书写风格有一定敏感性，但 synthetic 已能稳定识别

上线策略：

- 建议先小流量或限定科室灰度
- 前 1 到 2 周保留规则级命中复核
- 先收集误报样例，再决定是否转入默认启用

### 2.3 C 级：需真实病历重点观察

满足以下特征：

- 强依赖“病程记录 + 医嘱 + 报告 + 操作/输血/会诊执行”的闭环证据
- 对医院实际业务流程、医嘱颗粒度、文书口径差异高度敏感
- synthetic 能证明能力上限，但无法替代现场异构流程验证

上线策略：

- 不建议首批直接全量放开
- 先在客户真实病历上跑观察集
- 优先核查误报、漏报与“证据落点”是否符合客户习惯

  - 医嘱系统与病程系统分离

  - 同一业务动作可能落在不同文书或结构化系统里
- synthetic 可以证明规则具备识别能力，但不能直接证明客户现场证据分布稳定。

2. 逐条核对规则证据落点
3. 明确“病程未写”与“写在别处”的界线
4. 再决定是否进入默认启用

## 5. 与 synthetic 基线的关系

需要明确：

- 这份文档不是否定 synthetic 基线
- synthetic 已证明：`84` 条规则在当前模板资产下可以稳定回归
- 本文档只是把“能力已验证”进一步转换为“上线顺序建议”

也就是说：

- `84 / 84` 已收平，回答的是“能不能做”
- 分层上线，回答的是“先放哪些、后放哪些”

## 6. 推荐下一步

1. 在 `workstation-v4` 或后端规则配置里增加 `上线层级` 元数据
