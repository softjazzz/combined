## 3. 遗留问题清单

### 3.1 `sc` 样本池真实批次入口仍会错误回退到 `final`

现象：

- 对已出院病历发起 `sc` 样本批次时，`collect_records(scope="running")` 取不到记录。
- 链路随后回退到 `scope="all"` / `final`。
- `final` 记录经常 `medical_text` 为空，导致语义规则实际拿到的是错误上下文。

已确认案例：

- 真实批次 `job_id = 58bf98e6-e57d-45b2-9714-5dd3658f9f3e`
- 代表样本：
  - `2104525`
  - `2188335`
  - `2207717`
  - `2286345`

影响：

- 样本池官方入口还不能稳定复现“运行病历语义质控”。
- 当前很多语义命中只能通过 `running bundle` 直评验证，不能直接作为正式样本池批次验收出口。

建议动作：

- 修 `CustomQCWorkspaceService.collect_records()` 对已出院病历的 `running` 取数策略。
- 若 `matched_visit_id` 已存在且 `running_record_bundle` 可加载，应优先走 bundle，不应因 frontpage 出院态直接排除。

### 3.2 异常检查结果结构化抽取仍不兼容客户瘦表

现象：

- 当前 `exam_attention_report / lab_attention_report` 依赖较完整的结构化检查检验明细。
- 客户本地 `cdm.labtest_item_report` 字段非常瘦，缺少标准异常判定字段。
- 导致很多样本：
  - 没有 `lab_attention_report`
  - 没有 `exam_attention_report`
  - `timeline_facts` 里没有异常检查项

已确认案例：

- `2311318 / 范永勤`
  - `running bundle` 中：
    - `lab_attention_report = 0`
    - `exam_attention_report = 0`
    - 检验异常 `timeline_facts = 0`

影响：

- `SC-036` 很多时候只能退化为读病程正文，而不是“先抓异常项，再检查是否分析”。
- 命中的异常点可能与人工标注问题不完全一致。

建议动作：

- 为客户机瘦表增加兼容抽取：
  - 从 `labtest_master`
  - 或 `record_content`
  - 或 bundle 已装配文书正文
    解析出候选异常项。
- 形成“结构化异常摘要兜底层”，而不是只依赖标准明细列。

### 3.3 `Sheet2` 人工问题文本与系统实际命中证据仍存在偏差

现象：

- 部分样本能命中同一家族规则，但命中的具体证据点并不是人工问题文本原本指出的那一个。

已确认案例：

- `2311318 / 范永勤`
  - 人工问题：`4.7检验结果肾功异常，病程记录未分析，未请相应科室会诊`
  - 当前系统稳定命中的主证据：
    - `ESR`
    - `PCT`
    - `CRP`
  - 并不是 `UA 381μmol/L` 这条“肾功异常”本身

影响：

- 当前可证明“规则家族命中”，但还不能证明“完全复现人工问题原句”。
- 后续如果做召回率核算，需要区分：
  - `same_family_hit`
  - `same_evidence_hit`

建议动作：

- 在回归清单里增加命中类型标记：
  - `exact_hit`
  - `same_family_hit`
  - `mismatch`
- 不要把“同家族命中”直接等价成“完全还原人工问题”。

### 3.4 会诊闭环规则 `SC-070` 与 `LX-016` 判定口径不完全一致

现象：

- 第一批语义映射里，会诊执行闭环目前同时挂到：
  - `SC-070`
  - `LX-016`
- 真实样本上，两条规则可能给出不同结论。

已确认案例：

- `2188335 / 黄显秀`
  - 问题：`遵会诊意见，但实际并未按照会诊意见执行`
  - 当前结果：
    - `SC-070 = non_compliant`
    - `LX-016 = compliant`

影响：

- 会诊执行闭环家族当前存在规则重叠但结论不一致的问题。
- 如果直接拿两条规则同时出结果，联审侧会出现解释冲突。

建议动作：

- 明确 `SC-070` 与 `LX-016` 的边界：
  - 一条管“会诊记录完整性”
  - 一条管“会诊意见执行闭环”
- 或在样本验证链路里暂时只保留一条作为主判定规则。

### 3.5 上级查房“复制粘贴/代写异常”还没有稳定命中

现象：

- 当前第一批上级查房语义规则能打出“无内容 / 分析不足 / 审签异常”。
- 但“复制粘贴严重”“疑似代写”“与前一日相似度极高”这类问题还没有稳定复现。

已确认案例：

- `2207717 / 邹才林`
  - 人工问题：`2月4日副主任医师查房记录与2月3日主治医师查房记录复制粘贴严重（相识度100%）`
  - 当前结果：
    - `SC-049 = compliant`
    - `SC-050 = compliant`
    - `SC-052 = non_compliant`
  - 说明现有规则没有真正稳定抓到“复制粘贴严重”本身。

影响：

- 上级查房问题目前更偏“内容不足型命中”，不是“文本重复型命中”。
- 这会影响对 `Sheet2` 此类问题的还原度。

建议动作：

- 增加专门的“查房内容重复度/拷贝痕迹”规则，优先考虑：
  - 相邻查房记录正文相似度
  - 仅替换日期/称谓/个别数字的模式
- 不建议继续完全依赖现有语义 prompt 泛判。

### 3.7 正式联审展示仍以问题结果为主，合规结果可见性不足

现象：

- 当前回归已经能证明某些样本是“已评估且合规”。
- 但联审 / 样本验证展示链路仍主要面向问题卡片。

已确认案例：

- `2341278`
  - `SC-048 = compliant`
  - `SC-049 = compliant`
  - 之前之所以“不在问题列表”，并不是没识别，而是因为结果合规

影响：

- 用户容易把“页面没显示”误解成“系统没识别”。
- 对规则验收不利，尤其是合规样本回归。

建议动作：

- 后续增加“已评估且合规”的轻量可见性。
- 至少在回归工具或结果页提供：
  - 已命中规则数
  - 合规规则数
  - 不合规规则数
  - `uncertain` 数

## 4. 建议优先级

建议按下面顺序推进：

1. 修 `sc` 样本池真实批次入口，保证已出院病历也能按 `running bundle` 跑语义规则。
2. 做客户瘦表兼容的异常检查抽取，提升 `SC-036` 及相关规则的证据一致性。
3. 收口会诊闭环家族规则，解决 `SC-070 / LX-016` 结论不一致。
4. 新增“查房复制粘贴/高度重复”专项规则。
5. 继续从 `Sheet2` `manual_review` 池中拆第二批可执行规则。
