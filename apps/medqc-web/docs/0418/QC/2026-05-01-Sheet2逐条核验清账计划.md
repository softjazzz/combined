- 前端新展示契约

## 3. 逐条核验口径

每条人工问题最终只允许落到以下 4 类结论之一：

### 3.1 命中

- 对应病历已跑真实验证
- 主规则或明确映射规则命中
- 证据与人工问题一致或实质等价

### 3.2 同家族命中

- 病历中确实存在同类问题
- 但系统命中的规则或证据点与人工原文不完全同一句
- 可作为“规则族已覆盖”的阶段性结果

### 3.3 未命中

- 对应病历文本齐全
- 规则已执行
- 但未打出问题
- 需要继续补规则、补证据或修提示词

### 3.4 跳过

只有满足以下条件时才允许：

- 本地 PG 中缺目标原始病历文书
- 且 `release/0426` 或 `release/0426_full_auto` 快照中也缺相同原始文书
- 无法构造该问题所需的最基本证据链

`跳过` 必须记录：

- `skip_reason`
- 缺失的原始文书类型
- 检查过的表/快照路径

## 5. 推进顺序

### 5.1 第一阶段：把已映射问题逐条核完

先处理以下三类：

- `implemented`
- `partial`
- `ready_in_rule_library`

也就是优先把当前已经有规则基础的问题逐条清账，不再继续扩新规则。

### 5.2 第二阶段：处理 `manual_review`

对当前仍是 `manual_review` 的 `113` 条问题：

- 先继续归一
- 再补主规则
- 再逐条核验

### 5.3 第三阶段：补 blocked / skip 清单

对无法核验的问题，不拖主线，直接进入：

- `skip`
- `blocked`

但必须有证据说明为什么缺文书、缺哪张文书、在哪些数据源里确认过。

## 6. 批次执行策略

后续不再按“大而泛”的批次推进，而按以下两层执行：

### 6.1 问题族批量执行

适用于：

- 同一问题族下有多条病历
- 规则已基本稳定

执行方式：

- 一次跑同族病历
- 输出逐条台账结果

### 6.2 单病历逐条补洞

适用于：

- 同一病历的人工问题很具体
- 需要核规则是否真对应
- 或需要确认是否 `skip`

执行方式：

- 单病历定向跑主规则
- 单条补证据链
- 单条写结论

## 7. 跳过判定标准

以下情形允许直接跳过：

1. 对应原始文书在本地 PG 中不存在
2. 对应原始文书在 `0426` / `0426_full_auto` 快照中也不存在
3. 当前问题无法通过其他同类文书合理回退取证
4. 若强行继续，仅能靠人工问题原文“开卷命中”，不具备真实验证意义

以下情形**不允许**跳过：

1. 文书原表为空，但可从 `senior/daily_course_record` 等回退取证
2. 只是规则还没补齐
3. 只是模型当前没打出来
4. 只是当前映射还没收窄
