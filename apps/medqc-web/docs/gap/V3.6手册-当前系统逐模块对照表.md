# V3.6 手册 -> 当前系统逐模块对照表

## 1. 说明

- 对照基线：`docs/内涵质控V3.6用户手册20240407 .pdf`
- 核对范围：`apps/medqc-web` 当前前端页面、路由、API 调用、后端路由与显式 mock/fallback/TODO
- 本轮复刻范围修订：
  - 登录只做 `用户名/密码` 和 `手机号/密码` 两种方式
  - 不做扫码登录
  - 手机号不是独立账户体系，而是同一账户的备用登录标识
  - 用户注册/建档时需维护 `用户名 + 手机号`
  - 手机号登录按内网场景处理，不做短信验证码链路
- 结论口径：
  - `匹配`：主流程、关键操作、数据闭环已具备
  - `部分匹配`：存在页面或接口，但能力不完整或口径偏离手册
  - `明显缺失`：手册一级能力缺页、缺接口或仅停留在模型预留
  - `超出手册`：当前系统有扩展能力，但不属于本次复刻主目标

## 2. 总体判断

- 当前 `MedQC` 不是 V3.6 的直接复刻版，而是 `病历内涵质控后台 + 住院病案工作站 + DRG + 数据同步` 的混合系统。
- 与手册相比，最核心的差距不是零散按钮，而是产品骨架没有完全对齐。
- 当前最接近手册的是：
  - 运行病历/终末病历列表操作
  - 缺陷处理、整改闭环
  - 任务抽样与分配的基础后端能力
- 当前差距最大的三块是：
  - 门急诊病历产品线
  - 统计分析真实业务页
  - 规则运营后台

## 4. 核心差距总结

### 4.1 前端侧

- 最大问题不是“没有页面”，而是“页面体系不统一”。
- 工作站、DRG、规则 demo、测试页、传统质控后台并存，用户看到的是多套产品拼接。
- 统计分析和规则管理是当前最典型的“页面在、真实业务能力不在”。
- 运行/终末病历页最接近手册，但门急诊主线缺失，导致病历质控产品骨架不完整。

### 4.2 后端侧

- 缺门急诊病历的产品化接口闭环。
- 认证体系仍基于内存 `users_db`，未形成生产级持久化账号体系。
- 任务系统缺真正的定时任务执行器，`schedule_config` 仍偏数据模型预留。
- 统计分析缺专题统计、下钻明细、制度/指标报表。
- 规则后台只有规则接口集合，还不是手册要求的运营平台。
- Dashboard 场景分类口径不完整，前端场景切换与后端聚合维度未完全对齐。

## 5. 结论

如果目标是“复刻手册对应的成熟产品”，当前系统的真实状态可以概括为：

- `登录：部分匹配`
- `工作台：部分匹配`
- `病历质控：运行/终末部分匹配，门急诊明显缺失`
- `任务管理：部分匹配`
- `统计分析：明显缺失`
- `规则管理：明显缺失`
- `通知/整改/申诉：局部超出手册`

最重要的判断是：

> 当前系统已经具备一部分可复用能力，但还没有对齐 V3.6 的传统病历质控后台产品骨架。
