# Workstation V4 首页统一任务列表最终实施方案

## Summary

首页最终按“工作台”而不是“看板”设计，严格回到原始目标：

- 定位当日最关键质控问题
- 梳理个人特急待办
- 支持直接穿透至病历流程

因此首页不再采用“热点区 + 详情区 + 待办区 + 第二屏概览”的融合大页方案，而是收敛为：

- 一条紧凑工具栏
- 一条状态概览条
- 一个统一任务列表

首页主轴只保留一个：`今天该处理什么，按什么顺序处理，点哪里立刻进入处理`。

## Key Changes

### 1. 首页定位收敛

`/workstation-v4` 首页正式定位为：

- `admin / qc_manager` 的病案质控执行首页
- 不是 BI 看板
- 不是通知中心
- 不是全量病历池

首页只承担三件事：

- 给出当天最优先处理的病历任务
- 给出当前用户的特急待办
- 提供一键进入病历流程的入口

原“团队分析 / 批量汇总 / 分布图 / 趋势图”一律下沉到二级入口，不再作为首页主结构。

### 2. 页面结构改为单列任务驱动布局

首页结构固定为从上到下三段：

#### 工具栏

替代当前 `HomeHeroBar` 的大标题区，改成紧凑工作条，仅保留：

- 日期选择
- 科室筛选
- 流程筛选
- 搜索框
- 刷新按钮

约束：

- 去掉大标题区块、品牌标签、长说明文案
- 页面标题由导航层承担，不在页面主体重复强调
- 高度控制在一行工作台工具栏语义

#### 状态概览条

替代当前 `HomeKpiStrip` 的大卡片。

仅保留 4 个可点击指标：

- 待处理
- 高风险
- 已超时
- 进行中

展示形式：

- 一条水平状态条
- 数字 + 文案内联展示
- 点击后直接驱动统一任务列表筛选

明确去掉：

- 问题集中点
- 批量汇总

原因：这两个更偏统计，不直接产生动作。

#### 统一任务列表

替代现有：

- `HotspotListPanel`
- `HotspotDetailPanel`
- `MyTodoListPanel`

最终首页只有这一个主列表，不再并列两个主区。

### 3. 统一任务列表是首页唯一主工作区

核心原则：

- 用户不关心数据来源于 `hotspot` 还是 `todo`
- 用户只关心“现在先处理哪条”

因此首页将 `homeData.hotspots` 与 `homeData.my_todo_items` 合并为一个统一任务列表。

但为了避免语义混乱，列表行内保留来源标签：

- `问题`
- `待办`

不做分屏，不做两个并列列表，不做双主结构。

#### 列表分组

统一列表按优先级分为两组：

- `P0 / P1 紧急`
- `常规待办`

优先级判定规则：

- `severity = critical / high` 或 `priority = critical / high` -> 紧急组
- 其他 -> 常规组

同组内排序统一按：

1. 超时优先
2. 高风险优先
3. 未读优先
4. 活跃缺陷多优先
5. 最近触发优先

#### 列表行字段

每行固定展示：

- 来源标签：`问题` / `待办`
- 患者姓名
- `visit_id`
- 科室
- 流程类型
- 问题摘要
- 活跃缺陷数
- 时间
- 右侧动作：`立即处理`

可选附加：

- 风险色左边线
- `P0 / P1 / P2` 标签

约束：

- 不再保留单独的大表格表头
- 不再做“先选中再去右侧看详情”的双步交互
- 列表必须一屏内直接可读、可操作

### 4. 直接穿透到病历流程

首页所有主动作统一为一键进入病历流程。

行为规则：

- 点击整行：高亮当前任务，允许轻量展开上下文
- 点击 `立即处理`：
  - 直接进入 `/workstation-v4/worklist`
  - 自动带上 `record_id + action + from_stage`

workflow 映射继续沿用现有规则：

- `frontpage_generate` -> 首页生成
- `frontpage_qc` -> 首页质控
- `coding_qc` -> 编码质控
- `settlement_qc` -> 结算质控

次级动作规则：

- 不再强调“查看病历池”
- 不再要求用户先进入病历池再定位病历

### 5. 详情承接改为轻量模式

当前 `HotspotDetailPanel` 的大详情卡片不再作为首页默认主结构。

改法：

- 首页不保留右侧大详情面板
- 如需更多上下文，采用轻量承接方式之一：
  - 行内展开
  - 右侧轻抽屉

首版推荐：

- 先做行内展开摘要
- 展示：
  - 风险级别
  - workflow
  - 活跃缺陷数
  - 最新质控等级
  - 简要摘要

但不允许大面积占据首页宽度。

### 6. 第二屏默认移除

当前首页中的以下内容不再作为默认首页结构：

- 批量汇总
- 科室风险分布
- workflow 状态分布
- 趋势图
- 排行榜

处理方式：

- 从首页主视图移除
- 下沉到二级概览页
- 或通过“查看更多概览”进入

首页不再依赖滚动到第二屏完成主要任务。

### 7. 数据口径收敛

首页主接口仍复用：

- `GET /api/v1/workstation/home`

但前端消费语义需要收紧：

- `hotspots` 和 `my_todo_items` 在首页层合并为统一任务流
- `team_summary` 不再作为首页默认主消费对象
- `batch_summaries` 不再作为首页主模块

建议首页前端内部新增统一视图模型：

- `UnifiedTaskItem`

字段至少包含：

- `id`
- `source_type`：`hotspot | todo`
- `record_id`
- `visit_id`
- `patient_name`
- `department`
- `workflow_type`
- `severity`
- `priority`
- `summary`
- `active_defect_count`
- `unread_count`
- `task_status`
- `latest_created_at`
- `launch_action`
- `launch_stage`

这个模型只在前端聚合层存在，不要求本轮改后端接口。

## Public API / Type Changes

本轮不强制新增后端接口，优先复用：

- `GET /api/v1/workstation/home`

前端类型层新增：

- `UnifiedTaskItem`

前端组件收敛：

- `HomeHeroBar.vue` 重写为极简工具栏
- `HomeKpiStrip.vue` 退场，由 `StatusBar.vue` 替代
- 新增 `UnifiedTaskList.vue`

首页不再默认渲染：

- `HotspotListPanel.vue`
- `HotspotDetailPanel.vue`
- `MyTodoListPanel.vue`

路由保持不变：

- `/workstation-v4` = 首页
- `/workstation-v4/worklist` = 病历池 / 实际处理页

## Test Plan

### 首页结构验证

- 首页首屏只保留工具栏、状态概览条、统一任务列表
- 不再出现双主列表结构
- 不再依赖第二屏完成核心任务

### 任务列表验证

- `hotspot` 与 `todo` 在同一列表中展示
- 列表保留来源标签，但不做视觉分裂
- 紧急组与常规组分组正确
- 同组内排序符合优先级规则

### 穿透验证

- 点击 `立即处理` 可直接进入对应 workflow
- 不需要先进入病历池再手动筛病历
- workflow 跳转参数正确

### 空态验证

- 全部数据为 0 时，首页仍然紧凑
- 不出现大面积空白表格
- 不出现“请先选择一条记录”这类占屏提示块

### 回归验证

- 现有筛选、搜索、日期切换、刷新仍可用
- `/workstation-v4/worklist` 原执行能力不回归
- 后端 `/api/v1/workstation/home` 现有返回结构仍可被兼容消费

## Assumptions

- 首页目标严格按原始需求执行：关键问题、特急待办、直接穿透。
- 首页宁可偏克制，也不继续扩成“大杂烩”。
- 首版允许前端先聚合 `hotspots + my_todo_items`，不要求后端同步重构接口。
- 首版默认保留来源标签 `问题 / 待办`，采用“同列表、轻区分”的方案。
- 大详情卡、团队分布、批量汇总不属于首页主结构。
