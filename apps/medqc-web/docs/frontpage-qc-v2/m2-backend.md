# 首页质控 V2 · M2 后端说明

- 日期：2026-10-13
- 范围：存储表与迁移、后台批量任务、结果列表与详情、复核、统计、导出接口
- 不调用模型：CDM 只读，结果只写入新增的首页质控专用表

## 一、数据表（迁移 `20261013_000048_frontpage_qc_v2`）

split 模式建在 `qc` schema，单 schema 模式建在默认 schema。旧表 `qc_results` / `qc_defects` 不改动、不读取。

| 表 | 一行代表 | 关键字段 |
|---|---|---|
| `frontpage_qc_runs` | 一次批量任务 | 状态、筛选条件、病历三坐标列表、进度计数、失败样本（最多 50 条）、取消标记 |
| `frontpage_qc_results` | 一份首页的一次质控 | 三坐标、科室、出院日期、得分、等级、各类计数、可评分项占比、规则集版本、首页内容指纹、`is_latest` |
| `frontpage_qc_findings` | 一条不合规或资料不足 | 规则、严重程度、评分项、结论、扣分、明细、复核状态 |

- **旧库兼容**：迁移只新增表。表未迁移时，首页质控接口返回 503 并提示执行 `20261013_000048`，其他功能不受影响。
- **测试初始化**：`FrontpageQcStore.create_all()` 用于 SQLite 测试建表。迁移往返测试保证运行时表结构与迁移完全一致，包括列和索引。
- **重新质控**：新结果设为最新，旧结果保留为历史。上一次相同问题（规则和明细都一致）的复核结论会自动沿用，不用重复复核。

## 二、接口（`/api/v1/frontpage-qc`）

**权限**：
- 需要产品已激活。
- 角色限 `admin`、`super_admin`、`qc_manager`、`coder`。

| 方法 | 路径 | 说明 |
|---|---|---|
| GET | `/rules` | 规则目录：分组、扣分、启用/停用原因、同步缺口字段、等级阈值 |
| GET | `/filters` | 科室列表、日期范围（与病历池出院范围一致） |
| POST | `/runs` | 创建任务，二选一：按所选病历（`record_refs`），或按科室/出院日期/关键词筛选。单次上限 500 份；同一用户有进行中的任务时返回 409 |
| GET | `/runs?active=1` | 我的最近任务（可只看进行中） |
| GET | `/runs/{id}` | 任务进度。超过 10 分钟没有进展的 running 任务自动落为失败，前端可以停止轮询 |
| POST | `/runs/{id}/cancel` | 取消：只能取消自己的任务，管理员不受限 |
| GET | `/records` | 结果列表，筛选项见下方说明 |
| GET | `/record?institute_id&patient_id&visit_id` | 单份详情：最新结果与问题、当前首页字段视图、`stale`（首页内容或规则集变了、结果已过期） |
| POST | `/findings/{id}/review` | 复核：确认 / 误报（误报须填原因）/ 撤回为待复核；只能复核最新结果上的问题 |
| GET | `/analytics` | 统计：汇总、可自动计算的 2016 版指标、扣分规则 Top 10、提示 Top 10、资料不足 Top 10、科室排名 |
| POST | `/records/export` | 导出 Excel：所选病历或当前筛选；两个工作表：“病历结果”和“问题明细” |

`/records` 的筛选项：
- 科室、出院日期、关键词
- 等级：优秀 / 合格 / 不合格
- 问题类型：
  - `fail` 有扣分问题
  - `hint` 有提示
  - `data_gap` 有资料不足
  - `clean` 无问题
  - `unchecked` 未质控

## 三、执行方式

- 后台线程池（`submit_detached_task`）逐份执行：读取首页 → 规则 → 写结果。每 10 份更新一次进度，同时检查取消。
- 单份失败（如找不到首页）不中断任务，计入失败样本。结束状态有四种：
  - `completed`：全部成功
  - `completed_with_errors`：部分失败
  - `failed`：全部失败
  - `cancelled`：已取消
