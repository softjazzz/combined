# v0.4 开发验收记录

日期：2026-11-01。结论：控制服务开发与合成集成验证通过；客户环境部署和生产启用未执行。

## 已完成的功能

五路并行开发分别覆盖合同准入、持久队列、执行恢复、API/调度、部署离线交付。主协调完成配置装配、进程启动、原引擎衔接及统一回归。

- CLI和独立HTTP API受理人工任务，返回202及任务ID；接口、日期、模式、权限与幂等键统一校验。
- PostgreSQL独立控制库存储任务、执行单元、尝试、计划、触发记录和事件。API与worker使用不同的非超级用户角色。
- 常驻worker领取任务，独立执行进程调用既有ExtractService/PublishService。保持单源并发、数据事务、字段合同与原注册表。
- 失败保留审计，重试跳过已成功单元；raw成功而发布失败时只重试发布。取消在事务安全边界生效。
- 状态不明进入recovery_required并隔离后续领取；授权操作者通过CLI提交已核对的恢复声明，不手工改表、不假称自动确认提交状态。
- 每日/每周计划默认禁用，固定Asia/Shanghai日期语义，重复tick不重复生成任务。一般窗口最多7天；只有第一批web.mr允许每周最多60天replay，人工请求仍最多7天。
- 分离控制配置、执行绑定和秘密引用；API不读取Caché或数据面管理员秘密，不读取.env。
- Windows禁用任务模板、Linux迁移模板、初始化/验收/打包工具和Windows CPython3.10离线依赖。

## 交付和剩余工作

源码候选包与离线依赖附件分开，含逐文件CHECKSUMS和DSH_START。不会携带客户配置、密码、token、raw、正文、真实病例键、dump或私有日志。
