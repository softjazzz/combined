# 剩余接口集中验收包开发记录

日期：2026-11-01。客户真实执行尚未发生；本文只记录开发验证。

## 一次集中处理的范围

55个过程分为：第一批13个既有验收复用；本次重新读取其余42个（第二批17＋剩余25）。两个业务别名不充作新过程。

同一固定run manifest只准备4个全新验收库。原13接口和旧库不调用、不连接；业务库、冻结目录、任务、自动增量和checkpoint保持保护。所有新来源先完整保存源快照，再从快照回放正式raw/CDM引擎，不为dry和replay重复读取医院源。

已冻结39个候选字段/键/投影合同。3个没有源列证据的过程（手术记录、医保结算清单、住院费用明细）只探查并保存实际快照；即使过程恢复返回数据，也不能临场猜主键或映射。零样本接口只做一次明确的短窗口补样，不能据无数据判断临床文书缺失。

## 提前补齐的确定缺口

正式ORM和迁移000058一次补入23列：文书记录/签署9项、新生儿6项、病理7项、诊断主诊断原始标志1项。时间可空，无默认，不以提交时间代替；出生信息和标志等保留原始文本，不推断临床含义。

还修复了epidemic_record在旧000006中漏从public迁往cdm的问题。新迁移显式验证并保留既有表数据；两处都没有表时使用冻结DDL创建。未改写旧迁移、未执行任何客户迁移。

## 已实测的开发证据

- 新Windows CPython3.10虚拟环境从完整33个锁定wheel离线安装，pip check、正式ORM/initializer/Alembic导入通过。
- 在本机明确标记的PG18合成集群上，空库经过正式完整迁移到000058；42张目标均存在，部署运行身份分开。
- 合成来源执行126个固定日期窗口：39个有合同来源全部通过完整快照、键/目标catalog、正式raw、CDM两轮幂等和逐字段相等；3个无合同过程以模拟源错误隔离，不影响其他来源。
- ingest/CDM备份恢复至固定恢复库，逐表与序列指纹相等。
- 同一现场重跑源工厂调用0次，不重做已成功读取；坏时间值的独立合成场景正确阻断，未修改原始坏快照伪造通过。
- 关键字段统计、55来源矩阵和只含操作元数据的结果ZIP经过真实新库读取和打包验证。
- 局部软件修复后，只重新核验失败的只读闸门；数据变化会产生新备份版本，先确认恢复库属于上次备份才在同一恢复库原子恢复，不复用陈旧通过证据。

本次PG18合成结果不能替代医院Caché/PG16真实数据验收；最终DSH报告必须逐项保留源错误、样本不足、映射限制和在院对照不足。没有执行完整规则引擎或模型，也没有启用任何现场任务。

## 客户执行与收口

按DSH_START一次执行即可。源/样本问题按接口隔离继续；连接、权限、凭据、错误目标、资源和未知提交状态不能绕过。允许在本次新工作副本内修复纯软件问题，保留diff并测试后沿原run续跑，不重建一套库、不重抽成功源、不修改冻结合同的临床语义或主键。

有确认仍在院的本地清单时，只核对本次新scope窗口内病例出现情况，不把它称为全住院文书完整性证明；没有清单时明确blocked，不空跑或要求传出病例信息。所有正文、真实键、凭据和dump留在客户机，仅回传统计和受控状态。
