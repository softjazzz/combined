# 正式六接口整合 0.2.0

本次使用已验收的六接口合同扩展现有服务，复用原有分块、锁、独立批次审计和发布流程。
未合并 DSH 临时抽取器，也未修改业务应用 Alembic。仍按独立验收库推进，不部署正式库。

## 已实现

- 13 个接口的显式注册。双日期来源按 `(day, day)` 参数化调用，不把双日期接口当成
  按修改时间增量接口。CLI 导出全部合同；原七文书的历史导出保持兼容。
- 六接口与独立验收 JSON 逐字段对照，正式转换与已验收转换逐行对照。检验结果保留
  行级 print_order_id；检查报告只生成 cache-exam-v1 技术键，不关联医嘱、不派生申请。
- 技术键的目标重复预检使用真实源键字段，不会查询不存在的 __derived_document_id。
- schema、当前 raw、变化版本、增量断点同一数据事务；running 和失败状态通过控制
  连接独立保存。dry 即使误传入仓储也不会连接 PG。历史版本仅在新行或内容/schema变化
  时追加；相同数据不追加版本，保留原 local_sync_completed_at。
- CDM 核对实际列类型、主键和文本最大长度；超长拒绝，不裁剪；使用 IS DISTINCT FROM
  防止不变数据重复更新，written 取实际驱动行数。
- 正式发布读取使用一致快照，拒绝空哈希、无效哈希和 metadata 摘要不符。
- 新增只读验收工具，直接以正式转换对照客户已有 raw/CDM，不重抽、不迁移。

## 验证边界

开发机测试使用 fake 端口和驱动。新 SQL 004 需由部署身份在符合正式存储合同的独立库
应用；本轮没有执行 PostgreSQL DDL 或真实版本写入，不能宣称真实事务回归已完成。
DSH 当前只读步骤也不覆盖这部分，后续仍需在独立新克隆做真实事务故障注入。

现有 DSH 表结构与正式 ingest 不兼容。临时的事后 schema 补录仍保留其独立审计意义，
不能据此自动修 raw，也不能取消正式发布的空哈希阻断。完整临时历史版本的迁入需显式
迁移方案；004 只针对原正式服务升级，不能代替 DSH 存储迁移。

发布跨 ingest/CDM 两个数据库，CDM 先提交、血缘后提交，仍然不是分布式事务；后一步
失败时靠目标幂等重试。进程被杀或审计回写失败仍可能留下 running，需按已有运维流程
核查，不能仅凭成功路径测试宣称消除了全部故障残留。

源是否支持在院取数、全住院期间文书覆盖、签署数据可用性，以及完整质控规则结论，
均不属于本次整合已证实事项。
