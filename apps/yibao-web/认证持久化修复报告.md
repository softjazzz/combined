# Yibao 智慧医保质控系统 - 认证持久化修复报告

## 📋 问题概述

**修复前的问题现象：**
- 用户登录后，刷新浏览器页面时需要重新登录
- 用户状态没有在浏览器会话中持久化保存
- Token可能没有正确存储或自动刷新机制不完善
- 多标签页之间认证状态同步不一致

## 🔍 问题根因分析

通过深入分析代码，我们发现了以下关键问题：

### 1. TokenManager 的 token 过期检查逻辑问题
- `isTokenExpired` 方法使用了60秒的缓冲时间，可能导致有效token被误判为过期
- `shouldRefreshToken` 方法提前5分钟刷新，但没有考虑mock token的特殊情况
- token解析异常处理不够完善

### 2. Auth Store 初始化时序问题
- `initialize` 方法中先检查缓存用户信息，再验证token，但验证失败时没有正确处理
- Mock模式下生成的JWT格式可能不完全符合标准解析逻辑
- 初始化过程阻塞UI，影响用户体验

### 3. 路由守卫的认证检查过于严格
- 每次路由变化都会检查token并尝试刷新，可能导致不必要的认证失败
- 初始化和token检查的异步操作可能导致竞态条件
- 页面刷新场景没有特殊处理

### 4. 认证状态同步机制不完善
- `authSync.ts` 中的存储监听器可能没有正确处理所有认证状态变化场景
- 多标签页同步逻辑不够健壮

## 🔧 修复方案与实施

### 1. 优化 TokenManager 的持久化逻辑

**文件：** `apps/yibao-web/src/services/apiService.ts`

**主要改进：**
- 减少token过期检查的缓冲时间从60秒到30秒
- 改进token解析异常处理，增加详细的错误日志
- 优化`shouldRefreshToken`方法，对mock token使用更宽松的刷新策略
- 增强`isAuthenticated`方法的检查逻辑，确保认证状态的准确性
- 改进登录方法，确保用户信息正确持久化

**关键代码改进：**
```typescript
// 改进的token过期检查
static isTokenExpired(token: string, skewMs: number = 30000): boolean {
  try {
    if (!token || token.split('.').length !== 3) {
      return true
    }
    
    const payload = JSON.parse(atob(token.split('.')[1]))
    if (!payload.exp) {
      // 如果没有过期时间，认为是永久有效的mock token
      return false
    }
    
    return (payload.exp * 1000) < (Date.now() + skewMs)
  } catch (error) {
    console.warn('解析token失败:', error)
    return true
  }
}
```
