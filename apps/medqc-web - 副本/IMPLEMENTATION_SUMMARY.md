## 技术细节

### 后端配置重载机制

后端已经实现了动态配置重载功能，核心组件：

1. **LLMConfigLoader** (`app/services/llm_config_loader.py`)
   - `load_config()`: 从数据库加载 LLM 配置
   - `reload_config_for_service()`: 为服务重新加载配置

2. **SichuanQCService** (`app/services/sichuan_qc_service.py`)
   - `reload_config()`: 重新加载 LLM 配置

3. **API 端点** (`app/routers/qc_sichuan.py`)
   - `POST /api/v1/qc/sichuan/reload-config`: 重新加载配置的 API 端点

### 模型信息流转

1. **质控执行时**: 后端在 `evaluate_document_fast()` 方法中，将模型名称包含在返回结果的 `evaluation_summary.model` 字段中

2. **保存质控结果时**: 前端从 `response.data.evaluation_summary.model` 提取模型名称，传递给后端保存

3. **读取历史记录时**: 后端从保存的 JSON 文件中读取 `model` 字段（优先从 `evaluation_summary.model`，否则从顶层 `model` 字段）

4. **显示质控结果时**: 前端从历史记录数据中读取 `model` 字段，使用 Tag 组件显示

## 注意事项

1. **旧的历史记录**: 在实现此功能之前保存的质控结果没有 `model` 字段，这些记录不会显示模型标签。只有新执行的质控才会保存和显示模型信息。

2. **配置重载失败处理**: 如果后端配置重载失败（例如后端服务未运行），前端会显示警告提示，但不会阻断配置保存流程。用户可以选择手动重启后端服务。

3. **模型信息来源**: 模型名称来自后端的 `SichuanQCLLMClient.model` 属性，该属性在服务初始化时从数据库加载，或在配置重载时更新。
