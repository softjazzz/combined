# 复杂规则配置说明

## 📋 概述

本文档说明如何管理和配置**复杂规则列表**，为误判率高的规则提供增强的判定指导。

---

## 🎯 设计思路

### 渐进式优化策略

1. **第一阶段（已实施）**：
   - 为所有规则提取【检查要点】（方案 A）
   - 快速提升整体准确率到 60-70%

2. **第二阶段（持续优化）**：
   - 识别误判率高的复杂规则
   - 为这些规则额外提取【判定逻辑】
   - 针对性提升复杂规则的准确率

---

## 🔧 实现机制

### 代码位置

**文件**：`app/services/sichuan_qc_service.py`

**函数**：`_extract_enhanced_guidance()`

### 复杂规则列表

在 `_extract_enhanced_guidance()` 函数中定义：

```python
# 定义需要增强指导的复杂规则列表
# 这些规则在测试中误判率较高，需要额外的判定逻辑
complex_rules = {
    "LX-007",  # 入院记录缺辅助检查
    "LX-009",  # 入院记录缺初步诊断
    # 后续可以根据实际测试结果添加更多规则
}
```

### 提取逻辑

- **普通规则**：只提取【检查要点】
- **复杂规则**：提取【检查要点】+【判定逻辑】

---

## 📊 当前复杂规则列表

### LX-007：入院记录缺辅助检查

**误判原因**：
- LLM 对"辅助检查"的理解不够准确
- 容易将"记录不完整"误判为"缺失"

**增强策略**：
- 提取【检查要点】：明确检查范围
- 提取【判定逻辑】：明确判定标准

**效果预期**：
- 误判率从 100% 降低到 30-40%

---

### LX-009：入院记录缺初步诊断

**误判原因**：
- 规则包含 3 个独立的检查要点（无诊断、主次顺序错误、次要诊断遗漏）
- LLM 容易混淆这 3 个要点

**增强策略**：
- 提取【检查要点】：详细说明 3 个独立要点
- 提取【判定逻辑】：明确每个要点的判定标准

**效果预期**：
- 误判率从 100% 降低到 30-40%

---

## 🔍 如何识别复杂规则

### 识别标准

1. **误判率高**：在测试中误判率 > 50%
2. **规则复杂**：包含多个独立的检查要点
3. **判定模糊**：判定标准不够明确，容易产生歧义
4. **上下文依赖**：需要综合多个部分的信息才能判定

### 识别流程

1. **运行测试**：使用 `test_prompt_plans_with_llm.py` 测试质控效果
2. **分析误判**：查看哪些规则误判率高
3. **查看理由**：分析 LLM 的判定理由，找出误判原因
4. **决定是否增强**：如果误判原因是缺少判定逻辑，则添加到复杂规则列表

## 💡 优化建议

### 1. 保守添加

- 不要一次性添加太多复杂规则
- 每次添加 1-2 个，测试效果后再继续
- 避免过度优化导致 Token 消耗过大

### 2. 优先级排序

按以下优先级添加复杂规则：
1. **高频规则**：使用频率高的规则
2. **高误判率**：误判率 > 70% 的规则
3. **高影响**：误判后果严重的规则

### 3. 定期评估

- 每月评估一次复杂规则列表
- 移除效果不明显的规则
- 添加新发现的复杂规则

### 4. 成本控制

- 监控 Token 消耗和成本
- 如果成本增长过快，考虑：
  - 减少复杂规则数量
  - 优化提取逻辑，进一步压缩提示词
  - 调整 LLM 模型（使用更便宜的模型）

## ❓ 常见问题

### Q1: 为什么不对所有规则都使用增强指导？

**A**: 
- 增强指导会增加提示词长度和 Token 消耗
- 测试发现，只提取检查要点对大部分规则已经足够
- 只对误判率高的复杂规则使用增强指导，可以在准确率和成本之间取得平衡

### Q2: 如何判断一个规则是否需要增强指导？

**A**:
1. 运行测试脚本，查看误判率
2. 如果误判率 > 50%，分析误判原因
3. 如果误判原因是缺少判定逻辑，则添加到复杂规则列表
4. 如果误判原因是规则本身有问题，则需要修改规则

### Q3: 增强指导的效果如何评估？

**A**:
1. 添加前后对比准确率变化
2. 查看 LLM 的判定理由是否更准确
3. 监控 Token 消耗和成本变化
4. 综合评估性价比

### Q4: 如果增强指导后准确率仍然不高怎么办？

**A**:
1. 检查规则的 `custom_prompt` 是否清晰明确
2. 考虑修改规则的【判定逻辑】部分
3. 考虑在批量提示词中添加全局的判定标准说明
4. 如果规则本身有问题，与客户沟通修改规则
