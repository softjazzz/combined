# 临床质控演示平台 PRD（Clinical Workstation Demo）

## 1. 背景与目标

### 1.1 背景

- 现有 MedQC 系统中存在多个分散的 Demo 页面（如 LX33 规则演示、四川质控 Demo、病案首页自动生成 Demo 等），不利于向客户“一站式”展示系统能力。
- 客户（医院领导、信息科、质控科、临床医生）在评估质控系统时，最关心：
  - 系统在真实/模拟病历上的质控效果；
  - 规则的可解释性和可配置性；
  - 对医生/质控人员的实际使用体验。

### 1.2 目标

- 在 medqc-web 中构建一个统一入口的**临床质控演示平台**（Clinical Workstation Demo）：
  - 客户可以在浏览器中自行选择病例；
  - 浏览包含多种文书的完整病历；
  - 一键执行质控规则并查看详细结果；
  - 演示病案首页自动生成等能力。
- 平台同时支持：
  - 官方预置的多案例 mock 病历；
  - 客户临时录入/粘贴的自定义病历。
- 定位：**演示与验证规则效果**，非生产系统。

---

## 2. 用户与场景

### 2.1 用户角色

- 销售 / 实施人员：在会议、路演、医院现场进行演示。
- 医院领导 / 信息科：快速理解系统价值、质控覆盖范围与能力边界。
- 科室医生 / 质控科人员：在真实或模拟病历上体验质控结果和提示。

### 2.2 关键使用场景

1. **预置典型病例演示**
   - 从病例库中选择一个典型病例（包含多种文书，如入院、病程、手术、出院、护理等）。
   - 在统一工作站界面中按文书浏览、执行质控。
   - 查看每份文书及整病例的质控问题分布和得分情况。

2. **客户自带病历验证**
   - 客户在现场将自己的病历文本（单份或多份文书）粘贴到系统中，快速创建临时病例。
   - 运行质控规则，观察与医院现有人工质控结果是否一致。
   - 用于说服和“打样”。

3. **规则集 / 模式对比**
   - 在同一份病历上，切换不同规则集/模式（例如“默认规则集 / 四川 146 条 / LX33 专题 / 语义规则”）。
   - 对比不同模式下的命中问题、得分和提示差异。

4. **端到端流程演示**
   - 从多文书浏览 → 文书级质控 → 整病例质控 → 病案首页自动生成。
   - 可选接入医保/DRG 提示，为后续扩展留空间。

## 3. 产品范围（Scope）

### 3.1 本期包含

- 在前端新增统一入口页面（Clinical Workstation Demo），整合：
  - 多病例、多文书的浏览体验；
  - 文书级与整病例质控调用与展示；
  - 简单的病例录入（mock 与自定义）；
  - 病案首页草稿生成与展示。

### 3.2 本期不包含

- 完整的生产级账号体系、病区/科室管理。
- 海量病例的批量质控与调度。
- 复杂角色与权限控制（本期仅需要“演示模式”权限控制）。

## 4. 核心功能需求

### 4.1 病例与文书管理（Mock 数据层）

#### 4.1.1 病例库（Mock Case Library）

- 系统内置一批预置演示病例，可以存放在前端 JSON 或 Supabase 演示表中。
- 每个病例包括：
  - `caseId`
  - 脱敏后的患者信息（年龄段、性别等）
  - 科室（内科、外科、ICU 等）
  - 病种标签（肺癌、阑尾炎、脑卒中等）
  - 复杂度标签（低 / 中 / 高）
- 每个病例包含多份文书，示例：
  - 入院记录
  - 首次病程记录
  - 日常病程记录（1~N）
  - 手术申请单
  - 手术记录
  - 麻醉记录
  - 术后病程记录
  - 护理记录
  - 出院记录

- 前端提供筛选：
  - 按科室、病种、复杂度过滤；
  - 关键字搜索病例名称/简要描述。

#### 4.1.2 自定义病例（临时 Case）

- 用户可以创建一个“临时演示病例”：
  - 填写基本信息（仅用于展示）：
    - 姓名（可选）、年龄、性别
    - 科室、病种标签
  - 为该病例添加一份或多份文书：
    - 文书类型：选择（入院记录 / 病程记录 / 手术记录 / 护理记录 / 出院记录 / 其他）
    - 标题（可选）
    - 记录时间（可选）
    - 正文内容（多行文本框，支持粘贴）
- 临时病例存储策略：
  - 默认只保存在浏览器内存或演示数据库；
  - 页面刷新后可以选择清空或持久化有限数量（例如最近 10 条）。

#### 4.1.3 病例列表界面

- 在 Clinical Workstation 页的左侧或顶部提供“病例选择”区域：
  - Tab：`示例病例` / `自定义病例`
  - 支持过滤：科室、病种、复杂度
  - 支持快速搜索：按病例名称或病种关键字。
- 选择一个病例后：
  - 左侧“住院文书”菜单动态更新为该病例的文书列表；
  - 默认打开“入院记录”或权重最高的文书。

---

### 4.2 文书浏览与切换

#### 4.2.1 多文书导航

- 左侧栏结构：
  - 顶部标题：`住院文书`
  - 一级菜单：
    - 病案首页
    - 病案首页（病案科）
    - 病历文书（可折叠）
    - 书写病历（跳转到文书录入界面）
  - `病历文书` 子项由当前病例的文书列表动态生成：
    - 按文书类型（入院 / 首程 / 日程 / 手术 / 护理 / 出院）和时间排序；
    - 显示标题 + 时间（比如“入院记录 · 2022-03-03 17:11”）。
- 交互：
  - 点击文书条目：
    - 中间区域加载并展示该文书全文；
    - 更新右侧质控结果（可配置为自动触发或点击“质控分析”按钮触发）。

#### 4.2.2 文书正文展示

- 中间区域结构：
  - 顶部信息条：病例名称 / 当前文书标题 / 文书类型 / 时间 / 科室 / 医生。
  - 主正文区域：
    - 采用纸张样式布局（类似入院记录示例）；
    - 上半部分：基本信息网格（就诊类型、患者 ID、就诊 ID、年龄、性别等，可根据文书类型调整）；
    - 下半部分：主诉、现病史、既往史、查体、辅助检查、诊断、处理等分段。
  - 支持滚动，右侧 CDSS 不随正文滚动。

---

### 4.3 质控规则调用与展示

#### 4.3.1 文书级质控调用

- 在中间区域提供“质控分析”按钮：
  - 针对当前选中文书调用相应质控接口：
    - 四川病历 Demo：`POST /api/v1/qc/sichuan/evaluate`
    - 通用 Demo：可调用 `POST /api/v1/qc/analyze` 或语义规则接口。
  - 请求参数（建议统一模型）：
    - `visit_id`
    - `document_id`
    - `document_type`
    - `document_content`
    - `rule_set`（可选：如 `default` / `sichuan_146` / `lx33`）
    - `persist`（演示模式默认 false）
- 质控执行状态：
  - 按钮旁显示加载动画和“分析中…”提示；
  - 请求失败时在右侧面板显示错误信息，并提示用户稍后重试或检查配置。

#### 4.3.2 质控结果展示（右侧 CDSS 面板）

- Tab「病历质控」展示：
  - 概览统计：
    - 总规则数、命中问题数、违规严重程度分布；
    - 当前文书得分、整病例得分（若可用）。
  - 问题列表：
    - 每条包含：
      - 规则名称
      - 问题描述（医生友好描述）
      - 严重程度标签（严重/一般/轻微）
      - 扣分（如适用）
      - 关键证据片段（截取 1~3 行原文，支持高亮）
      - 问题定位（如“入院记录 · 现病史段落”）
      - 整改建议（可选）
    - 支持按严重程度排序或过滤。

- 交互：
  - 点击某条问题时，可选：
    - 在正文区域滚动并高亮对应文本（后续迭代）。
  - 提供“申诉”和“备注”输入框，仅在前端展示，不必持久化。

#### 4.3.3 整病例质控视图（可选）

- 提供“整病例质控”按钮：
  - 对当前病例的所有文书进行一次整体质控（如后端已有对应接口）。
  - 结果在一个弹窗或新 Tab 中展示：
    - 各文书问题数量和扣分情况；
    - 整病例总分和总体意见。

---

### 4.4 病案首页草稿与附加展示

#### 4.4.1 首页草稿生成

- 右侧 Tab「病案首页」：
  - 调用已有接口：
    - `POST /api/v1/frontpage/auto-generate-draft`
    - 入参：`visit_id` 或该病例的文书列表。
  - 显示主要字段：
    - 基本信息：姓名、性别、年龄、身份证号。
    - 入院/出院时间、住院天数。
    - 入院方式、入出院科室。
    - 主要诊断原文、其他诊断原文列表。
    - 主要手术原文、日期等。
  - 显示字段的置信度与证据来源（如有）。

#### 4.4.2 A4 打印预览

- 提供“查看 A4 版本”按钮：
  - 跳转到现有 `FrontPageDemoView` 或在 Drawer 中嵌入 A4 模板；
  - 使用同一个 `FrontPageDraft` 数据。

## 5. 非功能需求

### 5.1 易用性

- 面向非技术用户（医生、领导）设计：
  - 页面结构简单，术语清晰；
  - 从选病例到看到质控结果，步骤尽量不超过 3 步。

### 5.2 安全与隐私

- 示例病例必须是脱敏数据，不包含真实身份证号、手机号等敏感信息。
- 客户自录入的病历建议：
  - 默认不持久化到生产数据库；
  - 演示环境可配置“演示数据清空”功能。

### 5.3 性能与稳定性

- 单次质控请求建议在 5~15 秒内返回（LLM 场景视情况说明）。
- 失败时要有明确错误提示，不影响用户浏览其他内容。

## 6. 里程碑与迭代建议

### 6.1 MVP（Step 1）

- 完成 Clinical Workstation Demo 页面基础：
  - 接入预置 mock 病例（前端 JSON 即可）；
  - 实现左侧多文书导航 + 中间文书展示；
  - 右侧接通至少一种质控接口（如四川规则）和 frontpage 接口；
  - 可在 2~3 个 demo 病例之间切换并演示。

### 6.2 Step 2：自定义病例录入

- 增加“新建演示病例”流程：
  - 基本信息 + 多文书录入；
  - 保存到前端或演示库；
  - 支持对自定义病例运行质控和生成首页草稿。

### 6.3 Step 3：规则集/模式切换与整病例视图

- 在质控面板中增加规则集/模式选择器；
- 若后端支持，增加“整病例质控”视图，对比不同规则集结果。
