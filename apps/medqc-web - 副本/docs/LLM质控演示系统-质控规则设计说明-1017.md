## 1. 规则来源与分类

### 1.1 系统中现有的质控规则

系统中已经存在多套质控规则，来源不同、用途不同：

| 规则集 | 来源 | 数量 | 用途 | 存储位置 |
|--------|------|------|------|---------|
| **四川省质控规则** | 四川省卫健委 | 68 条 | 生产环境质控 | 数据库 `qc_rules` 表 |
| **语义质控规则** | 系统内置 | 7 条 | 基础质控检查 | `semantic-rules.ts` |
| **演示规则** | 演示系统专用 | 10-20 条 | 演示和测试 | `demoDataService.ts` |
| **模拟规则** | 组件内置 | 5-10 条 | UI 展示 | 各组件内部 |

### 1.2 规则分类体系

所有规则按照以下维度分类：

#### 按质控维度分类

```typescript
type QCCategory = 
  | 'completeness'  // 完整性：检查必填字段、必要章节
  | 'consistency'   // 一致性：检查数据前后一致、逻辑一致
  | 'rationality'   // 合理性：检查诊疗方案合理性
  | 'timeliness'    // 及时性：检查时间要求
  | 'compliance'    // 合规性：检查法规遵从
```

#### 按规则类型分类

```typescript
type RuleType = 
  | 'logical'    // 逻辑规则：基于条件判断（如字段存在性、时间计算）
  | 'semantic'   // 语义规则：基于 LLM 语义理解
  | 'hybrid'     // 混合规则：结合逻辑判断和语义分析
```

#### 按严重程度分类

```typescript
type Severity = 
  | 'critical'   // 严重：必须修正，影响病历合法性
  | 'major'      // 重要：应该修正，影响质控评分
  | 'minor'      // 轻微：建议修正，提示性问题
```

## 2. 规则数据结构

### 2.1 核心数据结构

```typescript
interface QualityControlRule {
  // 基本信息
  id: string                    // 规则唯一标识
  ruleCode?: string             // 规则编码（如 "SC-001"）
  name: string                  // 规则名称
  description: string           // 规则描述
  
  // 分类信息
  category: QCCategory          // 质控维度
  ruleType: RuleType            // 规则类型
  severity: Severity            // 严重程度
  
  // 权重和评分
  weight: number                // 规则权重（1-100）
  maxScore?: number             // 最大扣分
  
  // 适用范围
  targetSections?: string[]     // 适用的文书章节
  applicableRecordTypes?: string[] // 适用的病历类型
  applicableDepartments?: string[] // 适用的科室
  
  // 规则逻辑
  checkLogic: QCRuleLogic       // 检查逻辑配置
  promptTemplate?: string       // LLM 提示词模板
  
  // 状态和元数据
  isActive: boolean             // 是否启用
  version?: string              // 规则版本
  createTime?: string           // 创建时间
  updateTime?: string           // 更新时间
}

interface QCRuleLogic {
  type: 'content_check' | 'llm_analysis' | 'time_check' | 'conditional_check'
  required_sections?: string[]  // 必需章节
  min_length?: number           // 最小长度
  patterns?: string[]           // 搜索模式
  criteria?: string[]           // 判断标准
  time_requirements?: {
    deadline_hours: number
    from_admission: boolean
  }
}
```

## 3. 演示系统中的规则使用

### 3.1 规则加载策略

演示系统采用**多层回退策略**加载规则：

```
1. 优先：本地 API（FastAPI 后端）
   ↓ 失败
2. 回退：Supabase 数据库
   ↓ 失败
3. 兜底：内置模拟数据（demoDataService）
```

### 3.2 规则加载代码（qcDemo.ts）

```typescript
// 在 loadTestData() 方法中
try {
  // 1. 尝试本地 API
  const apiRules = await ApiService.getQCRules()
  if (apiRules.success && apiRules.data?.data) {
    rules = apiRules.data.data
    console.log('✅ 本地API质控规则加载成功:', rules.length)
  }
} catch (apiError) {
  // 2. 回退到 Supabase
  const supabaseRules = await demoDataService.getQCRules({
    limit: 50,
    ...ruleFilters.value
  })
  rules = supabaseRules
}

// 3. 如果还是失败，使用内置模拟数据
if (availableRules.value.length === 0) {
  availableRules.value = await demoDataService.getQCRules({ limit: 20 })
}
```

### 3.3 规则选择逻辑

#### 智能默认选择

系统会自动选择 3 条不同类别的活跃规则作为默认规则：

```typescript
if (selectedRules.value.length === 0 && availableRules.value.length > 0) {
  const categories = new Set<string>()
  const selectedRulesList: QualityControlRule[] = []
  
  for (const rule of availableRules.value.filter(r => r.isActive)) {
    if (selectedRulesList.length >= 3) break
    if (!categories.has(rule.category) || selectedRulesList.length < 2) {
      selectedRulesList.push(rule)
      categories.add(rule.category)
    }
  }
  
  selectedRules.value = selectedRulesList
}
```

#### 用户手动选择

用户可以在 `QCRulesDemoPanel` 组件中：
- 查看所有可用规则
- 按类别、严重程度筛选
- 添加/移除规则
- 查看规则详情

## 5. 规则参数扩展设计

### 5.1 为什么需要规则参数配置？

根据 PRD 文档（Phase 2），演示系统需要支持：
- 调整规则参数和阈值
- 配置规则权重
- 启用/禁用规则
- 配置严重程度

### 5.2 规则参数数据结构

```typescript
interface RuleParams {
  enabled: boolean              // 是否启用
  weight: number                // 权重（1-100）
  threshold?: number            // 阈值（0-100）
  severity: 'low' | 'medium' | 'high' | 'critical'  // 严重程度
}

// Store 中新增
const ruleParams = ref<Map<string, RuleParams>>(new Map())
```

### 5.3 规则参数配置界面设计

#### 方案 1：抽屉式配置（推荐）

在规则列表中，每条规则旁边有"配置"按钮，点击打开抽屉：

```vue

  v-model:visible="paramsDrawerVisible"
  title="规则参数配置"
  width="450"
>
  <a-form layout="vertical">
    <!-- 启用状态 -->
    <a-form-item label="启用状态">
      <a-switch v-model:checked="params.enabled" />

    <a-form-item v-if="rule.hasThreshold" label="阈值">
```

### 5.4 Store 方法扩展

```typescript
// 更新规则参数
function updateRuleParams(ruleId: string, params: RuleParams): void {
  ruleParams.value.set(ruleId, params)
  message.success('规则参数已更新')
}

// 获取规则参数
function getRuleParams(ruleId: string): RuleParams | undefined {
  return ruleParams.value.get(ruleId)
}

// 重置规则参数
function resetRuleParams(ruleId: string): void {
  ruleParams.value.delete(ruleId)
  message.success('规则参数已重置为默认值')
}
```

## 6. 规则与文书的映射关系

### 6.1 文书分类体系

系统使用标准六大类文书分类：

```typescript
type DocumentCategory = 
  | 'admission_record'      // 入院记录
  | 'progress_note'         // 病程记录
  | 'discharge_record'      // 出院记录
  | 'operation_record'      // 手术相关记录
  | 'examination_report'    // 辅助检查
  | 'consent_form'          // 知情同意书
```

### 6.2 规则与文书的关联

每条规则通过 `targetSections` 和 `applicableRecordTypes` 指定适用范围：

```typescript
{
  name: '入院记录完整性检查',
  targetSections: ['主诉', '现病史', '既往史', '体格检查'],
  applicableRecordTypes: ['inpatient'],
  // 该规则只适用于住院病历的入院记录
}
```

### 6.3 规则匹配逻辑

在执行质控分析时，系统会：

1. 获取选中的文书类型
2. 筛选适用于该文书类型的规则
3. 只执行匹配的规则

```typescript
const applicableRules = selectedRules.value.filter(rule => {
  // 如果规则没有指定适用范围，则适用于所有文书
  if (!rule.applicableRecordTypes || rule.applicableRecordTypes.length === 0) {
    return true
  }
  
  // 检查文书类型是否匹配
  return rule.applicableRecordTypes.includes(selectedDocument.type)
})
```

## 8. 常见问题

### Q1: 演示系统使用的是哪些规则？

**A**: 演示系统会尝试加载数据库中的真实规则（包括68条四川省规则），如果数据库不可用，则使用内置的模拟规则（10-20条）。

### Q2: 如何添加新的演示规则？

**A**: 有两种方式：
1. **数据库方式**：在 `qc_rules` 表中插入新规则
2. **代码方式**：在 `demoDataService.ts` 的 `getMockQCRules()` 方法中添加

### Q3: 规则参数配置会影响实际质控吗？

**A**: 在演示系统中，规则参数配置主要用于演示目的。实际质控分析由后端执行，参数配置可以传递给后端，但最终是否生效取决于后端实现。

### Q4: 如何确保规则与文书类型匹配？

**A**: 规则的 `applicableRecordTypes` 字段定义了适用的文书类型。在执行质控前，系统会自动筛选匹配的规则。
