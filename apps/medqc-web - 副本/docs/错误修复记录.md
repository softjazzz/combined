# 错误修复记录

## 🐛 发现的问题

在Phase 5完成后的测试中，发现了以下几个关键错误：

### 1. TypeError: _ctx.h is not a function
**错误位置**: `LLMQCDemoEnhanced.vue:56:22`
**错误原因**: 在Vue模板中使用了`h()`函数，但没有在script setup中正确导入
**修复方案**: 在script setup中添加`h`函数的导入

```typescript
// 修复前
import { ref, onMounted } from 'vue'

// 修复后  
import { ref, onMounted, h } from 'vue'
```

### 2. ReferenceError: state is not defined
**错误位置**: `qcDemo.ts:769:22` (saveDemoState函数)
**错误原因**: 在Pinia store中错误使用了`state`变量，应该使用具体的响应式变量
**修复方案**: 将所有`state.xxx`替换为对应的响应式变量`xxx.value`

```typescript
// 修复前
const stateToSave = {
  currentStep: state.currentStep,
  selectedRules: state.selectedRules,
  // ...
}

// 修复后
const stateToSave = {
  currentStep: currentStep.value,
  selectedRules: selectedRules.value,
  // ...
}
```

### 3. ReferenceError: generateId is not defined
**错误位置**: `qcDemo.ts:670:11` (simulateRandomNotification函数)
**错误原因**: 使用了`generateId`函数但没有定义
**修复方案**: 在store文件中添加`generateId`工具函数

```typescript
/**
 * 生成唯一ID
 */
const generateId = () => {
  return `id-${Date.now()}-${Math.random().toString(36).substr(2, 9)}`
}
```

## 🎯 经验总结

### 1. Vue 3 Composition API注意事项
- 在模板中使用的函数必须在script setup中导入或定义
- `h`函数用于程序化创建组件时必须显式导入
- 避免在模板中使用未导入的全局函数

### 2. Pinia状态管理最佳实践
- 在setup语法中，使用`ref()`创建的变量访问时需要`.value`
- 不要假设存在`state`对象，直接使用响应式变量
- 状态持久化时要注意响应式变量的正确访问方式

### 3. 工具函数管理
- 在store中使用的工具函数应该在store内部定义或从外部导入
- 避免使用未定义的全局函数
- 考虑将通用工具函数提取到独立的utils文件中

### 4. 错误调试技巧
- 仔细阅读错误信息中的文件名和行号
- 使用浏览器开发者工具查看完整的错误堆栈
- 逐个修复错误，避免一次性修改过多代码
