# 质控规则系统文档

## 概述

质控规则系统是医疗病案质量控制平台的核心组件，负责定义、管理和执行各种医疗质量检查规则。系统采用模块化设计，支持多种规则类型和执行方式。

## 系统架构

### 核心组件

1. **规则引擎** (`src/lib/qc-rules-engine.ts`)
   - 规则执行核心
   - 支持客观规则和主观规则
   - 集成AI分析能力

2. **规则服务** (`src/services/rules-service.ts`)
   - 规则CRUD操作
   - 批量操作支持
   - 数据验证和统计

3. **规则验证器** (`src/utils/rules-validator.ts`)
   - 规则数据完整性验证
   - 格式和逻辑检查
   - 批量验证支持

4. **规则配置** (`src/config/rules-config.ts`)
   - 规则分类和类型定义
   - 模板和配置管理
   - 权重计算规则

### 数据库结构

#### qc_rules 表
```sql
- id: UUID (主键)
- rule_code: 规则编码 (如: 1.1.1)
- name: 规则名称
- description: 规则描述
- category: 规则分类 (completeness/consistency/rationality/timeliness)
- rule_type: 规则类型 (objective/subjective/hybrid)
- severity: 严重程度 (critical/major/minor)
- max_score: 最大扣分 (0-100)
- weight: 权重 (0.1-5.0)
- check_logic: 检查逻辑配置 (JSON)
- prompt_template: AI提示模板
- is_active: 是否激活
- version: 版本号
- created_at: 创建时间
- updated_at: 更新时间
```

## 规则分类

### 1. 完整性规则 (Completeness)
检查病历记录的完整性，确保必要信息不缺失。

**特点:**
- 主要为客观规则
- 通常为单否项 (max_score = 0)
- 高优先级

**示例:**
- 患者基本信息完整性检查
- 入院记录完整性检查
- 出院记录完整性检查

### 2. 一致性规则 (Consistency)
检查病历内容的一致性，确保信息前后呼应。

**特点:**
- 混合规则类型
- 需要比较多个字段
- 中等权重

**示例:**
- 诊断一致性检查
- 时间逻辑一致性检查
- 用药与诊断一致性检查

### 3. 合理性规则 (Rationality)
检查医疗行为的合理性，确保符合医学规范。

**特点:**
- 主要为主观规则
- 需要AI分析
- 高权重

**示例:**
- 药物使用合理性检查
- 检查检验合理性检查
- 治疗方案合理性检查

### 4. 及时性规则 (Timeliness)
检查医疗行为的及时性，确保符合时间要求。

**特点:**
- 客观规则
- 基于时间计算
- 中等权重

**示例:**
- 病程记录及时性检查
- 医嘱执行及时性检查
- 检查报告及时性检查

## 规则类型

### 客观规则 (Objective)
基于明确标准的自动化检查规则。

**特征:**
- 可完全自动化执行
- 结果确定性强
- 执行速度快
- 不需要AI分析

**适用场景:**
- 字段完整性检查
- 格式验证
- 数值范围检查
- 时间逻辑检查

### 主观规则 (Subjective)
需要专业判断的评估规则。

**特征:**
- 需要AI分析
- 结果可能有主观性
- 执行时间较长
- 需要专业知识

**适用场景:**
- 医学合理性判断
- 内容质量评估
- 复杂逻辑分析
- 专业规范检查

### 混合规则 (Hybrid)
结合客观检查和主观判断的综合规则。

**特征:**
- 先进行客观检查
- 再进行主观分析
- 结果更准确
- 执行效率平衡

**适用场景:**
- 诊断一致性检查
- 治疗方案评估
- 复合条件判断
- 多维度分析

## 严重程度

### 严重 (Critical)
严重问题，可能影响医疗安全或质量。

**特点:**
- 通常为单否项 (max_score = 0)
- 最高优先级
- 必须立即处理

### 重要 (Major)
重要问题，需要重点关注和改进。

**特点:**
- 扣分范围: 5-20分
- 高优先级
- 影响质量等级

### 轻微 (Minor)
轻微问题，建议改进但不影响整体质量。

**特点:**
- 扣分范围: 1-10分
- 低优先级
- 持续改进项

## 使用指南

### 1. 初始化规则系统

```bash
# 完整初始化
npm run setup-rules-system

# 仅初始化综合规则
npm run init-comprehensive-rules
```

### 2. 规则管理界面

访问 `/rules` 页面进行规则管理：

- **查看规则列表**: 支持分类、严重程度、类型筛选
- **创建新规则**: 使用表单创建规则
- **编辑规则**: 修改现有规则配置
- **批量操作**: 批量激活、停用、删除规则
- **导入导出**: 规则配置的导入导出

### 3. 规则配置

#### 检查逻辑配置示例

**字段验证规则:**
```json
{
  "type": "field_validation",
  "required_fields": ["patient_name", "gender", "age"],
  "validation_rules": {
    "patient_name": {
      "min_length": 2,
      "max_length": 50,
      "pattern": "^[\\u4e00-\\u9fa5a-zA-Z\\s]+$"
    },
    "age": {
      "min": 0,
      "max": 150,
      "type": "integer"
    }
  }
}
```

**一致性检查规则:**
```json
{
  "type": "consistency_validation",
  "comparison_fields": ["admission_diagnosis", "discharge_diagnosis"],
  "consistency_rules": {
    "main_diagnosis_consistency": { "threshold": 0.8 }
  }
}
```

#### 提示模板配置

使用变量占位符创建动态提示模板：

```text
请检查患者基本信息是否完整，包括{fields}。
每个字段都应有实质性内容，不能为空或过于简单。

检查要点：
1. 姓名应为中文或英文
2. 年龄应在合理范围内
3. 身份证号格式应正确
```

### 4. 规则执行

规则通过QC规则引擎执行：

```typescript
import { QCRulesEngine } from '@/lib/qc-rules-engine'

// 执行单个规则
const result = await QCRulesEngine.executeRule(ruleId, recordData)

// 批量执行规则
const results = await QCRulesEngine.executeRules(ruleIds, recordData)
```

## 最佳实践

### 1. 规则编码规范
- 使用层级编码: `1.1.1`, `2.3.4`
- 第一级表示大类
- 第二级表示子类
- 第三级表示具体规则

### 2. 规则命名规范
- 使用描述性名称
- 包含检查对象和检查内容
- 避免过长或过短的名称

### 3. 权重设置原则
- 严重规则权重 > 重要规则权重 > 轻微规则权重
- 合理性规则权重 > 一致性规则权重 > 完整性规则权重
- 主观规则权重 > 混合规则权重 > 客观规则权重

### 4. 提示模板编写
- 使用清晰的检查指导
- 包含具体的检查要点
- 使用变量占位符提高复用性

## 扩展开发

### 1. 添加新的规则分类

1. 在 `rules-config.ts` 中添加新分类
2. 更新数据库枚举类型
3. 更新前端界面选项
4. 创建对应的规则模板

### 2. 自定义检查逻辑

1. 在 `qc-rules-engine.ts` 中添加新的检查类型
2. 实现对应的验证逻辑
3. 更新配置模式定义
4. 添加相应的测试用例

### 3. 集成外部系统

规则系统支持与外部系统集成：

- **HIS系统**: 获取患者基础数据
- **LIS系统**: 获取检验结果数据
- **PACS系统**: 获取影像检查数据
- **知识库**: 获取医学知识和指南

## 故障排除

### 常见问题

1. **规则执行失败**
   - 检查规则配置格式
   - 验证数据完整性
   - 查看错误日志

2. **AI分析超时**
   - 调整超时配置
   - 优化提示模板
   - 检查网络连接

3. **性能问题**
   - 优化规则查询
   - 使用批量执行
   - 启用结果缓存

### 日志和监控

系统提供详细的日志记录：

- 规则执行日志
- 错误和异常日志
- 性能监控数据
- 用户操作审计
