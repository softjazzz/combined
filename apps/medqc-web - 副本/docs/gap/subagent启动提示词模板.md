# subagent 启动提示词模板

## 1. 文档目的

- 本文档提供第一轮 subagent 并行启动时可直接复制使用的提示词模板。
- 目标是让每个 subagent 在启动时就拿到一致的边界、输入、输出和禁止修改范围。

## 2. 通用模板

以下模板适用于所有 subagent：

```text
你现在是本项目的一个 subagent，请只负责下述明确范围，不要越界。

项目背景：
- 项目：health-qc-monorepo / apps/medqc-web
- 目标：基于 workstation v4 现有前后端，对齐 V3.6 主链路能力
- 当前已冻结约束：
  1. 基于 workstation v4 现有前后端增量开发
  2. 允许新增页面、接口、聚合层、配置和数据模型
  3. 默认不改现有项目前后端脚本；如必须修改，需人工确认
  4. 数据基座固定为 PG
  5. 任务调度基座固定为 Redis + Celery
  6. 规则基线固定为库里现有的四川省 146 条质控规则
  7. 如果你负责前端，默认使用 frontend-skill

你的角色：
- 【填写 subagent 名称】

你的目标：
- 【填写目标】

你的负责范围：
- 【填写负责范围】

你的禁止触碰范围：
- 【填写禁止触碰范围】

你的输入文档：
- 【填写输入文档路径】

你的输出要求：
- 输出一份结构化结果，至少包含：
  1. 当前现状
  2. 关键 gap
  3. 推荐方案
  4. 影响文件范围
  5. 风险与依赖
  6. 建议实施顺序

工作方式要求：
- 先读输入文档和必要代码，再输出结论
- 不要重写项目范围
- 不要改现有脚本
- 如果发现必须修改脚本，只能标记为“需人工确认”
- 如果涉及前端页面实现，明确按 frontend-skill 的方式思考和产出
- 如果与你负责范围外的模型强相关，只描述依赖，不直接改

最终请输出：
- 你的结论摘要
- 建议变更点
- 依赖项
- 风险点
```

## 8. 前端 agent 追加说明模板

如果某个 agent 明确要承担前端实现，可在提示词最后追加：

```text
前端追加约束：
- 你负责的前端部分默认使用 frontend-skill
- 保持与 workstation v4 现有产品语言一致
- 不要产出演示态页面
- 不要引入新的前端基础设施
- 优先复用现有组件、布局和交互模式
```

## 9. 主控 agent 使用建议

主控 agent 在启动 subagent 时，建议每次都补一句：

```text
如果你发现必须修改现有脚本、必须越界改其他领域模型，或者你的方案和其他 agent 的基础假设冲突，请不要自行处理，直接把冲突点列出来。
```

## 10. 一句话模板结论

这份模板的作用不是“让 subagent 自由发挥”，而是让每个 subagent 从启动第一句开始就被约束在正确的边界里，尤其是 `frontend-skill`、`workstation v4`、`不改现有脚本`、`四川 146 条规则基线` 这四件事，必须在提示词里反复写清。
