## 4. 批次实施计划（A/B/C/D）

### Batch A（已完成项回填，P0）
目标：把已落地拆分与接入事实固化到交付基线，避免重复施工。

输入：
- 当前代码主干（V4/composables/components/router/api）。

输出：
- 已完成项清单与证据表（以本计划第 2 节、第 3 节为准）。
- 形成“后续只补缺口、不返工”的批次边界。

验收：
- 每条“已接入”都可定位到代码证据。
- 不与 PRD 条款编号冲突。

回滚边界：
- 文档层回滚，不影响代码。

失败判定：
- 无法给出对应代码证据的“已完成项”必须降级为“待验证/未完成”。

---

### Batch B（4.1.2 病案问题概览，高优先级，P0）
目标：补齐“当天病案问题集中点”能力，形成消息列表闭环。

实施内容：
1. 聚合层
- 将通知数据按“当天 + 问题类型 + 严重度 + 科室/病历”聚合为集中点。
- 支持集中点排序（高风险优先、数量优先、时间优先）。

2. 展示层
- 在 `WorkstationAssistPanel` 消息 Tab 增加“问题概览视图”。
- 保留未读/已读筛选与原消息明细视图。

3. 动作层
- 点击概览项可跳转对应病历与质控点处理位置。
- 保持单条已读、全部已读逻辑一致。

4. 可读性过滤
- 支持按科室、问题类型、严重度过滤。

验收指标（对应 PRD）：
- 当日问题聚合时效：P95 <= 60 秒。
- 跳转可用率：>= 99%。
- 未读状态准确率：>= 99%。

回滚边界：
- 限定在消息概览模块（composable + assist panel 视图层 + 配套接口）。

失败判定：
- 概览无法稳定聚合“当天问题集中点”。
- 跳转病历或未读计数出现明显不一致。

---

### Batch C（6.2.2 分组器本地化，必须完整交付，P0）
目标：按招标原文完成“配置工具 + 版本审计/回滚 + 一致率>=95%”闭环。

实施内容：
1. 前端改造（去 Mock 真实化）
- `GrouperConfig.vue` 由 Mock 数据改为真实 API 驱动。
- 新增能力：版本列表、发布、回滚、变更差异、当前生效版本。
- 一致率看板改为真实对照结果展示。

2. 前端 API 层
- `api/drg.ts` 新增/接入配置管理与一致率校验接口。
- 明确 Mock 仅用于开发开关，不作为验收路径。

3. 后端接口（`drg.py` 新增路由）
- 配置 CRUD：读取、保存、发布。
- 版本管理：版本列表、版本详情、回滚。
- 一致率校验：输入对照样本，输出一致率、差异明细、统计口径。
- 审计字段：版本号、操作人、操作时间、变更摘要。

4. 数据与口径
- 定义一致率对照样本集（医院/医保对照来源）。
- 固化统计公式与口径，避免验收时口径漂移。

验收指标（对应 PRD）：
- 配置工具可用性：可配置、保存、发布、回滚（现场通过）。
- 入组一致率：>= 95%（对照测试）。
- 变更可审计：记录可查、可追溯（现场通过）。

回滚边界：
- DRG 配置模块独立回滚，不影响既有分组查询页面。

失败判定：
- 仍依赖 Mock 才能运行。
- 无法回滚到指定版本。
- 无法输出可复核的一致率对照报告。

---

### Batch D（剩余“基本完成”条款统一验收与回归，P1）
目标：不改措辞，补全脚本化验证与真实数据回归，收敛交付风险。

实施内容：
- 条款覆盖：3.1.1 / 3.3.1 / 3.4.1 / 3.4.3 / 3.5.1 / 6.1.1 / 6.2.1 / 6.2.3 / 6.3.1。
- 统一回归脚本：
  - 功能冒烟（核心链路）
  - 性能与时效（P95）
  - 结果准确性抽样（PRD 指标）
- 补齐真实数据联调记录与报告模板。

验收：
- 每条“基本完成”对应至少一条自动化或半自动化验证记录。
- 输出可复用的验收记录模板与结果归档。

回滚边界：
- 以测试与验收脚本为主，不触发功能代码大改。

失败判定：
- 指标无可复核证据或结果不可复现。

## 7. 风险、约束与回滚策略

### 7.1 风险
- 风险 1：消息概览仅做“通知列表换皮”，未形成“集中点聚合”。
- 风险 2：6.2.2 前端去 Mock 后暴露后端能力缺口导致联调阻塞。
- 风险 3：一致率口径不统一导致验收争议。

### 7.2 缓解措施
- 4.1.2 先定义聚合模型，再落地 UI。
- 6.2.2 先补后端接口契约，再改前端页面。
- 提前固化一致率样本来源、统计公式、报告模板。

### 7.3 回滚策略
- 每个 Batch 独立提交，禁止跨 Batch 混改。
- 发现问题按 Batch 回滚，不做全量回退。
- Batch C 回滚需保留已发布版本快照，确保可恢复。
