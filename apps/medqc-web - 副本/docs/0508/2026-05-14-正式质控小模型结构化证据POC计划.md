# 正式质控小模型结构化证据 POC 计划

> 目的：验证“小参数模型抽取结构化证据 + 审核模型裁决”的正式质控链路是否能在保证准确性的前提下，减少大模型直接泛读病历的成本与不稳定性。本文为 POC 计划，不代表已进入正式业务链路。

## 背景

当前正式终末 `fast_screen_full / sc_content_full_v1` 已具备 84 条内涵质控能力，并完成阿里云百炼 10 病历只读抽检。现有链路大致为：

```text
规则 pack + bundle 文书上下文
  -> LLM 首审
  -> 后处理/二审裁决
  -> confirmed_defect / data_quality_gap / rejected_by_system
```

这条链路能跑通，但存在几个质量和成本问题：

- 首审模型需要阅读较长文书上下文，token 使用较高。
- 证据输入较散，模型可能抓到记录时间、文书标题、短片段等弱证据。
- 二审裁决效果受首审证据质量影响较大。
- 部分规则族需要跨文书、跨表证据，单纯 prompt 调整收益有限。

因此 POC 尝试将“证据抽取”和“质控裁决”拆开：

```text
bundle/CDM 文书
  -> 程序化切片/检索
  -> 小模型抽取结构化证据
  -> 程序化 coverage flags
  -> 审核模型裁决
  -> 四层准入分流
```

## POC 核心假设

1. 小模型更适合做证据抽取、字段归纳、JSON 填槽，不直接承担最终质控判断。
2. 审核模型只读取结构化证据包，而不是反复读取完整病历，可以降低大模型 token。
3. 规则族级别共享 evidence package，比“每条规则全病历重读”更高效。
4. 结构化证据能提升 confirmed_defect 的可解释性和可复核性。

## 非目标

- 不替换现有正式质控主链路。
- 不一次性改造 84 条规则。
- 不让小模型直接输出最终缺陷结论。
- 不为了增加缺陷数量而放宽 confirmed 准入。
- 不改 Sheet2 客户样本验证验收链路。

## POC 范围

### 首批规则族

优先选择近期误判、data gap、证据组织问题较集中的规则族：

| 规则族 | 示例规则 | POC 原因 |
| --- | --- | --- |
| 手术/病理/植入物 | SC-099、SC-100、SC-101 | 需要触发条件、手术记录、病理/耗材/植入物反证 |
| 异常检验检查处理 | SC-036 | 需要异常结果、病程分析、医嘱调整、复查闭环 |
| 会诊意见落实 | SC-070 | 需要会诊意见、病程落实、医嘱执行或反证 |
| 跨文书一致性 | SC-019、SC-083 | 需要入院、首次病程、病程、出院记录交叉对照 |

首轮建议只做 3 个 evidence package：

1. `surgery_pathology_implant_evidence`
2. `abnormal_result_followup_evidence`
3. `consultation_implementation_evidence`

### 样本范围

复用已有正式质控阿里云百炼 10 病历样本，不扩大样本：

- 保持 provider 稳定性可比。
- 可复用前一轮质量复核结果。
- 便于比较当前大模型直判链路和 POC 链路差异。

如需最小 smoke test，可先用：

- `1915580`
- `2024757`
- `2287309`

## 推荐链路

### 1. 程序化切片

从 bundle/CDM 中按规则族选取候选材料，避免小模型全病历泛读。

示例：

```text
surgery_pathology_implant_evidence:
  - surgery_record
  - postsurg_firstcourse_record
  - pathology_exam_master/report
  - surgery_inventory_record
  - inpat_bill_item
  - mr_surgery

abnormal_result_followup_evidence:
  - labtest_item_report
  - exam_item_report
  - daily_course_record
  - senior_course_record
  - inpat_drug_order
  - inpat_nondrug_order

consultation_implementation_evidence:
  - consultation_record
  - daily_course_record
  - senior_course_record
  - inpat_order
```

### 2. 小模型结构化抽取

小模型只输出 evidence package，不输出是否违规。

建议输出结构：

```json
{
  "visit_id": "1915580",
  "evidence_family": "surgery_pathology_implant_evidence",
  "trigger": {
    "status": "present | absent | unknown",
    "reason": "",
    "quotes": []
  },
  "required_evidence": [
    {
      "slot": "implant_mentioned",
      "status": "present | absent | unknown",
      "source_table": "",
      "document_title": "",
      "quote": "",
      "record_time": ""
    }
  ],
  "supporting_evidence": [],
  "contradicting_evidence": [],
  "missing_evidence": [],
  "coverage_flags": [],
  "data_quality_flags": [],
  "source_quote_quality": "strong | weak | missing"
}
```

关键约束：

- 引用必须来自输入材料，不允许编造。
- 无触发条件时 `trigger.status=absent`。
- 找不到证据时输出 `missing_evidence`，不要猜测。
- 标题、记录时间、模板小标题不能单独作为强证据。

### 3. 程序化 coverage flags

在小模型输出后增加确定性校验：

- 是否存在触发条件。
- 是否存在必需证据。
- quote 是否为空、过短或疑似只有标题/时间。
- 是否存在明确反证。
- 是否缺关键文书或关键结构化表。

这层用于防止小模型抽取质量波动直接影响二审。

### 4. 审核模型裁决

审核模型输入：

- rule_code / rule_name
- evidence package
- coverage flags
- 原有后处理准入要求

审核模型输出：

```json
{
  "rule_code": "SC-100",
  "decision": "confirmed_defect | data_quality_gap | rejected_by_system",
  "reason": "",
  "supporting_quote_ids": [],
  "missing_slots": [],
  "confidence": 0.0
}
```

裁决约束：

- `trigger=absent` 不得确认缺陷。
- required_evidence 不足时优先 `data_quality_gap`。
- 有明确反证时优先 `rejected_by_system`。
- 不允许空 reason 或无引用 confirmed。

## 对照实验设计

### Baseline

使用当前正式质控链路的既有结果：

- 阿里云百炼 10 病历只读抽检结果。
- 证据补强后质量复核结果。

### POC Run

对同一批 visit_id、同一批规则族运行：

```text
小模型 evidence extraction
  -> coverage flags
  -> 审核模型 adjudication
```

### 对比指标

| 指标 | 目标 |
| --- | --- |
| provider_error / timeout / parse_error | 必须为 0 |
| 小模型 JSON 解析成功率 | >= 95% |
| 大模型 token 使用 | 相比 baseline 下降 |
| 平均耗时 | 不高于 baseline，理想下降 |
| confirmed_defect 复核保留率 | 高于 baseline |
| data_quality_gap 可解释性 | 能定位缺文书/缺字段/缺反证/证据不足 |
| rejected_by_system 误驳回率 | 不高于 baseline |

## 风险与控制

### 风险 1：小模型抽取漏证据

控制：

- 小模型不直接裁决。
- coverage flags 标记 `source_quote_quality`。
- 审核模型可以要求 evidence package 中包含反证与 missing slots。

### 风险 2：小模型全病历重读导致更慢

控制：

- 必须先做规则族级切片。
- 每个 evidence package 服务多个规则。
- 禁止每条规则重复读取完整 bundle。

### 风险 3：结构化输出不稳定

控制：

- 使用严格 JSON schema。
- 解析失败进入 technical/internal，不进入业务结果。
- 记录 parse_error_count 和 retry_count。

### 风险 4：二审模型仍然自由发挥

控制：

- 二审 prompt 限定只能依据 evidence package。
- confirmed 必须引用 evidence slot。
- 空 quote / 空 reason 直接降级。

## 验收门槛

POC 可进入下一阶段的最低条件：

1. 10 病历稳定跑完，provider/parse/timeout 全为 0。
2. 小模型 JSON 解析成功率 >= 95%。
3. confirmed_defect 复核保留率高于当前 baseline。
4. data_quality_gap 能明确归因，而不是只有泛化描述。
5. 大模型 token 相比当前正式链路下降。
6. Sheet2 回归保持：

```text
exact_confirmed=156 / blocked_with_reason=102 / skip=25 / needs_exact_review=0
```
