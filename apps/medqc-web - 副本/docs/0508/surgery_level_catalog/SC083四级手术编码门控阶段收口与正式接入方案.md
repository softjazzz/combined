# SC083 四级手术编码门控阶段收口与正式接入方案

## 1. 背景

SC-083 关注“四级手术术前讨论是否体现多学科讨论”。此前正式质控和二轮 gate 中，存在把手术名称模糊命中、参与人员片段或“缺 MDT 字样”直接推向 confirmed 的风险。当前阶段已将判定拆成两层：

- 适用性判断：这是否是四级手术。
- 缺陷成立判断：四级手术的术前讨论是否缺少 MDT/多学科/相关专科参与和讨论结论。

本阶段只做只读验证和接入方案整理，不接正式 SC-083 主链路、不接页面、不写数据库。

## 2. 已完成验证

- 已从 `apps/medqc-web/docs/0508/三四级手术目录.pdf` 结构化生成 `surgery_level_catalog.csv/json`。
- 已实现 code-first 手术分级匹配，优先使用手术编码，不把名称 contains 当作 confirmed 依据。
- 已生成 SC-083 code gate 只读验证产物，区分行级匹配和病历级适用性。
- 已对 `2142472`、`2214679` 做保守二轮裁决：四级编码成立，但缺完整术前讨论正文/讨论结论，因此进入 `data_quality_gap`，不得 confirmed。

字段探查显示可用来源如下：

| 优先级 | 表 | 编码字段 | 名称字段 | 说明 |
|---:|---|---|---|---|

## 5. Code-first 匹配策略

匹配优先级：

1. `code_exact`：本地编码完全等于 catalog `surgery_code`。
2. `code_normalized`：大小写、空格、前导零等规范化后相等。
3. `code_prefix_ext`：编码扩展或细分命中，仅作为待核查候选。
4. `name_exact_candidate` / `name_contains_candidate`：仅作人工核查提示。

只允许 `code_exact` / `code_normalized` 命中四级作为 SC-083 适用性强证据。`code_prefix_ext`、名称候选、编码缺失或未命中都不能 confirmed。

当前匹配预检分布：

- `surgery_level_code_match_probe.csv`：141 行；`code_exact=45`、`code_normalized=3`、`code_prefix_ext=6`、`code_unmatched=67`、名称候选 16。
- `sc083_code_gated_second_pass_probe.csv`：90 行；病历级 `applicable_level4_by_code=17` 行、`not_applicable_level3_by_code=9` 行、`data_gap_code_unmatched=64` 行。

## 6. SC-083 判定矩阵

| 分支 | 条件 | 输出建议 | confirmed 说明 |
|---|---|---|---|
| 1 | `code_exact/code_normalized` 命中四级 + 完整术前讨论正文 + 参与人员证据 + 讨论结论证据 + 明确缺少 MDT/相关专科意见 | `confirmed_defect` 候选，建议仍进入二轮 LLM gate | 允许，但需可引用缺失要件和客户口径支持。 |
| 2 | `code_exact/code_normalized` 命中四级 + 只有参与人员片段，无完整讨论正文或讨论结论 | `data_quality_gap` | 不得 confirmed。 |
| 3 | `code_exact/code_normalized` 命中四级 + 术前讨论中已有 MDT/多学科/相关专科意见 | `rejected_by_system` | 缺陷不成立。 |
| 4 | 全部编码命中三级或以下 | `rejected_by_system` / `not_applicable` | SC-083 不适用。 |
| 5 | 编码缺失或编码未命中 catalog | `data_quality_gap` | 不能证明四级适用性。 |
| 6 | 仅名称候选命中四级 | `data_quality_gap` / `needs_catalog_review` | 名称候选不得 confirmed。 |
| 7 | `code_prefix_ext` 命中四级 | `data_quality_gap` / `needs_catalog_review` | 未建立可靠扩展编码规则前不得 confirmed。 |

## 8. 为什么当前不直接 confirmed

四级编码只能证明“SC-083 可能适用”，不能证明“术前讨论未多学科”。confirmed 还需要以下证据闭环：

- 完整术前讨论正文或结构化讨论结论。
- 参与人员列表。
- 讨论意见/主持人总结/风险预案等结论性内容。
- 能明确指出缺少哪些 MDT/相关专科意见。
- 客户确认的 MDT 口径：麻醉科、护理、同科上级医师是否足以构成多学科。

当前 `2142472` 和 `2214679` 只有参与人员片段，无法证明讨论正文完整，也无法证明相关专科意见确实缺失。因此应作为数据/证据缺口，而不是医生病历确认缺陷。

## 9. 正式接入建议

建议分阶段接入，先接 applicability gate 和 data gap 分流，confirmed 暂缓。

### 接入位置

- 优先作为 SC-083 二轮 gate / postprocessor 的 evidence coverage flag，不直接改主规则 prompt。
- 可在正式结果后处理层增加 `sc083_code_gate` 字段：
  - `visit_max_level`
  - `level4_match_type`
  - `level4_evidence_code`
  - `discussion_text_coverage`
  - `participant_coverage`
  - `conclusion_coverage`
  - `sc083_applicability`

### 对正式主链路的影响

- 不改变 84 条父规则数量。
- 不新增页面状态。
- 不把名称候选、编码缺失、编码未命中提升为 confirmed。
- `code_exact/code_normalized` 只作为适用性强证据，不自动判缺陷。

### 对页面展示的影响

- `data_quality_gap` 文案应解释为：已识别四级手术，但缺完整术前讨论正文/讨论结论，无法判断是否违反 SC-083。
- 避免展示为“确认缺陷”或“系统确认未 MDT”。

### 对客户沟通的解释

推荐口径：

> 系统已通过手术编码确认该病历存在四级手术，但当前可回收证据只有参与人员片段，缺少完整术前讨论正文和讨论结论。四级适用性成立不等于缺陷成立，因此当前按数据/证据缺口处理，待补齐术前讨论全文或客户确认 MDT 口径后再裁决。

## 10. 风险与待确认客户口径

- 手术编码体系是否与 PDF catalog 完全同源：`code_prefix_ext` 暂不能自动强判。
- 复合手术中任一四级编码是否触发 SC-083：当前建议触发适用性。
- 麻醉科、护理、同科上级医师是否满足“多学科”：需客户明确。
- 不同手术类型需要哪些相关专科：不能泛称“其他临床专科”，需有规则口径或结构化映射。
- 术前讨论正文完整性判断需要稳定文书字段或 bundle coverage。
