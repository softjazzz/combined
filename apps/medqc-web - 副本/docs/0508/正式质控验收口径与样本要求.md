# 正式质控验收口径与样本要求

生成时间：2026-05-09

## 背景结论

当前正式质控链路已经具备运行、并发、异常重试和结果分层能力，但当前小样本不能作为正式质控准确率验收集。关键原因是：Sheet2 历史人工质控问题对应的病历可能已经被医生修改，当前 PG/bundle 中的病历现状不再等同于人工质控当时的病历快照。

因此，当前病历未报出历史问题，不一定是漏报；当前病历报出其他问题，也不一定能和 Sheet2 历史问题一一对应。

## 三条链路边界

### 1. 客户样本验证页 / Sheet2 acceptance package

- 目标：验证历史人工质控样本能否被规则和证据链复现。
- 输入：Sheet2 人工问题、样本验证 ledger、exact review matrix、acceptance package。
- 输出：`exact_confirmed` / `blocked_with_reason` / `skip`。
- 适用问题：客户问“为什么这条人工问题系统能或不能复现”。
- 边界：不代表正式运行时对当前病历现状的实时质控结果。

当前 Sheet2 acceptance package 状态：`exact_confirmed=156`、`blocked_with_reason=102`、`skip=25`、`needs_exact_review=0`。其中 `blocked_with_reason` 表示已复核但当前规则/证据链不能精确复现人工问题原文，不是未完成。

### 2. 正式 final fast_screen 全量质控

- 目标：对当前本地 PG/bundle 中的病历现状做正式质控。
- 输入：当前 CDM 数据、bundle 证据、正式 final `fast_screen_full` 规则包。
- 输出：确认缺陷 / 待复核 / 数据缺口 / 内部技术异常。
- 适用问题：当前病历是否仍存在质量问题，输出是否有证据且能被医生/质控科接受。
- 边界：如果医生已修改病历，历史问题不应再强求出现。

### 3. 历史人工问题对照

- 目标：分析历史人工问题与当前病历现状是否一致。
- 必须区分：当前仍存在、已被医生修改、源文书/快照缺失、人工问题不可判。
- 适用问题：解释历史人工结论与当前系统结果差异。
- 边界：不能直接作为正式质控准确率验收。

## 正式质控准确率验收样本要求

如果要验收正式质控准确率，必须使用以下样本之一。

### A. 冻结病历快照

- 在人工质控当时导出或冻结 CDM 文书、结构化字段和 bundle。
- 系统和人工看到同一份病历。
- 适合做严格召回率、准确率和证据复现验收。

### B. 当前仍存在缺陷的样本

- 客户明确标注当前病历仍未修改，缺陷仍存在。
- 可用于评估实时质控召回。
- 需要保留关键原文截图或源表字段，避免“已修改”争议。

### C. 标准化构造样本

- 构造少量标准病历，明确植入缺陷。
- 适合回归规则、证据链、后处理准入层和页面展示。
- 不适合代表真实线上分布，但适合做可重复验收。

### D. 当前线上病历抽检

- 不对照历史 Sheet2。
- 只看当前系统输出是否有证据、是否可被质控员接受。
- 适合评估正式质控当前运行效果、误报风险和人工复核工作量。

## 当前已经完成的能力

- `sample_full_domain` 数据同步链路：客户样本同步不再只依赖核心 8 表，关键文书、诊断、医嘱、检查检验、手术等证据域已纳入。
- bundle 证据链：running/final/domain bundle 已能覆盖正式质控和样本验证所需的主要文书域。
- final `fast_screen_full` pack 并发：正式 final fast_screen 已从 pack 串行改为默认 `pack_concurrency=3`。
- provider 异常自动重试：失败 pack 后台自动重试 1 次，重试成功则替换异常结果；重试失败才进入内部技术异常。
- 后处理准入层：LLM 快筛输出已分层为确认缺陷、待复核、数据缺口、内部技术异常，不再把所有 `non_compliant` 直接展示为医生缺陷。
- 证据补强回放能力：已能从 `needs_review` 中选取候选并回放 bundle/structured_context 证据，验证证据构造器方向。

## 当前不能下的结论

- 不能用已被医生修改的当前病历判断正式质控漏报。
- 不能把 Sheet2 `blocked_with_reason` 当作正式质控失败。
- 不能用当前小样本 `confirmed_defect=0` 说明系统没有发现缺陷的能力。
- 不能把 Sheet2 历史人工问题和正式 final fast_screen 当前输出强行一一对应。

## 当前可以下的结论

- 正式运行链路可跑通。
- pack 并发后，单病历正式质控速度已进入可用区间。
- provider 偶发异常可在后台按失败 pack 自动重试。
- 结果已支持分层，技术异常、数据缺口和证据不足不会被包装成医生确认缺陷。
- 准确率验收需要冻结样本、当前仍存在缺陷的样本、标准化构造样本，或按当前线上病历抽检口径独立验收。

## 建议验收路径

1. 技术演示：使用当前正式 final fast_screen，展示 bundle、并发、重试、分层输出。
2. 准确率验收：由客户提供冻结快照或确认“当前仍存在缺陷”的病历清单。
3. 证据验收：对每条确认缺陷要求输出触发证据、缺陷证据、对照证据和原文引用。
4. 线上抽检：不引用 Sheet2 历史问题，按当前病历现状由质控员标注 accurate / acceptable / false_positive / evidence_insufficient。
