# 病案首页生成招标功能实现说明

## 本次实现范围

本次不重写首页生成系统，在既有 `frontpage` 抽取与 `settlement` 组装链路上扩展 M1 可运行闭环：

- 输入：`medical_text`、`documents` 或 `visit_id` 文书 bundle。
- 输出：卫健委病案首页草稿、医保结算清单草稿、字段覆盖报告、warnings。
- 场景：`nhc_frontpage`、`insurance_settlement`、`combined`。
- 前端：正式工作台“粘贴病历生成首页”入口支持场景选择，默认联合草稿。

## 后端接口

新增接口：

```text
POST /api/v1/frontpage/generate-report-draft
```

请求字段：

- `medical_text`：整份病历文本，优先级最高。
- `documents`：文书列表，优先级次之。
- `visit_id`：从 CDM 聚合真实文书 bundle；若无文书则返回输入错误，不再静默使用 demo。
- `patient_id`：用于医保结算清单 SQL 补充。
- `scene`/`report_scene`：生成场景，支持 `nhc_frontpage`、`insurance_settlement`、`combined`。

响应字段：

- `scene`：实际生成场景。
- `frontpage`：病案首页结构化草稿。
- `settlement`：医保结算清单草稿；仅医保/联合场景生成。
- `coverage`：招标字段覆盖报告。
- `warnings`：缺失字段、部分生成等提示。

旧接口 `/api/v1/frontpage/auto-generate-draft` 保持兼容，新增 `scene/report_scene` 仅作为兼容字段，不改变旧调用行为。

## Schema 扩展

`FrontPageDraft` 保留既有字段，同时在原分组内扩展结构化字段：

- `diagnoses.ed_diagnoses`
- `diagnoses.discharge_main_diagnosis`
- `diagnoses.discharge_other_diagnoses`
- `diagnoses.tcm_diagnoses`
- `diagnoses.admission_condition_details`
- `procedures.main_procedure`
- `procedures.other_procedures_structured`
- `other_medical_info.pathology`
- `other_medical_info.injury_poison`
- `other_medical_info.allergy`
- `other_medical_info.blood_type`
- `other_medical_info.ventilation`
- `other_medical_info.icu`
- `other_medical_info.coma`

诊断、手术、病理、损伤中毒外因均预留 `candidates/confidence/evidence`，其中 evidence 支持 `source_document/source_text/confidence/reason`。

## 抽取与后处理

统一生成服务 `FrontPageReportGenerationService` 复用既有 `FrontPageExtractionService.extract_from_text(..., context_strategy="full")`。

后处理层 `augment_frontpage_for_report` 负责：

- 由旧字段生成结构化诊断、手术、其他医疗信息。
- 保留每条诊断的入院病情推理结果。
- 将 ICD 候选转换为结构化 `candidates`。
- 为覆盖报告和结算清单提供稳定结构。

`visit_id` 输入优先走真实 CDM 文书上下文 `_get_llm_context_text`，没有文书时返回错误，避免“success 但 demo 空壳”。

## 医保结算清单映射

`SettlementAssemblyService` 已扩展为优先消费新结构化字段：

- 诊断列表优先使用 `discharge_main_diagnosis`、`discharge_other_diagnoses`，逐条保留 `admission_condition`。
- 手术列表优先使用 `main_procedure`、`other_procedures_structured`，输出术者/I助/II助/麻醉医师姓名和代码、切口愈合、麻醉方式。
- 其他医疗信息映射血型、病理、损伤中毒外因、ICU、呼吸机、昏迷时间等字段。

## 前端入口

正式工作台病案首页区域的“粘贴病历生成首页”弹窗新增场景选择：

- 联合草稿
- 病案首页
- 医保清单

生成后仍使用现有 `FrontpageWorkspacePanel` 展示首页草稿，并在病案首页区域显示覆盖状态、缺失数量和 warnings 摘要。

## 测试覆盖

新增 `test_frontpage_report_generation_service.py` 覆盖：

- `medical_text -> frontpage + settlement + coverage`
- `documents` 输入拼接
- `visit_id` 真实文书 bundle 聚合和缺文书错误
- 结构化诊断逐条入院病情映射
- 结构化手术字段映射到结算清单
- scene 别名兼容和非法场景错误

## 后续分阶段建议

M1 已形成可运行闭环，但完整招标交付仍建议继续推进：

- M2：将 prompt 进一步拆为诊断、手术、其他医疗、费用、人员多模块，并让 LLM 直接输出新结构。
- M3：补外部原因、病理、手术编码的本地候选和 LLM fallback 质量评估。
- M4：前端扩展完整字段覆盖明细、evidence 折叠表格和医保清单草稿工作区联动。
