# 正式质控P0子锚点前端接入验收

生成时间：2026-05-09

## 接入范围

- 后端 API：`POST /api/v1/qc/sichuan/evaluate-bundle`，当前响应对象原样透传 `subitem_anchor_results` 与父规则 `metadata.subitem_anchors`，未发现 serializer 丢字段。
- 前端 DTO/映射：`src/views/workstation-v4/utils/structuredQc.ts`，新增 `StructuredQCSubitemAnchor` 映射，保留 `anchor_id/subitem_name/anchor_evidence/anchor_decision_reason/display_status/display_bucket/can_show_as_defect/internal_only`。
- 前端页面：`src/views/workstation-v4/components/ContentQCTab.vue`，在内涵质控结果中以父规则附属信息和“专项检查项”入口展示。

## 展示口径

- `needs_review` 展示为“专项检查项（待复核）”。
- `data_quality_gap` 展示为“数据缺口”。
- 子锚点不展示为“确认缺陷”，`can_show_as_defect=false` 时不计入缺陷/问题数量。
- 字段缺失时默认不渲染子锚点列表，页面保持兼容。

## 验收结论

- 子锚点字段可从 API 映射到前端结构，不会在 DTO 层丢失。
- 父规则 `metadata.subitem_anchors` 可在父规则卡片和详情弹窗中作为轻量附属信息展示。
- 顶层 `subitem_anchor_results` 可通过摘要卡片“专项检查项”入口查看，不改变父规则数量。
- 本轮未改 Sheet2 acceptance package；Sheet2 回归保持 `exact_confirmed=156 / blocked_with_reason=102 / skip=25 / needs_exact_review=0`。

## 风险与后续

- 当前仅完成最小展示验收，尚未接入缺陷导出/整改任务流。
- 若后续进入正式页面发布，建议继续保持“待复核/数据缺口”分层，不进入确认缺陷数量和医生整改任务。
