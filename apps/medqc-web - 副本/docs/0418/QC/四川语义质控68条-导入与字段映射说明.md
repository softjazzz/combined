## 四川省住院病历语义质控 68 条

本文档说明本系统中“四川省住院病历语义质控规则清单（68条）”的来源、导入流程、字段映射策略，以及如何在 Supabase 中验证。

### 1. 规则来源与文件

- 源文档：`docs/四川省住院病历语义质控规则清单.md`
- 转换脚本：`/scripts/convert_sichuan_rules_md_to_json.py`
- 转换输出：`/tmp/sichuan_rules.json` 与 `/tmp/sichuan_rules_body.json`
  - 其中 `/tmp/sichuan_rules_body.json` 结构为：
    ```json
    {
      "rules": [ { …68条规则… } ]
    }
    ```

### 2. 导入入口

使用后端 API：

```bash
POST /api/semantic-rules/import
Content-Type: application/json
--data-binary @/tmp/sichuan_rules_body.json
```

接口已内置字段映射与校验，能自动适配数据库约束并做“更新或插入”。

### 3. 字段映射与数据库关联

目标表：`public.qc_rules`

| 源字段（JSON）        | 说明                  | 目标字段（qc_rules） | 备注                      |
| --------------------- | --------------------- | -------------------- | ------------------------- |
| rule_code             | 规则编码（如 SC-001） | rule_code            | 唯一键，用于更新/去重     |
| name                  | 规则名称              | name                 | 必填                      |
| description           | 规则描述              | description          | 可空                      |
| category              | 分类（中文/英文）     | category             | 映射见下                  |
| defect_level/severity | 缺陷级别（中文/英文） | severity             | 映射见下                  |
| rule_type             | 规则类型（可空/别名） | rule_type            | 映射见下                  |
| complexity            | 复杂度（元信息）      | —                    | 暂未入库（可放 metadata） |
| applicable_documents  | 适用文档（数组）      | —                    | 暂未入库（可放 metadata） |
| medical_domain        | 医学领域（字符串）    | —                    | 暂未入库（可放 metadata） |
| is_active             | 启用                  | is_active            | 默认 true                 |
| version               | 版本                  | version              | 统一字符串，如 "1.0"      |
| metadata              | 元信息（JSON）        | metadata             | 可选                      |

数据库必填：`rule_code`, `name`, `category`, `check_logic`, `created_by`。
导入时 `check_logic` 自动补为 `{}`，`created_by` 若表中存在用户会自动补入（否则需手动提供）。

#### 3.1 分类（category）映射

数据库允许值：`completeness | accuracy | timeliness | consistency | compliance`

映射策略（节选）：

- 中文包含“完整/缺失/齐全” → `completeness`
- 中文包含“一致/对应/吻合/语义” → `consistency`
- 中文包含“合理/不当/适宜/准确/正确” → `accuracy`
- 中文包含“时效/及时/延迟/时间” → `timeliness`
- 中文包含“合规/规范/遵循/依从” → `compliance`

#### 3.2 缺陷级别（severity）映射

数据库允许值：`critical | major | minor`

映射策略（节选）：

- 中文包含“致命/危急/紧急” → `critical`
- 中文包含“严重/重大/较大” → `major`
- 中文包含“一般/轻微/次要/3分/2分/1分” → `minor`

#### 3.3 规则类型（rule_type）映射

数据库允许值：`logical | semantic | hybrid`

映射策略（节选）：

- 倾向主观语义/需 LLM 推理（subjective/llm/ai/nlp/gpt/chatgpt） → `semantic`
- 明确规则/正则/模式匹配（objective/rule/regex/pattern） → `logical`
- 其他/混合 → `hybrid`（必要时）

### 4. 导入后验证

在 Supabase SQL 控制台验证：

```sql
-- 总数
select count(*) from public.qc_rules;

-- 四川68条
select count(*) from public.qc_rules where rule_code like 'SC-%';

-- 抽样查看
select rule_code, name, category, rule_type, severity
from public.qc_rules
where rule_code like 'SC-%'
order by rule_code
limit 10;
```

### 5. 常见问题

- 422/400 错误：多为 `page_size` 超限或分类/级别/类型枚举不匹配。
- `created_by` 为空：给 `user_profiles` 插入一个用户或在导入记录里显式提供。
- 统计为 50：前端接口分页默认 50，已在视图中通过 `count` 字段显示总数。
