## 3. 遗留问题清单

### 3.1 `final` 全量质控入口当前实际落成了“瘦 record 评估”，不是“final bundle 全量评估”

现象：

- 对已出院病历发起样本批次时，系统先按 `pool.scene=running` 调 `collect_records(scope="running")`。
- `collect_records()` 的 `running/final` 划分完全依赖 `MedicalRecordFrontpage` 是否存在出院时间。
- 已出院病历在这里自然取不到 `running` 记录，于是样本池入口会回退到 `scope="all"`。
- 但后续 batch 执行侧只有在 `current_scope == "final"` 时才会走 `final bundle` 一次性评估；当 `scope = "all"` 时，不会加载 bundle，而是直接回退成 `evaluate_document(medical_text)`。
- `collect_records(scope="all")` 返回的又只是前台首页瘦 record，`medical_text` 基本来自 `MedicalRecordFrontpage.record_content`，很多病例这里正文为空或极短。

因此当前问题不是“回退到 final”，而是：

- 名义上在做 `final` 全量质控
- 实际拿到的却是一条瘦 `record`
- 没有真正使用 `final_record_bundle` 里的全量病程、查房、会诊、辅助检查上下文

已确认案例：

- 真实批次 `job_id = 58bf98e6-e57d-45b2-9714-5dd3658f9f3e`
- 代表样本：
  - `2104525`
  - `2188335`
  - `2207717`
  - `2286345`

影响：

- 样本池官方入口还不能稳定复现“final 全量病历质控”。
- 很多本应属于 `final` 口径的问题点，当前只能通过 `running/final bundle` 直评验证，不能直接通过样本池正式批次稳定验收。
- 这会导致：
  - `SC-036` 这类依赖病程上下文的规则吃不到完整正文
  - 会诊、上级查房等运行期问题在终末全量质控入口下仍然召回不稳定

建议动作：

- 不要让样本池批次在 `running` 取不到时回退到 `scope="all"`。
- 对已出院病历，应直接切到 `scope="final"`，并强制走 `final_record_bundle` 评估路径。
- 更稳的做法是：样本池执行入口不要再把 `scope` 当成唯一证据入口，而是按病历逐条解析：
  - 在院病历优先 `running bundle`
  - 出院病历优先 `final bundle`
  - `all` 只保留给列表检索，不用于语义批量评估
- 同时补一条保护：
  - 若 `scope=all` 且命中病历存在 `institute_id/patient_id/visit_id`，应优先尝试 bundle，而不是直接退成长文本首页 record

### 3.2 异常检查结果结构化抽取仍不兼容客户瘦表

现象：

- 当前 `exam_attention_report / lab_attention_report` 依赖较完整的结构化检查检验明细。
- 客户本地 `cdm.labtest_item_report` 字段非常瘦，缺少标准异常判定字段。
- 导致很多样本：
  - 没有 `lab_attention_report`
  - 没有 `exam_attention_report`
  - `timeline_facts` 里没有异常检查项

已确认案例：

- `2311318 / 范永勤`
  - `running bundle` 中：
    - `lab_attention_report = 0`
    - `exam_attention_report = 0`
    - 检验异常 `timeline_facts = 0`

影响：

- `SC-036` 很多时候只能退化为读病程正文，而不是“先抓异常项，再检查是否分析”。
- 命中的异常点可能与人工标注问题不完全一致。

建议动作：

- 为客户机瘦表增加兼容抽取：
  - 从 `labtest_master`
  - 或 `record_content`
  - 或 bundle 已装配文书正文
    解析出候选异常项。
- 形成“结构化异常摘要兜底层”，而不是只依赖标准明细列。

### 3.3 `Sheet2` 人工问题文本与系统实际命中证据仍存在偏差

现象：

- 部分样本能命中同一家族规则，但命中的具体证据点并不是人工问题文本原本指出的那一个。

已确认案例：

- `2311318 / 范永勤`
  - 人工问题：`4.7检验结果肾功异常，病程记录未分析，未请相应科室会诊`
  - 当前系统稳定命中的主证据：
    - `ESR`
    - `PCT`
    - `CRP`
  - 并不是 `UA 381μmol/L` 这条“肾功异常”本身

影响：

- 当前可证明“规则家族命中”，但还不能证明“完全复现人工问题原句”。
- 后续如果做召回率核算，需要区分：
  - `same_family_hit`
  - `same_evidence_hit`

建议动作：

- 在回归清单里增加命中类型标记：
  - `exact_hit`
  - `same_family_hit`
  - `mismatch`
- 不要把“同家族命中”直接等价成“完全还原人工问题”。

### 3.4 会诊闭环规则 `SC-070` 与 `LX-016` 判定口径不完全一致

现象：

- 第一批语义映射里，会诊执行闭环目前同时挂到：
  - `SC-070`
  - `LX-016`
- 真实样本上，两条规则可能给出不同结论。

已确认案例：

- `2188335 / 黄显秀`
  - 问题：`遵会诊意见，但实际并未按照会诊意见执行`
  - 当前结果：
    - `SC-070 = non_compliant`
    - `LX-016 = compliant`

影响：

- 会诊执行闭环家族当前存在规则重叠但结论不一致的问题。
- 如果直接拿两条规则同时出结果，联审侧会出现解释冲突。

建议动作：

- 明确 `SC-070` 与 `LX-016` 的边界：
  - 一条管“会诊记录完整性”
  - 一条管“会诊意见执行闭环”
- 或在样本验证链路里暂时只保留一条作为主判定规则。

### 3.5 上级查房“复制粘贴/代写异常”已迁移到复制粘贴专项

现象：

- 这类问题不再继续用 `SC-050` 泛语义承接，已经迁移到新专项：
  - `issue_category = unreasonable_copy_content`
  - `CL-275 = 2 次以上病程/查房记录完全相同或高度重复`
- 当前旧链路里，`SC-050` 会继续保留“无病情分析 / 无诊疗意见 / 每周无上级查房 / 教学病历未体现新进展”这些原始省标口径。

已确认案例：

- `2207717 / 邹才林`
  - 人工问题：`2月4日副主任医师查房记录与2月3日主治医师查房记录复制粘贴严重（相识度100%）`
  - 当前结果：
    - 历史 `SC-049 = compliant`
    - 历史 `SC-050 = compliant`
    - 新专项 `CL-275` 为后续主承接规则
  - 说明：复制粘贴问题已从旧 `SC-050` 家族迁出，不再要求 `SC-050` 继续稳定命中此类样本。

影响：

- 旧问题“`SC-050` 没有真正稳定抓到复制粘贴本身”已不再作为阻塞项。
- 当前剩余工作转为：继续验证新专项 `CL-275` 的程序信号与样本回归基线。

建议动作：

- 后续只在新专项里继续增强：
  - 相邻/回看窗口内查房记录正文覆盖率
  - 首程病例特点 vs 入院记录
  - 首程拟诊讨论 vs 病例特点
  - 同科同病种拟诊讨论模板化检测
- 不再继续扩展 `SC-050` 去承担“复制粘贴严重”专项判断。

- 当前回归已经能证明某些样本是“已评估且合规”。

  - `SC-049 = compliant`

建议动作：

  - 已命中规则数
  - 合规规则数
  - 不合规规则数
  - `uncertain` 数

## 4. 建议优先级

建议按下面顺序推进：

1. 修样本池真实批次入口，保证终末全量质控时真正走 `final bundle`，而不是瘦首页 record。
2. 做客户瘦表兼容的异常检查抽取，提升 `SC-036` 及相关规则的证据一致性。
3. 收口会诊闭环家族规则，解决 `SC-070 / LX-016` 结论不一致。
4. 新增“查房复制粘贴/高度重复”专项规则。
5. 继续从 `Sheet2` `manual_review` 池中拆第二批可执行规则。
