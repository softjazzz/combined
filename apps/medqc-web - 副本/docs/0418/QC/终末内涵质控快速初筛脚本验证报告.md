# 终末内涵质控快速初筛脚本验证报告

## 1. 目的

在不修改主链路代码的前提下，通过独立脚本验证“终末内涵质控双轨 POC”中的快速初筛轨是否成立。

本次验证只关注三个问题：

1. 按文书域与判断层次固定分包，是否能显著降低耗时与 token。
2. 去掉 `fallback / single retry / selective refine` 后，结果是否仍具备业务可读性。
3. `qwen3.5-35b-a3b` 与 `qwen3.6-35b-a3b` 在该模式下是否存在明显差异。

---

## 2. 验证方式

使用独立脚本：

- `apps/medqc-web/backend/scripts/run_final_qc_fast_screen_poc.py`

执行特征：

- 不修改主系统执行逻辑
- 不走现有 orchestrator 的回退链路
- 禁用：
  - `fallback`
  - `single retry`
  - `selective refine`
- 批量输出模式：`minimal`
- 每个包只跑一次

固定分包如下：

1. 首次病程记录-病例特点包
   - `SC-023`
   - `SC-024`
2. 首次病程记录-诊断计划包
   - `SC-025`
   - `SC-026`
   - `SC-027`
3. 日常病程记录包
   - `SC-032`
   - `SC-033`
   - `SC-036`
4. 出院记录包
   - `SC-121`
   - `SC-122`
   - `SC-123`
   - `SC-125`

## 4. 总体结果

### 4.1 总表

| 样本         |            模型 | 墙钟时间 | 总 token | prompt token | completion token | completion 占比 | 第一轮最早返回 | 第一轮平均返回 |
| ------------ | --------------: | -------: | -------: | -----------: | ---------------: | --------------: | -------------: | -------------: |
| 2248248      | qwen3.5-35b-a3b |  14.985s |    16908 |        15499 |             1409 |           8.33% |          3.03s |          3.69s |
| 2248248      | qwen3.6-35b-a3b |    8.03s |    16957 |        15499 |             1458 |           8.60% |          1.52s |          1.96s |
| MV2-REAL-001 | qwen3.5-35b-a3b |  15.863s |    16153 |        14726 |             1427 |           8.83% |          2.51s |          3.90s |
| MV2-REAL-001 | qwen3.6-35b-a3b |   8.741s |    16172 |        14726 |             1446 |           8.94% |          1.70s |          2.11s |

### 4.2 直接结论

1. 快速初筛模式成立。
   - 两份病历、两个模型都能稳定落在 `8~16s` 内完成。
2. token 显著下降。
   - 总 token 稳定在 `1.6~1.7 万`
   - 相比当前主链路 `8 万+ token` 有明显下降。
3. 主要瓶颈不是输出。
   - completion token 只占总量 `8%~9%`
   - 当前时延主要仍受输入规模和回退链路影响。
4. 在快速初筛模式下，`qwen3.6-35b-a3b` 明显快于 `qwen3.5-35b-a3b`。

## 6. POC 视角的判断

### 6.1 已被验证成立的点

1. “按文书域 + 判断层次固定分包”是可行的。
2. “不做 fallback / retry / refine”可以显著压缩时间与 token。
3. 快速初筛模式下，模型输出更像“疑点发现”而非“最终裁决”，这符合双轨 POC 的目标。
4. `qwen3.6-35b-a3b` 当前更适合作为快速初筛默认模型。

### 6.2 仍需保留的判断

1. 这套模式不适合直接替代主链路做最终裁决。
2. 首次病程相关规则仍有较高灰度，尤其：
   - `SC-023`
   - `SC-024`
   - `SC-027`
3. `SC-123` 是当前最稳的硬问题候选。
4. `SC-121`、`SC-026` 在不同病历/模型上仍有波动，更适合放在待复核层。

## 7. 建议

### 7.1 快速初筛轨

默认采用：

- 模型：`qwen3.6-35b-a3b`
- 分包：
  - `SC-023 + SC-024`
  - `SC-025 + SC-026 + SC-027`
  - `SC-032 + SC-033 + SC-036`
  - `SC-121 + SC-122 + SC-123 + SC-125`
- 禁用：
  - `fallback`
  - `single retry`
  - `selective refine`

### 7.2 结果口径

- 首轮结果定位为：
  - `non_compliant`：明确问题
  - `uncertain`：待复核疑点
  - `compliant / not_applicable`：其余结果

### 7.3 当前不建议做的事

- 不建议把这条快速初筛轨直接改造成最终裁决链路
- 不建议在 POC 阶段重新引入大规模 fallback/refine
- 不建议在没有更多病历的情况下继续过度追求单条规则硬判

---

## 8. 最终结论

本次脚本验证已经足够支持进入“双轨 POC”的实施阶段：

1. **快速初筛轨是成立的**
   - 时间从分钟级降到秒级
   - token 从 `8 万+` 降到 `1.6~1.7 万`
2. **主瓶颈判断已经被验证**
   - 当前主问题是重复输入，而不是输出过长
3. **模型建议**
   - 快速初筛默认模型优先选 `qwen3.6-35b-a3b`
4. **产品定位要清楚**
   - 快速初筛 = 疑点发现引擎
   - 不是最终裁决引擎
