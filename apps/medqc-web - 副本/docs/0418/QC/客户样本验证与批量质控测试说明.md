# 客户样本验证与批量质控测试说明

## 1. 文档目的

本文档用于规范 `workstation-v4 / 客户样本验证` 功能的测试范围、执行步骤、用例清单与验收标准，确保以下链路在客户现场和研发联调环境中可重复验证：

- 客户模板导入
- 样本病历定向同步
- 真实病历池聚合
- 勾选部分病历发起内涵批量质控
- 病历级并发执行
- 任务进度展示
- 病历原文查看
- 质控结果查看

本文档面向：

- 研发自测
- 现场联调
- 客户验收演示

## 2. 测试范围

### 2.1 本轮纳入范围

- 场景：运行病历
- 页面：`/workstation-v4/customer-sample-validation`
- 模板导入：`住院号 / visit_id / 存在问题`
- 样本池到真实病历池聚合
- 按样本池定向同步病历到本地 PG
- 运行病历内涵质控批量执行
- 勾选部分真实病历发起质控
- 病历级并发数设置：`1 / 2 / 4`
- 同步任务与质控任务进度展示
- 病历联审详情抽屉查看原文

### 2.2 本轮不纳入范围

- 程序化时效规则的准确性验证
- 全院/全科室全量同步压测
- 终末病历主链路回归
- 客户全部历史问题与 LLM 命中率统计分析
- 复杂权限隔离与多租户验收

## 3. 前置条件

执行测试前，需满足以下条件：

### 3.1 系统环境

- 前端可正常访问
- 后端服务可正常访问
- 本地 PG 可正常连接
- 数据库迁移已执行到当前 head

建议启动方式：

```powershell
# 窗口1：后端
cd D:\medqc\medqc-web-customer-<版本号>\backend
py -3.10 -m alembic -c .\alembic.ini upgrade head
py -3.10 -m uvicorn app.main:app --app-dir . --host 0.0.0.0 --port 8001

# 窗口2：前端
py -3.10 D:\medqc\medqc-web-customer-<版本号>\tools\serve_dist_spa.py --host 0.0.0.0 --port 3000 --dir D:\medqc\medqc-web-customer-<版本号>\frontend\dist --api-target http://127.0.0.1:8001
```

### 3.2 数据条件

- 客户样本模板可获取
- 当前环境可以访问客户同步源数据库
- 当前样本池中的病历在源数据库存在

### 3.3 样本模板要求

模板最小字段：

- `住院号`
- `visit_id`
- `存在问题`

其中：

- `住院号` 与 `visit_id` 二选一至少填写一列
- `存在问题` 可为空

## 4. 测试对象说明

### 4.1 样本池

样本池是客户导入的一批病历验证集合，用于承接 Excel 模板导入内容。

### 4.2 真实病历池

真实病历池是样本池经过：

- 主键识别
- 住院号 / visit_id 映射
- 聚合

之后形成的病历级视图。前端主操作对象应为真实病历，而不是样本行。

### 4.3 任务类型

本轮涉及两类后台任务：

1. 样本病历同步任务
2. 内涵批量质控任务

## 5. 标准操作流程

建议按以下顺序执行：

1. 导入客户模板
2. 刷新样本池
3. 同步样本病历
4. 执行病历匹配
5. 在真实病历池中勾选部分病历
6. 设置并发病历数
7. 发起内涵验证
8. 查看任务进度
9. 查看病历原文
10. 查看质控结果

## 6. 测试用例清单

### 6.1 模板导入

#### TC-01 只填住院号导入

- 输入：仅填写 `住院号`
- 预期：
  - 导入成功
  - 样本池生成
  - 不因 `存在问题` 为空而失败

#### TC-02 只填 visit_id 导入

- 输入：仅填写 `visit_id`
- 预期：
  - 导入成功
  - 样本池生成

#### TC-03 同时填写住院号和 visit_id

- 输入：同时填写两列
- 预期：
  - 导入成功
  - 后续匹配优先使用能命中真实病历的标识

#### TC-04 模板格式错误

- 输入：缺失全部关键列
- 预期：
  - 导入失败
  - 页面给出明确错误提示

### 6.2 真实病历池聚合

#### TC-05 同一病历多条样本聚合

- 输入：多条样本对应同一份病历
- 预期：
  - 前端列表只显示一份真实病历
  - `关联人工问题数` 正确
  - 问题摘要不为空

#### TC-06 未匹配病历显示

- 输入：源库不存在对应住院号
- 预期：
  - `匹配状态 = unmatched`
  - 不可执行

### 6.3 样本病历同步

#### TC-07 只同步当前样本池病历

- 操作：点击 `同步样本病历`
- 预期：
  - 只同步当前样本池病历
  - 不按科室或全院整批拉取

#### TC-08 同步任务进度展示

- 操作：执行同步
- 预期：
  - 页面显示：
    - 当前阶段
    - 可同步病历数
    - 已完成表数 / 总表数
    - 当前同步表
    - 已拉取行数
    - 已写入行数

#### TC-09 同步后 bundle 状态更新

- 预期：
  - 病历同步完成后
  - `running bundle` 状态更新为可用

### 6.4 病历匹配

#### TC-10 执行病历匹配

- 操作：点击 `执行病历匹配`
- 预期：
  - 能回写 `institute_id / patient_id / visit_id`
  - 匹配状态更新正确

### 6.5 批量质控执行

#### TC-11 全量可执行病历验证

- 操作：不勾选任何病历，直接发起验证
- 预期：
  - 系统自动选择全部可执行病历

#### TC-12 勾选部分病历验证

- 操作：勾选 2~3 份病历后发起验证
- 预期：
  - 仅选中的真实病历被纳入本次任务

#### TC-13 勾选不可执行病历

- 操作：勾选未匹配/未同步/bundle 未就绪病历
- 预期：
  - 页面提示这些病历将被跳过
  - 若全部不可执行，则不发任务

#### TC-14 并发病历数设置

- 操作：分别选择 `1 / 2 / 4`
- 预期：
  - 后端收到 `max_parallel_records`
  - 任务按对应病历级并发执行

#### TC-15 任务进度展示

- 预期：
  - 页面显示：
    - 已处理病历数
    - 总病历数
    - 剩余病历数
    - 规则执行进度

### 6.6 病历查看与结果查看

#### TC-16 查看病历原文

- 操作：点击 `查看病历`
- 预期：
  - 打开病历联审详情风格抽屉
  - 可查看病历原文

#### TC-17 查看质控结果

- 操作：任务完成后打开结果
- 预期：
  - 可查看规则结果
  - 可查看证据与建议

#### TC-18 统计与明细一致

- 预期：
  - 顶部统计
  - 列表计数
  - 任务结果
    三者保持一致

## 7. 验收标准

满足以下条件，可判定本轮功能通过：

1. 客户模板可成功导入
2. 病历池按真实病历聚合，不重复
3. 样本病历可定向同步到本地 PG
4. 病历匹配可正常完成
5. 可勾选部分真实病历发起批量质控
6. 并发病历数设置真实生效
7. 同步和质控任务进度可见
8. 可打开病历原文抽屉
9. 可查看质控结果
10. 页面统计与结果明细一致

## 8. 已知限制

### 8.1 当前验证重点为内涵性质控

本轮重点验证：

- 运行病历内涵问题

不以程序化规则为主。

### 8.2 源数据库访问是前置条件

如果当前环境无法访问客户源数据库：

- 样本病历无法同步
- 病历匹配可能为空
- 批量质控无法真正执行

### 8.3 病历级并发不是无限并发

当前支持的前端可选并发档位：

- `1`
- `2`
- `4`

### 8.4 数据库迁移已做桥接

当前数据库曾存在仓库外 revision：

- `20260409_000018`

现已通过桥接迁移接入当前仓库链路。部署时建议执行：

```powershell
py -3.10 -m alembic -c .\alembic.ini upgrade head
```

## 9. 建议测试顺序

建议实际执行时按以下顺序：

1. TC-01 ~ TC-04
2. TC-05 ~ TC-10
3. TC-11 ~ TC-15
4. TC-16 ~ TC-18

先保证导入、同步、匹配这三步稳定，再测试批量质控。
