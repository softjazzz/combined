# Workstation V4 可自动化测试清单

## 1. 自动化范围

适合自动化的范围只覆盖“是否能跑通”和“是否按预期落库”，不直接判断医疗业务结果是否合理。

可自动化模块：

- 环境准入：`npm run build`、`npm run type-check`、`npm run test:unit:release`
- 后端健康检查：`/api/v1/health`、`/api/v1/ready`
- 数据库结构检查：V4 关键表、关键字段、关键索引存在性
- 鉴权检查：未登录返回 `401`，登录后请求带 `Bearer token`
- 页面可达性：登录后进入 `/workstation-v4` 及左侧正式导航
- 工作台主链路冒烟：列表加载、阶段切换、病历选中、详情面板打开
- 规则页冒烟：编码规则、首页规则、结算规则 3 个标签页
- ICD 查询链路：搜索、展开、结果渲染、编码回填接口成功
- 首页链路：生成草稿、保存、质控、导出接口响应
- 结算链路：结算页加载、结算质控执行、结果渲染
- 闭环链路基础断言：通知、申诉、整改、同步状态的新增或更新

## 2. 自动化准入闸门

上线前建议至少自动化以下检查：

| 类别   | 检查项                      | 通过标准                 |
| ------ | --------------------------- | ------------------------ |
| 工程   | `npm run build`             | 返回 0                   |
| 工程   | `npm run type-check`        | 返回 0                   |
| 工程   | `npm run test:unit:release` | 返回 0                   |
| 后端   | `GET /api/v1/health`        | 200                      |
| 后端   | `GET /api/v1/ready`         | 200                      |
| 数据库 | schema 校验                 | 无缺表缺字段             |
| 鉴权   | 未登录访问规则页接口        | `401 Unauthorized`       |
| 鉴权   | 登录后访问规则页接口        | 200 且带 `Authorization` |
| 前端   | 登录进入 `/workstation-v4`  | 页面加载成功             |
| 主链路 | 首页质控                    | 接口成功且落库成功       |
| 主链路 | 结算质控                    | 接口成功且落库成功       |

## 3. 自动化断言对象

关键断言表：

- 非 CDM：`sys_users`、`sys_departments`、`medical_records`、`medical_documents`、`ai_frontpage_draft`、`qc_result`、`qc_results`、`qc_defects`、`qc_rules`、`document_category_config`、`notifications`、`qc_appeals`、`qc_appeal_reviews`、`qc_remediation_tasks`、`qc_remediation_history`、`sync_visit_status`、`sync_watermarks`
- 可选增强：`document_qc_results`
- CDM：`mr`、`diagnosis`、`mr_surgery`、`mr_cost`、`admission_record`、结算相关主表

典型自动化断言：

- 登录后 `sys_users.last_login_at` 更新
- 生成首页草稿后 `ai_frontpage_draft` 新增或更新
- 首页质控后 `qc_result` 或 `qc_results`、`qc_defects` 有变化
- 文书质控后 `medical_documents.qc_status/qc_score/qc_last_analyzed` 更新
- 通知触发后 `notifications` 有新增
- 申诉整改后 `qc_appeals`、`qc_appeal_reviews`、`qc_remediation_tasks`、`qc_remediation_history` 有变化
- 同步动作后 `sync_visit_status` 或 `sync_watermarks` 有变化

## 4. 自动化边界

以下内容不应只靠自动化放行：

- 首页内容是否医学合理
- 质控结论是否业务合理
- 导出文件内容是否可交付
- 多角色菜单和按钮交互体验
- 复杂文书预览和三栏联动体验

自动化结论只能说明：

- 系统能跑
- 前后端能连
- 数据能落

不能单独说明：

- 业务正确
- 医学正确
- 体验可上线
