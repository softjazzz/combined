# 前端人工核对清单

脚本自动化只覆盖数据链路和接口链路，页面最终放行要靠这份清单兜底。

## 固定核对病例

- `patient_id = P-MOCK-001`
- 主验收病例：`visit_id = V-MOCK-D-001`
- 边界病例：`visit_id = V-MOCK-I-001`

## 核对步骤

- [ ] 登录进入 `/workstation-v4`
- [ ] 能在列表中定位主验收病例并打开详情
- [ ] 病历详情页能看到文书和基础信息
- [ ] 打开“病案首页”，系统首页字段有值或有可解释的空模板
- [ ] 执行首页质控，结果与 `case_e2e_report.json.frontpage_qc_summary` 基本一致
- [ ] 打开“结算清单”，能看到系统生成或同步得到的数据
- [ ] 执行结算质控，结果与 `case_e2e_report.json.settlement_qc_summary` 基本一致
- [ ] 打开分析面板，确认问题数量和级别与脚本报告基本一致
- [ ] 打开消息/通知，确认入口可用且无明显异常
- [ ] 用在院病例复核差异行为：允许结算不足，但不能出现前端崩溃或无解释空白
